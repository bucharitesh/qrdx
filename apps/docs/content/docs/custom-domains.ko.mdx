기본적으로 [동적 QR 코드](/docs/dynamic-qr-codes)에는 `https://qrdx.dev/q/aB3dE5f` 같은 단축 링크가 담깁니다. 사용자 지정 도메인을 연결하면 대신 `https://go.yourbrand.com/aB3dE5f`가 담기므로, 사람들이 스캔하기 전에 브랜드를 먼저 볼 수 있습니다. 리디렉션, 편집, 스캔 분석은 동일하게 작동합니다.

사용자 지정 도메인은 Pro(워크스페이스당 최대 5개)와 Business(최대 25개)에서 사용할 수 있습니다.

## 도메인 연결 [#connect-a-domain]

1. [설정 → 도메인](/dashboard?to=settings/domains)을 열고 `go.yourbrand.com` 같은 도메인을 입력합니다. 기존 웹사이트를 그대로 둘 수 있으므로 서브도메인을 권장합니다.
2. DNS 제공업체(도메인을 구입한 곳, Cloudflare 등)에서 해당 도메인에 표시된 DNS 레코드를 추가합니다.
   - 서브도메인에는 `CNAME` 레코드를 추가합니다.
   - 루트 도메인(`yourbrand.com`)에는 `A` 레코드를 추가합니다.
   - 소유권 확인이 필요하면 `TXT` 레코드도 표시됩니다.

   정확한 값은 대시보드에서 복사하세요. 대부분의 제공업체는 이름에 도메인 앞부분만(`go`, 루트는 `@`) 입력하도록 요구합니다.
3. **확인**을 클릭합니다. DNS 변경은 보통 몇 분 안에 반영되지만 최대 48시간이 걸릴 수 있으므로, 레코드를 아직 찾지 못하면 나중에 다시 시도하세요.

확인이 끝나면 동적 코드를 만들거나 편집할 때 **단축 링크 도메인** 선택기에 해당 도메인이 나타납니다. 확인된 도메인은 제거하기 전까지 확인된 상태로 유지되며, **DNS 확인**을 누르면 언제든 레코드를 다시 읽어옵니다.

<Callout type="info">
  3일 안에 확인되지 않은 도메인은 다른 계정이 추가할 수 있으므로, 직접 관리하지 않는 도메인을 누구도 선점할 수 없습니다.
</Callout>

<IfAvailable feature="domainConnect" id="one-click-dns-setup" title="원클릭 DNS 설정">

일부 DNS 제공업체는 서비스가 대신 레코드를 추가할 수 있게 해 주는 개방형 표준인 [Domain Connect](https://www.domainconnect.org)를 지원합니다. 제공업체가 이를 지원하고 QRdx 설정을 제공하면, DNS를 기다리는 도메인에 제공업체 이름이 들어간 **… 로 설정** 버튼이 표시됩니다.

1. 버튼을 클릭합니다. DNS 제공업체가 열리고 QRdx에 필요한 레코드가 나열됩니다.
2. 요청하면 그곳에서 로그인하고 변경을 승인합니다. 승인하기 전에는 아무것도 바뀌지 않습니다.
3. 도메인 페이지로 돌아오면 바로 DNS를 확인하고, 이후 30초 정도 동안 다시 확인합니다.

이 버튼은 `go.yourbrand.com` 같은 서브도메인에만 나타나며, 제공업체가 표시된 레코드를 정확히 그대로 추가할 수 있을 때만 나타납니다. 그렇지 않으면 위에서 설명한 대로 표의 레코드를 직접 추가하세요.

</IfAvailable>

## 코드에 사용하기 [#use-it-for-codes]

- **새 코드:** **코드 만들기**를 클릭하기 전에 **단축 링크 도메인**에서 도메인을 선택합니다.
- **기존 코드:** **링크 편집**에서 도메인을 선택하고 저장한 다음, 담기는 링크가 바뀌므로 QR 코드를 다시 다운로드합니다.

모든 코드는 기본 링크 `https://qrdx.dev/q/<slug>`에서도 계속 작동하므로, 코드를 도메인으로 옮기기 전에 인쇄한 QR 코드는 끊어지지 않습니다. 하지만 코드를 한 사용자 지정 도메인에서 다른 사용자 지정 도메인으로(또는 기본 링크로) 옮기면 이전 사용자 지정 도메인 링크로 인쇄한 QR 코드는 작동하지 않습니다. 저장하기 전에 대화상자에서 경고해 드려요.

### 나만의 백하프 [#your-own-back-halves]

Pro와 Business에서는 `go.yourbrand.com/spring-menu`처럼 내 도메인에서 코드의 [백하프](/docs/dynamic-qr-codes#custom-back-halves)를 직접 정할 수 있습니다. 백하프는 해당 도메인에서만 고유하면 되므로 다른 QRdx 고객이 `spring-menu`를 쓰고 있어도 상관없으며, 그 도메인에서 예약된 값은 `api`, `p`, `q`뿐입니다. 내 도메인에서 정한 백하프는 그 도메인에 속하며 `qrdx.dev/q/` 링크가 없습니다. 이런 코드를 다른 도메인으로 옮기면 그 도메인에서 사용 가능할 때 백하프가 유지되고, 기본 링크로 되돌리면 `qrdx.dev`에서 사용 가능할 때 유지되며, 그렇지 않으면 새로 생성된 백하프가 부여됩니다.

내 도메인에서는 다음과 같이 동작합니다.

- `https://go.yourbrand.com/<slug>`는 해당 도메인을 사용하는 코드로 리디렉션합니다. 다른 도메인이나 기본 링크만 사용하는 코드는 이곳에서 "찾을 수 없음" 페이지가 표시됩니다.
- `https://go.yourbrand.com/`에는 이 도메인이 QR 코드 링크를 호스팅한다는 간단한 페이지가 표시됩니다.
- `https://go.yourbrand.com/01/<GTIN>`([GS1 Digital Link](/docs/product-pages#gs1-digital-link))은 해당 GTIN을 가지며 코드가 이 도메인을 사용하는 제품 페이지를 엽니다.
- 그 밖의 모든 경로는 "찾을 수 없음"을 반환합니다. 이 도메인은 QRdx의 나머지 부분을 제공하지 않습니다.

변경 사항(새로 확인했거나 제거한 도메인)이 모든 서버에 반영되기까지 최대 1분이 걸립니다.

## 워크스페이스와 역할 [#workspaces-and-roles]

도메인은 추가한 워크스페이스에 속합니다. 소유자와 관리자가 도메인을 추가, 확인, 제거할 수 있으며, 모든 멤버는 워크스페이스의 확인된 도메인을 자신의 코드에 사용할 수 있습니다.

## 요금제와 도메인 제거 [#plans-and-removing-domains]

- 다운그레이드해도 문제가 생기지 않습니다. 확인된 도메인은 이를 사용하는 코드를 계속 제공합니다. Pro나 Business가 없으면 도메인을 추가하거나 확인할 수 없고 더 많은 코드를 도메인으로 옮길 수도 없지만, 해당 코드를 편집하고 도메인을 제거하는 것은 계속 가능합니다.
- 도메인을 제거하면 그 도메인의 코드는 기본 링크 `qrdx.dev/q/<slug>`로 되돌아갑니다. 도메인에서 정한 백하프는 `qrdx.dev`에서 사용 가능하면 그쪽으로 옮겨지고, 나머지는 새로 생성된 백하프를 받습니다. 사용자 지정 도메인 링크로 인쇄한 QR 코드는 작동하지 않으므로, 대화상자에 먼저 해당 도메인을 사용하는 코드 수가 표시됩니다.

## REST API [#rest-api]

[코드 API](/docs/dynamic-qr-codes#rest-api)는 `POST /v1/codes`와 `PATCH /v1/codes/{id}`에서 `domainId`(같은 워크스페이스에서 확인된 도메인의 ID)를 받습니다. `PATCH`에서 `"domainId": null`을 보내면 기본 링크로 되돌립니다. 코드를 도메인으로 옮기려면 Pro가 필요하며, 그렇지 않으면 `402 PLAN_REQUIRED`가 반환됩니다.

응답의 각 코드에는 다음 필드가 포함됩니다.

| 필드 | 설명 |
| --- | --- |
| `shortLink` | 담을 링크: 확인된 후에는 사용자 지정 도메인의 링크 |
| `defaultShortLink` | 항상 작동하는 `https://qrdx.dev/q/<slug>`. 사용자 지정 도메인에서 정한 백하프는 `null` |
| `domain` | `{ "id", "hostname", "verified" }` 또는 `null` |

## 셀프 호스팅 [#self-hosting]

도메인을 연결하는 방법은 배포 환경에 따라 다릅니다.

- **Vercel에서:** `VERCEL_API_TOKEN`(프로젝트에 접근할 수 있는 토큰), `VERCEL_PROJECT_ID`, 팀 프로젝트라면 `VERCEL_TEAM_ID`도 설정합니다. 그러면 Vercel Domains API를 통해 프로젝트에 도메인이 추가되며, TLS 인증서도 함께 발급됩니다. 이 변수가 없으면 Vercel은 프로젝트에 추가된 도메인만 라우팅하므로, 도메인 페이지에 사용자 지정 도메인이 설정되지 않았다고 안내됩니다.
- **그 외 환경**(Docker, Node.js): 해당 변수를 설정하지 않은 채로 둡니다. 도메인은 수동으로 확인합니다.
  1. `CNAME`(앱의 호스트 이름으로) 또는 `A` 레코드(서버의 IP)로 도메인이 서버를 가리키게 합니다.
  2. 리버스 프록시가 해당 도메인을 받아들이고, 그 도메인에 HTTPS를 제공하며(예: Caddy의 on-demand TLS 또는 certbot 인증서), 원래의 `Host` 헤더를 앱에 전달하게 설정합니다. nginx에서는 `proxy_set_header Host $host;`이며, Caddy는 기본으로 그렇게 합니다.
  3. 도메인 페이지에서 도메인을 추가하고, 표시된 `TXT` 레코드(`_qrdx-challenge.<your-domain>`, 값은 `qrdx-verify=<token>`)를 만든 다음 **확인**을 클릭합니다. 앱은 DNS 조회로 레코드를 확인합니다.

**원클릭 DNS 설정**(선택 사항)은 [Domain Connect](https://www.domainconnect.org)를 사용합니다. 지원하려는 각 DNS 제공업체가 승인한 자체 템플릿과 설정 링크에 서명하는 RSA 키가 필요합니다. `DOMAIN_CONNECT_PROVIDER_ID`, `DOMAIN_CONNECT_SERVICE_ID`, `DOMAIN_CONNECT_PRIVATE_KEY`(PEM)를 설정하고, 공개 키를 `_dck1.<provider id>`의 `TXT` 레코드로 게시하세요. 저장소의 QRdx 자체 템플릿(`domain-connect/`)은 제공업체가 서명을 QRdx의 키와 대조해 확인하므로 qrdx.dev에서만 작동합니다. 게시한 키가 일치하기 전까지는 버튼이 표시되지 않으며, 앱이 그 이유를 로그에 남깁니다.

앱은 `Host` 헤더로 사용자 지정 도메인을 인식합니다. 앱 자체 URL, `NEXT_PUBLIC_SHORT_LINK_BASE_URL`, `localhost`, `*.vercel.app`으로 들어오는 요청은 항상 메인 앱으로 처리됩니다.
