By the end of this guide you will have QRdx running at your own URL: the QR editor, accounts, dynamic QR codes with scan analytics, hosted pages, workspaces and saved themes, on a Postgres database you control. The Docker Compose path takes about half an hour, most of it the first image build.

The web app is open source under the AGPL-3.0 license. Two parts are not: workspace single sign-on and the audit log live in the `ee/` folders under the QRdx commercial license and stay off unless you set a license key (`QRDX_EE_LICENSE`). Using them in production needs a written agreement with QRdx; see [LICENSING.md](https://github.com/qrdxinc/qrdx/blob/main/LICENSING.md). You don't need any of this to use the [`qrdx` React library](/docs/getting-started) or the [CLI](/docs/developers/cli): they run anywhere without a backend, under the MIT license. [Open source at QRdx](/open-source-qr-code-generator) lists each part of the repository and its license.

<Callout type="warn" title="The Docker setup is new">
  If a step doesn't work as written, [open an issue](https://github.com/qrdxinc/qrdx/issues) with the command you ran and its output.
</Callout>

## Before you start

- Docker with Compose v2 and BuildKit (Docker Desktop and current Docker Engine include both), or Node.js 22 (22.22.3 or later) and [Bun](https://bun.com/docs/installation) 1.4 for the manual setup.
- At least 8 GB of memory for Docker while the image builds.
- A way to sign in, so accounts can be created: a GitHub or Google OAuth app, or [Resend](https://resend.com) for email sign-in codes. Sign-in codes are emailed only when `NEXT_PUBLIC_APP_URL` isn't `localhost`. `bun run dev` prints them in the terminal instead, but the Docker image doesn't, so a local Docker test needs GitHub or Google sign-in.
- Postgres: the container bundled in `docker-compose.yml`, or a [Neon](https://neon.tech) database.
- For anything beyond a local test, a domain and a reverse proxy that terminates HTTPS.

The docs are not part of a self-hosted instance. Your instance sends every docs link (`/docs` and the pages under it, their Markdown copies and `/llms-full.txt`) to the same pages on qrdx.dev.

### How the database connection works

The app talks to Postgres through Neon's serverless HTTP driver.

- **Neon:** works directly. Set `DATABASE_URL` to your Neon connection string.
- **Plain Postgres:** needs a Neon-compatible HTTP proxy in front of it. `docker-compose.yml` runs one ([local-neon-http-proxy](https://github.com/TimoWilhelm/local-neon-http-proxy)) and sets `DATABASE_HTTP_ENDPOINT` so the app sends its queries there.

The schema comes from `packages/database/schema.ts` and is applied with `drizzle-kit push`. There are no migration files to run by hand.

## Quick start with Docker Compose

### 1. Clone the repository

```bash title="Terminal"
git clone https://github.com/qrdxinc/qrdx.git
cd qrdx
```

### 2. Configure the environment

Copy the example file to the repository root, where Compose reads it, and generate the session secret:

```bash title="Terminal"
cp apps/app/.env.example .env
openssl rand -base64 32
# prints a 44-character string: paste it as BETTER_AUTH_SECRET below
```

Open `.env` and set these values. Every other line can stay commented out.

```bash title=".env"
NEXT_PUBLIC_APP_URL=https://qr.example.com
BETTER_AUTH_URL=https://qr.example.com
BETTER_AUTH_SECRET=<the string openssl printed>

# One sign-in provider. The callback URL for GitHub is
# <NEXT_PUBLIC_APP_URL>/api/auth/callback/github
GITHUB_CLIENT_ID=<client ID of your GitHub OAuth app>
GITHUB_CLIENT_SECRET=<its client secret>
```

Where each value comes from:

| Variable | Where to get it |
| --- | --- |
| `NEXT_PUBLIC_APP_URL` | The public URL of your instance, no trailing slash. Keep `http://localhost:3000` for a local test. |
| `BETTER_AUTH_URL` | The same value. Uncomment the line. |
| `BETTER_AUTH_SECRET` | The output of `openssl rand -base64 32`. |
| `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET` | A [GitHub OAuth app](https://github.com/settings/developers) whose callback URL is `<your url>/api/auth/callback/github`. |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | Instead of GitHub: a [Google OAuth client](https://console.cloud.google.com/apis/credentials) whose redirect URI is `<your url>/api/auth/callback/google`. |

Leave `DATABASE_URL` as it is: Compose points the app at its own Postgres container and ignores the value in `.env`. To change the database password, set `POSTGRES_PASSWORD` before the first start.

### 3. Start the stack

```bash title="Terminal"
docker compose up -d --build
```

This builds the image, starts Postgres and the proxy, runs the one-shot `migrate` service (`drizzle-kit push`) and then starts the app on port 3000. The first build takes several minutes. When it's done, the four services look like this:

```text title="docker compose ps (columns trimmed)"
NAME              SERVICE    STATUS
qrdx-db-1         db         running (healthy)
qrdx-db-proxy-1   db-proxy   running
qrdx-migrate-1    migrate    exited (0)
qrdx-app-1        app        running
```

`migrate` is meant to exit: it syncs the schema and stops. To watch the schema sync and the app start:

```bash title="Terminal"
docker compose logs -f migrate app
```

### 4. Sign in

Open `NEXT_PUBLIC_APP_URL` in a browser and sign in with GitHub, Google or an email code. Your account is created on first sign-in.

### 5. Make yourself an admin

Add the email address of the account you created in step 4 to `.env`:

```bash title=".env"
ADMIN_EMAILS=you@example.com
```

Recreate the app container so it reads the change, then sign in and open `/admin`:

```bash title="Terminal"
docker compose up -d app
```

The address becomes an admin the first time it opens `/admin`. `ADMIN_USER_IDS` works the same way with user ids.

## Use Neon or another managed Postgres

You can skip the bundled Postgres and run only the app image. Set `DATABASE_URL` in `.env` to your Neon connection string and leave `DATABASE_HTTP_ENDPOINT` unset.

```bash title="Terminal"
docker build -t qrdx --build-arg NEXT_PUBLIC_APP_URL=https://qr.example.com .
docker run -d --env-file .env -p 3000:3000 qrdx
```

Apply the schema once, and again after each update, with the migrator image:

```bash title="Terminal"
docker build --target migrator -t qrdx-migrate .
docker run --rm -e DATABASE_URL="<your connection string>" qrdx-migrate
```

## Manual setup with Node.js

```bash title="Terminal"
git clone https://github.com/qrdxinc/qrdx.git
cd qrdx
bun install

cp apps/app/.env.example apps/app/.env.local   # then edit it as in step 2

bun run db:push                                # apply the schema
bun run --filter app dev                       # http://localhost:3000
```

For production, build and start the app:

```bash title="Terminal"
bun x turbo build --filter=app
bun run --filter app start
```

`bun run db:push` connects with Neon's driver, so it needs a Neon database. To use the Docker Postgres for local development instead, start it with `docker compose up -d db db-proxy`, apply the schema with `docker compose run --rm migrate`, and set these in `apps/app/.env.local`:

```bash title="apps/app/.env.local"
DATABASE_URL=postgresql://postgres:postgres@localhost:5432/qrdx
DATABASE_HTTP_ENDPOINT=http://localhost:4444/sql
```

## Environment variables

[`apps/app/.env.example`](https://github.com/qrdxinc/qrdx/blob/main/apps/app/.env.example) lists every variable with a note on where to get it. The app checks every value when it starts and refuses to start on a missing required value or an invalid one, naming the variable.

### Required

| Variable | Purpose |
| --- | --- |
| `NEXT_PUBLIC_APP_URL` | Public URL of your instance |
| `DATABASE_URL` | Postgres connection string (set by Compose) |
| `BETTER_AUTH_SECRET` | Signs sessions and cookies |

Add one OAuth provider (GitHub or Google), or Resend for email sign-in codes, so people can sign in.

<Callout type="info" title="NEXT_PUBLIC_* values are fixed at build time">
  `NEXT_PUBLIC_*` values are inlined into the browser bundle when the app is built, so changing one means rebuilding. The Docker build reads `.env` only for six of them, passed as build arguments in `docker-compose.yml`: `NEXT_PUBLIC_APP_URL`, `NEXT_PUBLIC_POSTHOG_KEY`, `NEXT_PUBLIC_POSTHOG_HOST`, `NEXT_PUBLIC_FEATUREBASE_APP_ID` and the two Pro product ids. To set another one in the Docker image (the Business product ids, `NEXT_PUBLIC_QRDX_EUR_PRICES`, `NEXT_PUBLIC_SHORT_LINK_BASE_URL`, the Turnstile site key or the Umami ids), add it to the `app` service's `build.args` in `docker-compose.yml` and as an `ARG` in the Dockerfile's build stage, then run `docker compose up -d --build`. The manual setup reads them all from `apps/app/.env.local`.
</Callout>

### Scheduled jobs

Two routes do the recurring work: `/api/cron/webhooks` retries failed webhook deliveries and deletes old audit log rows, and `/api/cron/digest` sends the weekly digest. On Vercel, `apps/app/vercel.json` schedules them. Anywhere else, nothing calls them until you do. Set `CRON_SECRET` and call both from your scheduler with it:

```text title="crontab (times in UTC)"
0 4 * * *  curl -fsS -H "Authorization: Bearer $CRON_SECRET" https://qr.example.com/api/cron/webhooks
0 9 * * 1  curl -fsS -H "Authorization: Bearer $CRON_SECRET" "https://qr.example.com/api/cron/digest?shard=all"
```

Without the header, the routes answer `401` in production. [Notifications](/docs/notifications#self-hosting) explains the digest's `shard` parameter.

## Reverse proxy and HTTPS

Put the app behind a reverse proxy such as Caddy, nginx or Traefik that terminates TLS, and don't expose port 3000 to the internet directly. Rate limiting, the security emails and the [audit log](/docs/help/teams/audit-log) read the client IP from `X-Real-IP` first and then from the first `X-Forwarded-For` address (on Vercel, `X-Vercel-Forwarded-For` comes in between), so the proxy must set these headers and the app must only be reachable through it. Have the proxy set `X-Real-IP` to the address it received the connection from. A proxy that only appends to `X-Forwarded-For` lets a client put any address first.

```nginx title="nginx server block (the relevant lines)"
location / {
  proxy_pass http://127.0.0.1:3000;
  proxy_set_header Host $host;
  proxy_set_header X-Real-IP $remote_addr;
  proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
  proxy_set_header X-Forwarded-Proto $scheme;
}
```

Caddy sets these headers by default. Once HTTPS works, change `NEXT_PUBLIC_APP_URL` and `BETTER_AUTH_URL` to the `https://` URL, update the OAuth callback URLs, and rebuild.

### Content-Security-Policy

Production builds send a Content-Security-Policy on QRdx's own pages: signed-in pages get a fresh script nonce per request, prerendered pages an allowlist of script hosts. Hosted pages (`/p`) get a loose policy, because they run the owner's pixels and embed media from anywhere. If your reverse proxy also sets `Content-Security-Policy`, browsers enforce both, so leave it out there. Set `CSP_REPORT_ONLY=1` to send the policy as report-only while you check a new setup; violations are logged by `/api/csp-report`. Add `CSP_HTTPS=1` when you serve over HTTPS outside Vercel, so browsers upgrade any `http://` resource. Both are read where the app runs and, for the prerendered pages' header, where it is built; the Dockerfile doesn't pass them to the build, so add them as build arguments too if the prerendered pages need them.

## Update QRdx

Back up the database first (see below). Then pull and rebuild. The `migrate` service syncs the schema again before the app starts.

```bash title="Terminal"
git pull
docker compose up -d --build
```

For the manual setup, run `git pull`, `bun install` and `bun run db:push`, then rebuild and restart.

If a schema change would drop data, `drizzle-kit push` asks for confirmation and the `migrate` service waits for an answer it can't get. In that case, run it in a terminal to review and confirm the changes:

```bash title="Terminal"
docker compose run --rm migrate
```

## Back up and restore

Everything QRdx stores is in Postgres, except uploaded files, which are in your R2 bucket. Dump the database before every update and on a schedule:

```bash title="Terminal"
docker compose exec db pg_dump -U postgres qrdx > qrdx-backup.sql
```

To restore into an empty database:

```bash title="Terminal"
docker compose exec -T db psql -U postgres qrdx < qrdx-backup.sql
```

With Neon, use its own backups and branching instead.

## What is different from qrdx.dev

- **Docs** open on qrdx.dev. Your instance redirects every docs URL there.
- **Payments and plans** need Polar. Without it, every account has the Free limits, and nobody can upgrade. The limits themselves are in `apps/app/lib/plans.ts`, which you can change for your instance.
- **The affiliate program, pay-by-invoice requests, non-profit discounts and the enterprise contact form** are QRdx's own sales and run only where QRdx itself runs. A self-hosted copy has none of them.
- **Scan locations:** country, region and city come from Vercel's geo headers. Behind Cloudflare only the country is read (`CF-IPCountry`); elsewhere locations show as unknown, and [area rules](/docs/precise-location#route-scans-by-area) only match scans with a shared location.
- **Custom domains** are verified with a DNS `TXT` record and routed by your reverse proxy, unless you run on Vercel with the Domains API variables set. The **Set up with …** button needs your own Domain Connect template: QRdx's works only for qrdx.dev.
- **Chat bots and integrations** each need an app you register with that service (see the table above).
- **Admin pages** are served by the app itself; qrdx.dev proxies some of them to a separate console.

## Troubleshooting

### "Invalid environment variables" on startup

The log names each missing or invalid variable, then says where to set it. A required value is missing, or an optional one is set to something invalid: a URL that isn't a full `http://` or `https://` address, or a secret that is too short. An empty value counts as unset and is fine. Fix the named variables in `.env` and recreate the container with `docker compose up -d app`.

### OAuth `redirect_uri` mismatch

The callback URL in your OAuth app must be exactly `<NEXT_PUBLIC_APP_URL>/api/auth/callback/github` or `/api/auth/callback/google`. Set `BETTER_AUTH_URL` to the same base URL as `NEXT_PUBLIC_APP_URL`.

### The app can't reach the database (`fetch failed`)

With plain Postgres, `DATABASE_HTTP_ENDPOINT` must point at the running proxy. Check `docker compose ps db-proxy` shows it running.

### `migrate` never finishes

`drizzle-kit push` is waiting for a confirmation. Run `docker compose run --rm migrate` in a terminal and answer it; see [Update QRdx](#update-qrdx).

### A changed `NEXT_PUBLIC_*` value has no effect

Rebuild the image: `docker compose up -d --build`.

### Port 4444 is already in use

Change the `db-proxy` port mapping in `docker-compose.yml`. Only local development on the host uses it.

### "the --mount option requires BuildKit"

Your Docker has no BuildKit. Install the `buildx` plugin, or update Docker.

### The build stops with `Killed` or exit code 137

Docker ran out of memory. Give it at least 8 GB (Docker Desktop: **Settings** → **Resources**) and run `docker compose up -d --build` again.

### "sign-in code email is off for this deployment"

Email codes aren't sent while `NEXT_PUBLIC_APP_URL` is `localhost`. Use GitHub or Google sign-in for a local test.

Still stuck? [Open an issue](https://github.com/qrdxinc/qrdx/issues) with the output of `docker compose logs app`, with secrets removed.
