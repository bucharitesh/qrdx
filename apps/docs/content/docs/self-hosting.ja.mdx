QRdx は AGPL-3.0 ライセンスで公開されており、Web アプリ（QR エディタ、アカウント、2 段階認証とパスキー、動的コードとホスト型ページ、チーム、保存済みテーマ、コミュニティギャラリー、このドキュメント）を自分のサーバーで実行できます。ワークスペースのシングルサインオンとワークスペースの監査ログは例外です。これらは商用ライセンスの `ee/` フォルダーに含まれており、ライセンスキー（`QRDX_EE_LICENSE`）を設定しない限り無効のままです。本番環境で使用するには、QRdx との書面による契約が必要です。詳しくは [LICENSING.md](https://github.com/bucharitesh/qrdx/blob/main/LICENSING.md) をご覧ください。[`qrdx` React ライブラリ](/docs/getting-started)や CLI を使うだけであれば、これらは一切不要です。どちらもバックエンドなしでどこでも動作します。

<Callout type="warn">
  Docker のセットアップは新しい機能です。うまく動作しない場合は、[Issue を作成](https://github.com/bucharitesh/qrdx/issues)してください。
</Callout>

## 要件 [#requirements]

- Compose v2 と BuildKit を備えた Docker（Docker Desktop と最新の Docker Engine にはどちらも含まれています）、または手動セットアップ用の Node.js 22（22.22.3 以降）と [Bun](https://bun.com/docs/installation) 1.4
- イメージのビルド中に Docker が使用できる 8 GB 以上のメモリ
- アカウントを作成できるサインイン手段：GitHub または Google の OAuth アプリ、あるいはメールのサインインコード用の [Resend](https://resend.com)。コードがメールで送信されるのは、`NEXT_PUBLIC_APP_URL` が `localhost` ではない場合のみです。`bun run dev` ではコードがターミナルに表示されますが、Docker イメージでは表示されないため、ローカルで Docker をテストする場合は GitHub または Google でのサインインが必要です。
- Postgres：`docker-compose.yml` に同梱のコンテナ、または [Neon](https://neon.tech) のデータベース

### データベース接続の仕組み [#how-the-database-connection-works]

アプリは Neon のサーバーレス HTTP ドライバーを通じて Postgres と通信します。

- **Neon：** そのまま動作します。`DATABASE_URL` に Neon の接続文字列を設定してください。
- **通常の Postgres：** 前段に Neon 互換の HTTP プロキシが必要です。`docker-compose.yml` ではプロキシ（[local-neon-http-proxy](https://github.com/TimoWilhelm/local-neon-http-proxy)）を起動し、`DATABASE_HTTP_ENDPOINT` を設定して、アプリのクエリがそこへ送られるようにしています。

スキーマは `packages/database/schema.ts` にあり、`drizzle-kit push` で適用されます。

## Docker Compose でのクイックスタート [#quick-start-with-docker-compose]

### 1. リポジトリをクローンする [#1-clone-the-repository]

```bash
git clone https://github.com/bucharitesh/qrdx.git
cd qrdx
```

### 2. 環境を設定する [#2-configure-the-environment]

```bash
cp .env.example .env
```

`.env` を編集します。

- `BETTER_AUTH_SECRET`：`openssl rand -base64 32` で生成します
- `NEXT_PUBLIC_APP_URL`：インスタンスの公開 URL です。例：`https://qr.example.com`。ローカルでテストする場合は `http://localhost:3000` のままにしてください。
- `BETTER_AUTH_URL`：コメントアウトを外し、同じ値を設定します
- `GITHUB_CLIENT_ID` / `GITHUB_CLIENT_SECRET`：コールバック URL を `<your url>/api/auth/callback/github` に設定した [GitHub OAuth アプリ](https://github.com/settings/developers)から取得します
- または `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET`：リダイレクト URI を `<your url>/api/auth/callback/google` に設定した [Google OAuth クライアント](https://console.cloud.google.com/apis/credentials)から取得します

`DATABASE_URL` を設定する必要はありません。Compose がアプリを専用の Postgres コンテナに接続します。データベースのパスワードを変更するには、最初の起動前に `POSTGRES_PASSWORD` を設定してください。

### 3. スタックを起動する [#3-start-the-stack]

```bash
docker compose up -d --build
```

イメージをビルドし、Postgres とプロキシを起動し、1 回限りの `migrate` サービス（`drizzle-kit push`）を実行してから、ポート 3000 でアプリを起動します。初回のビルドには数分かかります。

```bash
docker compose ps                    # migrate should show "exited (0)"
docker compose logs -f migrate app   # follow the schema sync and the app
```

### 4. 最初のユーザーを作成する [#4-create-your-first-user]

ブラウザーで `NEXT_PUBLIC_APP_URL` を開き、GitHub、Google、またはメールコードでサインインします。アカウントは初回サインイン時に作成されます。

### 5. 最初の管理者を作成する [#5-create-your-first-admin]

作成したアカウントのメールアドレスを `.env` に追加します。

```bash
ADMIN_EMAILS=you@example.com
```

変更を反映するためにアプリのコンテナを再作成し、サインインして `/admin` を開きます。

```bash
docker compose up -d app
```

`ADMIN_USER_IDS` も同様に動作し、こちらはユーザー ID を指定します。

## Neon などのマネージドデータベースを使う [#using-neon-or-another-managed-database]

同梱の Postgres を使わず、アプリのイメージだけを実行できます。

```bash
docker build -t qrdx --build-arg NEXT_PUBLIC_APP_URL=https://qr.example.com .
docker run -d --env-file .env -p 3000:3000 qrdx
```

`.env` の `DATABASE_URL` に Neon の接続文字列を設定し、`DATABASE_HTTP_ENDPOINT` は未設定のままにします。スキーマは、マイグレーター用イメージで 1 回適用してください（更新のたびに再度適用します）。

```bash
docker build --target migrator -t qrdx-migrate .
docker run --rm -e DATABASE_URL="<your connection string>" qrdx-migrate
```

## 手動セットアップ（Node.js） [#manual-setup-nodejs]

```bash
git clone https://github.com/bucharitesh/qrdx.git
cd qrdx
bun install

cp .env.example apps/docs/.env.local                    # then edit it
echo 'DATABASE_URL=<your connection string>' > packages/database/.env

bun run db:push                                          # apply the schema
bun run --filter docs dev                                # http://localhost:3000
```

本番環境では、アプリをビルドして起動します。

```bash
bun x turbo build --filter=docs
bun run --filter docs start
```

`bun run db:push` は Neon のドライバーで接続するため、Neon のデータベースが必要です。ローカル開発で代わりに Docker の Postgres を使うには、`docker compose up -d db db-proxy` で起動し、`docker compose run --rm migrate` でスキーマを適用して、`apps/docs/.env.local` に次の値を設定します。

```bash
DATABASE_URL=postgresql://postgres:postgres@localhost:5432/qrdx
DATABASE_HTTP_ENDPOINT=http://localhost:4444/sql
```

## リバースプロキシとHTTPS [#reverse-proxy-and-https]

TLSを終端するCaddy、nginx、Traefikなどのリバースプロキシの背後にアプリを置き、ポート3000をインターネットに直接公開しないでください。レート制限、セキュリティ関連のメール、[監査ログ](/docs/help/teams/audit-log)は、クライアントIPを `X-Real-IP` から、次に `X-Forwarded-For` の最初のアドレスから読み取ります。そのため、プロキシがこれらのヘッダーを設定し、アプリにはプロキシ経由でのみ到達できるようにしてください。プロキシには、接続を受け付けた元のアドレスを `X-Real-IP` に設定させます（nginxでは `proxy_set_header X-Real-IP $remote_addr;`）。`X-Forwarded-For` に追記するだけのプロキシでは、クライアントが先頭に任意のアドレスを入れられてしまいます。

HTTPSを設定したら、`NEXT_PUBLIC_APP_URL` と `BETTER_AUTH_URL` を `https://` のURLに変更し、OAuthのコールバックURLを更新して、再ビルドしてください。

### Content-Security-Policy [#content-security-policy]

本番ビルドでは、QRdx自身のページでContent-Security-Policyが送信されます。サインイン済みのページにはリクエストごとに新しいスクリプトnonceが付与され、プリレンダリングされたページにはスクリプトホストの許可リストが適用されます。ホスト型ページ（`/p`）には緩いポリシーが適用されます。所有者のピクセルが実行され、任意の場所のメディアが埋め込まれるためです。リバースプロキシでも `Content-Security-Policy` を設定すると、ブラウザーは両方を適用するため、プロキシ側では設定しないでください。新しい環境を確認する間は、`CSP_REPORT_ONLY=1` をビルド時と実行時に設定すると、ポリシーがレポート専用で送信されます。違反は `/api/csp-report` でログに記録されます。Vercel以外でHTTPS配信する場合は `CSP_HTTPS=1` を追加すると、ブラウザーが `http://` のリソースをアップグレードします。

## アップデート [#updating]

まず、データベースをバックアップします。

```bash
docker compose exec db pg_dump -U postgres qrdx > qrdx-backup.sql
```

次に、pullして再ビルドします。`migrate` サービスが、アプリの起動前に再度スキーマを同期します。

```bash
git pull
docker compose up -d --build
```

手動セットアップの場合は、`git pull`、`bun install`、`bun run db:push` を実行してから再ビルドしてください。

スキーマの変更でデータが削除される場合、`drizzle-kit push` は確認を求めます。その場合は、ターミナルで `docker compose run --rm migrate` を実行して、変更内容を確認し承認してください。
## トラブルシューティング [#troubleshooting]

- **起動時に「Invalid environment variables」と表示される:** ログに、不足している変数や無効な変数の名前が表示されます。省略可能な変数は、空の値を設定するのではなく、コメントアウトしてください。
- **「BETTER_AUTH_SECRET is missing」または「You are using the default secret」と表示される:** `BETTER_AUTH_SECRET` を設定し、コンテナーを再作成してください。
- **OAuthの `redirect_uri` が一致しない:** OAuthアプリに設定するコールバックURLは、必ず `<NEXT_PUBLIC_APP_URL>/api/auth/callback/<github|google>` にしてください。`BETTER_AUTH_URL` にも同じベースURLを設定します。
- **アプリがデータベースに接続できない(`fetch failed`):** 通常のPostgresを使う場合、`DATABASE_HTTP_ENDPOINT` は稼働中のプロキシを指している必要があります。`docker compose ps db-proxy` で確認してください。
- **`migrate` が終了しない:** `drizzle-kit push` が確認入力を待っています。[アップデート](#updating)を参照してください。
- **`NEXT_PUBLIC_*` の値を変更しても反映されない:** イメージを再ビルドしてください。
- **ポート4444がすでに使用されている:** `docker-compose.yml` の `db-proxy` のポートマッピングを変更してください。このポートを使うのは、ホスト上でのローカル開発のみです。
- **「the --mount option requires BuildKit」と表示される:** お使いのDockerにBuildKitがありません。`buildx` プラグインをインストールするか、Dockerをアップデートしてください。
- **ビルドが `Killed` または終了コード137で停止する:** Dockerのメモリが不足しています。8 GB以上を割り当て(Docker Desktop: 設定 → Resources)、`docker compose up -d --build` をもう一度実行してください。
- **「sign-in code email is off for this deployment」と表示される:** `NEXT_PUBLIC_APP_URL` が `localhost` の間は、メールコードは送信されません。ローカルでテストする場合は、GitHubまたはGoogleでサインインしてください。
