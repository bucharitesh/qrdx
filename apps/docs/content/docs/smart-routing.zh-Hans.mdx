[动态二维码](/docs/dynamic-qr-codes)通常会把每次扫描都发送到同一个目标地址。使用智能路由后，同一个印刷出来的二维码可以在 iPhone 上打开 App Store，在 Android 上打开 Google Play，为西班牙语访客打开西班牙语页面，或者在非营业时间显示不同的优惠。你可以在[控制台](/dashboard?to=codes)中该二维码的页面里，通过 **智能路由** 面板进行设置（打开一个二维码，然后打开它的 **设置** 标签页）。

智能路由和 UTM 参数属于 Pro 和 Business 的功能。它们适用于打开网站链接的二维码；[托管页面](/docs/landing-pages)不会重定向，因此没有路由功能。

## 规则的工作方式 [#how-rules-work]

- 每个二维码最多可以有 20 条**规则**。每条规则包含条件（“当”）和动作（“则”）。
- 每次扫描时，规则会**从上到下**依次检查。**第一条所有条件都匹配的规则**决定这次扫描的去向。可以使用箭头调整规则顺序。
- 没有任何规则匹配时，扫描会前往二维码的主目标地址。
- 没有条件的规则会匹配每一次扫描，因此排在它后面的规则永远不会运行。
- 将规则**关闭**即可保留它但不使用。
- 更改会对下一次扫描生效；你无需重新印刷二维码。

如果某条规则因故无法判断，扫描仍会前往主目标地址：路由绝不会导致二维码失效。

## 条件 [#conditions]

每个条件都可以用 **不是** 反选（例如“国家不是 US”）。

| 条件 | 匹配时机 | 说明 |
| --- | --- | --- |
| 设备 | 扫描者使用手机、平板、桌面设备或其他设备 | 来自浏览器的 user agent |
| 操作系统 | iOS、Android、Windows、macOS、Linux、ChromeOS、HarmonyOS 等 | iPhone 和 iPad 都算作 iOS |
| 国家 | 扫描来自所列国家之一 | 2 位字母代码，如 `US, CA, GB` |
| 地区 | 扫描来自所列地区之一 | 如 `US-CA, US-NY` 这样的代码（国家 + 行政区） |
| 语言 | 访客的浏览器首选语言是所列语言之一 | `es` 匹配所有西班牙语变体（`es-MX`、`es-ES`）；`pt-BR` 仅匹配巴西葡萄牙语 |
| 时段 | 扫描发生在所选的星期几，且在你选定时区的两个时间点之间 | 像 22:00–02:00 这样的时间段会跨过午夜，并归属于它开始的那一天 |
| 日期范围 | 扫描发生在两个日期之间 | 一侧留空表示“截至”或“自”；日期使用你浏览器的时区 |
| 扫描次数 | 是前 N 次扫描之一，或第 N 次之后的任意扫描 | 统计已记录的扫描（不含机器人），因此在许多人同时扫描时只是近似值 |
| 区域 | 扫描者位于某个点的指定半径（100 米到 500 公里）内 | 开启[精确位置](/docs/precise-location)时使用扫描者共享的位置，否则使用其 IP 地址的大致位置 |

国家、地区以及区域所用的基于 IP 的位置都来自扫描者的 IP 地址，QRdx 不会存储该地址。位置未知时，位置条件不会匹配（而“不是”条件会匹配）。[精确位置与地理围栏](/docs/precise-location)介绍了区域设置，包括如何让二维码只在某个区域内生效。

## 智能应用链接 [#smart-app-links]

选择 **添加规则 → 智能应用链接**，可一次创建两条规则：iOS 前往你的 App Store 链接，Android 前往你的 Google Play 链接。其他所有人（桌面设备、其他手机）前往主目标地址，例如你的网站。

## A/B 测试 [#ab-tests]

将规则的动作设为 **在多个 URL 之间分流 (A/B)**，然后添加 2 到 5 个变体，每个变体包含一个 URL 和一个权重。70 和 30 的分配会把大约 70% 的访客发送到第一个 URL。

- 分配是**固定的**：同一天再次扫描的访客会得到相同的变体。它基于匿名的每日访客哈希，绝不使用 Cookie。
- 二维码的分析会显示自分流的变体或权重上次更改以来**每个变体的扫描次数**。每次扫描都会记录它所得到的变体。在 QRdx 开始记录变体之前的扫描，会按你当前的规则重新推算，并且该卡片会标记为估算值。
- 分流也可以带有条件，例如“仅对德国的访客进行 A/B 测试”。

## 测试你的规则 [#test-your-rules]

面板底部的 **测试你的规则** 会基于你尚未保存的更改，显示在任意设备、操作系统、国家、地区、语言、日期和时间、扫描序号及访客条件下，一次扫描会前往哪里。它会列出匹配的规则以及其他规则未匹配的原因，并显示包含 UTM 参数的最终 URL。

## UTM 参数 [#utm-parameters]

**UTM 参数** 面板会把 `utm_source`、`utm_medium`、`utm_campaign`、`utm_term`、`utm_content` 以及最多 10 个你自己的参数添加到每次扫描打开的 URL 中，以便分析工具区分二维码带来的流量。

- 参数在路由之后添加，附加到扫描最终前往的 URL 上。
- URL 中已有的参数绝不会被替换，URL 的其余部分会与你输入的完全一致。
- 以 `qrdx_` 开头的名称保留给[转化跟踪](/docs/tracking-and-conversions)使用。

## 套餐与降级 [#plans-and-downgrades]

在 Pro 上保存的规则和 UTM 参数在降级后仍会继续生效：限制只会阻止创建新的内容。没有 Pro 时，你仍可以关闭和删除规则或移除 UTM 参数；要修改它们则需要再次使用 Pro。
