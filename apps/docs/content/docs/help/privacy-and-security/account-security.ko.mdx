## 유출될 비밀번호가 없어요 [#no-password-to-leak]

QRdx에는 비밀번호가 없습니다. Google, GitHub 또는 이메일로 받은 일회용 코드로 로그인합니다<IfAvailable feature="passkeys">. 패스키로도 로그인할 수 있습니다</IfAvailable>.<IfAvailable feature="sso"> 워크스페이스가 Business 요금제라면 회사의 [싱글 사인온](/docs/help/teams/single-sign-on)으로 로그인하게 하거나, 이를 필수로 설정할 수도 있습니다.</IfAvailable>

따라서 이메일 계정과 Google 또는 GitHub 계정이 QRdx의 열쇠가 됩니다. 이 계정들에도 2단계 인증을 켜 두세요.

<IfAvailable feature="sso" id="if-your-company-requires-single-sign-on" title="회사에서 싱글 사인온을 필수로 설정한 경우">
Business 워크스페이스는 회사 이메일 도메인에 [싱글 사인온을 필수로 설정](/docs/help/teams/single-sign-on#require-single-sign-on)할 수 있습니다. 내 주소가 해당 도메인이라면 다음과 같이 적용됩니다.

- 싱글 사인온으로만 로그인할 수 있습니다. 이메일 코드, Google, GitHub<IfAvailable feature="passkeys">, **패스키로 계속하기**</IfAvailable>로는 로그인되지 않습니다.
- 회사 로그인 페이지를 거친 뒤에도 2단계 인증이 적용됩니다<IfAvailable feature="passkeys">. 패스키는 두 번째 단계로 계속 사용할 수 있습니다</IfAvailable>.
- 로그인은 한 번에 최대 24시간 유지되며, 이후에는 싱글 사인온으로 다시 로그인해야 합니다.
- QRdx 이메일을 도메인 밖의 주소로 바꿀 수 없습니다.

워크스페이스에서 이 설정을 켜면 싱글 사인온으로 시작하지 않은 세션은 로그아웃됩니다. 워크스페이스 소유자는 다른 로그인 방법을 계속 쓸 수 있으므로, 회사 로그인 페이지에 문제가 생겨도 모두가 접속하지 못하는 일은 없습니다.
</IfAvailable>

## 2단계 인증 켜기 [#turn-on-two-step-verification]

[2단계 인증](/docs/help/privacy-and-security/two-step-verification)을 켜면 어떤 방식으로 로그인하든 로그인 후 두 번째 단계를 요구합니다. <IfAvailable feature="passkeys">패스키 또는 </IfAvailable>인증 앱의 코드를 사용합니다. 이메일이나 Google 계정에 누군가 접근하더라도 두 번째 단계 없이는 QRdx에 들어올 수 없습니다. 두 번째 단계를 진행할 수 없을 때 쓸 수 있는 백업 코드 10개도 받게 됩니다. 2단계 인증을 켜면 내 계정에 로그인된 다른 모든 브라우저와 기기가 로그아웃되므로, 각 기기에서 두 번째 단계와 함께 다시 로그인해야 합니다.

<IfAvailable feature="passkeys" id="add-a-passkey" title="패스키 추가하기">
[패스키](/docs/help/privacy-and-security/passkeys)는 지문, 얼굴 또는 화면 잠금으로 본인임을 확인합니다. QRdx 공식 사이트에서만 작동하므로 비슷하게 만든 가짜 사이트에서는 가져갈 수 없습니다. **패스키로 계속하기**로 단독 로그인할 수도 있고, 두 번째 단계로 사용할 수도 있습니다. 2단계 인증이 꺼진 상태에서 패스키를 추가하면 2단계 인증이 켜지며, 다른 기기는 로그아웃됩니다.
</IfAvailable>

## 변경 시 본인 확인을 요청해요 [#changes-ask-you-to-confirm-its-you]

로그인한 상태여도 계정 보안과 관련된 변경 전에는 QRdx가 [본인 확인](/docs/help/privacy-and-security/two-step-verification#confirm-its-you)을 요청합니다. 이메일 주소 변경, 계정 삭제, 2단계 인증 켜기/끄기, 새 백업 코드 발급, 두 번째 단계 방법 변경, Google 또는 GitHub 연결/해제가 해당합니다. API 키 또는 OAuth 앱의 클라이언트 시크릿 생성, 내 계정을 사용하려는 앱 승인, 웹훅 추가 또는 URL 변경, 웹훅 서명 시크릿 표시 또는 교체, Slack 또는 Discord 알림 웹훅 추가, 스캔이나 폼 응답을 다른 도구로 보내는 연동 연결도 마찬가지이며, 워크스페이스에서는 워크스페이스 삭제, 역할 변경, 멤버 제거, 관리자 초대가 해당합니다.<IfAvailable feature="sso"> 워크스페이스의 싱글 사인온 연결 변경과 싱글 사인온 필수 설정도 마찬가지입니다.</IfAvailable>

2단계 인증을 켜 둔 경우에는 <IfAvailable feature="passkeys">패스키, </IfAvailable>인증 앱 코드 또는 백업 코드로 확인하며, 이메일로 받은 코드는 사용할 수 없습니다. 꺼 둔 경우에는 QRdx가 이메일로 보내는 6자리 코드<IfAvailable feature="passkeys">, 패스키가 있다면 패스키,</IfAvailable> 또는 연결해 둔 Google이나 GitHub 계정으로 다시 로그인하는 방법을 쓸 수 있습니다<IfAvailable feature="sso"> (워크스페이스의 싱글 사인온이 OIDC를 사용하는 경우 싱글 사인온도 가능합니다)</IfAvailable>. 확인은 해당 브라우저에서 10분간 유효합니다.

이메일 주소를 변경할 때는 새 주소로 전송된 코드도 필요합니다. 변경 후에는 다른 모든 곳에서 로그아웃되고, 이전 주소로 변경되었다는 이메일이 전송됩니다. 이메일에 접근할 수 없나요? [해결 방법](/docs/help/account-and-billing/sign-in#lost-access-to-your-email)을 확인하세요.

## 새로운 곳에서 사용된 로그인 [#a-sign-in-used-somewhere-new]

로그인하면 QRdx는 로그인한 국가와 "macOS의 Chrome" 같은 브라우저 정보를 기록해 둡니다. 이후 그 로그인이 다른 국가의 다른 브라우저에서 사용되면, 계정에서 다른 작업을 하기 전에 [본인 확인](/docs/help/privacy-and-security/two-step-verification#confirm-its-you)을 요청합니다. 확인하기 전까지 그 브라우저는 QRdx의 다른 모든 곳에서 로그아웃된 것으로 처리됩니다. 그래서 누군가 내 브라우저에서 로그인 정보를 복사해 멀리서 사용하더라도, 본인 확인까지 통과하지 못하면 쓸 수 없습니다.

국가와 브라우저가 둘 다 바뀐 경우에만 확인을 요청합니다. 같은 브라우저로 여행하거나 브라우저나 시스템을 업데이트하는 것은 해당하지 않습니다. 확인을 마치면 QRdx는 그 로그인에 대해 새 국가와 브라우저를 기록합니다. 대신 로그아웃한 뒤 다시 로그인해도 됩니다.

이는 추가 확인일 뿐 완전한 보장은 아닙니다. 복사된 로그인이 같은 국가나 같은 종류의 브라우저에서 사용되면 확인을 요청하지 않습니다. QRdx는 호스팅 제공업체가 국가 정보를 제공할 때만 국가를 알 수 있으며, 제공되지 않는 곳에서는 이 확인이 실행되지 않습니다. 알아볼 수 없는 로그인을 종료하려면 [다른 기기 로그아웃](#sign-out-other-devices)을 하세요.

## 계정 보안 관련 이메일 [#emails-about-your-accounts-security]

다음과 같은 경우 계정 이메일 주소로 메일을 보냅니다.

- 브라우저나 기기가 처음으로 내 계정에 로그인했을 때
- 2단계 인증이 켜지거나 꺼졌을 때, 인증 앱<IfAvailable feature="passkeys"> 또는 패스키</IfAvailable>가 추가되거나 제거되었을 때, 새 백업 코드가 만들어졌을 때
- 로그인 또는 본인 확인에 백업 코드가 사용되었을 때(남은 코드 수 포함)
- 지원팀에 2단계 인증 해제가 요청되었을 때(해제되는 날짜와 막는 방법 포함), 그리고 그 요청이 취소되었을 때
- 이메일 주소가 변경되었을 때(이전 주소로 전송)

각 이메일에는 무슨 일이 있었는지, 어떤 기기와 브라우저("macOS의 Chrome" 등)인지, 대략적인 위치, IP 주소, 시각이 담겨 있습니다. **보안 검토**를 누르면 보안 설정이 열립니다. 본인이 한 일이 아니라면 이메일의 안내를 따르고 지원팀에 문의하세요.

로그인 코드나 본인 확인 코드처럼 코드가 담긴 이메일에는 코드를 요청한 대략적인 위치가 표시됩니다. QRdx는 전화, 채팅, 이메일로 코드를 요구하지 않습니다. 코드를 다른 사람에게 알려 주지 마세요.

### 새 로그인 [#new-sign-ins]

QRdx는 로그인을 마칠 때 설정하는 쿠키로 브라우저를 알아봅니다. 이 쿠키가 없는 브라우저나 기기가 내 계정에 로그인하면 이메일을 받게 됩니다. 2단계 인증을 켜 둔 경우에는 두 번째 단계를 마친 뒤에 전송됩니다.

QRdx가 이미 알아보는 브라우저에서 다시 로그인할 때나 계정을 만들 때는 이메일이 전송되지 않습니다. 쿠키를 삭제하거나 비공개 창을 사용하면 그곳에서의 다음 로그인은 새 로그인으로 간주됩니다.

새 브라우저마다 각각 이메일이 전송되며, 하루 최대 10통까지입니다. 로그인이 한꺼번에 몰려도 받은 편지함이 넘치지 않도록 하기 위해서입니다. 모든 로그인은 여전히 **세션**에 표시됩니다. QRdx는 가장 최근에 사용한 브라우저 50개를 기억하고, 400일 동안 로그인하지 않은 브라우저는 잊습니다.

<IfAvailable feature="sso">
한 가지 예외가 있습니다. 워크스페이스의 SAML ID 공급자를 통해 로그인하고 2단계 인증이 꺼져 있다면, QRdx가 돌아오는 시점에 브라우저를 알아볼 수 없어 이 이메일을 보내지 않습니다.
</IfAvailable>

## 로그인 유지 기간 [#how-long-you-stay-signed-in]

로그인은 최대 30일간 유지됩니다. 그 후에는 해당 브라우저에서 얼마나 자주 사용했는지와 관계없이 QRdx가 다시 로그인하도록 요청합니다. 브라우저에서 약 일주일 동안 QRdx를 사용하지 않으면 그곳에서는 더 일찍 로그아웃됩니다.

## 다른 기기 로그아웃 [#sign-out-other-devices]

**설정** → **프로필 및 보안**으로 이동하세요. **세션**에서 기기 하나를 로그아웃하거나 **다른 모든 곳에서 로그아웃**을 클릭합니다. 이 작업은 본인 확인을 요구하지 않으므로 바로 할 수 있습니다.

2단계 인증을 켜면 다른 모든 기기도 로그아웃됩니다. 지원팀이 대신 2단계 인증을 끄는 경우에는 [7일을 기다려야](/docs/help/privacy-and-security/two-step-verification#lost-your-phone-and-your-backup-codes) 하며, 그날 지금 사용 중인 기기를 포함한 모든 기기가 로그아웃됩니다.<IfAvailable feature="sso"> 회사에서 싱글 사인온을 필수로 설정하기 시작하면 싱글 사인온으로 시작하지 않은 세션은 로그아웃되며, 싱글 사인온 세션은 최대 24시간 유지됩니다.</IfAvailable>

## 연결한 앱 제거하기 [#remove-apps-you-connected]

다른 앱이 내 QRdx 계정을 사용하도록 허용했다면 **설정** → **승인된 앱**에 표시됩니다. 사용하지 않는 앱은 제거하세요. 앱은 로그아웃한 뒤에도 계속 작동하므로, 앱을 승인할 때는 본인 확인을 요청합니다.

## 보안 문제 신고하기 [#report-a-security-problem]

제목이 `[security]`로 시작하는 이메일을 [support@qrdx.dev](mailto:support@qrdx.dev)로 보내 주세요. 공개 GitHub 이슈에는 올리지 말아 주세요. [보안 정책](/legal/security)을 참고하세요.

유해한 QR 코드는 보안 버그가 아닙니다. 이 경우에는 [신고](/docs/help/privacy-and-security/report-abuse)해 주세요.
