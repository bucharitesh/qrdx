2段階認証(2FAとも呼ばれます)は、サインインに2つ目のステップを加える機能です。メールコード、Google、GitHub<IfAvailable feature="sso">(またはワークスペースのシングルサインオン)</IfAvailable>でサインインしたあと、QRdxは<IfAvailable feature="passkeys">パスキー、または</IfAvailable>認証アプリの6桁のコードを求めます。メールやGoogleアカウントに不正にアクセスされても、これがなければQRdxにはサインインできません。

<IfAvailable feature="passkeys">
[パスキー](/docs/help/privacy-and-security/passkeys)は、指紋、顔、画面ロック、セキュリティキーのいずれかで本人確認を行います。QRdx自身のサイトでのみ動作するため、偽サイトにパスキーを盗まれることはありません。
</IfAvailable>

認証アプリも使えます。30秒ごとに変わる6桁のコードを表示するアプリであれば利用でき、ほとんどのパスワードマネージャーのワンタイムコード機能も含まれます。QRdxは、2つ目のステップのコードをメールやテキストメッセージでは送信しません。

両方を設定して、サインイン時に手元にある方を使うこともできます。

## オンにする [#turn-it-on]

1. **設定** → **プロフィールとセキュリティ**に移動します。
2. **2段階認証**の下で**オンにする**をクリックし、[本人確認](#confirm-its-you)を行います。
3. 以下の手順で、2つ目のステップを設定します<IfAvailable feature="passkeys">。**パスキー**または**認証アプリ**を選択してください</IfAvailable>。
4. 10個のバックアップコードを保存します。コピーするか、テキストファイルとしてダウンロードし、パスワードマネージャーなど安全な場所に保管してください。QRdxが表示するのは一度きりです。**バックアップコードを保存しました**にチェックを入れ、**完了**をクリックします。

<IfAvailable feature="passkeys">
パスキーの場合は、提案された名前(「Chrome on macOS」のようなブラウザとシステム名)のままにするか、任意の名前を入力して**続ける**をクリックし、ブラウザにパスキーを保存させます。
</IfAvailable>

認証アプリの場合は、アプリでQRコードをスキャンするか、その下に表示されるキーを入力します。アプリに表示された6桁のコードを入力し、**確認**をクリックします。

これで2段階認証がオンになり、アカウントにサインインしている他のすべてのブラウザとデバイスはサインアウトされます。それぞれ、2つ目のステップを使って再度サインインする必要があります。オンにしたブラウザはサインインしたままです。<IfAvailable feature="passkeys"> もう一方の方法を後から追加するには、同じセクションを使います。すでにあるバックアップコードはそのまま使え、誰もサインアウトされません。</IfAvailable>

<IfAvailable feature="passkeys">
2段階認証でパスキーを使えるようになる前にパスキーを追加していた場合、設定に**パスキーを2つ目のステップとして使用できます**と表示されます。**オンにする**をクリックして本人確認を行い、そのパスキーで確認してから、バックアップコードを保存してください。この操作でも、他のデバイスはサインアウトされます。
</IfAvailable>

2段階認証のオン/オフ、方法の追加や削除、新しいバックアップコードの作成、バックアップコードの使用があるたびに、アカウントのアドレスにメールが届きます。サポートに2段階認証のオフを依頼した場合にも届きます。

## 2段階認証でサインインする [#sign-in-with-it]

いつもどおりにサインインすると、QRdxが2つ目のステップを求めます。

<IfAvailable feature="passkeys">
パスキーがある場合は、ブラウザのパスキーのプロンプトが自動的に開きます。ブラウザによってはクリックしないと開かないことがあり、その場合は**パスキーで続ける**をクリックしてください。プロンプトを閉じた場合やタイムアウトした場合は、もう一度試すか、別の方法を選んでください。
</IfAvailable>

ステップの下にある**認証コードを使用**と**バックアップコードを使用**で、利用できる他の方法に切り替えられます。QRdxはこのブラウザで最後に使った方法を記憶し、次回はそれから始めます。

認証コードは30秒ごとに変わるため、拒否された場合は次のコードを待ってください。

各サインインのステップでは、間違ったコードを5回まで入力できます<IfAvailable feature="passkeys">。検証に失敗したパスキーも1回として数えます</IfAvailable>。それを超えたら、サインインをやり直してください。連続で10回間違えると、QRdxはそのアカウントのコードを15分間受け付けなくなります。

このステップは10分で期限切れになります。期限が切れたら、もう一度サインインしてください。

## バックアップコード [#backup-codes]

バックアップコードは、スマートフォン<IfAvailable feature="passkeys">やパスキー</IfAvailable>が手元にないときに、2つ目のステップの代わりに使えます。2つ目のステップで**バックアップコードを使用**をクリックし、コードを入力します。コードは`ABCDE-FGH23`のような形式で、大文字のアルファベットと2から9の数字で構成されます。0、O、1、Iは紛らわしいため含まれません。小文字で入力することも、ダッシュの有無も問いません。各コードは一度だけ使えます。

バックアップコードを使うたび(サインインでも本人確認でも)、アカウントのアドレスに、残りのコード数を記したメールが届きます。心当たりがない場合は、誰かがバックアップコードを持っているということです。すぐにサポートへ連絡してください。

設定には残りのコード数が表示されます。2個以下になったら、**新しいコード**をクリックして本人確認を行い、新しいコードを作成してください。古いコードは使えなくなります。

## 信頼済みデバイス [#trusted-devices]

2つ目のステップで**このデバイスでは30日間再度確認しない**にチェックを入れると、そのブラウザでは30日間このステップが省略されます。自分のデバイスでのみ使ってください。2段階認証をオフにすると、信頼済みデバイスはすべて削除されます。

## 2つ目のステップを求められるサインイン [#which-sign-ins-ask-for-it]

すべてのサインインで求められます。メールコード、Google、GitHub<IfAvailable feature="sso">、ワークスペースのシングルサインオン</IfAvailable>が対象です。すでにサインインしているブラウザで再度サインインする場合も含まれます。

<IfAvailable feature="passkeys">
**パスキーで続ける**でのサインインは例外です。パスキーでのサインインは、デバイスと指紋、顔、画面ロックという2つの要素をすでに使っているため、QRdxは2つ目のステップを求めません。QRdxは、そのように本人確認を行うパスキーのみを受け付けます。
</IfAvailable>

## 方法を変更する [#change-your-methods]

**設定** → **プロフィールとセキュリティ**の**2段階認証**の下で、認証アプリの設定や削除を行えます<IfAvailable feature="passkeys">。パスキーの追加、名前の変更、削除もできます</IfAvailable>。変更のたびに本人確認が必要です。

最後の方法を削除すると、2段階認証はオフになり、バックアップコードも使えなくなります。QRdxは確認の前にその旨を知らせます。

## 本人確認 [#confirm-its-you]

アカウントのセキュリティに関わる変更の前には、サインイン中であっても、QRdxが本人確認を求めます。対象は次のとおりです。

- メールアドレスの変更
- アカウントの削除
- 2段階認証のオン/オフ、新しいバックアップコードの作成
- 認証アプリの追加または削除<IfAvailable feature="passkeys">、パスキーの追加、名前の変更、削除</IfAvailable>
- GoogleまたはGitHubアカウントの連携と連携解除
- APIキーの作成、OAuthアプリの作成、またはそのアプリの新しいクライアントシークレットの作成
- **承認**画面での、QRdxアカウントの利用を求めるアプリの承認
- Webhookエンドポイントの追加、エンドポイントのURLの変更、署名シークレットの表示またはローテーション
- SlackまたはDiscordの通知Webhookの追加、スキャンやフォームの回答を他のツールに送信する連携の接続
- ワークスペースでの操作: ワークスペースの削除、メンバーのロールの変更、メンバーの削除、メールまたは参加リンクによる管理者の招待、[2段階認証の必須化](/docs/help/teams/require-two-step-verification)と必須の解除

<IfAvailable feature="sso">
ワークスペースのシングルサインオン接続の作成、編集、検証、削除、およびシングルサインオンの必須化も対象です。
</IfAvailable>

2段階認証がオンの場合は、<IfAvailable feature="passkeys">パスキー、</IfAvailable>認証アプリのコード、またはバックアップコード(使用すると無効になります)で確認します。QRdxはここではメールで送るコードを提供しません。そのため、メールにアクセスできるだけではセキュリティ設定を変更できません。

オフの場合は、次のいずれかで確認できます。

- QRdxがメールで送る6桁のコード
- 連携済みのGoogleまたはGitHubアカウントでの再サインイン<IfAvailable feature="sso">、またはOIDCを使用するワークスペースのシングルサインオン</IfAvailable>

<IfAvailable feature="passkeys">
パスキーがある場合は、それも使えます。
</IfAvailable>

再サインインを選ぶと、そのサインインに移動してアカウントの選択またはサインインを求められ、その後、元のページに戻ります。離れている間、変更は保存されないため、戻ってからもう一度行ってください。連携したアカウントを使ってください。QRdxは別のアカウントに切り替えたり、アカウントを作成したりしません。

そのため、メールにアクセスできなくても、別の方法で本人確認ができます。どの方法も使えない場合は、[メールにアクセスできなくなった場合](/docs/help/account-and-billing/sign-in#lost-access-to-your-email)をご覧ください。

本人確認は、そのブラウザで10分間有効です。続けて複数の変更を行う場合、確認は一度だけです。

サインインも、そのブラウザで10分間、本人確認として扱われます。2段階認証がオンの場合、対象となるのは2つ目のステップに応答したサインイン<IfAvailable feature="passkeys">または**パスキーで続ける**を使ったサインイン</IfAvailable>だけで、信頼済みデバイスによってステップが省略されたサインインは含まれません。<IfAvailable feature="sso"> IDプロバイダーのアプリダッシュボードからQRdxを開いた場合も、2つ目のステップに応答していなければ対象になりません。</IfAvailable>

他のデバイスのサインアウトでは本人確認を求めないため、他の誰かがアカウントに入った場合でも、すぐにサインアウトさせることができます。

## オフにする [#turn-it-off]

**設定** → **プロフィールとセキュリティ** に移動し、**2段階認証** の **オフにする** をクリックして、ご本人であることを確認します。バックアップコードと、認証アプリを設定している場合はその設定が削除されます。

参加しているワークスペースが[2段階認証を必須にしている](/docs/help/teams/require-two-step-verification)場合、再びオンにするまでそのワークスペースを開けません。

## スマートフォンとバックアップコードの両方をなくした場合 [#lost-your-phone-and-your-backup-codes]

<IfAvailable feature="passkeys">パスキー、</IfAvailable>認証アプリ、またはバックアップコードがまだ手元にある場合は、それを使ってサインインし、設定で認証方法を変更してください。

2段階目の認証手段をすべてなくした場合は、アカウントのメールアドレスから [support@qrdx.dev](mailto:support@qrdx.dev) にメールを送り、状況をお知らせください。私たちに連絡してきた人がご本人とは限らないため、そのメールアドレスからのリクエストであることを確認したうえで、サポートによるオフの処理は7日間保留されます。

- **発生した当日に、そのメールアドレスへメールを送ります。** それまでは何も変わらず、現在サインインしている場所ではサインインしたままです。
- **ご自身で依頼していない場合は、中止してください。** 認証アプリまたはバックアップコードでサインインすると、処理が取り消されます。<IfAvailable feature="passkeys"> パスキーでのサインインでは取り消されません。このリセットはデバイスをなくした場合のためのもので、パスキーがそのデバイスに入っている可能性があるためです。</IfAvailable> **設定** → **プロフィールとセキュリティ** の **2段階認証** にある **キャンセル** をクリックして[ご本人であることを確認](#confirm-its-you)するか、メールに返信することでも取り消せます。取り消されたときもメールでお知らせします。
- **その日になると、2段階認証がオフになります。** 認証アプリの設定、バックアップコード、信頼済みデバイスが削除され、<IfAvailable feature="passkeys">パスキーは残り、</IfAvailable>アカウントはすべてのデバイスでサインアウトされます。その旨もメールでお知らせします。その後は通常どおりサインインし、あらためてオンにしてください。
