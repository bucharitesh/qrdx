---

싱글 사인온을 사용하면 회사 구성원이 이메일 코드, Google, GitHub 대신 ID 공급자를 통해 QRdx에 로그인할 수 있습니다. 이메일 도메인 하나에 연결 하나를 설정하고 도메인 소유권을 증명하면, 해당 도메인의 사용자가 로그인하려고 회사 이메일을 입력할 때 싱글 사인온이 안내됩니다. 이 방법으로 로그인하면 워크스페이스 멤버가 됩니다. [싱글 사인온을 필수로 설정](#require-single-sign-on)하면 해당 도메인에서는 ID 공급자만 로그인 방법이 됩니다.

싱글 사인온은 **Business** 요금제에 포함된 기능입니다. 워크스페이스의 소유자 또는 결제 멤버 중 한 명이 Business를 사용 중이면 워크스페이스에서 이 기능을 쓸 수 있습니다. [시트와 워크스페이스 한도](/docs/help/teams/seats)를 참고하세요.

싱글 사인온은 QRdx 상용 라이선스에 포함된 Business 기능입니다. 셀프 호스팅 QRdx 서버에서 이 기능을 켜려면 라이선스 키(`QRDX_EE_LICENSE`)가 필요합니다. [셀프 호스팅](/docs/self-hosting#optional-services)을 참고하세요.

## 시작하기 전에 [#before-you-start]

- 워크스페이스의 **소유자** 또는 **관리자**여야 합니다.
- `acme.com` 같은 이메일 도메인에 DNS 레코드를 추가할 수 있어야 합니다.
- 연결을 설정, 변경, 확인, 삭제하거나 싱글 사인온을 필수로 설정할 때는 먼저 [본인 확인](/docs/help/privacy-and-security/two-step-verification#confirm-its-you)을 해야 합니다. 패스키 또는 2단계 인증 코드로 확인하고, 2단계 인증이 꺼져 있으면 이메일로 받은 코드로 확인합니다. OIDC 연결이라면 연결을 통해 다시 로그인해도 됩니다. 한 번 확인하면 이후 10분 동안의 변경에 적용됩니다.

QRdx는 ID 공급자가 요구하는 표준 OIDC 및 SAML 2.0 설정을 사용합니다. 아래 단계에 필요한 값이 나와 있으며, 값을 붙여넣을 위치는 공급자에 따라 다릅니다.

## OIDC로 설정하기 [#set-up-with-oidc]

1. 워크스페이스에서 **설정** → **싱글 사인온**으로 이동합니다. **OIDC**가 선택되어 있습니다.
2. ID 공급자에서 QRdx용 웹 앱(OIDC 클라이언트)을 만들고, 페이지에 표시된 **Redirect URI**를 허용된 리디렉션으로 추가합니다.
3. QRdx로 돌아와 다음을 입력합니다.
   - **이메일 도메인**: 회사 도메인입니다(예: `acme.com`).
   - **Issuer URL**: 공급자의 issuer입니다. 나머지 정보는 `<issuer>/.well-known/openid-configuration`에서 읽으므로, issuer가 해당 문서와 정확히 일치해야 합니다.
   - 만든 앱의 **Client ID**와 **Client secret**.
4. **연결 저장**을 클릭합니다.

QRdx는 `openid`, `email`, `profile` 스코프를 요청하며 PKCE를 사용합니다. issuer는 인터넷에서 HTTPS로 접근할 수 있어야 하며, 사설 네트워크에 있는 ID 공급자는 지원하지 않습니다.

## SAML 2.0으로 설정하기 [#set-up-with-saml-20]

1. 워크스페이스에서 **설정** → **싱글 사인온**으로 이동하고 **SAML 2.0**을 선택합니다.
2. ID 공급자에서 페이지에 표시된 값으로 QRdx용 SAML 앱을 만듭니다.
   - **Assertion Consumer Service (ACS) URL**
   - **Entity ID (audience)**
   - **Metadata URL**: 공급자가 URL에서 QRdx 설정을 읽을 수 있는 경우에 사용합니다.
3. 사용자의 이메일 주소를 **NameID**(이메일 형식) 또는 `email`이라는 속성으로 보내세요. 이름은 `givenName`과 `surname`(또는 `firstName`과 `lastName`, 혹은 X.500 이름 `urn:oid:2.5.4.42`와 `urn:oid:2.5.4.4`)으로 보내거나, 표시 이름(`displayName`, `name` 또는 `urn:oid:2.16.840.1.113730.3.1.241`)으로 보냅니다. 이름이 없으면 QRdx는 주소에서 @ 앞부분을 사용합니다.
4. QRdx로 돌아와 **이메일 도메인**을 입력하고 공급자의 **메타데이터 XML**을 붙여넣습니다. 또는 **대신 세부 정보 입력**을 클릭하고 **로그인 URL(SSO URL)**, 공급자의 **entity ID**, **서명 인증서**를 입력합니다.
5. **연결 저장**을 클릭합니다.

공급자는 응답에 서명해야 하며 HTTP-Redirect 로그인 URL을 포함해야 합니다. QRdx는 유효한 서명이 없거나 유효 시간(`NotBefore`와 `NotOnOrAfter`)이 없는 응답을 거부합니다.

서명은 SHA-256 이상이어야 합니다. QRdx는 SHA-1로 서명하거나 다이제스트한 응답을 거부합니다. 공급자에서 QRdx 앱이 SHA-1로 설정되어 있다면 SHA-256으로 바꾸세요.

QRdx는 로그인 요청에 서명하지 않습니다. 공급자에서 QRdx 앱에 서명된 요청을 요구하도록 설정했다면 해제하세요. 그렇지 않으면 사용자가 로그인하기 전에 거부됩니다.

## 도메인 확인하기 [#verify-your-domain]

도메인 소유권을 증명하기 전에는 아무도 연결을 통해 로그인할 수 없습니다.

1. 싱글 사인온 페이지의 **확인**에서 TXT 레코드의 **이름**과 **값**을 복사합니다.
2. DNS 공급자에서 TXT 레코드를 추가합니다.
3. **확인**을 클릭합니다. 새 레코드가 반영되기까지 몇 분, 때로는 더 오래 걸릴 수 있습니다. QRdx가 아직 레코드를 찾지 못하면 그렇다고 알려 주니, 잠시 기다린 후 다시 시도하세요.

확인 값은 7일 동안 유효합니다. 만료되면 페이지를 새로고침해 새 값을 받고 레코드를 업데이트하세요.

확인된 도메인은 하위 도메인도 포함하므로 `acme.com`은 `eu.acme.com`도 포함합니다. 도메인은 하나의 워크스페이스에서만 싱글 사인온용으로 확인할 수 있습니다. 다른 워크스페이스가 이미 해당 도메인이나 겹치는 도메인을 확인했다면, 저장하거나 확인할 때 QRdx가 알려 줍니다.

## 팀원에게 보이는 화면 [#what-your-team-sees]

1. 로그인 페이지에서 회사 이메일을 입력하고 다른 이메일 로그인과 마찬가지로 **이메일로 코드 받기**를 클릭합니다.
2. 코드를 보내기 전에 QRdx가 주소의 도메인을 확인합니다. 확인된 도메인이면 회사에서 싱글 사인온으로 로그인한다고 안내하고 **SSO로 계속하기**를 제공합니다. 사용자가 요청하지 않으면 코드는 전송되지 않습니다.
3. **SSO로 계속하기**를 누르면 ID 공급자로 이동하고, 이후 QRdx로 돌아와 로그인된 상태로 워크스페이스에 들어갑니다.

[싱글 사인온을 필수로 설정](#require-single-sign-on)하지 않았다면 **이메일로 코드 받기**를 대신 선택할 수도 있습니다. 이메일 입력란 아래의 **SSO로 로그인**도 계속 사용할 수 있으며, 회사 이메일을 입력하면 바로 ID 공급자로 이동합니다.

QRdx는 도메인이 확인되었고 워크스페이스가 Business 요금제일 때만 싱글 사인온을 안내합니다. 이 확인은 도메인만 보기 때문에 특정 사람이 QRdx 계정을 가지고 있는지는 드러나지 않습니다.

[2단계 인증](/docs/help/privacy-and-security/two-step-verification)을 켠 사용자는 ID 공급자 로그인 후에도 QRdx가 두 번째 단계를 요청합니다. 해당 기기에서 다시 묻지 않도록 선택한 경우는 예외입니다. 싱글 사인온을 필수로 설정한 경우에도 마찬가지입니다.

SSO로 로그인할 때마다 해당 사용자가 워크스페이스에 속해 있는지 확인합니다.

- 멤버가 아닌 사용자는 **새 멤버**에서 선택한 역할인 **멤버**(기본값) 또는 **뷰어**로 참여합니다.
- 워크스페이스 초대가 대기 중인 사용자는 초대에 지정된 역할로 참여하며, 초대는 수락됨으로 표시됩니다.
- 기존 멤버는 현재 역할을 그대로 유지합니다. 역할은 **팀** 페이지에서 언제든 변경할 수 있습니다.

워크스페이스에서 제거한 사용자도 포함됩니다. 이들은 다음에 SSO로 로그인할 때 다시 참여합니다.

같은 이메일 주소의 QRdx 계정이 이미 있다면 SSO 로그인은 그 계정을 사용합니다. 사용자는 자신의 워크스페이스와 그 안의 모든 항목을 그대로 유지합니다.

QRdx는 공급자가 보낸 주소가 확인된 도메인에 속할 때만 연결을 통해 사용자를 로그인시킵니다. 같은 주소로 이메일 코드를 받는 등 다른 로그인 방법은 싱글 사인온을 필수로 설정하지 않는 한 계속 작동합니다.

이메일 주소는 ID 공급자에서 확인된 상태여야 합니다. 공급자가 주소가 확인되지 않았다고 QRdx에 알리면(OIDC의 `email_verified` 클레임, 또는 SAML의 `email_verified` 혹은 `emailVerified` 속성이 false인 경우) QRdx는 사용자를 로그인시키지 않고, 계정을 만들지 않으며, 기존 계정도 연결하지 않습니다. 사용자에게는 관리자에게 공급자에서 주소를 확인해 달라고 요청하라는 메시지가 표시됩니다. 공급자가 어느 쪽도 알려 주지 않으면 QRdx는 확인된 도메인에 한해 공급자를 신뢰합니다.

QRdx에서 로그아웃해도 ID 공급자에서는 로그아웃되지 않습니다. 사용자가 공급자에 계속 로그인되어 있는 동안에는 다음 SSO 로그인이 비밀번호를 묻지 않고 바로 진행됩니다. 공용 컴퓨터에서는 ID 공급자에서도 로그아웃하세요.

## ID 공급자에서 QRdx 열기 [#open-qrdx-from-your-identity-provider]

SAML 연결을 사용하면 ID 공급자에서 바로 시작할 수도 있어요. ID 공급자의 앱 대시보드에서 QRdx 앱을 클릭하면 QRdx 로그인 페이지를 거치지 않고 QRdx에 로그인돼요. 이를 흔히 IdP 시작 로그인이라고 해요.

ID 공급자에서 QRdx용으로 만든 SAML 앱을 열고, 앱 대시보드에 사용자에게 표시되는지, 그리고 ID 공급자에서 시작하는 로그인이 허용되어 있는지 확인하세요. 사용자는 워크스페이스의 대시보드로 이동해요. QRdx는 앱이 보내는 **RelayState**를 무시하므로, QRdx가 요청하지 않은 로그인으로는 열리는 페이지를 정할 수 없어요.

QRdx에서 로그인을 시작할 때와 같은 규칙이 적용돼요. 도메인이 인증되어 있어야 하고, 워크스페이스가 Business 플랜이어야 하며, 응답이 SHA-256 이상의 서명으로 서명되어 있어야 해요. QRdx에는 다음도 필요해요.

- ID가 있고 암호화되지 않은 어서션이 정확히 하나여야 해요.
- 어서션의 만료 시간(`Conditions`의 `NotOnOrAfter`)이 있어야 해요. 대부분의 ID 공급자가 기본으로 보내요.

응답 하나로는 한 번만 로그인할 수 있어요. 같은 응답이 다시 도착하면 QRdx는 이를 거부하고 다시 로그인하라고 안내해요. 2단계 인증을 켠 사용자에게는 QRdx가 먼저 두 번째 단계를 요청한 다음 대시보드로 이동시켜요.

앱 대시보드에서 시작한 로그인은 사용자가 두 번째 단계에 응답하지 않았다면 [본인 확인](/docs/help/privacy-and-security/two-step-verification#confirm-its-you)으로 인정되지 않아요. QRdx가 두 번째 단계를 요청하지 않았기 때문이에요. 확인을 요구하는 변경을 하기 전에는 평소처럼 본인 확인을 해야 해요.

OIDC 연결은 항상 QRdx에서 시작해요. ID 공급자의 앱 대시보드에 QRdx를 넣으려면 QRdx 로그인 페이지로 연결되는 링크로 추가하세요.

## Single sign-on 필수로 설정 [#require-single-sign-on]

도메인이 인증되면 해당 도메인 사용자가 ID 공급자로만 로그인하도록 설정할 수 있어요. **Single sign-on** 페이지에서 도메인의 **Require single sign-on for**를 켜세요. 연결과 마찬가지로 하위 도메인도 포함돼요.

켜져 있는 동안, 해당 도메인의 주소에는 다음이 적용돼요.

- 이메일 코드, Google, GitHub로는 로그인할 수 없어요<IfAvailable feature="passkeys">. **Continue with passkey**도 마찬가지예요</IfAvailable>. 회사에서 single sign-on을 요구한다는 안내와 **Continue with SSO**가 표시돼요.
- ID 공급자로 로그인한 후에도 [2단계 인증](/docs/help/privacy-and-security/two-step-verification)은 계속 적용돼요.<IfAvailable feature="passkeys"> 패스키는 두 번째 단계로 여전히 사용할 수 있어요.</IfAvailable>
- 로그인은 최대 24시간 유지돼요. 그 후에는 ID 공급자를 다시 거쳐야 해요. 따라서 ID 공급자에서 할당을 해제한 사용자는 QRdx에 다시 로그인할 수 없고, 하루 안에 로그아웃돼요.
- QRdx 이메일을 다른 도메인의 주소로 바꿀 수 없고, 다른 사람의 이메일을 사용자 도메인의 주소로 바꿀 수도 없어요. 해당 도메인의 주소는 single sign-on으로 로그인해야만 QRdx에 들어올 수 있어요.

이 설정을 켜면 single sign-on으로 시작하지 않은 세션은 모두 로그아웃되고, single sign-on으로 시작한 세션은 해당 로그인 후 24시간 뒤에 종료돼요. 이에 대한 이메일은 발송되지 않으며, 다음에 로그인할 때 SSO로 로그인하라는 안내가 표시돼요.

**소유자는 다른 로그인 방법을 계속 쓸 수 있어요.** 이 설정은 워크스페이스 소유자에게는 적용되지 않아요. 소유자는 이메일 코드, Google, GitHub<IfAvailable feature="passkeys">, 패스키</IfAvailable>를 그대로 사용할 수 있고, 세션이 단축되지 않으며, 이메일도 변경할 수 있어요. 그래서 ID 공급자에 문제가 생겨도 모두가 이 설정에서 잠기지 않아요. 소유자 역할은 꼭 필요한 소수에게만 부여하세요.

켜려면 다음이 필요해요.

- Business 플랜의 **소유자** 또는 **관리자**여야 하고, 인증된 도메인이 있어야 하며, [본인 확인](/docs/help/privacy-and-security/two-step-verification#confirm-its-you)을 요청받아요.
- 해당 도메인의 주소를 가진 관리자라면 먼저 single sign-on으로 로그인하세요. 그러지 않으면 설정을 켤 때 로그아웃되고, 그렇게 로그인해 보면 연결이 작동하는지도 확인할 수 있어요.

설정을 끄거나, 연결을 삭제하거나, 워크스페이스가 Business 플랜에서 벗어나면 더 이상 필수가 아니에요. 사용자는 현재 세션을 유지하고 다른 로그인 방법을 다시 사용할 수 있어요. 모든 QRdx 서버에 반영되기까지 최대 1분이 걸릴 수 있어요. 그 1분 사이에 다른 방법으로 로그인한 사용자는 바로 로그아웃될 수 있고, 1분 후에 다시 로그인할 수 있어요.

Single sign-on은 로그인에 관한 기능이에요. API 키는 로그인이 아니므로 필수로 설정해도 API 키는 막히지 않아요. 반면 **Team** 페이지에서 사용자를 제거하면 그 사용자가 워크스페이스용으로 만든 API 키는 중지돼요.

## 사용자를 완전히 제거하기 [#remove-someone-for-good]

SSO로 로그인할 때마다 해당 사용자가 다시 추가되므로, **Team** 페이지에서 제거하는 것만으로는 충분하지 않아요.

1. ID 공급자에서 QRdx 앱의 할당을 해제하거나(또는 계정을 비활성화하여) QRdx에 로그인하지 못하게 하세요.
2. 그런 다음 **Team** 페이지에서 제거하세요. 사용자의 주소가 인증된 도메인에 속하면 제거 대화상자에서 알려 드려요.

[single sign-on을 필수로 설정](#require-single-sign-on)했다면 1단계만으로도 24시간 안에 QRdx에서 로그아웃돼요. 멤버에서 제외되고 워크스페이스용 API 키도 작동하지 않도록 **Team** 페이지에서도 제거하세요.

워크스페이스에서 제거해도 해당 사용자의 QRdx 계정은 삭제되지 않아요. 해당 주소에 single sign-on이 필수가 아니라면 이메일 코드, Google, GitHub로 자신의 워크스페이스에 계속 로그인할 수 있어요.

## 연결 변경 또는 삭제 [#change-or-remove-the-connection]

- **Replace secret**(OIDC) 또는 **Replace certificate**(SAML)은 ID 공급자에서 시크릿이나 인증서를 교체할 때 연결을 업데이트해요. 메타데이터 XML로 설정한 SAML 연결은 삭제한 후 다시 설정해야 변경할 수 있어요.
- **Remove**는 single sign-on을 끄고 필수 설정도 해제해요. 모든 사용자는 워크스페이스에 남아 있으며 이메일 코드, Google, GitHub로 로그인할 수 있어요.

## 플랜이 변경되면 [#if-the-plan-changes]

워크스페이스가 더 이상 Business 플랜이 아니면 로그인 도중이더라도 아무도 SSO로 로그인할 수 없고, single sign-on 필수 설정도 해제돼요. 사용자에게는 안내 메시지가 표시되며 다른 방법으로 로그인할 수 있어요. 연결과 설정은 그대로 유지되므로 워크스페이스가 다시 Business 플랜이 되면 다시 작동하고, 삭제도 계속 할 수 있어요.

## 지원하지 않는 기능 [#what-isnt-supported]

- 자동 프로비저닝 및 제거(SCIM). ID 공급자에서 사용자를 제거해도 워크스페이스에서는 제거되지 않아요. [single sign-on 필수](#require-single-sign-on)가 아니면 QRdx 세션도 종료되지 않으므로 **Team** 페이지에서도 제거하세요([사용자를 완전히 제거하기](#remove-someone-for-good) 참고).
- ID 공급자의 역할 또는 그룹. 모든 사용자는 **New members** 아래에 설정된 역할로 가입해요.
- 워크스페이스당 둘 이상의 연결 또는 둘 이상의 도메인.
- OIDC 연결에서 ID 공급자가 시작하는 로그인(SAML에서는 작동해요. [ID 공급자에서 QRdx 열기](#open-qrdx-from-your-identity-provider) 참고), SAML 싱글 로그아웃, 암호화된 어서션.
- 인터넷에서 접근할 수 없는 ID 공급자.
