审计日志是 QRdx 商业许可下的 Business 功能。自托管的 QRdx 服务器需要许可证密钥(`QRDX_EE_LICENSE`)才能启用;请参阅[自托管](/docs/self-hosting#optional-services)。

<IfAvailable feature="auditLog">

审计日志会列出成员在工作区中所做的更改:谁做的、改了什么、什么时候改的。所有者和管理员可以在 **设置** → **审计日志** 中查看,并可筛选日志,或将其导出为 CSV 文件。

## 谁可以使用 [#who-has-it]

审计日志属于 **Business** 套餐。只要工作区的某位所有者或账单成员使用 Business,该工作区就拥有此功能。请参阅[席位与工作区限制](/docs/help/teams/seats)。

历史记录从工作区开通 Business 时开始。在此之前,或工作区使用其他套餐期间所做的更改不会被记录。如果工作区不再使用 Business,记录会停止;已保存的条目会保留到满 {facts.auditLogRetentionDays} 天,工作区重新使用 Business 后,你可以再次看到这些条目。

只有 **所有者** 和 **管理员** 可以打开并导出审计日志。成员、查看者和账单成员不能。请参阅[角色](/docs/help/teams/roles)。

## 记录的内容 [#whats-recorded]

每条记录包含时间、更改人、更改内容和对象(二维码、页面、人员或域名)。在适用时,记录还会保留旧值和新值,例如二维码原来的目标地址和新的目标地址。点击条目上的箭头即可查看。

更改人可以是某个人,也可以是代表某个人操作的 API 密钥或应用。通过 [REST API](/docs/developers/rest-api) 使用 API 密钥所做的更改会显示该密钥的名称;通过你授权的应用所做的更改会显示该应用的名称。<IfAvailable feature="slackBot"> 在 Slack 中使用 `/qr track` 创建的二维码,会显示关联的人员并标注“通过 Slack”,同时附上 Slack 用户和工作区的 ID。当所有者或管理员在 [设置 → API 密钥与应用](/dashboard?to=settings/developers) 中撤销某个 Slack 账号的关联时,该操作会记录在“开发者”类别下。</IfAvailable>

每条记录还会保留请求的 IP 地址和设备,即浏览器和系统,例如“macOS 上的 Chrome”。系统自行做出的更改(例如因账单产生的套餐变更)则没有这两项信息。

以下更改会被记录:

- **二维码:** 创建(包括导入和复制)、目标地址更改、重命名、设计更改、短链接更改、链接控制更改(密码开启或关闭、开始和结束日期、扫描次数上限、备用 URL)、路由规则更改、暂停或恢复、归档或取消归档、移入回收站、还原、永久删除、还原到早期版本、移到其他文件夹、移入或移出其他工作区。文件夹和标签的创建、重命名或删除。
- **页面:** 创建、发布、删除。
- **团队:** 发送和撤销邀请、通过邀请、加入链接或单点登录加入的人员、角色变更、被移除的人员、主动退出的人员,以及加入链接的开启、更改或关闭。无论更改是在 QRdx 中还是通过其 API 完成,都会被记录。
- **安全:** “要求两步验证”和“要求单点登录”的开启或关闭(开启单点登录时还会记录它让多少个会话退出登录)、单点登录的设置、更改、验证或移除、新成员首次通过单点登录登录时获得的角色,以及审计日志的导出。
- **开发者:** API 密钥的创建和撤销(包括名称和权限范围)、应用的授权或撤销、Webhook 端点的添加、更改或删除,以及 Webhook 签名密钥的更换。对于端点,日志只保留其服务器,例如 `https://hooks.zapier.com/…`,因为 Webhook URL 的其余部分通常是保密的。
- **域名:** 自定义域名的添加、验证或移除。
- **工作区:** 名称或 URL 的更改,以及工作区升级到 Business(记录为“账单”)。

审计日志绝不会保存 API 密钥、OAuth 令牌、密码、Webhook URL 的路径或查询参数、Webhook 签名密钥,以及单点登录的客户端密钥或证书。它只记录这些内容被创建、更换或移除,而不记录其具体值。

你授权的应用作用于你自己的工作区,因此授权或撤销应用会记录在该工作区中。

以下内容不在审计日志中:

- 扫描、表单回复和分析数据,它们不属于对工作区的更改(请在“分析”和“回复”中查看);
- 对你个人账号的更改,例如姓名、邮箱或两步验证。

## 筛选日志 [#filter-the-log]

最新的更改排在最前,每次显示 50 条。点击底部的 **加载更多** 可查看更早的记录。

- **操作人**:某一个人,包括代表此人操作的 API 密钥和应用。
- **类别**:二维码(含文件夹和标签)、页面、团队、安全、开发者、域名或工作区。
- **起始** 和 **截止**:要显示的第一天和最后一天。日期按 UTC 计算;每条记录上的时间则按你所在的时区显示。

## 导出为 CSV [#export-as-csv]

点击 **导出 CSV**,即可下载当前筛选结果,按从新到旧排序。一次导出最多包含 {facts.auditLogExportRows} 条记录。如需导出更多,请每次导出较短的日期范围。

文件中每个更改占一行,包含:UTC 时间、类别、操作、一句话描述、更改人(以及 API 密钥或应用,如有)、对象、IP 地址、设备,以及 JSON 格式的旧值和新值。

导出操作本身也会被记录,并附带所使用的筛选条件。

## 条目保留多久 [#how-long-entries-are-kept]

条目会保留 {facts.auditLogRetentionDays} 天,之后被删除。删除工作区时,其审计日志也会一并删除。

审计日志中的 IP 地址和设备属于在该工作区工作的人员的个人数据。QRdx 如何处理这些数据,请参阅[隐私政策](/legal/privacy-policy)。
