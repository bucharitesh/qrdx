監査ログは、QRdx の商用ライセンスに含まれる Business 向け機能です。セルフホストの QRdx サーバーで有効にするには、ライセンスキー(`QRDX_EE_LICENSE`)が必要です。詳しくは[セルフホスティング](/docs/self-hosting#optional-services)をご覧ください。

<IfAvailable feature="auditLog">

監査ログには、ワークスペースでメンバーが行った変更が、誰が行ったか、何が変わったか、いつ行ったかとともに記録されます。オーナーと管理者は **Settings** → **Audit log** で閲覧でき、絞り込みや CSV ファイルへのエクスポートもできます。

## 利用できるプラン [#who-has-it]

監査ログは **Business** プランの機能です。ワークスペースのオーナーまたは請求担当メンバーのいずれかが Business プランであれば、そのワークスペースで利用できます。[シートとワークスペースの上限](/docs/help/teams/seats)をご覧ください。

履歴は、ワークスペースが Business プランになった時点から始まります。それ以前や、他のプランだった間に行われた変更は記録されません。ワークスペースが Business プランでなくなると記録は止まりますが、すでに保存されたエントリーは {facts.auditLogRetentionDays} 日が経過するまで残り、ワークスペースが Business プランに戻れば再び閲覧できます。

監査ログを開いてエクスポートできるのは、**オーナー**と**管理者**だけです。メンバー、閲覧者、請求担当メンバーはできません。[ロール](/docs/help/teams/roles)をご覧ください。

## 記録される内容 [#whats-recorded]

各エントリーには、時刻、変更を行った人、変更内容、対象(コード、ページ、メンバー、ドメイン)が含まれます。該当する場合は、コードの変更前と変更後のリンク先のように、変更前の値と変更後の値も保存されます。エントリーの矢印をクリックすると表示されます。

変更を行った主体は、メンバー本人、またはメンバーの代わりに動作する API キーやアプリです。API キーを使って [REST API](/docs/developers/rest-api) で行った変更にはキーの名前が、承認したアプリを通じて行った変更にはアプリの名前が表示されます。<IfAvailable feature="slackBot"> Slack で `/qr track` を使って作成したコードには、紐付けられたメンバーが「via Slack」として表示され、Slack のユーザー ID とワークスペース ID も記録されます。オーナーまたは管理者が [Settings → API keys & apps](/dashboard?to=settings/developers) で Slack アカウントの連携を解除すると、その操作は Developers に記録されます。</IfAvailable>

各エントリーには、リクエストの IP アドレスとデバイス(「Chrome on macOS」のようなブラウザーとシステム)も保存されます。請求によるプラン変更など、システムが行う変更には、どちらもありません。

次の変更が記録されます。

- **コード:** 作成(インポートやコピーを含む)、リンク先の変更、名前の変更、デザインの変更、短縮リンクの変更、リンク制御の変更(パスワードのオンとオフ、開始日と終了日、スキャン数の上限、フォールバック URL)、ルーティングルールの変更、一時停止と再開、アーカイブとアーカイブ解除、ゴミ箱への移動、復元、完全な削除、以前のバージョンの復元、別のフォルダーへの移動、別のワークスペースへの移動または別のワークスペースからの移動。フォルダーとタグの作成、名前の変更、削除。
- **ページ:** 作成、公開、削除。
- **チーム:** 招待の送信と取り消し、招待、参加リンク、シングルサインオンによる参加、ロールの変更、メンバーの削除、メンバーの退出、参加リンクのオン、変更、オフ。これらは、QRdx と API のどちらで変更しても記録されます。
- **セキュリティ:** 「Require two-step verification」と「Require single sign-on」のオンとオフ(シングルサインオンをオンにした場合は、サインアウトされたセッション数も記録されます)、シングルサインオンの設定、変更、検証、削除、シングルサインオンで初めてサインインした新規メンバーに付与されるロール、監査ログのエクスポート。
- **Developers:** API キーの作成と無効化(名前とスコープ)、アプリの承認と取り消し、Webhook エンドポイントの追加、変更、削除、Webhook の署名シークレットの再発行。エンドポイントについては、Webhook URL の残りの部分は秘密であることが多いため、`https://hooks.zapier.com/…` のようにサーバー部分のみが保存されます。
- **ドメイン:** カスタムドメインの追加、検証、削除。
- **ワークスペース:** 名前または URL の変更、ワークスペースの Business プランへの移行(「Billing」として記録されます)。

監査ログには、API キー、OAuth トークン、パスワード、Webhook URL のパスやクエリ、Webhook の署名シークレット、シングルサインオンのクライアントシークレットや証明書は保存されません。作成、再発行、削除されたという事実だけが記録され、値は記録されません。

承認したアプリはご自身のワークスペースで動作するため、アプリの承認と取り消しはそのワークスペースに記録されます。

次のものは監査ログに含まれません。

- スキャン、フォームの回答、分析データ。これらはワークスペースの変更ではありません(Analytics と Responses で確認できます)。
- 名前、メールアドレス、2 段階認証など、ご自身のアカウントに対する変更。

## ログの絞り込み [#filter-the-log]

新しい変更から順に、50 件ずつ表示されます。古い変更は、下部の **Load more** をクリックすると表示されます。

- **Who**: 特定のメンバー。そのメンバーの代わりに動作する API キーとアプリも含まれます。
- **Category**: Codes(フォルダーとタグを含む)、Pages、Team、Security、Developers、Domains、Workspace。
- **From** と **To**: 表示する最初の日と最後の日。日付は UTC で、各エントリーの時刻はお使いのタイムゾーンで表示されます。

## CSV としてエクスポート [#export-as-csv]

**Export CSV** をクリックすると、現在の絞り込み結果が新しい順にダウンロードされます。1 回のエクスポートに含められるのは最大 {facts.auditLogExportRows} 件です。それ以上の場合は、日付の範囲を短くして分けてエクスポートしてください。

ファイルには、変更ごとに 1 行ずつ、UTC の時刻、カテゴリー、アクション、内容を説明する文、変更を行った人(API キーまたはアプリがある場合はそれも)、対象、IP アドレス、デバイス、変更前と変更後の値(JSON)が含まれます。

エクスポートも、使用した絞り込み条件とともに記録されます。

## エントリーの保存期間 [#how-long-entries-are-kept]

エントリーは {facts.auditLogRetentionDays} 日間保存され、その後削除されます。ワークスペースを削除すると、その監査ログも一緒に削除されます。

監査ログに含まれる IP アドレスとデバイスは、ワークスペースで作業するメンバーの個人データです。QRdx での取り扱いについては、[プライバシーポリシー](/legal/privacy-policy)をご覧ください。
