---
title: "单点登录（SSO）"
description: "让团队成员通过贵公司的身份提供商，使用 OIDC 或 SAML 2.0 登录 QRdx。属于 Business 套餐功能。"
---

单点登录让贵公司的成员通过身份提供商登录 QRdx，而不必使用邮箱验证码、Google 或 GitHub。您为一个邮箱域名设置一个连接，并证明您拥有该域名。之后，该域名下的成员在登录时输入工作邮箱，就会看到单点登录选项。通过这种方式登录，他们会成为您工作区的成员。您还可以[强制使用](#require-single-sign-on)单点登录，让身份提供商成为该域名唯一的登录方式。

单点登录属于 **Business** 套餐。只要工作区的某位所有者或账单成员使用 Business，该工作区就拥有此功能。请参阅[席位与工作区限制](/docs/help/teams/seats)。

单点登录是 QRdx 商业许可下的 Business 功能。自托管的 QRdx 服务器需要许可证密钥（`QRDX_EE_LICENSE`）才能启用；请参阅[自托管](/docs/self-hosting#optional-services)。

## 开始之前 [#before-you-start]

- 您需要是工作区的**所有者**或**管理员**。
- 您需要能够为您的邮箱域名（例如 `acme.com`）添加 DNS 记录。
- 设置、修改、验证或删除连接，以及强制使用单点登录，都需要您先[确认是本人操作](/docs/help/privacy-and-security/two-step-verification#confirm-its-you)：可使用通行密钥或两步验证码；如果未开启两步验证，则使用我们发送到您邮箱的验证码，或者对于 OIDC 连接，通过该连接重新登录。一次确认对接下来 10 分钟内的修改都有效。

QRdx 使用身份提供商要求的标准 OIDC 和 SAML 2.0 设置。下面的步骤列出了各项取值；具体粘贴到哪里，取决于您的提供商。

## 使用 OIDC 设置 [#set-up-with-oidc]

1. 在工作区中，前往**设置** → **单点登录**。此时已选中 **OIDC**。
2. 在您的身份提供商中，为 QRdx 创建一个 Web 应用（OIDC 客户端），并将页面上显示的 **Redirect URI** 添加为允许的重定向地址。
3. 回到 QRdx，填写：
   - **邮箱域名**：贵公司的域名，例如 `acme.com`。
   - **Issuer URL**：提供商的 issuer。QRdx 会从 `<issuer>/.well-known/openid-configuration` 读取其余配置，因此 issuer 必须与该文档完全一致。
   - 您所创建应用的 **Client ID** 和 **Client secret**。
4. 点击**保存连接**。

QRdx 请求 `openid`、`email` 和 `profile` 这几个 scope，并使用 PKCE。issuer 必须能通过 HTTPS 从互联网访问；不支持位于私有网络中的身份提供商。

## 使用 SAML 2.0 设置 [#set-up-with-saml-20]

1. 在工作区中，前往**设置** → **单点登录**，然后选择 **SAML 2.0**。
2. 在您的身份提供商中，使用页面上显示的值为 QRdx 创建一个 SAML 应用：
   - **Assertion Consumer Service (ACS) URL**
   - **Entity ID (audience)**
   - **Metadata URL**（如果您的提供商可以从 URL 读取 QRdx 的设置）
3. 将用户的邮箱地址作为 **NameID**（邮箱格式）发送，或作为名为 `email` 的属性发送。姓名方面，发送 `givenName` 和 `surname`（或 `firstName` 和 `lastName`，或 X.500 名称 `urn:oid:2.5.4.42` 和 `urn:oid:2.5.4.4`），或发送显示名称（`displayName`、`name` 或 `urn:oid:2.16.840.1.113730.3.1.241`）。如果没有姓名，QRdx 会使用邮箱地址中 @ 之前的部分。
4. 回到 QRdx，输入您的**邮箱域名**，并粘贴提供商的 **metadata XML**。或者点击**改为手动输入详细信息**，填写**登录 URL（SSO URL）**、提供商的 **entity ID** 和它的**签名证书**。
5. 点击**保存连接**。

您的提供商必须对响应签名，并提供 HTTP-Redirect 登录 URL。QRdx 会拒绝没有有效签名或没有有效期时间（`NotBefore` 和 `NotOnOrAfter`）的响应。

签名必须使用 SHA-256 或更强的算法。QRdx 会拒绝使用 SHA-1 签名或摘要的响应；如果您的提供商为 QRdx 应用设置了 SHA-1，请改为 SHA-256。

QRdx 不会对其登录请求签名。如果您的提供商设置为要求 QRdx 应用发送已签名的请求，请关闭该选项，否则用户在登录之前就会被拒绝。

## 验证您的域名 [#verify-your-domain]

在您证明拥有该域名之前，任何人都无法通过该连接登录。

1. 在单点登录页面的**验证**部分，复制 TXT 记录的**名称**和**值**。
2. 在您的 DNS 提供商处添加该 TXT 记录。
3. 点击**验证**。新记录可能需要几分钟才会生效，有时更久。如果 QRdx 暂时没有找到该记录，会给出提示；请稍等后重试。

验证值的有效期为 7 天。如果过期，请刷新页面获取新的值，并更新记录。

已验证的域名同样涵盖其子域名，因此 `acme.com` 也涵盖 `eu.acme.com`。一个域名只能在一个工作区中通过单点登录验证。如果其他工作区已经验证了该域名，或验证了与之重叠的域名，QRdx 会在您保存或验证时告知您。

## 团队成员会看到什么 [#what-your-team-sees]

1. 在登录页面，他们输入工作邮箱，并点击**通过邮件发送验证码**，与任何邮箱登录一样。
2. 在发送验证码之前，QRdx 会检查该邮箱地址的域名。对于您已验证的域名，它会提示贵公司使用单点登录登录，并提供**使用 SSO 继续**。除非用户主动要求，否则不会发送验证码。
3. **使用 SSO 继续**会将他们带到您的身份提供商，然后返回 QRdx，此时已登录并进入您的工作区。

除非您[强制使用单点登录](#require-single-sign-on)，否则他们也可以改选**通过邮件发送验证码**。邮箱输入框下方的**使用 SSO 登录**同样可用：它会询问工作邮箱，然后直接跳转到您的身份提供商。

只有在域名已验证且工作区使用 Business 套餐时，QRdx 才会提供单点登录。该检查只针对域名本身，因此不会显示某人是否拥有 QRdx 账户。

如果有人开启了[两步验证](/docs/help/privacy-and-security/two-step-verification)，在您的身份提供商让其登录之后，QRdx 仍会要求第二步验证，除非他们选择在该设备上不再询问。强制使用单点登录时同样如此。

每次 SSO 登录都会确保该用户在您的工作区中：

- 非成员会以您在**新成员**下选择的角色加入：**成员**（默认）或**查看者**。
- 有待处理工作区邀请的用户会以邀请中的角色加入，并且该邀请会标记为已接受。
- 已有成员保留其现有角色。您可以在**团队**页面更改任何人的角色。

这也包括您已从工作区移除的人员：他们下次使用 SSO 登录时会重新加入。

如果某人已有使用相同邮箱地址的 QRdx 账户，使用 SSO 登录时会使用该账户。他们保留自己的工作区及其中的所有内容。

只有当您的提供商发送的邮箱地址属于您已验证的域名时，QRdx 才会通过您的连接让用户登录。他们的其他登录方式，例如发送到同一地址的邮箱验证码，仍然可用，除非您强制使用单点登录。

邮箱地址必须在您的身份提供商中完成验证。如果提供商告知 QRdx 某个地址未验证（OIDC 的 `email_verified` 声明，或 SAML 的 `email_verified` 或 `emailVerified` 属性被设为 false），QRdx 不会让该用户登录，不会为其创建账户，也不会关联现有账户。他们会看到一条消息，提示请管理员在身份提供商中验证邮箱地址。如果您的提供商没有明确说明，QRdx 会对您已验证的域名予以信任。

退出 QRdx 并不会让任何人退出您的身份提供商。只要他们仍在那里保持登录，下次 SSO 登录就会直接通过，不再询问密码。在共用电脑上，请同时退出您的身份提供商。

## 从你的身份提供商打开 QRdx [#open-qrdx-from-your-identity-provider]

使用 SAML 连接时，用户也可以从身份提供商开始登录：在其应用控制台中点击 QRdx 应用，即可登录 QRdx，无需经过 QRdx 的登录页面。这通常称为 IdP 发起的登录。

在身份提供商中，打开你为 QRdx 创建的 SAML 应用，确认它会显示在用户的应用控制台中，并且允许从身份提供商发起登录。用户登录后会进入你工作区的控制台。QRdx 会忽略应用发送的任何 **RelayState**，因此 QRdx 并未请求的登录无法决定打开哪个页面。

适用的规则与从 QRdx 发起登录时相同：域名必须已验证，工作区必须使用 Business，响应必须使用 SHA-256 或更强的算法签名。QRdx 还要求：

- 有且仅有一个带 ID 且未加密的断言；
- 断言带有过期时间（其 `Conditions` 中的 `NotOnOrAfter`），大多数身份提供商默认会发送。

每个响应只能登录一次。如果同一个响应再次到达，QRdx 会拒绝它，并要求用户重新登录。如果用户启用了两步验证，QRdx 会先要求完成第二步，再将其带到控制台。

从应用控制台登录不算作[确认是你本人](/docs/help/privacy-and-security/two-step-verification#confirm-its-you)，除非用户完成了第二步验证，因为 QRdx 并未要求这一步。在进行需要确认的更改之前，他们会照常进行确认。

OIDC 连接始终从 QRdx 开始。若要把 QRdx 放进身份提供商的应用控制台，请将其添加为指向 QRdx 登录页面的链接。

## 强制使用单点登录 [#require-single-sign-on]

域名验证完成后，你可以让身份提供商成为该域名下用户唯一的登录方式。在 **Single sign-on** 页面中，开启域名对应的 **Require single sign-on for**。与连接一样，它也涵盖子域名。

开启后，对于该域名下的地址：

- 邮箱验证码、Google 和 GitHub 都无法让他们登录<IfAvailable feature="passkeys">，**Continue with passkey** 也不行</IfAvailable>。他们会看到提示：你的公司要求使用单点登录，以及 **Continue with SSO**。
- 身份提供商让他们登录之后，他们的[两步验证](/docs/help/privacy-and-security/two-step-verification)仍然适用。<IfAvailable feature="passkeys">通行密钥仍可用作第二步验证。</IfAvailable>
- 一次登录最多持续 24 小时。之后他们需要再次通过身份提供商登录，因此在身份提供商中取消分配的人无法再次登录 QRdx，并会在一天内被登出。
- 他们的 QRdx 邮箱无法更改为其他域名的地址，其他人的邮箱也无法更改为你域名下的地址。通过单点登录登录，是该域名下的地址进入 QRdx 的唯一途径。

开启后，你域名下所有用户中并非通过单点登录开始的会话都会被登出，而通过单点登录开始的会话会在该次登录 24 小时后结束。不会有人收到相关邮件；他们下次会被要求使用 SSO 登录。

**所有者保留其他登录方式。** 以上规则不适用于工作区的所有者：他们仍可使用邮箱验证码、Google 或 GitHub<IfAvailable feature="passkeys">，或通行密钥</IfAvailable>登录，会话不会被缩短，也可以更改邮箱。因此，身份提供商出问题不会让所有人都无法访问此设置。请只把所有者角色授予确实需要的少数人。

开启方法：

- 你需要是 Business 套餐上的**所有者**或**管理员**，并且已有验证过的域名，同时需要[确认是你本人](/docs/help/privacy-and-security/two-step-verification#confirm-its-you)。
- 如果你是管理员且地址属于该域名，请先通过单点登录登录。否则开启后你会被登出，而用这种方式登录也能证明连接可用。

关闭它、移除连接，或工作区不再使用 Business，都会停止强制要求。用户保留现有会话，并可以再次使用其他登录方式。该变更可能需要最多一分钟才能传递到所有 QRdx 服务器：在这一分钟内用其他方式登录的人可能会被立即登出，一分钟后可再次登录。

单点登录只涉及登录。API 密钥不属于登录，因此强制单点登录不会让它们失效；而在 **Team** 页面移除某人，则会让他们为工作区创建的 API 密钥失效。

## 彻底移除某人 [#remove-someone-for-good]

由于每次 SSO 登录都会把用户重新加入，仅在 **Team** 页面移除他们是不够的：

1. 在身份提供商中，取消他们对 QRdx 应用的分配（或停用他们在那里的账号），使其无法再登录 QRdx。
2. 然后在 **Team** 页面移除他们。当对方的地址属于你已验证的域名时，移除对话框会提醒你。

如果你[强制使用单点登录](#require-single-sign-on)，第 1 步还会在 24 小时内将他们登出 QRdx。也请在 **Team** 页面移除他们，这样他们就不再是成员，其为工作区创建的 API 密钥也会失效。

从工作区移除某人并不会删除其 QRdx 账号。除非其地址被要求使用单点登录，否则他们仍可通过邮箱验证码、Google 或 GitHub 登录自己的工作区。

## 更改或移除连接 [#change-or-remove-the-connection]

- **Replace secret**（OIDC）或 **Replace certificate**（SAML）用于在身份提供商处轮换后更新连接。通过元数据 XML 设置的 SAML 连接，需要先移除再重新设置才能更改。
- **Remove** 会关闭单点登录，并停止强制要求。所有人仍留在工作区中，并可使用邮箱验证码、Google 或 GitHub 登录。

## 套餐变更时 [#if-the-plan-changes]

如果工作区不再使用 Business，任何人都无法通过 SSO 登录（包括登录进行到一半时），单点登录也不再被强制要求。用户会看到一条提示，并可改用其他方式登录。连接及其设置会保留，因此工作区恢复 Business 后会重新生效，你也仍然可以将其移除。

## 不支持的功能 [#what-isnt-supported]

- 自动开通和移除（SCIM）。在身份提供商中移除某人不会将其从工作区移除。如果没有[强制使用单点登录](#require-single-sign-on)，也不会结束其 QRdx 会话；请同时在 **Team** 页面移除他们（参见[彻底移除某人](#remove-someone-for-good)）。
- 来自身份提供商的角色或群组。所有人都以 **New members** 下设置的角色加入。
- 每个工作区使用多个连接或多个域名。
- 使用 OIDC 连接时从身份提供商发起登录（SAML 支持：参见[从你的身份提供商打开 QRdx](#open-qrdx-from-your-identity-provider)）、SAML 单点登出，以及加密断言。
- 无法从互联网访问的身份提供商。
