Webhook mengirim peristiwa dari sebuah workspace ke URL yang Anda kendalikan, saat peristiwa itu terjadi. Gunakan webhook untuk memperbarui CRM saat seseorang mengisi formulir, mengirim pesan ke alat internal saat sebuah kode mencapai 1.000 pemindaian, atau menyimpan salinan data pemindaian Anda sendiri.

Webhook, hook Zapier/Make, dan peringatan Slack/Discord termasuk dalam paket **Business**. Peringatan email dan ringkasan mingguan termasuk dalam Pro; lihat [Notifikasi](/docs/notifications).

## Tambahkan endpoint [#add-an-endpoint]

1. Buka [Pengaturan → Webhook](/dashboard?to=settings/webhooks) di workspace yang peristiwanya ingin Anda terima. Tautan ini membuka workspace yang terakhir Anda gunakan; pilih workspace lain di pengalih workspace dan Anda tetap berada di halaman yang sama.
2. Klik **Add endpoint**, masukkan URL `https://` dan pilih peristiwanya. QRdx lebih dulu meminta Anda [mengonfirmasi bahwa ini Anda](/docs/help/privacy-and-security/two-step-verification#confirm-its-you), dan meminta lagi saat Anda mengubah URL endpoint; mengubah peristiwanya atau menjedanya tidak memerlukan konfirmasi.
3. Salin **signing secret** yang ditampilkan setelah menyimpan. Pemilik dan admin dapat menampilkannya lagi, atau memutarnya, nanti setelah [mengonfirmasi bahwa itu mereka](/docs/help/privacy-and-security/two-step-verification#confirm-its-you).
4. Klik **Send test**. QRdx mengirim peristiwa `ping` bertanda tangan dan menampilkan status respons.

Pemilik dan admin mengelola endpoint; anggota dapat melihat endpoint beserta log pengirimannya. Sebuah workspace dapat memiliki hingga 20 endpoint.

URL endpoint harus berupa nama host `https://` publik. Alamat IP, `localhost`, dan nama yang mengarah ke jaringan privat ditolak, dan pengalihan tidak diikuti.

## Peristiwa [#events]

| Peristiwa | Kapan | Catatan |
| --- | --- | --- |
| `scan.created` | Kode dinamis dipindai | Dikelompokkan: paling banyak satu permintaan per menit per endpoint, dikirim dalam beberapa menit, berisi hingga 100 pemindaian dan `count` yang tepat |
| `scan.milestone` | Pemindaian ke-1 sebuah kode, lalu ke-10, 100, 500, 1.000, 5.000, 10.000, 50.000, 100.000, 500.000 dan 1.000.000, lalu setiap satu juta | Dipicu sekali per tonggak |
| `code.created` | Kode dinamis dibuat (dasbor atau API) | Satu peristiwa per kode, termasuk pada pembuatan massal |
| `code.updated` | Tujuan, judul, desain, atau domain tautan pendek sebuah kode berubah | `changes` memuat daftar kolom yang berubah |
| `form.submitted` | Seseorang mengirim formulir di halaman yang di-hosting | Menyertakan jawabannya |
| `ping` | Anda mengklik **Send test** | |

Pemindaian oleh bot, pratinjau tautan, dan prefetcher, serta pengulangan cepat dari satu pengunjung, tidak dihitung dan tidak memicu peristiwa, persis seperti pada [analitik pemindaian](/docs/dynamic-qr-codes).

## Payload [#payloads]

Setiap permintaan adalah `POST` dengan isi JSON dan header berikut:

| Header | Nilai |
| --- | --- |
| `Content-Type` | `application/json` |
| `User-Agent` | `QRdx-Webhooks/1.0 (+https://qrdx.dev/docs/webhooks)` |
| `X-QRdx-Event` | Jenis peristiwa, misalnya `code.created` |
| `X-QRdx-Delivery` | ID pengiriman: sama pada setiap percobaan ulang, sehingga Anda dapat mengabaikan duplikat |
| `X-QRdx-Timestamp` | Detik Unix saat percobaan ini ditandatangani |
| `X-QRdx-Signature` | `t=<timestamp>,v1=<hex HMAC-SHA256>` |

Isi permintaan selalu berupa envelope:

```json
{
  "id": "evt_cm3x8c1a20001",
  "type": "code.created",
  "created_at": "2026-10-31T09:30:00.000Z",
  "data": {
    "code": {
      "id": "cm3x7q2l40000",
      "slug": "aB3dE5f",
      "title": "Spring menu",
      "short_link": "https://qrdx.dev/q/aB3dE5f",
      "destination_url": "https://example.com/menu",
      "status": "active",
      "scan_count": 0,
      "created_at": "2026-10-31T09:30:00.000Z",
      "updated_at": "2026-10-31T09:30:00.000Z"
    },
    "actor_id": "user_123"
  }
}
```

Satu kelompok `scan.created`:

```json
{
  "id": "evt_cm3x9d0b10002",
  "type": "scan.created",
  "created_at": "2026-10-31T09:31:00.000Z",
  "data": {
    "window_started_at": "2026-10-31T09:31:00.000Z",
    "window_seconds": 60,
    "count": 2,
    "scans": [
      {
        "scan_id": "cm3x9d0b00001",
        "code": { "id": "cm3x7q2l40000", "slug": "aB3dE5f", "title": "Spring menu" },
        "scanned_at": "2026-10-31T09:31:00.000Z",
        "country": "DE",
        "region": "BE",
        "city": "Berlin",
        "device_type": "mobile",
        "os": "iOS",
        "browser": "Safari",
        "referer": null,
        "source": "qr"
      }
    ]
  }
}
```

Jika lebih dari 100 pemindaian masuk dalam satu menit, `scans` berisi 100 yang pertama dan `count` berisi total yang tepat. `source` bernilai `nfc` untuk sentuhan pada [tag NFC](/docs/nfc) dan `qr` untuk pemindaian QR. Payload pemindaian tidak pernah menyertakan alamat IP atau hash pengunjung.

Peristiwa lain membawa:

- `scan.milestone`: `milestone`, `code` (`id`, `slug`, `title`, `scan_count`) dan `scan` yang mencapainya.
- `code.updated`: seperti `code.created`, ditambah `changes`, misalnya `["destination_url"]`.
- `form.submitted`: `response_id`, `page` (`id`, `title`), `code` (`id`, `slug`, atau `null`), `fields` (`name`, `label`, `value` sebagai teks) dan `submitted_at`.

## Verifikasi tanda tangan [#verify-signatures]

Hitung HMAC-SHA256 dari `<timestamp>.<raw body>` dengan signing secret Anda, lalu bandingkan dengan `v1` di `X-QRdx-Signature`. Gunakan isi permintaan mentah, sebelum parsing JSON apa pun, dan tolak timestamp yang lebih lama dari lima menit.

```ts
import { createHmac, timingSafeEqual } from "node:crypto";

export function isFromQRdx(rawBody: string, header: string, secret: string) {
  const parts = Object.fromEntries(
    header.split(",").map((part) => part.trim().split("=", 2)),
  );
  const timestamp = Number(parts.t);
  if (!timestamp || Math.abs(Date.now() / 1000 - timestamp) > 300) return false;

  const expected = createHmac("sha256", secret)
    .update(`${timestamp}.${rawBody}`)
    .digest("hex");
  const received = Buffer.from(parts.v1 ?? "");
  return (
    received.length === expected.length &&
    timingSafeEqual(received, Buffer.from(expected))
  );
}
```

Memutar secret berlaku seketika: secret lama tidak lagi lolos verifikasi, jadi perbarui server Anda segera setelah memutar.

## Percobaan ulang dan log pengiriman [#retries-and-the-delivery-log]

Balas dengan status `2xx` apa pun dalam 10 detik. Respons lain (status galat, pengalihan, batas waktu habis, host tidak dapat dijangkau) dianggap gagal, dan QRdx mencoba lagi dengan jeda yang makin panjang, minimal 1 menit, 4 menit, 16 menit, 1 jam, 4 jam, 17 jam, dan 24 jam. Setiap percobaan ulang dikirim dalam beberapa menit setelah jedanya berakhir. Totalnya 8 percobaan selama sekitar dua hari, setelah itu pengiriman ditandai **Failed**.

Halaman **Deliveries** setiap endpoint menampilkan 50 pengiriman terakhir beserta status, jumlah percobaan, galat terakhir, dan payload-nya. **Retry** mengirim ulang satu pengiriman segera (termasuk yang sudah terkirim). Pengiriman disimpan selama 30 hari.

Pengiriman bisa tiba lebih dari sekali (percobaan ulang setelah respons lambat, percobaan ulang manual) dan tidak berurutan. Gunakan `X-QRdx-Delivery` atau `id` pada envelope untuk mengabaikan duplikat.

Menonaktifkan endpoint menghentikan pengiriman baru; menghapusnya juga menghapus lognya. Jika paket sebuah workspace tidak lagi mencakup webhook, endpoint tetap disimpan tetapi tidak ada yang dikirim sampai workspace itu kembali ke Business. Kode QR Anda tetap berfungsi dalam kedua kasus.

## Zapier, Make, dan n8n (REST Hooks) [#zapier-make-and-n8n-rest-hooks]

Alat otomasi dapat berlangganan dan berhenti berlangganan sendiri melalui REST Hooks API. Lakukan autentikasi dengan [kunci API](/docs/developers/api-keys) atau token akses OAuth, seperti pada [API kode](/docs/dynamic-qr-codes#rest-api): `codes:write` untuk berlangganan atau berhenti berlangganan, `codes:read` untuk menampilkan daftar. URL hook sering kali rahasia, jadi dengan `codes:read` saja `target_url` hanya menampilkan host (`https://hooks.zapier.com/…`). Permintaan dengan token bekerja pada workspace Anda sendiri; kunci bekerja pada workspace tempat kunci itu dibuat. Berlangganan dengan sesi browser Anda yang sedang masuk, bukan dengan kunci atau token, meminta Anda lebih dulu [mengonfirmasi bahwa ini Anda](/docs/help/privacy-and-security/two-step-verification#confirm-its-you), dan menjawab `403` dengan `CONFIRMATION_REQUIRED` sampai Anda melakukannya dalam 10 menit terakhir. Langganan adalah endpoint biasa: langganan muncul di Pengaturan → Webhook, tempat Anda juga dapat menghapusnya.

| Metode | Path | Deskripsi |
| --- | --- | --- |
| `POST` | `/v1/hooks` | Berlangganan. Body: `target_url` (atau `hookUrl` milik Zapier) dan `event` (atau array `events`). Mengembalikan `201` dengan `id` langganan dan `secret`-nya |
| `DELETE` | `/v1/hooks/{id}` | Berhenti berlangganan (`204`) |
| `GET` | `/v1/hooks` | Menampilkan daftar langganan dan endpoint |
| `GET` | `/v1/hooks/{id}` | Satu langganan |
| `GET` | `/v1/hooks/sample?event=<event>` | Contoh payload terbaru untuk `event`, sebagai array ("perform list" milik Zapier) |

```bash
curl https://api.qrdx.dev/v1/hooks \
  -H "Authorization: Bearer $QRDX_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"target_url": "https://hooks.zapier.com/hooks/standard/123/abc/", "event": "form.submitted"}'
```

```json
{
  "id": "cm3xa1b2c0003",
  "target_url": "https://hooks.zapier.com/hooks/standard/123/abc/",
  "events": ["form.submitted"],
  "event": "form.submitted",
  "active": true,
  "created_at": "2026-10-31T09:40:00.000Z",
  "secret": "whsec_..."
}
```

Tanpa Business, panggilan berlangganan mengembalikan `402 PLAN_REQUIRED`. Pengiriman `scan.created` adalah satu kelompok, jadi di Zapier gunakan item baris `data.scans` untuk menangani setiap pemindaian.

Di n8n, node QRdx Trigger dari [node QRdx untuk n8n](/docs/developers/n8n) melakukan panggilan ini untuk Anda dan memeriksa setiap tanda tangan. Node Webhook biasa juga bisa digunakan, disiapkan seperti endpoint lainnya.

## Hosting mandiri [#self-hosting]

Pengiriman dikirim langsung; percobaan ulang dan kelompok pemindaian yang menitnya sudah berakhir dikirim oleh job terjadwal. QRdx menjalankannya setiap 5 menit dari workflow GitHub Actions, yang berfungsi di paket Hobby gratis Vercel, dan `apps/docs/vercel.json` juga menjalankannya secara penuh sekali sehari. GitHub dapat memulai eksekusi terjadwal terlambat, jadi harapkan percobaan ulang dalam beberapa menit, bukan tepat pada menitnya.

Untuk melakukan hal yang sama, salin `.github/workflows/webhook-worker.yml`, tambahkan `CRON_SECRET` Anda sebagai secret Actions dan URL job Anda sebagai variabel `WEBHOOK_WORKER_URL`. Atau panggil job dari penjadwal apa pun dengan `CRON_SECRET` yang Anda tetapkan di environment:

```bash
# every 1-5 minutes
curl -H "Authorization: Bearer $CRON_SECRET" https://your-host/api/cron/webhooks
```

Dengan `?source=github` ditambahkan ke URL, job lebih dulu memeriksa penanda kecil di Upstash Redis dan mengembalikan `{"skipped": true}` tanpa menjalankan kueri ke database jika tidak ada yang jatuh tempo, sehingga database yang menyusut hingga nol dapat tetap tertidur (tanpa Upstash, job selalu berjalan penuh). Pertahankan satu panggilan per hari tanpa parameter itu: eksekusi tersebut selalu menjalankan job penuh dan memperbaiki penanda.
