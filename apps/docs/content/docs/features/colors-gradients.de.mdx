Mit Farben und Verläufen gestaltest du QR-Codes im Look deiner Marke.

## Einfarbige Flächen [#solid-colors]

```tsx
import { QRCode } from 'qrdx';

<QRCode
  value="https://example.com"
  size={256}
  fgColor="#1a56db"
  bgColor="#f9fafb"
  eyeColor="#0d47a1"
  dotColor="#3b82f6"
/>
```

Unterstützte Formate: `#hex`, `rgb()`, `rgba()`, `hsl()`, `hsla()`, benannte Farben

Mit `eyeColors` legst du jedes Auge einzeln fest (`topLeft`, `topRight`, `bottomLeft`, jeweils mit einer `outer`- und einer `inner`-Farbe oder einem Verlauf); siehe [Muster](/docs/features/patterns#per-eye-colors).

### Transparenter Hintergrund [#transparent-background]

`bgColor="transparent"` zeichnet keinen Hintergrund. PNG- und SVG-Downloads sind dadurch durchsichtig, und PDF- und EPS-Dateien haben keine Hintergrundfüllung. Platziere den Code auf einer hellen, einfarbigen Fläche: Decoder brauchen die hellen Lücken zwischen den Modulen.

## Lineare Verläufe [#linear-gradients]

```tsx
import { QRCodeCanvas } from 'qrdx';

<QRCodeCanvas
  value="https://example.com"
  size={256}
  fgColor={{
    type: 'linear',
    stops: [
      { offset: 0, color: '#667eea' },
      { offset: 1, color: '#764ba2' }
    ],
    x1: 0, y1: 0,
    x2: 1, y2: 1
  }}
/>
```

### Verlaufsrichtungen [#gradient-directions]

- **Horizontal**: `x1: 0, y1: 0, x2: 1, y2: 0`
- **Vertikal**: `x1: 0, y1: 0, x2: 0, y2: 1`
- **Diagonal**: `x1: 0, y1: 0, x2: 1, y2: 1`

### Verläufe mit mehreren Stopps [#multi-stop-gradients]

```tsx
<QRCodeCanvas
  value="https://example.com"
  size={256}
  fgColor={{
    type: 'linear',
    stops: [
      { offset: 0, color: '#667eea' },
      { offset: 0.3, color: '#764ba2' },
      { offset: 0.7, color: '#f093fb' },
      { offset: 1, color: '#f5576c' }
    ],
    x1: 0, y1: 0, x2: 1, y2: 1
  }}
/>
```

## Radiale Verläufe [#radial-gradients]

```tsx
<QRCodeCanvas
  value="https://example.com"
  size={256}
  fgColor={{
    type: 'radial',
    stops: [
      { offset: 0, color: '#ff6b6b' },
      { offset: 1, color: '#4ecdc4' }
    ],
    cx: 0.5, cy: 0.5,
    r: 0.5
  }}
/>
```

## Farb-Utilities [#color-utilities]

### Kontrast prüfen [#check-contrast]

```tsx
import { getContrastRatio, getContrastLevel } from 'qrdx';

const ratio = getContrastRatio('#000000', '#ffffff');
// Returns: 21

const level = getContrastLevel(ratio);
// Returns: { level: 'AAA', warning: false, message: 'Excellent contrast' }
```

### Kontrast-Richtlinien [#contrast-guidelines]

- **Minimum**: Verhältnis 3,0:1
- **Empfohlen**: 4,5:1 oder höher
- **Ausgezeichnet**: 7,0:1 oder höher

## Winkelverläufe [#angular-gradients]

Ein Winkelverlauf läuft im Uhrzeigersinn um die Mitte der gefüllten Fläche, wie CSS `conic-gradient`. `angle` ist der Startpunkt des Verlaufs, in Grad im Uhrzeigersinn von oben. Die Offsets laufen von 0 bis 100 um die volle Drehung.

```tsx
<QRCode
  value="https://example.com"
  fgColor={{
    type: "angular",
    angle: 30,
    stops: [
      { color: "#1d4ed8", offset: 0 },
      { color: "#7c3aed", offset: 50 },
      { color: "#1d4ed8", offset: 100 },
    ],
  }}
/>
```

SVG kennt keinen konischen Verlauf, deshalb zeichnet der Code einen Fächer aus dünnen Keilen, etwa zwei Farbstufen voneinander entfernt. PDF und EPS zeichnen dieselben Keile.

## Durchsichtige Farben [#see-through-colors]

Farben und Verlaufsstopps können einen Alphawert enthalten, etwa `#1d4ed8cc` oder `rgba(29, 78, 216, 0.8)`. SVG schreibt ihn als `fill-opacity` und `stop-opacity`, und PDF behält ihn bei. EPS kennt keine Transparenz, daher wird eine durchsichtige Farbe mit dem Hintergrund gemischt. Die Scan-Prüfung beurteilt eine durchsichtige Farbe so, wie sie auf dem Hintergrund aussieht.

## Bildfüllungen [#image-fills]

Eine Bildfüllung legt ein Bild über den Hintergrund, die Punkte oder die Augen. Das Bild liegt über dem ganzen Code, sodass Punkte und Augen, die sich eines teilen, ein einziges Bild zeigen.

```tsx
<QRCode
  value="https://example.com"
  fgColor={{
    type: "image",
    src: "data:image/jpeg;base64,…",
    fit: "cover", // or "contain", "tile"
    position: "center",
    scale: 1,
    opacity: 0.45,
    underlay: "#000000",
  }}
/>
```

- `src` ist das Bild selbst, wie bei einem Logo. QRdx speichert eine Bildfüllung (in Codes, Themes und der REST API) nur als base64-`data:image`-URL (PNG, JPEG, WebP oder GIF) mit höchstens 1,5 MB; ein Bild über einen Link wird abgelehnt. PNG und JPEG werden in jedem Export eingebettet, und Server rufen nie einen Link ab.
- `underlay` ist eine einfarbige Fläche unter dem Bild. `opacity` lässt sie durchscheinen: Über Schwarz dunkelt sie ein Foto für die Punkte ab, über Weiß hellt sie eines für den Hintergrund auf.
- Die Details eines Bildes wirken auf eine Kamera wie Rauschen, deshalb verlangt die Scan-Prüfung mehr Kontrast: 7:1 in den Punkten oder Augen, 12:1 dahinter (`SCAN_IMAGE_CONTRAST_MIN`). Sie misst ein Bild an seinem hellsten und dunkelsten Zehntel (`getImageTones`). Im Editor findet „Make it scannable" die Deckkraft über dem Underlay, die besteht.
- SVG, PNG und PDF unterstützen Bildfüllungen. EPS nicht ([Downloads](/docs/features/downloads#eps)).

Bildfüllungen verhalten sich wie Logos. Sie bleiben beim Design im Editor, in gespeicherten Codes und in gespeicherten Themes. In `?style=`-Links, veröffentlichten Community-Stilen, Get-code-Snippets und im Kontext des Chats fehlen sie: Dort wird jede Bildfüllung durch ihre Underlay-Farbe ersetzt. Die Image API (`GET /v1/qr`) und der MCP-Server unterstützen sie noch nicht. `POST /v1/codes` und `PATCH /v1/codes/{id}` nehmen eine nur als `data:image`-URL an und antworten bei allem anderen mit 400; eine ID für hochgeladene Dateien gibt es für Bilder noch nicht.

Winkelverläufe und Bildfüllungen sind im qrdx-Quellcode enthalten und erscheinen mit dem nächsten npm-Release. qrdx 0.0.46 auf npm enthält sie nicht.
