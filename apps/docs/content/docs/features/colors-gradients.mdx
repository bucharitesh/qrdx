Apply colors and gradients to create branded QR codes.

## Solid Colors

```tsx
import { QRCode } from 'qrdx';

<QRCode
  value="https://example.com"
  size={256}
  fgColor="#1a56db"
  bgColor="#f9fafb"
  eyeColor="#0d47a1"
  dotColor="#3b82f6"
/>
```

Supported formats: `#hex`, `rgb()`, `rgba()`, `hsl()`, `hsla()`, named colors

`eyeColors` sets each eye on its own (`topLeft`, `topRight`, `bottomLeft`, each with an `outer` and `inner` color or gradient); see [Patterns](/docs/features/patterns#per-eye-colors).

### Transparent background

`bgColor="transparent"` paints no background, so PNG and SVG downloads are see-through and PDF and EPS files have no background fill. Place the code on a light, plain surface: decoders need the light gaps between modules.

## Linear Gradients

```tsx
import { QRCodeCanvas } from 'qrdx';

<QRCodeCanvas
  value="https://example.com"
  size={256}
  fgColor={{
    type: 'linear',
    stops: [
      { offset: 0, color: '#667eea' },
      { offset: 1, color: '#764ba2' }
    ],
    x1: 0, y1: 0,
    x2: 1, y2: 1
  }}
/>
```

### Gradient Directions

- **Horizontal**: `x1: 0, y1: 0, x2: 1, y2: 0`
- **Vertical**: `x1: 0, y1: 0, x2: 0, y2: 1`
- **Diagonal**: `x1: 0, y1: 0, x2: 1, y2: 1`

### Multi-Stop Gradients

```tsx
<QRCodeCanvas
  value="https://example.com"
  size={256}
  fgColor={{
    type: 'linear',
    stops: [
      { offset: 0, color: '#667eea' },
      { offset: 0.3, color: '#764ba2' },
      { offset: 0.7, color: '#f093fb' },
      { offset: 1, color: '#f5576c' }
    ],
    x1: 0, y1: 0, x2: 1, y2: 1
  }}
/>
```

## Radial Gradients

```tsx
<QRCodeCanvas
  value="https://example.com"
  size={256}
  fgColor={{
    type: 'radial',
    stops: [
      { offset: 0, color: '#ff6b6b' },
      { offset: 1, color: '#4ecdc4' }
    ],
    cx: 0.5, cy: 0.5,
    r: 0.5
  }}
/>
```

## Color Utilities

### Check Contrast

```tsx
import { getContrastRatio, getContrastLevel } from 'qrdx';

const ratio = getContrastRatio('#000000', '#ffffff');
// Returns: 21

const level = getContrastLevel(ratio);
// Returns: { level: 'AAA', warning: false, message: 'Excellent contrast' }
```

### Contrast Guidelines

- **Minimum**: 3.0:1 ratio
- **Recommended**: 4.5:1 or higher
- **Excellent**: 7.0:1 or higher

## Angular gradients

An angular gradient sweeps clockwise around the centre of what it fills, like CSS `conic-gradient`. `angle` is where the sweep starts, in degrees clockwise from the top. Offsets run from 0 to 100 around the turn.

```tsx
<QRCode
  value="https://example.com"
  fgColor={{
    type: "angular",
    angle: 30,
    stops: [
      { color: "#1d4ed8", offset: 0 },
      { color: "#7c3aed", offset: 50 },
      { color: "#1d4ed8", offset: 100 },
    ],
  }}
/>
```

SVG has no conic gradient, so the code draws a fan of thin wedges, about two color levels apart. PDF and EPS draw the same wedges.

## See-through colors

Colors and gradient stops can carry alpha, such as `#1d4ed8cc` or `rgba(29, 78, 216, 0.8)`. SVG writes it as `fill-opacity` and `stop-opacity`, and PDF keeps it. EPS has no transparency, so a see-through color is mixed with the background. The scan check judges a see-through color the way it looks on the background.

## Image fills

An image fill paints a picture through the background, the dots or the eyes. The picture is laid over the whole code, so dots and eyes that share one show a single picture.

```tsx
<QRCode
  value="https://example.com"
  fgColor={{
    type: "image",
    src: "data:image/jpeg;base64,…",
    fit: "cover", // or "contain", "tile"
    position: "center",
    scale: 1,
    opacity: 0.45,
    underlay: "#000000",
  }}
/>
```

- `src` is a data URL, as with a logo. PNG and JPEG embed in every export. Servers never fetch a link.
- `underlay` is a solid color under the picture. `opacity` lets it through: over black it darkens a photo for the dots, and over white it lightens one for the background.
- A picture's detail reads as noise to a camera, so the scan check asks for more contrast: 7:1 in the dots or eyes, 12:1 behind them (`SCAN_IMAGE_CONTRAST_MIN`). It measures a picture by its lightest and darkest tenth (`getImageTones`). In the editor, "Make it scannable" finds the opacity over the underlay that passes.
- SVG, PNG and PDF carry image fills. EPS can't ([Downloads](/docs/features/downloads#eps)).

Image fills travel like logos. They stay with the design in the editor, in saved codes and in saved themes. They don't go into `?style=` links, published community styles, Get code snippets or the chat's context: each image fill gives way to its underlay color there. The image API (`GET /v1/qr`) and the MCP server don't take them yet. `POST /v1/codes` takes one only as a data URL, the way it takes `customLogo`; there's no uploaded-file id for pictures yet.

Angular gradients and image fills are in the qrdx source and ship with the next npm release. qrdx 0.0.46 on npm doesn't have them.
