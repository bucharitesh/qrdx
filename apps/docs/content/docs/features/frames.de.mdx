Füge einen „Scan me"-Rahmen hinzu, prüfe vor der Veröffentlichung, ob ein Design sich scannen lässt, und exportiere eine Vektordatei in exakter physischer Größe.

## Call-to-Action-Rahmen [#call-to-action-frames]

Jeder Rahmen, den QRdx zeichnet, ist eine Rahmen-Spezifikation: eine kleine JSON-Beschreibung von Formen, Beschriftungen und Farben. Eine Engine zeichnet jede Spezifikation, deshalb sieht ein Rahmen in SVG, PNG, PDF und EPS gleich aus. QRdx hat {facts.frames} Rahmen: {facts.frameStyles} eingebaute Rahmen und {facts.officialFrames} [offizielle Rahmen](#official-frames). Du kannst auch eigene erstellen oder einen aus der [Community](/community/frames) wählen.

Die Prop `frame` zeichnet einen Rahmen um den Code. Sie funktioniert bei `QRCode`, `QRCodeSVG`, `QRCodeCanvas`, `getQRAsSVG`, `getQRData` und allen Download-Helfern.

```tsx
import { QRCode } from "qrdx";

<QRCode
  value="https://example.com/menu"
  frame={{ style: "banner-bottom", text: "Scan for the menu", color: "#1e3a8a" }}
/>
```

Der Rahmen wird **um** den Code herum hinzugefügt: Die Ausgabe wird größer, und die QR-Module und die Ruhezone werden nie verdeckt, sodass die Scanbarkeit unverändert bleibt. Ein heller Abstand in der Hintergrundfarbe des Codes trennt den Code vom Rahmen.

### Eingebaute Rahmen [#built-in-frames]

Ein eingebauter Rahmen wird über seinen `style` benannt. Die Optionen füllen die Beschriftungen und Farben seiner Spezifikation:

| Option | Standard | Hinweise |
| --- | --- | --- |
| `style` | — | Einer der {facts.frameStyles} eingebauten Rahmen unten oder `none` (`FRAME_STYLES`) |
| `text` | `"Scan me"` | Bis zu 24 Zeichen. Übergib `""`, um die Beschriftung auszublenden |
| `color` | `#000000` | Rahmenfarbe (`gradient-border`: Startfarbe, Standard Violett) |
| `textColor` | Weiß auf dem Rahmen, `color` auf hellen Flächen | Beschriftungsfarbe |
| `secondaryText` | keine | Zweite Beschriftung, bis zu 24 Zeichen: das untere Band von `banner-top-bottom`, der untere Bogen von `circle`, die Fußzeile von `menu-card` |
| `secondaryColor` | `#db2777` | Endfarbe von `gradient-border` |
| `fontScale` | `1` | Beschriftungsgröße von 0.5 bis 1.5; Beschriftungen schrumpfen weiterhin, damit sie passen |

Die eingebauten Rahmen, nach `style`:

- Banner und Rahmenlinien: `banner-bottom`, `banner-top`, `banner-top-bottom`, `border`, `rounded-border`, `gradient-border`, `focus` (Eckklammern)
- Sprechblasen: `speech-bubble`, `speech-bubble-top`, `chat-bubble`
- Abzeichen: `circle` (Text rund um einen Ring), `badge` (Band), `sticker` (ausgestanzt mit Schatten)
- Objekte: `polaroid`, `phone`, `ticket`, `tag` (Anhänger mit Loch), `envelope`, `menu-card`

Jeder dieser Namen steht für eine Spezifikation in der Engine, und die Namen bleiben dauerhaft gültig. Gespeicherte Designs, Image-API-Links, CLI-Flags und Code, die sie verwenden, zeichnen weiterhin denselben Rahmen. Rahmen, die die Zeile ihrer Beschriftung weglassen, wenn es keine Beschriftung gibt, etwa die Rahmenlinien, tun das weiterhin.

`BUILT_IN_FRAMES` listet sie mit Namen und Spezifikationen auf (`BUILT_IN_FRAME_SPECS` enthält die Spezifikationen nach Style). `frameSpecOf` gibt die Spezifikation zurück, die ein beliebiger Rahmen zeichnet, und `getFrameColors` die Farben, mit denen er malt:

```tsx
import { BUILT_IN_FRAMES, frameSpecOf, getFrameColors } from "qrdx";

BUILT_IN_FRAMES.map((frame) => frame.name); // ["Banner", "Top banner", …]

// A built-in style's spec, or a custom frame's own
const ticket = frameSpecOf({ style: "ticket" });

// The frame's options, else its spec's defaults
getFrameColors({ style: "border", color: "#1e3a8a" });
// { frame: "#1e3a8a", text: "#1e3a8a", accent: "#1e3a8a" }
```

Wenn du mehr als Beschriftungen und Farben ändern willst, starte einen eigenen Rahmen aus einer eingebauten Spezifikation: `{ style: "custom", spec: frameSpecOf({ style: "ticket" }) }` zeichnet dasselbe Ticket, und du kannst seine Formen bearbeiten.

Alle Rahmen, in deinem Browser dekodiert, siehst du unter [Formen, Augen und Rahmen](/docs/styles#frames). Jeder Rahmen besteht aus einfachen Formen und Text mit deckenden Farben, deshalb stimmen die Exporte in SVG, PNG, PDF und EPS überein (der Verlaufsrahmen wird in feinen einfarbigen Stufen gezeichnet, und die gebogenen Buchstaben des Kreisrahmens sind in jedem Format gedrehter Text).

```tsx
<QRCode
  value="https://example.com"
  frame={{ style: "circle", text: "Scan me", secondaryText: "example.com", fontScale: 1.2 }}
/>
```

Die Beschriftung nutzt den System-Font-Stack, es wird also nichts heruntergeladen. Weil die Ausgabe größer wird, nutze `getFrameDimensions(size, frame)`, wenn du die endgültige Breite und Höhe brauchst:

```ts
import { getFrameDimensions } from "qrdx";

getFrameDimensions(400, { style: "banner-bottom" }); // { width: 496, height: 568 }
```

`FRAME_STYLES`, `frameSchema` (zod) und die Typen `QRFrame` / `FrameStyle` werden ebenfalls aus `qrdx/types` für die serverseitige Validierung exportiert. `GRADIENT_FRAME_DEFAULTS` (die Standardfarben des Verlaufsrahmens) und `FRAME_GAP_RATIO` werden weiterhin für Code exportiert, der sie verwendet hat; der Abstand jedes Rahmens ist das Padding seiner Spezifikation (`getFrameGapRatio`).

### Im Playground [#in-the-playground]

**Design → Rahmen** hat eine Auswahl für alle Rahmen. Die Gruppe **Klassisch** enthält die eingebauten Rahmen, neben den geformten Codes, den offiziellen Rahmen und den Rahmen, die du gespeichert hast. Jeder Rahmen wird auf dieselbe Weise bearbeitet: Beschriftung, zweite Zeile, Farben und Textgröße, dazu Icons bei Rahmen, die welche haben. Ein Design mit eingebautem Rahmen behält seinen `style`-Namen, sodass Links, Bild-URLs und Code-Snippets kurz bleiben.

Die Gruppe **Geformte Codes** bringt den Code selbst in eine Form: einen Kreis oder ein Herz aus dekorativen Punkten oder eine Form, die du hochlädst ([`shape`](/docs/features/patterns#circle-codes)). Ein geformter Code ersetzt einen Rahmen: Wählst du einen, wird der Rahmen entfernt, und wählst du einen Rahmen, wird die Form entfernt.

### In der CLI [#in-the-cli]

```bash
qrdx generate "https://example.com/menu" --frame banner-bottom --frame-text "Scan for the menu" -o menu.png
```

`--frame-color` und `--frame-text-color` akzeptieren Hex-Farben. Wenn du Text oder Farben ohne `--frame` angibst, wird `banner-bottom` verwendet.

### Rahmen-Spezifikationen [#frame-specs]

Eine Rahmen-Spezifikation ist JSON mit `kind: "qrdx.frame"`, `version: 1`, einer `artboard`-Größe, einer `qr`-Box, in die der Code kommt, Standard-`colors`, den `shapes`, die hinter dem Code gemalt werden, und den `labels`. Formen sind Rechtecke (mit optionalem Loch), Kreise und Ringe, Ellipsen, Polygone, Pfade, Linien und eingebaute Icons. Sie werden mit einem Theme-Token (`frame`, `text`, `accent`, `background`), einer Hex-Farbe, einer Mischung aus zwei Farben oder einem Verlauf gefüllt. Eine Spezifikation enthält kein Markup, keine Links und keine Bilder. Prüfe eine Spezifikation, die du nicht selbst geschrieben hast, mit `frameSpecSchema` oder `getFrameSpecIssues` aus `qrdx/types`, bevor du sie speicherst. Die Engine prüft sie vor dem Zeichnen noch einmal.

Die eingebauten Rahmen haben diese optionalen Felder mitgebracht. Spezifikationen ohne sie werden wie bisher gezeichnet:

| Feld | Was es bewirkt |
| --- | --- |
| `labels[].collapse` | `{ y, height }`. Zeigt die Beschriftung keinen Text, wird das Band von `y` bis `y + height` herausgeschnitten: Zeilen darunter rücken nach oben, und das Artwork wird kürzer. Formen, die ganz im Band liegen, entfallen, und Formen, die es kreuzen, werden kürzer. Ein Band darf weder den Code noch sein Padding noch ein anderes Band kreuzen. |
| `qr.plate` | `"opaque"` (der Standard) oder `"background"`. Die Engine malt unter den Code eine Platte in der Hintergrundfarbe des Codes. Ist dieser Hintergrund durchsichtig, malt `"opaque"` die Platte und `background` füllt mit Weiß, sodass Artwork nie durch die Ruhezone scheint. `"background"` lässt sie durchsichtig und lässt die Platte weg. Das ist nur erlaubt, wenn unter der Platte nichts als `background`-Füllungen oder ein Ring liegt, dessen Loch die Platte enthält. |
| `colors.text` | Eine Hex-Farbe oder eine Mischung aus `frame`, `accent`, `background` und Hex-Farben, etwa `{ "mix": ["frame", "accent"], "amount": 0.5 }` für die Beschriftung des Verlaufsrahmens. Das ist der Standard; `textColor` hat weiterhin Vorrang. |

Die Zeile einer Textbeschriftung darf auch in das Padding der Platte hineinreichen, solange sie vom Code fernbleibt und ihre Großbuchstaben bei der größten Textgröße (`fontScale` 1.5) nicht ins Padding ragen. Die Rahmenlinien setzen ihre Beschriftung auf diese Weise direkt unter den Code.

qrdx 0.0.51 und älter lehnen Spezifikationen ab, die diese Felder verwenden oder eine Beschriftungszeile ins Padding setzen. Aktualisiere also die Engine, bevor du eine solche Spezifikation anderswo zeichnest.

## Offizielle Rahmen [#official-frames]

Zusätzlich zu den eingebauten Rahmen hat QRdx {facts.officialFrames} offizielle Rahmen: fertige Designs für Calls to Action, Restaurants und Cafés, Geschäfte und Verpackungen, Beauty und Wellness, Events und Hochzeiten, Hotels und Reisen, Immobilien, Autos und Parken, Gesundheit und Bildung, Sport und Fitness, Business und Social Media sowie gemeinnützige Organisationen und Gemeinschaftsgruppen. {facts.seasonalFrames} davon sind für Feiertage und Jahreszeiten, vom Mondneujahr, Holi, Eid und Diwali bis zu Hanukkah, Ostern, Thanksgiving und Weihnachten. Jeder ist eine Rahmen-Spezifikation mit Beschriftungen und Farben, die du ändern kannst, unter CC0 veröffentlicht, und jeder ist darauf getestet, dass er aus Handy-Entfernung scannt.

Öffne im [Playground](/playground) **Rahmen** und dann **Mehr**. Suche nach Name, Verwendung oder Feiertag oder wähle eine Gruppe. Rahmen für die anstehenden Feiertage und Jahreszeiten stehen zuerst. Du findest sie auch in der [Community](/community/frames), veröffentlicht von @qrdx.

Die Engine exportiert sie als `OFFICIAL_FRAMES`:

```tsx
import { getOfficialFrame, QRCode } from "qrdx";

const diwali = getOfficialFrame("diwali-diya"); // undefined for an unknown id

{diwali && (
  <QRCode
    value="https://example.com/offers"
    frame={{ style: "custom", spec: diwali.spec, text: "Scan for offers" }}
  />
)}
```

`OFFICIAL_FRAME_INDEX` listet jeden Rahmen ohne seine Spezifikation auf, sodass eine Auswahl die ganze Bibliothek zeigen und Spezifikationen erst bei Bedarf laden kann. In der [Image API](/docs/developers/image-api#community-items) und im [MCP-Server](/docs/developers/mcp) verwendest du einen offiziellen Rahmen als Community-Element, etwa `item=frame:diwali-diya`.

## Wird er scannen? [#will-it-scan]

`getScanScore` schätzt, wie zuverlässig sich ein Design scannen lässt. Die Funktion läuft im Browser und lädt [jsQR](https://github.com/cozmo/jsQR) bei Bedarf nach.

```ts
import { getScanScore } from "qrdx";

const { score, grade, checks } = await getScanScore({
  value: "https://example.com",
  bodyPattern: "circle",
  cornerEyePattern: "gear",
});
// score: 0–100, grade: "great" | "ok" | "risky" | "fails"
// checks: [{ id, passed, message, fix? }]
```

Das wird geprüft:

- **Dekodierung bei 96, 160 und 320 px.** Das Design wird in jeder Breite gerendert, mit kameraähnlicher Unschärfe und Kontrastverlust versehen und mehrmals in leicht unterschiedlichen Maßstäben dekodiert.
- **Kontrast** zwischen jeder Farbe des Codes (einschließlich Verlaufsstopps, Augen- und Punktfarben) und dem Hintergrund sowie die Frage, ob der Code dunkel auf hell ist.
- **Logo-Abdeckung** im Vergleich zu dem, was die Fehlerkorrekturstufe wiederherstellen kann.
- **Ruhezone**: der Rand plus der Abstand, den ein Rahmen hinzufügt.
- **Risiko der Augenform**: `circle`-Augen werden von manchen Scanner-Apps eventuell nicht erkannt (und die veralteten `curly`-Augen, falls ein gespeichertes Design sie noch verwendet, scheitern an strengen Dekodern).
- **Stilpaare** (`style-pair`): Formen, die in unseren Dekodiertests gemeinsam scheitern, etwa `small-square`-Punkte neben quadratischen Augen, sowie veraltete Zentren in gespeicherten Designs (siehe `getStylePairRisk`).

`getImageScanScore(fileOrImage)` macht dasselbe für ein vorhandenes Bild: Es liefert den dekodierten Inhalt sowie Prüfungen zu Dekodierung, Kontrast, Polarität, Ruhezone und Auflösung, die aus den Pixeln gemessen werden. Der [Scan-Checker](/tools/scan-checker) basiert darauf.

<Callout type="info">
  Der Score ist eine Heuristik, die auf einem einzigen Open-Source-Decoder beruht. Kamera-Apps auf Smartphones sind oft toleranter. Sieh ihn daher als Orientierung an und teste wichtige Drucke per Scan.
</Callout>

## Druckfertiger Export [#print-ready-export]

`downloadPrintPDF` schreibt ein Vektor-PDF in exakter physischer Größe. Module, Augen und Rahmen sind Vektorpfade (ein Logo bleibt ein Rasterbild).

```ts
import { downloadPrintPDF, downloadPrintSVG, getPrintLayout } from "qrdx";

const props = { value: "https://example.com", frame: { style: "banner-bottom" } } as const;

await downloadPrintPDF(props, {
  size: 40, // width of the code itself
  unit: "mm", // or "in"
  bleed: 3, // millimetres on every side
  cropMarks: true,
  colorMode: "cmyk",
});

await downloadPrintSVG(props, { size: 1.5, unit: "in" }); // width="…in" height="…in"

const layout = getPrintLayout(props, { size: 40 });
layout.trimWidth; // finished width in mm, frame included
layout.maxScanDistance; // 400 (mm)
```

- `size` ist die Breite des Codes; ein Rahmen vergrößert das fertige Maß.
- Mit Beschnitt reicht der Hintergrund (oder die Farbe eines quadratischen Rahmens) über die Schnittkante hinaus, sodass beim Zuschneiden kein weißer Streifen bleibt. Die Schnittmarken liegen außerhalb des Beschnitts.
- `colorMode: "cmyk"` verwendet eine einfache Umrechnung (`rgbToCmyk`: K = 1 − max(R, G, B), kein ICC-Profil; reines Schwarz wird nur mit K gedruckt). Bitte deine Druckerei um eine farbverwaltete Umrechnung, wenn exakte Markenfarben wichtig sind.
- Lineare und radiale Verläufe werden im PDF als weiche Farbverläufe gedruckt, in CMYK, wenn das PDF CMYK ist; das Druck-SVG behält sie bei, bleibt aber RGB.
- Rahmentext im PDF verwendet Helvetica Bold, daher werden Zeichen außerhalb von Latin-1 eventuell nicht dargestellt. Nutze für andere Schriften das SVG.
- `getQRAsPrintPDF` und `getQRAsPrintPDFBuffer` geben die Datei zurück, statt sie herunterzuladen, und funktionieren auch in Node.

**Wie groß du drucken solltest:** Ein Code lässt sich ab etwa der zehnfachen Breite als Abstand scannen, also Größe ≈ Scan-Abstand ÷ 10 (2 cm breit für 20 cm). Dichtere Codes brauchen mehr; der [Druckgrößen-Rechner](/tools/print-size) berücksichtigt das.
