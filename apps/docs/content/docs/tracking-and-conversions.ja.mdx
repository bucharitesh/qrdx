すべての[動的QRコード](/docs/dynamic-qr-codes)は、Cookieを使わずにスキャンを記録します。さらに、ホスト型ページに独自のピクセルを読み込んだり（Pro）、購入などのコンバージョンを、訪問者を連れてきたスキャンに紐付けたり（Business）できます。どちらも[ダッシュボード](/dashboard?to=codes)にあるコードのページの **Settings** タブで設定します。

## すべてのコードで使える分析 [#analytics-on-every-code]

各コードのページには、時間ごとのスキャン数、国、都市、デバイス、OS、ブラウザ、リファラーに加えて、次の情報が表示されます。

- **スキャンされる時間帯：** 時間帯別および曜日別のスキャン数を、UTCまたはご自身のタイムゾーンで表示します。
- **言語：** 各訪問者のブラウザの優先言語です。ブラウザが言語を送信しない場合や、言語が記録される前のスキャンは「Unknown」と表示されます。
- **A/B分割：** 各[A/B分割ルール](/docs/smart-routing#ab-tests)のバリアントごとのスキャン数です。
- **ページのアクティビティ**（ホスト型ページ）：ページビュー数、ユニークビューア数、タップ数、そして最もタップされたリンクとボタンです。
- **コンバージョン**（コードにコンバージョンがある場合）。

[ダッシュボード → Analytics](/dashboard?to=analytics)では、ワークスペース内のすべてのコードを合算して確認できます。合計、スキャン数の推移、上位のコード、国、デバイス、言語、スキャン時間帯のほか、最大4つのコードを並べて比較することもできます。

ボットやリンクプレビューはカウントされません。「ユニーク」は、1人の訪問者を1日につき1回として数えます。IPアドレスは保存されません。

## ホスト型ページのトラッキングピクセル（Pro） [#tracking-pixels-on-hosted-pages-pro]

ホスト型ページを開くコードでは、**Tracking pixels** パネルで独自のタグをそのページに読み込めます。

| プロバイダー | IDの形式 |
| --- | --- |
| Google Analytics 4 | `G-XXXXXXXXXX` |
| Google Tag Manager | `GTM-XXXXXXX` |
| Meta (Facebook) pixel | 6〜20桁の数字 |
| TikTok pixel | 10〜30文字の英数字 |
| LinkedIn Insight Tag | パートナーID、3〜12桁の数字 |

ピクセルは、お客様が設定した場合にのみ読み込まれます。QRdxがホスト型ページに独自のサードパーティスクリプトを追加することはありません。

Google Tag Managerは、ページが[カスタムドメイン](/docs/custom-domains)のいずれかで開かれた場合にのみ読み込まれます。コンテナは任意のスクリプトを実行できるため、訪問者がQRdxにサインインしている可能性のあるqrdx.devでは実行されません。

**同意。** ピクセルは、訪問者が同意するまで読み込まれません。

- **必要な場合のみ**（デフォルト）：EU/EEA、英国、スイスの訪問者と、所在地が不明な訪問者には、使用するプロバイダー名を示した短いバナーが表示され、**Accept** または **Decline** を選択します。選択内容はそのページに対して記憶され、**Cookie settings** から変更できます。それ以外の地域では、Global Privacy Controlシグナルを送信するブラウザを除き、ピクセルがすぐに読み込まれます。
- **すべての訪問者：** 全員に最初にバナーが表示されます。

プライバシーポリシーの整備や、ピクセルが収集したデータの利用については、お客様の責任となります。

ご自身のウェブサイトを開くコードは、そのままサイトに移動するため、ピクセルはサイト側に追加してください。

## コンバージョントラッキング（Business） [#conversion-tracking-business]

コンバージョントラッキングでは、どのスキャンが売上、会員登録、その他の目標につながったかを、売上額とともに確認できます。

1. ウェブサイトを開くコードで、**Conversion tracking** をオンにします。すると、スキャンのたびに署名付きの `qrdx_sid` パラメーターが付いたURL（例：`https://shop.example/?qrdx_sid=…`）が開きます。
2. 訪問者が最初に到達するページと、コンバージョンが発生するページにスニペットを追加します。

```html
<script async src="https://qrdx.dev/conversions.js"></script>
<script>
  window.qrdx = window.qrdx || function () {
    (window.qrdx.q = window.qrdx.q || []).push(arguments);
  };
  // Where the conversion happens, e.g. your order confirmation page:
  qrdx("conversion", { name: "purchase", value: 49.99, currency: "USD", id: "ORDER-1234" });
</script>
```

スクリプトは `qrdx_sid` をお客様のドメインのファーストパーティCookieに30日間保存し（ブラウザのセッション中のみ保持するには、scriptタグに `data-storage="session"` を追加します）、アドレスバーから削除します。コンバージョンはスキャンから訪れた訪問者についてのみ送信されるため、それ以外の訪問者が追跡されることはありません。

| フィールド | 意味 |
| --- | --- |
| `name` | 発生した内容。例：`purchase`、`signup`（デフォルトは `conversion`） |
| `value` | 金額。小数点以下2桁まで（省略可） |
| `currency` | `USD` のようなISO 4217コード。金額を指定した場合のデフォルトは `USD` |
| `id` | 注文IDまたはイベントID。同じIDを2回送信しても1回だけ記録されます |
| `metadata` | 追加のキーと値のペア（最大20個、省略可） |

### サーバーから送信する [#from-your-server]

バックエンドからコンバージョンを報告するには（ブラウザからより確実です）、`qrdx_sid` を注文と一緒に保管し、`codes:write` スコープを持つ[APIキー](/docs/developers/api-keys)または[OAuthアクセストークン](/docs/developers/rest-api#get-an-access-token)を使ってAPIを呼び出します。

```bash
curl -X POST https://api.qrdx.dev/v1/conversions \
  -H "Authorization: Bearer $QRDX_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"sid": "<qrdx_sid>", "name": "purchase", "value": 49.99, "currency": "USD", "id": "ORDER-1234"}'
```

トークンを使う場合は、スキャンが特定できないときに `sid` の代わりに `"code": "<code id>"` を送ることもできます。APIは、新しいコンバージョンには `201` を返し、`id` がすでに記録済みの場合は `"duplicate": true` とともに `200` を返します。

### 制限事項 [#limits]

- スキャンは、発生から30日間、紐付けの対象になります。
- `qrdx_sid` は署名されているため、推測したり、別のコードを指すように変更したりすることはできません。
- ブラウザからの報告には、そのコードでコンバージョントラッキングがオンになっている必要があります。また、各スキャンが1時間あたりに報告できるコンバージョン数には上限があります。
- ワークスペースがBusinessでなくなると、コンバージョンは記録されなくなります。既存のコンバージョンは分析に残り、トラッキングはいつでもオフにできます。
