Eine gehostete Landingpage ist eine mobile Seite, die QRdx für dich unter `https://qrdx.dev/p/<slug>` (oder auf deiner [eigenen Domain](/docs/custom-domains)) ausliefert. Jede Seite kommt mit einem [dynamischen QR-Code](/docs/dynamic-qr-codes), sodass du die Seite auch nach dem Druck des Codes weiter bearbeiten und jeden Scan sehen kannst.

## Seite erstellen [#create-a-page]

1. Öffne [Dashboard → Seiten & Formulare](/dashboard?to=pages) und klicke auf **Neue Seite**, oder klicke in der Code-Liste auf **Neuer Code** und wähle statt **Website-Link** einen Seitentyp.
2. Wähle einen der {facts.hostedPageTypes} [Seitentypen](#page-types) und eine Vorlage aus der zugehörigen Galerie.
3. Klicke auf **Seite erstellen**. Der Editor öffnet sich mit den Blöcken der Vorlage, und den QR-Code kannst du unter **QR-Code** herunterladen.

Du hast schon einen Code gedruckt, der eine Website öffnet? Öffne ihn und klicke auf **Typ ändern**, um ihn mit demselben Kurzlink in eine Seite umzuwandeln. Siehe [Ändern, was ein gedruckter Code öffnet](/docs/help/dynamic-codes/change-the-type).

Vorlagen starten mit Beispielnamen, Preisen, Zahlen und Fotos, damit du siehst, wie die Seite aufgebaut ist. Bis zur ersten Veröffentlichung erinnert dich der Editor daran, sie durch deine eigenen Inhalte zu ersetzen.

## Seitentypen [#page-types]

Jeder Seitentyp ist ein Ausgangspunkt: Jeder Block lässt sich zu jeder Seite hinzufügen, und eine Seite aus einem Typ kann wie ein anderer aussehen.

| Seitentyp | Gedacht für | Startet mit |
| --- | --- | --- |
| **Link list** | Link in Bio, Creator, Podcasts | Profilkopf, Links, Social-Icons |
| **Social media** | Alle Profile hinter einem Code | Profilkopf, eine Zeile pro Netzwerk mit deinem Handle |
| **Business** | Läden, Salons, Büros | Öffnungszeiten, Adresse und Karte, Kontakt, ein Call-to-Action |
| **vCard Plus** | Digitale Visitenkarten | Kontaktkarte mit **Kontakt speichern** |
| **Menu** | Cafés, Restaurants, Bars | Speisekarte, Wi-Fi, Öffnungszeiten ([mehr](/docs/forms-and-pages#menu)) |
| **Coupon** | Rabatte und Gratisaktionen | Gutschein mit Barcode und **Einlösen** ([mehr](/docs/forms-and-pages#coupon)) |
| **Event** | Partys, Konferenzen, Webinare, Hochzeiten | Event mit Kalendereintrag ([mehr](/docs/forms-and-pages#event)) |
| **App download** | Ein Code für alle App-Stores | App-Download ([mehr](/docs/forms-and-pages#app-download)) |
| **Feedback & forms** | Bewertungen, NPS-Umfragen, Anmeldungen | Formular und Bewertungslinks ([mehr](/docs/forms-and-pages#forms)) |
| **Product** | Verpackungen, Etiketten, Hang Tags | Zutaten, Allergene, Nährwerte, Zertifizierungen, Pflege, GS1 Digital Link ([mehr](/docs/product-pages)) |
| **Appointments** | Salons, Praxen, Nachhilfe | Leistungen und Preise, ein Formular für Terminanfragen, Öffnungszeiten |
| **Payments & tips** | Trinkgeld, Spenden, Rechnungen | Zahlungslinks und Bankdaten zum Kopieren |
| **Property listing** | Immobilien zum Kauf oder zur Miete, Tage der offenen Tür | Preis und Eckdaten, Fotos, Makler, ein Formular für Besichtigungsanfragen oder Anmeldung |
| **Pet ID tag** | Halsbandanhänger, Vermisstenplakate | Anruf-Button, Angaben zum Tier, ein „Gefunden“-Formular |
| **Medical ID** | Anhänger, Armbänder, Allergiekarten | Notfallkontakt, Erkrankungen, Allergien, Medikamente |
| **PDF** | Broschüren, Handbücher, Dokumentbibliotheken | Ein PDF zum Lesen oder Herunterladen, oder mehrere Dateien |
| **Images** | Galerien und Portfolios | Fotogalerie |
| **MP3 / Audio** | Musik, Podcasts, Sprachnachrichten | Audio-Player |
| **Video** | Produktvideos, Clips | Video |
| **Playlist** | Mixe, Audiotouren, Hörbücher | Mehrere Titel, die nacheinander abgespielt werden |
| **Custom page** | Alles andere | Eine leere Seite oder eine Ankündigung |

Wo Datei-Uploads nicht eingerichtet sind, werden die Typen, die auf einem Upload basieren (PDF, Images, MP3 / Audio, Video und Playlist), in der Auswahl ausgeblendet.

**Appointments** sendet Terminanfragen an die [Antworten](/docs/forms-and-pages#responses) und Benachrichtigungen der Seite und kann auf dein Buchungstool verlinken. Einen Live-Kalender mit freien Zeiten zeigt die Seite nicht: Du bestätigst jede Anfrage selbst.

**Payments & tips** nimmt nie eine Zahlung entgegen. Jeder Button öffnet die eigene Seite der Zahlungs-App (PayPal, Venmo, Cash App, Revolut, Wise), und für Bankdaten, UPI-IDs und Wallet-Adressen gibt es Kopier-Buttons.

**Pet ID tag**- und **Medical ID**-Seiten kann jeder lesen, der den Code scannt. Füge nur hinzu, was jemandem hilft, der dein Tier findet oder dir in einem Notfall hilft.

## Bearbeiten und veröffentlichen [#edit-and-publish]

Der Editor hat drei Tabs und eine Live-Vorschau im Smartphone-Format. Tippe in der Vorschau auf einen Block, um zu seinen Einstellungen zu springen.

- **Blocks**: Füge Blöcke mit **Block hinzufügen** hinzu, ordne sie per Ziehen (oder mit den Pfeil-Buttons) neu an, blende einen Block aus, ohne ihn zu löschen, dupliziere oder entferne ihn. Jeder Block hat sein eigenes Formular; Probleme (zum Beispiel ein Link ohne `https://`) werden am Block markiert und müssen vor dem Veröffentlichen behoben werden.
- **Design**: Verwende die Farben eines deiner [gespeicherten QR-Themes](/dashboard?to=themes), damit die Seite zum gedruckten Code passt, wähle eine vorgegebene Palette oder lege jede Farbe selbst fest. Wähle eine Schriftart, einen Eckenradius, einen einfarbigen Hintergrund, einen Farbverlauf oder ein Hintergrundbild und optional ein Logo. **Farben anpassen** leitet lesbare Text- und Kartenfarben aus deinem Hintergrund und deiner Akzentfarbe ab, und bei niedrigem Textkontrast erscheint eine Warnung.
- **Settings**: die Beschreibung und das Bild der Share-Vorschau, ob Suchmaschinen die Seite indexieren dürfen (standardmäßig aus) und eigenes CSS bei Business.

Klicke auf **Veröffentlichen** (oder drücke <kbd>⌘</kbd>/<kbd>Ctrl</kbd> + <kbd>S</kbd>), um deine Änderungen live zu schalten. Für Besucher ändert sich erst etwas, wenn du veröffentlichst; unveröffentlichte Änderungen bleiben in deinem Browser gespeichert, sodass du sie nach dem Schließen des Tabs wiederherstellen kannst. Jede Veröffentlichung wird als Version gespeichert. Wenn ein Teammitglied dieselbe Seite veröffentlicht, während du sie bearbeitest, fordert QRdx dich zum Neuladen auf, statt seine Änderungen zu überschreiben.

| Divider, Spacer | Hilfen fürs Layout |

### vCard Plus und Kontakt speichern [#vcard-plus-and-save-contact]

**Kontakt speichern** lädt eine vCard-3.0-Datei (`.vcf`) herunter, die Smartphones in der Kontakte-App öffnen. Sie enthält Name, Firma, Position, Telefonnummern, E-Mail-Adressen, Website, Adresse, Bio, die Social-Profile der Seite und das Foto. Fotos, die in den QRdx-Speicher hochgeladen wurden, werden in die Datei eingebettet; Fotos, die von anderen Websites verlinkt sind, werden als Link aufgenommen (QRdx lädt nie Bilder von anderen Websites herunter). **Teilen** öffnet das Share-Sheet des Smartphones oder kopiert auf Computern den Seitenlink.

## Pläne [#plans]

| | Kostenlos | Pro | Business |
| --- | --- | --- | --- |
| Gehostete Seiten | 3 | Unbegrenzt | Unbegrenzt |
| Footer „Made with QRdx“ | Sichtbar | Entfernt | Entfernt |
| White-Label (dein Logo als Browser-Icon, kein QRdx-Branding) | — | — | ✓ |
| Eigenes CSS | — | — | ✓ |

Die Limits verhindern nur, dass du neue Seiten erstellst. Seiten, die du bereits hast, funktionieren in jedem Plan weiter, auch nach einem Downgrade. Bei einem Downgrade von Business wird eigenes CSS einfach nicht mehr angewendet. Außerdem belegt jede Seite einen der dynamischen QR-Codes deines Plans. Siehe [Pläne und Limits](/docs/plans-and-limits).

### Eigenes CSS (Business) [#custom-css-business]

Schreibe einfaches CSS unter **Einstellungen → Eigenes CSS**. Die Regeln gelten nur innerhalb deiner Seite: Jeder Selektor ist auf den Seiteninhalt begrenzt, und jeder Block lässt sich mit `.lp-block-<type>` ansprechen, zum Beispiel `.lp-block-links a` oder `.lp-block-contact h1`. Aus Sicherheitsgründen kann CSS keine Dateien laden (`url()`, `@import`, `@font-face`), keine Backslash-Escapes verwenden und unterstützt nur die At-Regeln `@media`, `@supports`, `@container` und `@keyframes`.

## Das bekommen Besucher [#what-visitors-get]

- Schnelle, serverseitig gerenderte Seiten, die für Smartphones gebaut sind, ohne QRdx-Analytics- oder Chat-Skripte. Tracking-Pixel werden nur geladen, wenn du sie selbst in den Code einfügst.
- Für Suchmaschinen unsichtbar, außer du aktivierst **In Suchmaschinen anzeigen**.
- Vorschauen beim Teilen (Titel, Beschreibung, Bild) für Chat-Apps und soziale Netzwerke. Passwortgeschützte Codes zeigen in Vorschauen nie Details der Seite.
- Ein kleiner Link **Missbrauch melden** auf jeder Seite, auch auf White-Label-Seiten.

Passwortschutz, Start- und Enddatum, Scan-Limits und Pausieren aus den [Code-Steuerungen](/docs/code-controls) gelten auch für die Seite und ihre **Kontakt speichern**-Datei, selbst wenn jemand den Seitenlink direkt öffnet.
