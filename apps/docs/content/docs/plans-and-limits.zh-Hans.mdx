## 限额 [#limits]

| | 免费版 | Pro | Business |
| --- | --- | --- | --- |
| 动态二维码 | 10 | 不限 | 不限 |
| 扫描次数 | 不限 | 不限 | 不限 |
| 托管落地页 | 3 个，页脚带有“Made with QRdx” | 不限，无页脚 | 不限，白标，自定义 CSS |

| 创建更多工作区 | 否 | 是 | 是 |
| 智能路由、A/B 测试、UTM 标签 | 否 | 是 | 是 |
| 密码、定时、过期、扫描次数限制 | 否 | 是 | 是 |
| 再营销像素 | 否 | 是 | 是 |
| 转化追踪 | 否 | 否 | 是 |
| 邮件摘要与提醒 | 否 | 是 | 是 |

| [客户门户](/docs/client-portal) | 否 | 否 | 是 |

只有处于活动状态的动态二维码才计入二维码数量限额，已归档的二维码不计入。扫描次数不计入任何限额，任何套餐都不会因流量而暂停二维码。唯一的扫描次数上限，是您自己在二维码上设置的上限。

API 额度按工作区计算，在 UTC 00:00 重置。每个计入额度的请求都会返回 `X-RateLimit-Limit`、`X-RateLimit-Remaining` 和 `X-RateLimit-Reset`，方便您随时查看。每分钟限额请参阅 [REST API](/docs/developers/rest-api)。

## 工作区 [#workspaces]

限额按每个[工作区](/docs/teams)分别计算，工作区采用其所有者和[账单成员](/docs/teams#roles)中最高的套餐。每个人都有一个自己的工作区，创建账号时自动生成，您是其所有者，因此使用您的套餐。在其他工作区中，只要有一位所有者使用 Business，该工作区的所有人就都享有 Business 限额，成员无需各自订阅。

创建更多工作区需要 Pro 或 Business。所有者和账单成员均为免费版的工作区有 1 个席位（仅您自己），Pro 最多 3 个，Business 不限。席位包括成员（含所有者）以及待处理的邀请，因此请撤销不再需要的邀请以释放席位。如果所有者的套餐发生变化，现有成员会保留，只是无法再发出新的邀请。

## 超出限额、降级和取消 [#going-over-a-limit-downgrading-and-cancelling]

<Callout type="info">
  限额只会阻止新建内容。在所有套餐中，现有二维码都会继续跳转，降级、付款失败或取消之后也一样。这就是 [Never-Hostage 保障](/guarantee)。
</Callout>

- **超出限额：** 在降到限额以内之前，您无法继续创建。您仍可编辑、归档和导出现有内容。
- **超出每日 API 额度：** 在 UTC 00:00 之前，API 调用会返回 `429`。您的二维码仍会继续跳转，网站也能正常使用。
- **降级：** 二维码、落地页和已验证的自定义域名继续有效。分析数据只显示新套餐所包含的历史时长。
- **取消：** 您的套餐会在已付费周期结束前一直有效，之后账号转为免费版。
- **付款失败：** 订阅失效后，效果与取消相同。不会暂停任何内容。

因您自己选择的原因而结束的二维码，例如设置了过期日期、暂停或扫描次数限制，会把扫描者引导到您的备用 URL，或一个中性的“This campaign has ended”页面，绝不会跳转到 QRdx 的页面。

## 账单 [#billing]

请在[定价页面](/pricing)升级。如需更改套餐、在按月和按年之间切换、更新银行卡或取消订阅，请在设置中打开 **Manage subscription**，它会带您进入 Polar 账单门户。一个订阅覆盖您的整个账号，因此在已有订阅期间，套餐变更需通过该门户办理，而不是重新结账。

## 自托管 [#self-hosting]

[自托管](/docs/self-hosting)实例使用相同的套餐。限额统一定义在一个文件中，即 `apps/docs/lib/plans.ts`，您可以为自己的实例修改它。未配置 Polar 时，无法升级，所有账号都使用免费版限额。
