This page draws every shape the library offers, with its option name and the value to copy into `bodyPattern`, `cornerEyePattern`, `cornerEyeDotPattern` or `frame.style`. Use it to pick a look before you write code. Each tile is drawn by the same renderer as your downloads and decoded in your browser with jsQR, one at a time, so the **Scans** badge is a live result.

Every value is also tested in the package (`packages/qrdx/tests/catalog-*.test.ts`): it decodes through a phone-camera model (contrast loss and a quarter-module blur) at 4, 6 and 9 pixels per module, next to every other body, eye and center, at error correction L, M, Q and H, at 148 px and 1024 px, light-on-dark, with brand colors and with a center logo. A few pairings are weak together; see [Pairs to avoid](#pairs-to-avoid).

## Body patterns

The shape of the data modules (`bodyPattern`, default `circle`). Connected styles (`liquid`, `classy`) merge neighboring modules into one outline. `random-dots` and `mosaic` vary per module but are deterministic: the same value always draws the same code.

## Eye frames

The outer ring of the three corner markers (`cornerEyePattern`, default `gear`). `leaf`, `leaf-reverse`, `drop` and `petal` turn each eye so it faces the corner of the code. Each tile pairs the eye with its recommended center.

## Eye centers

The solid center of each corner marker (`cornerEyeDotPattern`, default `circle`), shown inside square eyes.

## Frames

Call-to-action frames are drawn around the code, so the code and its quiet zone are never covered and the downloaded image grows to fit. Each built-in frame below is a frame spec, drawn by the same engine as the [official and community frames](/docs/features/frames). Every frame takes `text` (up to 24 characters), `color`, `textColor` and `fontScale` (0.5 to 1.5). `banner-top-bottom`, `circle` and `menu-card` also show `secondaryText`; `gradient-border` runs from `color` to `secondaryColor`.

<QrCatalog kind="frame" />

```tsx title="components/framed-code.tsx"
import { QRCode } from "qrdx";

export function FramedCode() {
  return (
    <QRCode
      value="https://example.com"
      bodyPattern="liquid"
      cornerEyePattern="leaf"
      cornerEyeDotPattern="leaf"
      frame={{ style: "circle", text: "Scan me", secondaryText: "example.com" }}
    />
  );
}
```

## Pairs to avoid

A few pairings of shapes that scan on their own fail together in the package's decode tests. The playground does not let you pick them together, and the scan score warns about them (`style-pair`):

- `diamond` bodies next to `square` eyes, `pacman` next to `rounded`, and `small-square` next to `square` or `rounded` eyes are missed up close.

`circle` eyes read in both decoders the tests use (jsQR and ZXing) but are marked **caution**: some scanner apps miss them. The pairs ship in the package as `WEAK_BODY_EYES`, and `getStylePairRisk(props)` returns the warning for a style.

## Retired shapes

`curly` eyes and `diamond`, `star` and `banner` centers were removed because they do not scan reliably: ZXing (the decoder in most Android scanners) misses curly eyes and diamond and star centers at phone distances, and jsQR misses banner centers in every sharp render. Codes saved with them still load and render exactly as before, and the image API still draws them for existing links, but no picker, preset or AI theme offers them. Their names are kept only as deprecated values (`RETIRED_CORNER_EYE_PATTERNS`, `RETIRED_CORNER_EYE_DOT_PATTERNS`).
