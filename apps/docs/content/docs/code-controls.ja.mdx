すべての[動的QRコード](/docs/dynamic-qr-codes)には、[ダッシュボード](/dashboard?to=codes)のコードのページに **アクセスとスケジュール** パネルがあります（コードを開き、**設定** タブを開きます）。変更は次回のスキャンから反映されるため、コードを再印刷する必要はありません。

| 設定 | スキャンした人に表示される内容 | プラン |
| --- | --- | --- |
| 一時停止 | フォールバックURL、または「このキャンペーンは一時停止中です」という中立的なページ | すべてのプラン |
| パスワード | パスワード入力画面。正しいパスワードを入力するとコードが開きます | ProとBusiness |
| 開始 | 開始前：「まだ開始されていません」というページ | ProとBusiness |
| 終了 | 終了後：フォールバックURL、または「キャンペーンは終了しました」という中立的なページ | ProとBusiness |
| スキャン上限 | 上限に達した後：フォールバックURL、または「終了」ページ | ProとBusiness |
| フォールバックURL | 一時停止中、終了後、上限超過のコードがユーザーを転送する先 | ProとBusiness |

## 一時停止 [#pause]

**コードを一時停止** をオンにすると、イベントの合間などにコードを一時的に停止できます。オフにすると再開します。停止中のスキャンは、フォールバックURLを設定していればそこへ、設定していなければキャンペーンが一時停止中であることを伝えるシンプルなページへ転送されます。一時停止はすべてのプランで無料です。

## パスワード [#password]

パスワード（4文字以上）を設定すると、コードをスキャンした人にはまずパスワード入力画面が表示されます。正しいパスワードを入力すると、そのブラウザーは6時間ロック解除された状態になります。これは短縮リンクと、そこから開くホスト型ページの両方に適用されます。パスワードを変更または削除すると、以前のパスワードでロックを解除していたすべてのブラウザーが再びロックされます。

パスワードはbcryptハッシュとして保存されます。QRdxが後からパスワードを表示することはできず、置き換えることだけが可能です。同じ訪問者による誤ったパスワードの入力が繰り返されると、処理が遅くなります。

## 開始日と終了日 [#start-and-end-dates]

- **開始：** それまでの間、スキャンすると「このキャンペーンはまだ開始されていません。後でもう一度このコードをスキャンしてください。」と表示されます。
- **終了：** その時点以降、スキャンはフォールバックURLへ転送されるか、「このキャンペーンは終了しました」と表示されます。

日時はお使いのタイムゾーンで入力され、正確な時刻として保存されるため、コードはどこでも同じ瞬間に終了します。終了は開始より後に設定する必要があります。

## スキャン上限 [#scan-limit]

上限は、アナリティクスと同じ方法でスキャンを数えます。ボット、リンクのプレビュー、同じデバイスからの短時間の連続スキャンはカウントされません。コードが上限に達すると、以降のスキャンはフォールバックURLまたは「終了」ページへ転送されます。上限を引き上げるか解除すると、コードは再び利用できるようになります。

## フォールバックURL [#fallback-url]

一時停止中、期限切れ、上限超過のコードがユーザーを転送するアドレスです。ホームページや次のキャンペーンなどを指定できます。設定しない場合は、シンプルで中立的なページが表示されます。このページには広告、QRdxの宣伝、サインアップの案内は一切表示されず、キャンペーンの状況と「不正を報告」リンクのみが表示されます。

フォールバックURLには、コードの転送先と同じ安全性チェックが行われます。

## プランとダウングレード [#plans-and-downgrades]

- 一時停止はすべてのプランで利用できます。
- パスワード、日付、スキャン上限、フォールバックURLの設定や変更には、ProまたはBusinessが必要です。
- **ダウングレードによってコードが終了したりロックされたりすることはありません。** Proのときに設定したコントロールは、設定したとおりに動作し続けます。また、どのプランでも設定を削除できます。

## リンクの安全性チェック [#safety-checks-on-links]

QRdxは、転送先とフォールバックURLを保存する際にすべて確認します。

- [Google Web Risk](https://cloud.google.com/web-risk)にマルウェア、フィッシング、望ましくないソフトウェアとして登録されているリンクは拒否されます（サーバーにWeb Riskキーがある場合）。大量の一括処理などでWeb Riskが時間内に応答できない場合は、コードが作成され、その後すぐにリンクが再確認されます。そのときにWeb Riskに登録されていれば、コードはオフになり、担当者が確認します。
- `javascript:`、`data:` などのウェブ以外のリンクは拒否されます。
- アカウントの最初の7日間は、URL短縮サービス、IPアドレスそのもの、紛らわしい（ホモグリフ）ドメインを指すコードは、オフの状態で保存され、**審査待ち** になります。パネルにその旨が表示されます。お客様側で必要な操作はなく、問題がなければ担当者がコードをオンにします。新規アカウントは、1時間あたり最大30個の動的QRコードを作成できます。有料プランのワークスペースでは {facts.newPaidAccountHourlyCodes} 個です。上限を超えると、エラーにコードを再び作成できるまでの残り時間（分）が表示され、ダッシュボードからのインポートはそれまで一時停止します。

どなたでも [qrdx.dev/report-abuse](/report-abuse) からコードを報告できます。審査の結果オフになったコードはすべてのユーザーに対して動作しなくなり、所有者が再びオンにすることはできません。

## セルフホスティング [#self-hosting]

- `WEB_RISK_API_KEY`：Web Risk APIを有効にしたGoogle CloudのAPIキーです。設定しない場合、リンクは上記のオフラインルールでのみチェックされます。
- `NEXT_PUBLIC_TURNSTILE_SITE_KEY` と `TURNSTILE_SECRET_KEY`：公開の報告フォームで使用するCloudflare Turnstileです（任意）。
- ロック解除用のCookieは `BETTER_AUTH_SECRET` で署名されます。
