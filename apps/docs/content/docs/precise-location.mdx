Every [dynamic QR code](/docs/dynamic-qr-codes) records the country, region and city of each scan from the network. Precise location goes further: the code asks scanners to share their position, people who allow it show up in the analytics as points rounded to about 100 m, and [smart routing](/docs/smart-routing) can send them somewhere different depending on where they are. Use it for codes on site, such as a venue, a store or a trail, where "which city" isn't enough.

<Callout type="info" title="Pro and Business">
  Asking for precise location is part of Pro and Business. It is off for every code until you turn it on, and each scanner decides for themselves in their browser. See [Plans and limits](/docs/plans-and-limits).
</Callout>

In a hurry? [See your scans](/docs/help/dynamic-codes/scans) covers the analytics, and [Send scans to different links](/docs/help/dynamic-codes/routing) the rules.

## How it works

{/* diagram: precise-location-flow | A scan reaching the short link, the browser's location prompt, the rounded point stored with the scan and used by an area rule, and the redirect to the destination | concept drawing */}

When the setting is on and someone scans the code, their browser asks whether to share their location. If they allow it, the browser rounds the position to 3 decimal places (about 100 m) before sending it, QRdx rounds it again, and the point is stored with that scan together with the accuracy the browser reported. Exact positions never reach QRdx. If they skip or decline, the scan is still counted with its country, region and city from the network, as always.

## Turn it on

Open the code from [Codes](/dashboard?to=codes), go to its **Settings** tab and switch on **Ask scanners for precise location** in the **Precise location** panel. It works for codes that open a website link and for codes that open a hosted page.

{/* shot: precise-location-panel | The Precise location panel on a code's Settings tab with the Ask scanners for precise location switch on | Dashboard → Codes → open a code → Settings → Precise location */}

## What scanners see

**Codes that open a website link** show a short "Share your location?" step before the link opens, with **Allow** and **Skip**. Allow brings up the browser's own location prompt. The step never stops anyone from getting to your link:

- Skip opens the link straight away.
- If the scanner declines in the browser, or the browser can't find a location, the link opens.
- If there's no location 8 seconds after they tap Allow, the link opens anyway.
- A browser that has already said no for the site skips the step on its own, and one that has already said yes shares without a second tap.
- Without JavaScript, the link opens at once.

The step names the site the scanner will land on and links to the privacy policy.

{/* shot: location-step | The Share your location? step on a phone, with the Allow and Skip buttons and the destination's name | Scan a code with precise location on */}

**Codes that open a hosted page** open the page right away, as usual. Once it has loaded, the browser asks for the location on the page; the page never waits for an answer. It only asks right after a scan, never when someone opens the page's address directly.

When the setting is off, nothing changes: scans go straight to the destination with no extra step.

## In analytics

The code's **Analytics** tab has a **Precise locations** card, apart from the IP-based countries and cities. It shows how many scanners were asked, how many shared their location and what share that is, then each shared point with its number of scans, average accuracy and latest scan. Sort the table by any of those, and open a point in OpenStreetMap to see where it is.

{/* shot: precise-locations-card | The Precise locations card with the asked and shared counts and the table of points | Dashboard → Codes → open a code → Analytics */}

The CSV export has `latitude`, `longitude`, `location_accuracy_m` and `location_source` columns. `location_source` is `gps` for a shared location, `ip` when the code asked but the scanner didn't share, and empty when the code didn't ask.

Shared analytics links (**Share analytics...** in a code's menu) never show precise locations. They stay at country level. Precise locations are kept as long as the rest of the code's scans, and your plan decides how far back you can see them. See [What QRdx records when someone scans](/docs/help/privacy-and-security/scan-data).

## Route scans by area

In the code's **Smart routing** panel, add a rule with an **Area** condition: a center point and a radius between 100 m and 500 km. To get the center, right-click a place in a map app and copy its coordinates (for example `40.7580, -73.9855`), or click **Use my location** while you're there. **Check on a map** opens the point in OpenStreetMap.

{/* shot: area-condition | An Area condition in a routing rule with the coordinates, the radius slider and the Use my location and Check on a map buttons | Dashboard → Codes → open a code → Settings → Smart routing → Add rule → Area */}

QRdx checks the area with the best location it has for that scan:

1. The location the scanner shared in the step, when precise location is on and they allowed it.
2. Otherwise, the approximate location of their IP address. On qrdx.dev this comes from Vercel's IP geolocation and is usually the center of the scanner's city or area, so it suits radii of several kilometers. It's used to route the scan and never stored.

When neither is available, area conditions don't match, and "is not" area conditions do. **Test your rules** has a **Location (for areas)** field, so you can check where a scan from any point would go.

### Only inside an area

To show something only to people at a place, such as a venue or a store:

1. Add a rule with an Area condition around the place, and set its URL to the content for people who are there.
2. Set the code's main destination to a page for everyone else, for example one that says the offer is only available on site.

Turn on precise location as well, so a location the scanner shares decides, down to about 100 m. Without it, the IP location decides, which is only city-level.

Browsers let people fake their location, so an area rule isn't access control. Use a [password](/docs/code-controls#password) for anything that must stay private.

## Good to know

- Bots, link previews and HEAD requests never see the step; they get the usual redirect.
- On a code with a password, the scan that shows the password form skips the step. Once a browser is unlocked, its later scans are asked like any other.
- If your workspace moves to Free, QRdx stops asking for precise locations. Saved area rules keep working with the IP location, and turning the setting off never needs a plan.

## For developers

Send `PATCH /v1/codes/{id}` with `{"preciseLocation": true}` to turn the step on; every code reports the setting in its `preciseLocation` field ([Update a code](/docs/developers/api/update-code)). [`GET /v1/codes/{id}/scans`](/docs/developers/api/get-code-scans) returns `latitude`, `longitude`, `locationAccuracyM` and `locationSource` on each listed scan, plus a `preciseLocations` summary.

## Self-hosting

Self-hosted copies that don't run on Vercel have no IP coordinates, so area rules there only match scans with a shared location. See [Self-hosting](/docs/self-hosting#what-is-different-from-qrdxdev).
