Webhooksは、ワークスペースで発生したイベントを、発生した時点で指定したURLに送信します。たとえば、フォームが送信されたらCRMを更新する、コードのスキャン数が1,000に達したら社内ツールに投稿する、スキャンデータの独自コピーを保持する、といった用途に使えます。

Webhooks、Zapier/Makeのフック、Slack/Discordのアラートは**Business**プランに含まれます。メールアラートと週次ダイジェストはProに含まれます。詳しくは[通知](/docs/notifications)をご覧ください。

## エンドポイントを追加する [#add-an-endpoint]

1. イベントを受け取りたいワークスペースで[設定 → Webhooks](/dashboard?to=settings/webhooks)を開きます。リンクを開くと最後に使ったワークスペースが表示されます。ワークスペース切り替えで別のワークスペースを選んでも、同じページのままです。
2. **エンドポイントを追加**をクリックし、`https://`のURLを入力してイベントを選びます。最初に[本人確認](/docs/help/privacy-and-security/two-step-verification#confirm-its-you)が求められ、エンドポイントのURLを変更するときにも再度求められます。イベントの変更や一時停止では求められません。
3. 保存後に表示される**署名シークレット**をコピーします。オーナーと管理者は、[本人確認](/docs/help/privacy-and-security/two-step-verification#confirm-its-you)を行えば、あとからシークレットを再表示したりローテーションしたりできます。
4. **テスト送信**をクリックします。QRdxは署名付きの`ping`イベントを送信し、レスポンスのステータスを表示します。

エンドポイントを管理できるのはオーナーと管理者です。メンバーはエンドポイントと配信ログを閲覧できます。1つのワークスペースに作成できるエンドポイントは最大20個です。

エンドポイントのURLは、公開された`https://`のホスト名でなければなりません。IPアドレス、`localhost`、プライベートネットワークに解決される名前は拒否され、リダイレクトは追跡されません。

## イベント [#events]

| イベント | タイミング | 備考 |
| --- | --- | --- |
| `scan.created` | 動的QRコードがスキャンされたとき | バッチ送信：エンドポイントごとに1分あたり最大1リクエスト、数分以内に送信され、最大100件のスキャンと正確な`count`を含みます |
| `scan.milestone` | コードの1回目のスキャン、続いて10、100、500、1,000、5,000、10,000、50,000、100,000、500,000、1,000,000回目のスキャン、以降は100万回ごと | マイルストーンごとに1回発生します |
| `code.created` | 動的QRコードが作成されたとき（ダッシュボードまたはAPI） | コード1件につき1イベント。一括作成でも同様です |
| `code.updated` | コードのリンク先、タイトル、デザイン、短縮リンクのドメインが変更されたとき | `changes`に変更されたフィールドが一覧で入ります |
| `form.submitted` | ホスト型ページでフォームが送信されたとき | 回答が含まれます |
| `ping` | **テスト送信**をクリックしたとき | |

ボット、リンクプレビュー、プリフェッチャーによるスキャンや、同一訪問者による短時間の連続スキャンはカウントされず、イベントも発生しません。これは[スキャン分析](/docs/dynamic-qr-codes)と同じ扱いです。

## ペイロード [#payloads]

すべてのリクエストは、JSON本文と次のヘッダーを持つ`POST`です。

| ヘッダー | 値 |
| --- | --- |
| `Content-Type` | `application/json` |
| `User-Agent` | `QRdx-Webhooks/1.0 (+https://qrdx.dev/docs/webhooks)` |
| `X-QRdx-Event` | イベントの種類（例：`code.created`） |
| `X-QRdx-Delivery` | 配信ID。再試行でも同じ値なので、重複を無視できます |
| `X-QRdx-Timestamp` | この試行が署名されたUNIX秒 |
| `X-QRdx-Signature` | `t=<timestamp>,v1=<hex HMAC-SHA256>` |

本文は常にエンベロープ形式です。

```json
{
  "id": "evt_cm3x8c1a20001",
  "type": "code.created",
  "created_at": "2026-10-31T09:30:00.000Z",
  "data": {
    "code": {
      "id": "cm3x7q2l40000",
      "slug": "aB3dE5f",
      "title": "Spring menu",
      "short_link": "https://qrdx.dev/q/aB3dE5f",
      "destination_url": "https://example.com/menu",
      "status": "active",
      "scan_count": 0,
      "created_at": "2026-10-31T09:30:00.000Z",
      "updated_at": "2026-10-31T09:30:00.000Z"
    },
    "actor_id": "user_123"
  }
}
```

`scan.created`のバッチ：

```json
{
  "id": "evt_cm3x9d0b10002",
  "type": "scan.created",
  "created_at": "2026-10-31T09:31:00.000Z",
  "data": {
    "window_started_at": "2026-10-31T09:31:00.000Z",
    "window_seconds": 60,
    "count": 2,
    "scans": [
      {
        "scan_id": "cm3x9d0b00001",
        "code": { "id": "cm3x7q2l40000", "slug": "aB3dE5f", "title": "Spring menu" },
        "scanned_at": "2026-10-31T09:31:00.000Z",
        "country": "DE",
        "region": "BE",
        "city": "Berlin",
        "device_type": "mobile",
        "os": "iOS",
        "browser": "Safari",
        "referer": null,
        "source": "qr"
      }
    ]
  }
}
```

1分間に100件を超えるスキャンがあった場合、`scans`には最初の100件が入り、`count`には正確な合計が入ります。`source`は、[NFCタグ](/docs/nfc)へのタップなら`nfc`、QRのスキャンなら`qr`です。スキャンのペイロードにIPアドレスや訪問者のハッシュは含まれません。

その他のイベントには次の内容が含まれます。

- `scan.milestone`：`milestone`、`code`（`id`、`slug`、`title`、`scan_count`）、マイルストーンに到達した`scan`。
- `code.updated`：`code.created`と同じ内容に加えて`changes`（例：`["destination_url"]`）。
- `form.submitted`：`response_id`、`page`（`id`、`title`）、`code`（`id`、`slug`、または`null`）、`fields`（`name`、`label`、テキストとしての`value`）、`submitted_at`。

## 署名を検証する [#verify-signatures]

署名シークレットを使って`<timestamp>.<raw body>`のHMAC-SHA256を計算し、`X-QRdx-Signature`の`v1`と比較します。JSON解析の前の生のリクエスト本文を使い、5分より古いタイムスタンプは拒否してください。

```ts
import { createHmac, timingSafeEqual } from "node:crypto";

export function isFromQRdx(rawBody: string, header: string, secret: string) {
  const parts = Object.fromEntries(
    header.split(",").map((part) => part.trim().split("=", 2)),
  );
  const timestamp = Number(parts.t);
  if (!timestamp || Math.abs(Date.now() / 1000 - timestamp) > 300) return false;

  const expected = createHmac("sha256", secret)
    .update(`${timestamp}.${rawBody}`)
    .digest("hex");
  const received = Buffer.from(parts.v1 ?? "");
  return (
    received.length === expected.length &&
    timingSafeEqual(received, Buffer.from(expected))
  );
}
```

シークレットのローテーションは即座に反映されます。古いシークレットでは検証できなくなるため、ローテーションの直後にサーバーを更新してください。

## 再試行と配信ログ [#retries-and-the-delivery-log]

10秒以内に任意の`2xx`ステータスで応答してください。それ以外（エラーステータス、リダイレクト、タイムアウト、到達できないホスト）は失敗として扱われ、QRdxは1分、4分、16分、1時間、4時間、17時間、24時間以上と、待ち時間を延ばしながら再試行します。各再試行は、待ち時間が終わってから数分以内に送信されます。合計で約2日間に8回試行し、その後も届かなければ配信は**失敗**になります。

各エンドポイントの**配信**ページには、直近50件の配信が、ステータス、試行回数、最後のエラー、ペイロードとともに表示されます。**再試行**をクリックすると、配信を即座に再送します（配信済みのものも可能です）。配信は30日間保持されます。

配信は、複数回届いたり（応答が遅れたあとの再試行や手動の再試行）、順序が前後したりすることがあります。`X-QRdx-Delivery`またはエンベロープの`id`を使って重複を無視してください。

エンドポイントを無効にすると新しい配信は止まります。削除するとログも削除されます。ワークスペースのプランがWebhooksを含まなくなった場合、エンドポイントは保持されますが、再びBusinessになるまで何も送信されません。どちらの場合も、QRコードは引き続き動作します。

## Zapier、Make、n8n（REST Hooks） [#zapier-make-and-n8n-rest-hooks]

自動化ツールは、REST Hooks APIを通じて自分で登録と解除ができます。認証には、[コードAPI](/docs/dynamic-qr-codes#rest-api)と同様に、[APIキー](/docs/developers/api-keys)またはOAuthアクセストークンを使います。登録と解除には`codes:write`、一覧取得には`codes:read`が必要です。フックのURLは秘密であることが多いため、`codes:read`のみの場合、`target_url`にはホストだけが表示されます（`https://hooks.zapier.com/…`）。トークンによるリクエストはご自身のワークスペースに対して動作し、キーはそのキーを作成したワークスペースに対して動作します。キーやトークンではなく、サインイン中のブラウザセッションで登録する場合は、最初に[本人確認](/docs/help/privacy-and-security/two-step-verification#confirm-its-you)が求められ、直近10分以内に確認していないと`403`と`CONFIRMATION_REQUIRED`が返ります。登録は通常のエンドポイントなので、設定 → Webhooksに表示され、そこから削除もできます。

| メソッド | パス | 説明 |
| --- | --- | --- |
| `POST` | `/v1/hooks` | 登録します。本文：`target_url`（またはZapierの`hookUrl`）と`event`（または`events`配列）。`201`と、登録の`id`およびその`secret`を返します |
| `DELETE` | `/v1/hooks/{id}` | 登録を解除します（`204`） |
| `GET` | `/v1/hooks` | 登録とエンドポイントを一覧表示します |
| `GET` | `/v1/hooks/{id}` | 登録を1件取得します |
| `GET` | `/v1/hooks/sample?event=<event>` | `event`の最近のサンプルペイロードを配列で返します（Zapierの「perform list」用） |

```bash
curl https://api.qrdx.dev/v1/hooks \
  -H "Authorization: Bearer $QRDX_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"target_url": "https://hooks.zapier.com/hooks/standard/123/abc/", "event": "form.submitted"}'
```

```json
{
  "id": "cm3xa1b2c0003",
  "target_url": "https://hooks.zapier.com/hooks/standard/123/abc/",
  "events": ["form.submitted"],
  "event": "form.submitted",
  "active": true,
  "created_at": "2026-10-31T09:40:00.000Z",
  "secret": "whsec_..."
}
```

Businessでない場合、登録の呼び出しは`402 PLAN_REQUIRED`を返します。`scan.created`の配信は1つのバッチなので、Zapierでは`data.scans`の明細項目を使って各スキャンを処理してください。

n8nでは、[n8n用QRdxノード](/docs/developers/n8n)のQRdx Triggerノードがこれらの呼び出しを代行し、署名も毎回検証します。通常のWebhookノードも、ほかのエンドポイントと同じように設定すれば使えます。

## セルフホスティング [#self-hosting]

配信はすぐに送信されます。再試行と、1分が経過したスキャンのバッチは、スケジュールされたジョブが送信します。QRdxはこのジョブをGitHub Actionsのワークフローから5分ごとに実行しており、Vercelの無料Hobbyプランでも動作します。また`apps/docs/vercel.json`でも、1日1回フルで実行します。GitHubはスケジュール実行の開始が遅れることがあるため、再試行は分単位の正確さではなく、数分以内に行われるものとお考えください。

同じ構成にするには、`.github/workflows/webhook-worker.yml`をコピーし、`CRON_SECRET`をActionsのシークレットとして、ジョブのURLを変数`WEBHOOK_WORKER_URL`として追加します。または、環境に設定した`CRON_SECRET`を使って、任意のスケジューラーからジョブを呼び出します。

```bash
# every 1-5 minutes
curl -H "Authorization: Bearer $CRON_SECRET" https://your-host/api/cron/webhooks
```

URLに`?source=github`を付けると、ジョブはまずUpstash Redis内の小さなマーカーを確認し、実行すべきものがなければデータベースに問い合わせずに`{"skipped": true}`を返します。これにより、ゼロまでスケールダウンするデータベースを停止したままにできます（Upstashがない場合は、常にジョブ全体を実行します）。このパラメーターなしの呼び出しを1日1回は残してください。その実行は常にジョブ全体を行い、マーカーを修復します。
