以下のスタイルはすべて、ダウンロードする画像と同じレンダラーで描画されています。各スタイルにはオプション名と、コピーして使える API の値を載せています。各タイルは、ここでブラウザー上で [jsQR](https://github.com/cozmo/jsQR) を使って1つずつデコードしています。そのため、**Scans** バッジは約束ではなく、実際の結果を表しています。

これらはすべてパッケージ内でもテストされています(`packages/qrdx/tests/catalog-*.test.ts`)。各値は、スマートフォンのカメラを想定したモデル(コントラストの低下と、モジュールの4分の1の幅のぼかし)で、1モジュールあたり4、6、9ピクセルの条件でデコードされます。他のすべてのボディ、アイ、センターと組み合わせ、誤り訂正レベルは L、M、Q、H、サイズは 148 px と 1024 px、暗い背景に明るい色、ブランドカラー、中央ロゴありの各条件でテストしています。さらに、ZXing と sharp によるレンダリングでも確認しました。一部の組み合わせは相性が良くありません。[避けるべき組み合わせ](#pairs-to-avoid)をご覧ください。

## ボディパターン [#body-patterns]

データモジュールの形です(`bodyPattern`)。連結型のスタイル(`liquid`、`classy`)は、隣り合うモジュールを1つの輪郭にまとめます。`random-dots` と `mosaic` はモジュールごとに変化しますが、結果は決定的で、同じ値であれば常に同じコードが描画されます。

<QrCatalog kind="body" />

## アイフレーム [#eye-frames]

3つの角にあるマーカーの外側のリングです(`cornerEyePattern`)。`leaf`、`leaf-reverse`、`drop`、`petal` は、各アイをコードの角に向けて回転させます。各タイルでは、アイと推奨のセンターを組み合わせています。

<QrCatalog kind="eye" />

## アイセンター [#eye-centers]

各角のマーカーの中心にある塗りつぶし部分です(`cornerEyeDotPattern`)。四角いアイの中に表示しています。

<QrCatalog kind="dot" />

## フレーム [#frames]

行動喚起フレームはコードの周囲に描画されるため、コードとクワイエットゾーンが隠れることはなく、ダウンロードする画像はフレームに合わせて大きくなります。以下の組み込みフレームはそれぞれフレーム仕様で、[公式フレームとコミュニティフレーム](/docs/features/frames)と同じエンジンで描画されます。どのフレームでも `text`(24文字まで)、`color`、`textColor`、`fontScale`(0.5〜1.5)を指定できます。`banner-top-bottom`、`circle`、`menu-card` では `secondaryText` も表示されます。`gradient-border` は `color` から `secondaryColor` へのグラデーションになります。

<QrCatalog kind="frame" />

```tsx
import { QRCode } from "qrdx";

<QRCode
  value="https://example.com"
  bodyPattern="liquid"
  cornerEyePattern="leaf"
  cornerEyeDotPattern="leaf"
  frame={{ style: "circle", text: "Scan me", secondaryText: "example.com" }}
/>;
```

## 避けるべき組み合わせ [#pairs-to-avoid]

単体ではスキャンできる形でも、組み合わせるとデコードテストに失敗するものがあります。Playground ではこれらを同時に選べないようにしており、スキャンスコアも警告します(`style-pair`)。

- `diamond` のボディと `square` のアイ、`pacman` と `rounded`、`small-square` と `square` または `rounded` のアイ(近距離で読み取れません)。

`circle` のアイは、テストしている両方のデコーダー(jsQR と ZXing)で読み取れますが、一部のスキャナーアプリでは読み取れないため **caution** と表示しています。これらの組み合わせはパッケージに `WEAK_BODY_EYES` として含まれており、`getStylePairRisk(props)` はスタイルに対する警告を返します。

## 廃止されたシェイプ [#retired-shapes]

`curly` のアイと、`diamond`、`star`、`banner` のセンターは、確実にスキャンできないため削除しました。多くの Android スキャナーが使うデコーダーである ZXing は、スマートフォンでの通常の距離では curly のアイと diamond、star のセンターを読み取れず、jsQR は sharp によるすべてのレンダリングで banner のセンターを読み取れません。これらで保存したコードは、これまでどおり読み込まれて描画されます。画像 API も、既存のリンク向けには引き続きそれらを描画します。ただし、ピッカー、プリセット、AI テーマでは提供されません。名前は非推奨の値としてのみ残しています(`RETIRED_CORNER_EYE_PATTERNS`、`RETIRED_CORNER_EYE_DOT_PATTERNS`)。
