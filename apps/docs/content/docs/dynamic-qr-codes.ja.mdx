動的QRコードには、最終的なURLの代わりに `https://qrdx.dev/q/aB3dE5f` のような短縮リンクがエンコードされます。スキャンすると短縮リンクが開き、設定したリンク先にリダイレクトされます。リンク先はいつでも変更できるため、印刷済みのコードが古くなることはなく、スキャンはすべてカウントされます。

Playgroundや `qrdx` ライブラリで作成する静的QRコードは、これまでどおり無料で無制限に使えます。動的QRコードにはQRdxアカウントが必要です。

## 動的コードを作成する [#create-a-dynamic-code]

- **ダッシュボード:** [ダッシュボード](/dashboard)を開き、**New code** をクリックして、リンク先のURLと任意のタイトルを入力します。コードはPNG、WebP、SVGでダウンロードできます。
- **Playground:** コンテンツタイプで **URL** を選び、リンクを入力して **Make it dynamic** をオンにします。QRコードが短縮リンクに切り替わり、デザインはそのまま維持されます。そのあとでURLを編集した場合は、**Point it to the new URL** をクリックするとリンク先が更新されます。**Save design to code** を使うと、現在のデザインがコードに保存されます。

リンク先は `http://` または `https://` のリンクである必要があります。ユーザー名やパスワードを含むリンクと、ほかのQRdx短縮リンクへのリンクは拒否されます。

## カスタムバックハーフ [#custom-back-halves]

すべてのコードには、`/q/` の後ろの部分であるバックハーフとして、ランダムな7文字が割り当てられます。ProとBusinessでは、`https://qrdx.dev/q/spring-menu` のように好きなバックハーフを自分で選べます。コードの作成時または編集時に **Custom back-half** を入力すると、入力中にそのバックハーフが使用可能かどうかがダイアログに表示されます。

- 3〜64文字で、使えるのは英字、数字、`-`、`_` です。先頭と末尾を `-` にすることはできません。
- バックハーフは、自動生成されたものと同様に大文字と小文字が区別されます。`Spring-Menu` と `spring-menu` は別のリンクです。
- `qrdx.dev` では、バックハーフはQRdx全体で一意である必要があり、QRdxのページ名に見える語(`admin`、`api`、`docs`、`login`、`pricing`、`settings` など)は予約されています。
- 独自の[カスタムドメイン](/docs/custom-domains)では、そのドメイン内で一意であればよく、予約されているのは `api`、`p`、`q` のみです。そのため `go.yourbrand.com/pricing` も使えます。このようなバックハーフはドメインに属するため、`qrdx.dev/q/` のリンクはありません。
- コードのバックハーフを変更すると、リンクも変わります。古いバックハーフで印刷したQRコードは使えなくなるため、コードをダウンロードし直してください。

## コードを管理する [#manage-codes]

ダッシュボードでは次の操作ができます。

- **Edit link:** リンク先やタイトルを変更します。印刷済みのコードはそのまま使え、次のスキャンから新しいリンク先が開きます。
- **Change type:** ウェブサイトのリンクを[ホスト型ページ](/docs/landing-pages)に、ページをリンクに、またはページを別の種類のページに切り替えます。短縮リンクとスキャンはそのまま引き継がれます。詳しくは[印刷済みコードの開き先を変更する](/docs/help/dynamic-codes/change-the-type)をご覧ください。
- **Edit design in playground:** コードをエディタで開きます。短縮リンクとの紐付けは維持されます。
- **Archive:** コードを復元するまで、短縮リンクには「現在は無効です」というページが表示されます。アーカイブしたコードはプランの上限にカウントされません。
- **Move to trash:** 短縮リンクには「現在は無効です」というページ(HTTP 410)が表示され、コードはプランにカウントされなくなります。**Trash** から復元できるほか、そこで完全に削除することもでき、その場合はスキャン履歴も削除されます。その後、短縮リンクには「QRコードが見つかりません」というページが表示されます。API経由での削除(`DELETE /v1/codes/{id}`)は、即座に完全削除されます。
- **Duplicate:** リンク先、デザイン、フォルダ、タグ、メモを新しいコードにコピーします。新しい短縮リンクが発行され、スキャン数は0から始まります。
- **Version history:** すべての変更がコードのページに記録されます。バージョンを復元すると、その前に現在の設定が保存されるため、復元は取り消せます。

## コードを整理する [#organize-codes]

- **フォルダ:** 最大5階層までネストできます。コードをフォルダにドラッグするか、**Move to folder** を使います。フォルダを削除すると、そのコードとサブフォルダは1階層上に移動します。
- **タグ:** 複数のタグで絞り込むと、そのすべてを持つコードが表示されます。
- **お気に入りとメモ:** コードにスターを付けたり、非公開のメモを残したりできます。メモは検索の対象になります。
- **検索** は、タイトル、リンク先、メモ、タグ、バックハーフが対象です(短縮リンクを貼り付けると、そのコードを探せます)。
- **一括操作:** コードを選択して、移動、タグ付け、一時停止、アーカイブ、お気に入り登録、ゴミ箱への移動、PNG、WebP、SVGファイルのZIPとしてのダウンロードができます。
- **CSVインポート:** **Codes → Import** では、1つのCSV(リンク先、タイトル、フォルダ、タグ、任意のカスタムバックハーフは `slug` 列)から最大{facts.importRows}件の動的コードを作成できます。すべてのコードを1つのフォルダに振り分けたり、全コードにタグを追加したりすることもできます。長いインポートは一時停止でき、ページを再読み込みしたり接続が切れたりしても、コードが重複して作成されることなく途中から再開されます。完了すると、各行の短縮リンクを含む結果のCSVと、PNGまたはSVG形式のコードをまとめたZIPが出力されます。2行以上のインポートとカスタムバックハーフにはProが必要です。

コードは、作成したワークスペースに属します。ワークスペースのメンバーは全員、コードを作成・編集できます。メンバーは自分のコードを削除でき、オーナーと管理者はワークスペース内のすべてのコードを削除できます。

<Callout type="info">
  コードがなくなることはありません。プランをダウングレードしても、既存のコードが無効になることはありません。上限を超えている間も、コードの編集とアーカイブはできます。ただし、上限を下回るまでは、新しいコードの作成や復元はできません。
</Callout>

## スキャン分析 [#scan-analytics]

各コードには分析ページがあり、直近7日、30日、90日、1年、3年(プランの履歴期間による制限あり)のスキャン数の推移、ユニークビジター、上位の国と都市、デバイス、OS、ブラウザ、リファラーを確認できます。選択した期間のスキャンはCSVとしてエクスポートできます。

スキャンごとに記録される内容は次のとおりです。

- 時刻(UTC)。ホスティングプラットフォームが提供する場合は、国、地域、都市も記録されます(qrdx.devではVercelのジオヘッダー)
- デバイスの種類、OS、ブラウザ(ユーザーエージェントから判別)
- リファラーのホスト名のみ。完全なURLは記録されません。QRコードのスキャンでは、ほとんどの場合リファラーがありません。
- ビジターハッシュ: IPアドレス、ユーザーエージェント、日付にソルトを加えたSHA-256です。1日あたりのユニークビジターを数えるために使われ、IPアドレス自体は保存されません。
- ProとBusinessで、コードが[正確な位置情報を要求](/docs/precise-location)し、スキャンした人が許可した場合: 小数点以下3桁(約100 m)に丸めた位置情報と、そのブラウザが報告した精度

既知のボット、リンクプレビュー、ブラウザのプリフェッチはカウントされません。

## REST API [#rest-api]

`https://api.qrdx.dev/v1/codes` でコードをプログラムから管理できます。リクエストは、[APIキー](/docs/developers/api-keys)またはOAuthアクセストークン（`Authorization: Bearer <key or token>`）で認証します。キーまたはトークンには `codes:read` または `codes:write` スコープが必要です。取得方法は [REST API](/docs/developers/rest-api) をご覧ください。キーは作成したワークスペースに対して動作し、トークンによるリクエストはご自身のワークスペースに対して動作します。ログイン中のブラウザセッションからのリクエストも利用でき、ダッシュボードで最後に開いたワークスペースに対して動作します。

| メソッド | パス | 説明 |
| --- | --- | --- |
| `GET` | `/v1/codes` | コードを一覧表示します。クエリ：`status`（`active`、`archived`、`all`）、`q`、`limit`（100以下）、`offset` |
| `POST` | `/v1/codes` | コードを1件作成するか、最大{facts.apiBatchCodes}件の配列で作成します（配列はProが必要です）。本文：`destinationUrl`、任意の `title`、`style`、`domainId`、`slug` |
| `GET` | `/v1/codes/{id}` | コードを1件取得します |
| `PATCH` | `/v1/codes/{id}` | `destinationUrl`、`title`、`style`、`domainId`（[カスタムドメイン](/docs/custom-domains)）、`slug`、`archived` を更新するか、`kind` を `redirect` と `page` の間で切り替えます |
| `DELETE` | `/v1/codes/{id}` | コードとそのスキャンを削除します |
| `GET` | `/v1/codes/{id}/scans` | `range`（`7d`、`30d`、`90d`、`365d`、`1095d`。プランの履歴期間までに制限されます）の分析データを取得します。個別のスキャンを取得するには `limit`（500以下）を、次のページを取得するには `before`（最後の `scannedAt`）を追加します |

コードを作成します。

```bash
curl https://api.qrdx.dev/v1/codes \
  -H "Authorization: Bearer $QRDX_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"destinationUrl": "https://example.com/menu", "title": "Spring menu"}'
```

```json
{
  "data": {
    "id": "cm3x...",
    "slug": "aB3dE5f",
    "shortLink": "https://qrdx.dev/q/aB3dE5f",
    "defaultShortLink": "https://qrdx.dev/q/aB3dE5f",
    "domain": null,
    "destinationUrl": "https://example.com/menu",
    "title": "Spring menu",
    "contentType": "url",
    "kind": "redirect",
    "pageId": null,
    "status": "active",
    "style": null,
    "scanCount": 0,
    "lastScannedAt": null,
    "archivedAt": null,
    "createdAt": "2026-10-31T12:00:00.000Z",
    "updatedAt": "2026-10-31T12:00:00.000Z",
    "organizationId": null
  }
}
```

`slug` を渡すと、バックハーフを指定できます（ProとBusiness。ルールは[カスタムバックハーフ](#custom-back-halves)をご覧ください）。`domainId` を指定した場合はそのドメインで、指定しない場合は `qrdx.dev` で重複が確認されます。

```bash
curl https://api.qrdx.dev/v1/codes \
  -H "Authorization: Bearer $QRDX_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"destinationUrl": "https://example.com/menu", "slug": "spring-menu"}'
```

レスポンスには `"slug": "spring-menu"` と `"shortLink": "https://qrdx.dev/q/spring-menu"` が含まれます。カスタムドメインで指定したバックハーフは、そのドメインにのみ存在するため、`"defaultShortLink": null` になります。配列で送る場合、`slug` はすべて異なる必要があります。

### 1回のリクエストで多数のコードを作成する [#many-codes-in-one-request]

ProとBusinessでは、最大{facts.apiBatchCodes}件のコードを配列で送信できます。自動生成されるバックハーフは、バッチ内で重複することも、既存のコードと衝突することもありません。Google Web Riskが時間内に確認できなかったリンクは、バッチ作成の直後に再度確認され、リンクが登録されていたコードは無効になります（[リンクの安全性チェック](/docs/code-controls#safety-checks-on-links)）。バッチは全件成功か全件失敗のどちらかです。いずれかの行に問題がある場合（無効な宛先、使用済みまたは予約済みの `slug`、安全でないリンクなど）は何も作成されず、エラーの `data.details` にすべての問題が `index`（配列内での行の位置、0始まり）ごとに一覧表示されます。

バッチごとに一意の値（UUIDなど）を指定した `Idempotency-Key` ヘッダーを送信してください。リクエストがタイムアウトした場合や接続が切断された場合は、同じキーで同じリクエストをもう一度送信します。最初の試行で作成されたコードが `Idempotent-Replayed: true` ヘッダー付きで返され、途中で中断された試行は、コードが重複して作成されることなく完了します。

```bash
curl https://api.qrdx.dev/v1/codes \
  -H "Authorization: Bearer $QRDX_TOKEN" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: 6f1c2a9e-spring-tables" \
  -H "Prefer: return=minimal" \
  -d '[{"destinationUrl": "https://example.com/table/1", "title": "Table 1"},
       {"destinationUrl": "https://example.com/table/2", "title": "Table 2"}]'
```

各コードはデザイン付きで返されます。ワークスペースのデフォルトテーマにロゴが埋め込まれている場合、大きなバッチではデータ量が膨らみます。`Prefer: return=minimal` を送信すると、`style` を除いた各コード（ID、スラッグ、リンク、宛先、タイトル、ステータス、作成日時）が返されます。レスポンスが4 MBに収まらないバッチは、何も作成されずに `PAYLOAD_TOO_LARGE` で拒否されます。

宛先を変更します。

```bash
curl -X PATCH https://api.qrdx.dev/v1/codes/cm3x... \
  -H "Authorization: Bearer $QRDX_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"destinationUrl": "https://example.com/summer-menu"}'
```

`style` には、Playgroundと同じデザインフィールド（`fgColor`、`bgColor`、`bodyPattern`、`cornerEyePattern`、`level` など）を指定できます。ロゴには `logoIcon`<IfAvailable feature="fileStorage">、またはアップロード済みファイルの `logoFileId`</IfAvailable> を送信します（[コードのstyleに指定するロゴ](/docs/developers/rest-api#code-logos)）。`shortLink` は、たとえば [`qrdx` ライブラリ](/docs/getting-started)や[Image API](/docs/developers/image-api)でQRコードにエンコードしてください。

エラーは共通のJSON形式 `{ "code": "...", "message": "...", "status": 400 }` で返され、修正方法を説明するページがある場合は `docs` リンクも付きます。

| ステータス | コード | 発生する場合 |
| --- | --- | --- |
| 400 | `VALIDATION_ERROR`、`INVALID_SLUG` | 本文またはクエリが無効です（詳細は `data` に含まれ、バッチでは `index` ごとに示されます）。または、`slug` がルールに違反しているか予約済みです |
| 401 | `UNAUTHORIZED`、`INVALID_TOKEN` | `Authorization: Bearer` トークンがないか、無効、期限切れ、または失効しています（[トークンを取得する](/docs/developers/rest-api#get-an-access-token)） |
| 402 | `LIMIT_REACHED`、`PLAN_REQUIRED` | プランのアクティブなコード数の上限を超えているか、Proなしで一括作成またはカスタム `slug` を使用しました |
| 403 | `INSUFFICIENT_SCOPE`、`FORBIDDEN` | トークンに必要なスコープがないか、ワークスペースのロールでは実行できない操作です |
| 404 | `NOT_FOUND` | コードが存在しないかご自身のものではない、またはそのエンドポイントがありません |
| 409 | `SLUG_TAKEN` | 別のコードがすでにその `slug` を使用しています（`qrdx.dev` 上、またはカスタムドメイン上） |
| 429 | `RATE_LIMITED` | リクエストが多すぎます。`Retry-After` ヘッダーの時間が経過してから再試行してください |

## セルフホスティング [#self-hosting]

動的QRコードは、セルフホストしたインスタンスでも動作します。

- `NEXT_PUBLIC_SHORT_LINK_BASE_URL` は、短縮リンクのオリジンを設定します。デフォルトはアプリのURLです。
- `SCAN_HASH_SALT` は、訪問者ハッシュに使用するシークレットソルトを設定します。未設定の場合は、`BETTER_AUTH_SECRET` から生成されます。
- 国、地域、市区町村は、Vercelのジオヘッダーから取得されます。Cloudflareを経由する場合は国のみ取得でき（`CF-IPCountry`）、それ以外の環境では位置情報は不明と表示されます。
- エリアルールは、スキャンした人が位置情報を共有しなかった場合、VercelのIP座標（`x-vercel-ip-latitude`、`x-vercel-ip-longitude`）を使用します。それ以外の環境では、位置情報が共有されたスキャンにのみ一致します。
- レート制限は、Upstash Redisを設定している場合に適用されます。
