動的QRコードは、最終的なURLではなく、`https://qrdx.dev/q/aB3dE5f` のような短いリンクをエンコードします。スキャンすると短いリンクが開き、設定した送信先にリダイレクトされます。送信先はいつでも変更できるため、印刷済みのコードが古くなることはなく、スキャンはすべて集計されます。

プレイグラウンドと`qrdx`ライブラリで作成した静的QRコードは、引き続き無料で無制限に利用できます。動的コードにはQRdxアカウントが必要です。

## 動的コードを作成する [#create-a-dynamic-code]

- **ダッシュボード:** [ダッシュボード](/dashboard)を開き、**新しいコード**をクリックして、送信先URLと任意のタイトルを入力します。コードはPNG、WebP、SVGでダウンロードできます。
- **プレイグラウンド:** コンテンツタイプで**URL**を選び、リンクを入力して**動的にする**をオンにします。QRコードは短いリンクに切り替わり、デザインはそのまま残ります。後からURLを編集した場合は、**新しいURLに変更**をクリックして送信先を更新します。**デザインをコードに保存**をクリックすると、現在のデザインがコードとともに保存されます。

送信先は`http://`または`https://`のリンクである必要があります。ユーザー名やパスワードを含むリンク、およびQRdxの他の短いリンクへのリンクは受け付けられません。

## カスタムの後半部分 [#custom-back-halves]

すべてのコードには、`/q/`に続く7文字のランダムな後半部分が割り当てられます。ProとBusinessでは、代わりに任意の文字列を指定できます。たとえば`https://qrdx.dev/q/spring-menu`のようにします。コードの作成または編集時に**カスタムの後半部分**を入力すると、入力中にその文字列が空いているかどうかがダイアログに表示されます。

- 3〜64文字。英字、数字、`-`、`_`を使用でき、`-`で始めたり終えたりすることはできません。
- 後半部分は、生成されたものと同様に大文字と小文字を区別します。`Spring-Menu`と`spring-menu`は別のリンクです。
- `qrdx.dev`では、後半部分はQRdx全体で一意である必要があり、QRdxのページとして読める単語（`admin`、`api`、`docs`、`login`、`pricing`、`settings`など）は予約されています。
- 独自の[カスタムドメイン](/docs/custom-domains)では、後半部分はそのドメイン内で一意であればよく、予約されているのは`api`、`p`、`q`のみです。そのため`go.yourbrand.com/pricing`も使えます。このような後半部分はそのドメインに属し、`qrdx.dev/q/`のリンクはありません。
- コードの後半部分を変更すると、そのコードのリンクも変わります。古い後半部分で印刷されたQRコードは機能しなくなるため、コードを再度ダウンロードしてください。

## コードを管理する [#manage-codes]

ダッシュボードから次のことができます。

- **リンクを編集:** 送信先またはタイトルを変更します。印刷済みのコードは引き続き機能し、次回のスキャンで新しい送信先が開きます。
- **タイプを変更:** Webサイトのリンクを[ホスト型ページ](/docs/landing-pages)に変更したり、ページをリンクに戻したり、ページを別のページタイプに変更したりできます。短いリンクとスキャン履歴は残ります。詳しくは[印刷済みコードの移動先を変更する](/docs/help/dynamic-codes/change-the-type)を参照してください。
- **プレイグラウンドでデザインを編集:** コードをエディターで開きます。短いリンクには引き続き紐づいたままです。
- **アーカイブ:** コードを復元するまで、短いリンクには「もう有効ではありません」というページが表示されます。アーカイブされたコードは、プランの上限にはカウントされません。
- **ゴミ箱に移動:** 短いリンクには「もう有効ではありません」というページ（HTTP 410）が表示され、コードはプランにカウントされなくなります。**ゴミ箱**から復元するか、そこで完全に削除できます。完全に削除するとスキャン履歴も削除され、短いリンクには「QRコードが見つかりません」というページが表示されます。APIの`DELETE /v1/codes/{id}`で削除した場合は、即座に完全に削除されます。
- **複製:** 送信先、デザイン、フォルダー、タグ、メモを、新しい短いリンクを持つ新しいコードにコピーします。スキャン履歴はコピーされません。
- **バージョン履歴:** 変更はすべてコードのページに記録されます。バージョンを復元すると、先に現在の設定が保存されるため、復元は取り消せます。

## コードを整理する [#organize-codes]

- **フォルダー:** 最大5階層までネストできます。コードをフォルダーにドラッグするか、**フォルダーに移動**を使用します。フォルダーを削除すると、その中のコードとサブフォルダーは1階層上に移動します。
- **タグ:** 複数のタグで絞り込むと、それらすべてを持つコードを表示できます。
- **お気に入りとメモ:** コードにスターを付け、非公開のメモを残せます。メモは検索できます。
- **検索:** タイトル、送信先、メモ、タグ、後半部分が対象です（短いリンクを貼り付けると、そのコードを検索できます）。
- **一括操作:** コードを選択して、移動、タグ付け、一時停止、アーカイブ、お気に入り登録、ゴミ箱への移動、またはPNG、WebP、SVGファイルのZIPとしてダウンロードできます。
- **CSVインポート:** **コード → インポート**で、1つのCSVから最大{facts.importRows}件の動的コードを作成できます（CSVには送信先、タイトル、フォルダー、タグ、`slug`列の任意のカスタム後半部分を含めます）。すべてのコードを1つのフォルダーにまとめたり、全コードにタグを追加したりすることもできます。長いインポートは一時停止でき、再読み込みや接続切断の後も、コードを重複させずに途中から再開します。完了時には、各行の短いリンクを記載した結果CSVと、コードをPNGまたはSVGでまとめたZIPが出力されます。1行より多くインポートする場合と、カスタムの後半部分を使用する場合は、Proが必要です。

コードは作成されたワークスペースに属します。ワークスペースのすべてのメンバーがコードを作成および編集できます。メンバーは自分のコードを削除でき、オーナーと管理者はワークスペース内の任意のコードを削除できます。

<Callout type="info">
  コードが無効になることはありません。プランをダウングレードしても既存のコードは停止しません。上限を超えている場合でも、コードの編集とアーカイブはできます。上限を下回るまで、新しいコードの作成と復元ができないだけです。
</Callout>

## スキャン分析 [#scan-analytics]

各コードには分析ページがあり、直近7日、30日、90日、1年、3年、またはコードの最初のスキャン以降の全期間について、時間ごとのスキャン数、ユニークビジター数、上位の国と都市、デバイス、OS、ブラウザー、参照元を確認できます（履歴はプランによって制限されます。全期間はProとBusinessで利用できます）。選択した期間のスキャンはCSVでエクスポートできます。

各スキャンについて記録される内容は次のとおりです。

- 時刻（UTC）、およびホスティングプラットフォームが提供する場合は国、地域、都市（qrdx.devではVercelの地理情報ヘッダー）
- ユーザーエージェントから判別したデバイスタイプ、OS、ブラウザー
- 参照元のホスト名のみ。完全なURLは記録しません。ほとんどのQRスキャンには参照元がありません。
- ビジターのハッシュ: IPアドレス、ユーザーエージェント、日付のソルト付きSHA-256です。日ごとのユニークビジター数を数えるために使われ、IPアドレス自体は保存されません。
- ProとBusinessのみ: コードが[正確な位置情報を要求](/docs/precise-location)し、スキャンする側が許可した場合に、小数点以下3桁（約100m）に丸めた位置情報と、ブラウザーが報告した精度

既知のボット、リンクプレビュー、ブラウザーのプリフェッチはカウントされません。

## REST API [#rest-api]

`https://api.qrdx.dev/v1/codes` でコードをプログラムから管理できます。リクエストは、`codes:read` または `codes:write` スコープを持つ [APIキー](/docs/developers/api-keys) または OAuth アクセストークン（`Authorization: Bearer <key or token>`）で認証します。取得方法は [REST API](/docs/developers/rest-api) を参照してください。キーは作成されたワークスペースに対して動作し、トークンによるリクエストは自分のワークスペースに対して動作します。サインイン済みのブラウザセッションからのリクエストも使用でき、その場合は最後に開いたワークスペースに対して動作します。

| メソッド | パス | 説明 |
| --- | --- | --- |
| `GET` | `/v1/codes` | コードを一覧表示します。クエリ: `status`（`active`、`archived`、`all`）、`q`、`limit`（≤ 100）、`offset` |
| `POST` | `/v1/codes` | 1つのコード、または最大 {facts.apiBatchCodes} 個までの配列を作成します（配列にはProが必要です）。ボディ: `destinationUrl`、任意の `title`、`style`、`domainId`、`slug` |
| `GET` | `/v1/codes/{id}` | 1つのコードを取得します |
| `PATCH` | `/v1/codes/{id}` | `destinationUrl`、`title`、`style`、`domainId`（[カスタムドメイン](/docs/custom-domains)）、`slug` または `archived` を更新します。または `kind` を `redirect` と `page` の間で切り替えます |
| `DELETE` | `/v1/codes/{id}` | コードとそのスキャンを削除します |
| `GET` | `/v1/codes/{id}/scans` | `range`（`7d`、`30d`、`90d`、`365d`、`1095d`、Proおよび Business では `all`。プランの履歴保持期間により制限されます）の分析データを取得します。個別のスキャンには `limit`（≤ 500）を追加し、次のページには `before`（最後の `scannedAt`）を指定します |

コードを作成するには次のようにします:

```bash
curl https://api.qrdx.dev/v1/codes \
  -H "Authorization: Bearer $QRDX_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"destinationUrl": "https://example.com/menu", "title": "Spring menu"}'
```

```json
{
  "data": {
    "id": "cm3x...",
    "slug": "aB3dE5f",
    "shortLink": "https://qrdx.dev/q/aB3dE5f",
    "defaultShortLink": "https://qrdx.dev/q/aB3dE5f",
    "domain": null,
    "destinationUrl": "https://example.com/menu",
    "title": "Spring menu",
    "contentType": "url",
    "kind": "redirect",
    "pageId": null,
    "status": "active",
    "style": null,
    "scanCount": 0,
    "lastScannedAt": null,
    "archivedAt": null,
    "createdAt": "2026-10-31T12:00:00.000Z",
    "updatedAt": "2026-10-31T12:00:00.000Z",
    "organizationId": null
  }
}
```

`slug` を指定すると後半部分を選べます（ProおよびBusinessのみ。ルールは [カスタム後半部分](#custom-back-halves) を参照してください）。`domainId` を指定した場合はそのドメインで重複が確認されます。指定しない場合は `qrdx.dev` で確認されます:

```bash
curl https://api.qrdx.dev/v1/codes \
  -H "Authorization: Bearer $QRDX_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"destinationUrl": "https://example.com/menu", "slug": "spring-menu"}'
```

レスポンスには `"slug": "spring-menu"` と `"shortLink": "https://qrdx.dev/q/spring-menu"` が含まれます。カスタムドメインで選んだ後半部分は、そのドメインでしか存在しないため、`"defaultShortLink": null` になります。配列では、すべての `slug` が互いに異なる必要があります。

### 1回のリクエストで複数のコードを作成する [#many-codes-in-one-request]

ProおよびBusinessでは、最大 {facts.apiBatchCodes} 個のコードを配列で送信できます。生成される後半部分は、同じバッチ内で重複せず、既存のコードとも衝突しません。Google Web Risk がすぐに確認できなかったリンクは、バッチ作成の直後に再度確認されます。そのリンクが危険なものとしてリストされていた場合、そのコードは無効になります（[リンクの安全性チェック](/docs/code-controls#safety-checks-on-links)）。バッチは全件成功か全件失敗のいずれかです。いずれかの行に問題がある場合（無効な送信先、使用済みまたは予約済みの `slug`、安全でないリンクなど）、何も作成されず、エラーの `data.details` に問題のある行がすべて `index` で示されます。`index` は配列内の位置（0始まり）です。

バッチごとに一意の値（UUIDなど）を `Idempotency-Key` ヘッダーに設定してください。リクエストがタイムアウトしたり接続が切れたりした場合は、同じキーで同じリクエストを再送してください。すると、最初の試行で作成されたコードが `Idempotent-Replayed: true` ヘッダー付きで返されます。途中で中断された試行は、コードを二重に作成することなく完了されます。

```bash
curl https://api.qrdx.dev/v1/codes \
  -H "Authorization: Bearer $QRDX_TOKEN" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: 6f1c2a9e-spring-tables" \
  -H "Prefer: return=minimal" \
  -d '[{"destinationUrl": "https://example.com/table/1", "title": "Table 1"},
       {"destinationUrl": "https://example.com/table/2", "title": "Table 2"}]'
```

各コードはそのデザインとともに返されます。ワークスペースのデフォルトテーマにロゴが埋め込まれている場合、大きなバッチではその分サイズが増えます。`Prefer: return=minimal` を送信すると、各コードが `style` なし（ID、slug、リンク、送信先、タイトル、ステータス、作成日時）で返されます。レスポンスが 4 MB に収まらないバッチは、何も作成される前に `PAYLOAD_TOO_LARGE` で拒否されます。

送信先を変更するには次のようにします:

```bash
curl -X PATCH https://api.qrdx.dev/v1/codes/cm3x... \
  -H "Authorization: Bearer $QRDX_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"destinationUrl": "https://example.com/summer-menu"}'
```

`style` には、プレイグラウンドと同じデザインのフィールド（`fgColor`、`bgColor`、`bodyPattern`、`cornerEyePattern`、`level` など）を指定します。ロゴを設定するには、`logoIcon` を送信します<IfAvailable feature="fileStorage"> か、アップロードしたファイルの `logoFileId` を送信します</IfAvailable>（[コードの style 内のロゴ](/docs/developers/rest-api#code-logos)）。QRコードには `shortLink` をエンコードしてください。たとえば [`qrdx` ライブラリ](/docs/getting-started) や [Image API](/docs/developers/image-api) を使用できます。

エラーはすべて同じJSON形式で返されます。`{ "code": "...", "message": "...", "status": 400 }` の形式で、修正方法を説明するページがある場合は `docs` リンクも含まれます:

| ステータス | コード | 発生する条件 |
| --- | --- | --- |
| 400 | `VALIDATION_ERROR`、`INVALID_SLUG` | ボディまたはクエリが無効（詳細はバッチの場合 `data` に、`index` ごとに記載されます）、または `slug` がルールに違反している、もしくは予約されている |
| 401 | `UNAUTHORIZED`、`INVALID_TOKEN` | `Authorization: Bearer` トークンがない、または無効、期限切れ、取り消し済み（[トークンを取得する](/docs/developers/rest-api#get-an-access-token)） |
| 402 | `LIMIT_REACHED`、`PLAN_REQUIRED` | プランの有効なコード数の上限を超えている、またはProなしで一括作成やカスタム `slug` を使おうとしている |
| 403 | `INSUFFICIENT_SCOPE`、`FORBIDDEN` | 必要なスコープがないトークン、またはこの操作を行えないワークスペースのロール |
| 404 | `NOT_FOUND` | コードが存在しない、または自分のものではない、もしくはエンドポイントが存在しない |
| 409 | `SLUG_TAKEN` | その `slug` は別のコードで使用されている（`qrdx.dev` またはカスタムドメイン上） |
| 429 | `RATE_LIMITED` | リクエストが多すぎます。`Retry-After` ヘッダーの時間が経過してから再試行してください |

## セルフホスティング [#self-hosting]

動的コードは、セルフホストしたインスタンスでも動作します:

- `NEXT_PUBLIC_SHORT_LINK_BASE_URL` は、短縮リンクのオリジンを設定します。デフォルトはアプリのURLです。
- `SCAN_HASH_SALT` は、訪問者ハッシュ用の秘密のソルトを設定します。設定しない場合は、`BETTER_AUTH_SECRET` から生成されます。
- 国、地域、都市は Vercel のジオヘッダーから取得されます。Cloudflare の背後では国のみ利用でき（`CF-IPCountry`）、それ以外の環境では位置が不明と表示されます。
- スキャナーが位置情報を共有しなかった場合、エリアルールは Vercel の IP 座標（`x-vercel-ip-latitude`、`x-vercel-ip-longitude`）を使用します。それ以外の環境では、位置情報を共有したスキャンにのみ一致します。
- レート制限は、Upstash Redis が設定されている場合に適用されます。
