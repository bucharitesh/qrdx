호스팅 페이지에는 QRdx에 업로드한 파일을 표시할 수 있어요. 메뉴나 브로슈어 PDF, 사진 갤러리, 음악이나 팟캐스트, 비디오가 그 예입니다. 업로드한 파일은 **대시보드 → 파일**에 보관되며, 업로드한 워크스페이스에 속합니다. 파일마다 고정된 링크가 있어서 파일을 교체해도 링크는 계속 작동해요.

## 업로드할 수 있는 파일 [#what-you-can-upload]

| 종류 | 형식 |
| --- | --- |
| PDF | PDF |
| 이미지 | JPEG, PNG, WebP, GIF, AVIF |
| 오디오 | MP3, M4A, AAC, Ogg, WAV |
| 비디오 | MP4, WebM, MOV |

H.264 비디오가 담긴 MP4는 모든 브라우저에서 재생됩니다. 휴대폰으로 촬영한 MOV 파일도 대개 재생되지만, 브라우저에서 재생되지 않으면 MP4로 변환하세요. SVG, HTML, 압축 파일, 오피스 문서는 업로드할 수 없습니다. 그래서 스토리지에서 제공되는 어떤 파일도 방문자의 브라우저에서 코드를 실행할 수 없어요.

모든 업로드는 사용하기 전에 검사합니다. 파일 크기가 미리 알린 크기와 일치해야 하고, 파일의 첫 바이트가 해당 형식의 파일과 실제로 일치해야 해요. 예를 들어 `.pdf`로 이름만 바꾼 HTML 페이지는 거부됩니다. 거부된 업로드는 스토리지에서 삭제되고 **차단됨**으로 표시돼요.

## 플랜별 한도 [#limits-per-plan]

| 플랜 | 워크스페이스당 스토리지 | 최대 파일 크기 |
| --- | --- | --- |
| 무료 | 50 MB | 10 MB |
| Pro | 5 GB | 100 MB |
| Business | 50 GB | 250 MB |

워크스페이스에는 소유자들이 가진 플랜 중 가장 높은 플랜이 적용됩니다. 한도는 새 업로드만 막아요. 플랜을 다운그레이드했거나 워크스페이스가 스토리지 한도를 넘은 경우에도, 이미 업로드한 모든 파일은 그 파일을 사용하는 모든 페이지에서 계속 제공됩니다. 새 파일을 업로드하려면 필요 없는 파일을 삭제하거나 플랜을 업그레이드하세요.

## 페이지에서 파일 사용하기 [#use-files-on-a-page]

파일을 표시하는 블록은 다섯 가지입니다. 각 블록에서는 업로드한 파일이나 다른 곳에 호스팅된 파일의 링크를 사용할 수 있어요.

- **PDF**는 태블릿과 컴퓨터에서 문서를 페이지 안에 바로 보여 주며, **PDF 열기**(휴대폰에서는 전체 화면 뷰어)와 **다운로드** 버튼이 함께 표시돼요.
- **갤러리**는 사진을 1~3열 그리드로 보여 줍니다. 사진을 탭하면 전체 화면으로 열리고, 스와이프하거나 방향키로 넘겨 볼 수 있어요.
- **오디오**는 커버 이미지와 재생 목록이 있는 트랙을 재생하며, 한 곡이 끝나면 다음 곡이 시작돼요. 다운로드 버튼은 선택 사항입니다.
- **비디오 파일**은 업로드한 MP4나 WebM을 재생하며, GIF처럼 음소거 상태로 반복 재생하도록 설정할 수도 있어요. YouTube, Vimeo, Loom은 **비디오** 블록을 사용하세요. 이 블록은 누군가 재생을 탭하기 전까지 YouTube에서 아무것도 불러오지 않고 비디오를 삽입합니다.
- **다운로드**는 사람들이 저장할 수 있는 파일을 목록으로 보여 주며, 파일마다 라벨을 지정할 수 있어요.

**새 코드**의 **PDF**, **이미지**, **MP3 / 오디오**, **비디오** 페이지 유형을 선택하면 이 블록들이 미리 배치된 상태로 시작할 수 있어요.

블록에서 **업로드**를 선택하면 기기에서 파일을 추가하고, **내 파일에서 선택**을 선택하면 이전에 업로드한 파일을 다시 사용할 수 있어요. 링크를 붙여 넣어도 됩니다.

## 파일 교체 또는 삭제 [#replace-or-delete-a-file]

**대시보드 → 파일**을 열고 파일 옆의 메뉴를 사용하세요.

- **링크 복사**는 파일 자체의 링크(`https://qrdx.dev/api/files/<id>`)를 복사합니다. 이 링크를 동적 QR 코드의 이동 주소로 사용할 수도 있어요.
- **파일 교체**는 같은 링크 뒤에 새 내용을 업로드합니다. 예를 들어 다음 시즌 메뉴로 바꿀 때 쓸 수 있어요. 해당 파일을 사용하는 페이지와 코드에는 1분 안에 새 버전이 표시됩니다. 파일은 같은 종류의 파일로만 교체할 수 있어요(PDF는 PDF로만 교체).
- **삭제**는 파일을 완전히 삭제합니다. 페이지나 코드에서 아직 그 파일을 사용 중이면 QRdx가 먼저 해당 목록을 보여 줍니다. 삭제하면 그 페이지들에서 파일이 있던 자리에 "파일을 사용할 수 없음"이 표시돼요.

멤버는 자신이 업로드한 파일을 교체하고 삭제할 수 있으며, 소유자와 관리자는 워크스페이스의 모든 파일을 관리할 수 있어요.

## 신고된 파일 [#reported-files]

모든 호스팅 페이지에는 **악용 신고** 링크가 있습니다. 파일이 규칙을 위반하거나 저작권자가 삭제를 요청하면 QRdx가 해당 파일을 차단할 수 있어요. 차단된 파일은 1분 안에 모든 페이지와 QRdx 링크에서 더 이상 제공되지 않으며(페이지에는 "파일을 사용할 수 없음"이 표시됩니다), 동일한 사본(최대 25 MB)은 다시 업로드할 수 없어요.

## 스토리지 설정(셀프 호스팅) [#set-up-storage-self-hosting]

파일 업로드에는 [Cloudflare R2](https://developers.cloudflare.com/r2/)를 사용합니다. R2가 없으면 파일 페이지에 "이 서버에 스토리지가 설정되지 않았습니다"가 표시되고, 업로드 API는 `503`으로 응답하며, 블록에서는 다른 곳에 호스팅된 파일의 링크만 사용할 수 있어요.

1. Cloudflare 대시보드에서 **R2**를 열고 버킷을 만드세요. 예: `qrdx-files`.
2. **R2 → Manage API tokens**에서 해당 버킷에 대한 **Object Read & Write** 권한이 있는 토큰을 만드세요.
3. 다음 환경 변수를 설정하고 다시 시작하세요.

   ```bash
   R2_ACCOUNT_ID=your-cloudflare-account-id
   R2_ACCESS_KEY_ID=token-access-key-id
   R2_SECRET_ACCESS_KEY=token-secret-access-key
   R2_BUCKET=qrdx-files
   # Optional: serve files from a public bucket URL or custom domain
   R2_PUBLIC_BASE_URL=https://files.example.com
   ```

4. 버킷에 CORS 정책을 추가하세요(**Settings → CORS policy**). 브라우저는 R2에 직접 업로드하므로, 버킷은 앱의 origin에서 오는 `Content-Type` 헤더가 포함된 `PUT` 요청을 허용해야 해요.

   ```json
   [
     {
       "AllowedOrigins": ["https://qrdx.example.com", "http://localhost:3000"],
       "AllowedMethods": ["PUT", "GET", "HEAD"],
       "AllowedHeaders": ["Content-Type"],
       "ExposeHeaders": ["ETag"],
       "MaxAgeSeconds": 3600
     }
   ]
   ```

   `https://qrdx.example.com`을 사람들이 대시보드를 열 때 사용하는 origin(스킴과 호스트, 끝에 슬래시 없음)으로 바꾸세요. `http://localhost:3000`은 로컬 개발 서버에서 업로드할 때만 남겨 두세요.

### 공개 파일 또는 사전 서명된 링크 [#public-files-or-presigned-links]

방문자는 항상 `/api/files/<id>`를 통해 파일을 열며, 이 주소는 저장된 객체로 리디렉션됩니다.

- `R2_PUBLIC_BASE_URL`을 설정하면(버킷에 연결한 사용자 지정 도메인 또는 `r2.dev` URL. `r2.dev` URL은 Cloudflare가 요청 수를 제한하며 테스트용으로만 권장합니다) 공개 URL로 리디렉션됩니다. 객체 키에는 임의의 id가 들어 있어서 파일 목록을 조회하거나 주소를 추측할 수 없어요.
- 설정하지 않으면 버킷은 비공개로 유지되고, 모든 리디렉션은 1시간 후에 만료되는 사전 서명된 링크로 이루어집니다.

어느 쪽이든 교체, 삭제 또는 차단된 파일은 1분 안에 QRdx 링크를 통한 제공이 중단됩니다. 차단된 파일은 공개 URL에서도 즉시 사라져요. 해당 객체는 임의의 부분이 포함된 `quarantine/` 키로 이동하고(관리자가 복원할 수 있도록 보관됩니다), QRdx 링크는 `410 Gone`으로 응답합니다.

브라우저는 `staging/` 키로 업로드합니다. 업로드 검사가 끝나면 QRdx는 검사한 버전을 정확히 그대로 파일 자체의 키로 복사하므로, 아직 유효한 업로드 링크로는 검사를 마친 파일을 교체할 수 없어요.

<Callout type="info">
  끝까지 완료되지 않은 업로드는 두 시간 후부터 스토리지 사용량에 포함되지 않으며, 다음에 누군가 해당 워크스페이스에 업로드할 때 정리됩니다. 중단된 업로드의 잔여 파일도 삭제되도록, 버킷에 접두사가 `staging/`인 객체를 하루 후에 삭제하는 객체 수명 주기 규칙(**Settings → Object lifecycle rules**)을 추가하세요.
</Callout>
