모든 [동적 QR 코드](/docs/dynamic-qr-codes)에는 [대시보드](/dashboard?to=codes)의 코드 페이지에 **Access & schedule** 패널이 있어요(코드를 열고 **Settings** 탭을 여세요). 변경 사항은 다음 스캔부터 적용되므로 코드를 다시 인쇄할 필요가 없어요.

| 제어 | 스캔한 사람에게 보이는 화면 | 플랜 |
| --- | --- | --- |
| 일시 중지 | 대체 URL 또는 "이 캠페인은 일시 중지되었습니다"라는 중립 페이지 | 모든 플랜 |
| 비밀번호 | 비밀번호 화면. 올바른 비밀번호를 입력하면 코드가 열려요 | Pro 및 Business |
| 시작 | 시작 전: "아직 시작되지 않았습니다" 페이지 | Pro 및 Business |
| 종료 | 종료 후: 대체 URL 또는 "캠페인이 종료되었습니다"라는 중립 페이지 | Pro 및 Business |
| 스캔 제한 | 제한에 도달하면: 대체 URL 또는 "종료" 페이지 | Pro 및 Business |
| 대체 URL | 일시 중지, 종료, 제한 초과된 코드가 사람들을 보내는 곳 | Pro 및 Business |

## 일시 중지 [#pause]

**Pause code**를 켜면 두 행사 사이처럼 코드를 잠시 멈출 수 있고, 끄면 다시 시작돼요. 일시 중지 중의 스캔은 대체 URL을 설정했다면 그곳으로 이동하고, 설정하지 않았다면 캠페인이 일시 중지되었다고 알리는 간단한 페이지로 이동해요. 일시 중지는 모든 플랜에서 무료예요.

## 비밀번호 [#password]

비밀번호(4자 이상)를 설정하면 코드를 스캔한 사람에게 먼저 비밀번호 화면이 표시돼요. 올바른 비밀번호를 입력하면 해당 브라우저는 6시간 동안 잠금이 해제된 상태로 유지돼요. 이는 짧은 링크와 그 링크가 여는 호스팅 페이지 모두에 적용돼요. 비밀번호를 변경하거나 삭제하면 이전 비밀번호로 잠금을 해제한 모든 브라우저가 다시 잠겨요.

비밀번호는 bcrypt 해시로 저장돼요. QRdx는 나중에 비밀번호를 보여줄 수 없고 교체만 할 수 있어요. 한 방문자가 잘못된 비밀번호를 반복해서 입력하면 속도가 제한돼요.

## 시작일과 종료일 [#start-and-end-dates]

- **Starts:** 그때까지는 스캔하면 "이 캠페인은 아직 시작되지 않았습니다. 나중에 이 코드를 다시 스캔해 주세요."라고 표시돼요.
- **Ends:** 그 시점부터는 스캔하면 대체 URL로 이동하거나 "이 캠페인은 종료되었습니다"라고 표시돼요.

날짜는 사용자의 시간대로 입력하고 정확한 시각으로 저장되므로, 코드는 어디서나 같은 순간에 종료돼요. 종료 시각은 시작 시각보다 뒤여야 해요.

## 스캔 제한 [#scan-limit]

제한은 분석과 같은 방식으로 스캔을 집계해요. 봇, 링크 미리보기, 한 기기에서 짧은 시간에 반복되는 스캔은 집계되지 않아요. 코드가 제한에 도달하면 이후 스캔은 대체 URL 또는 "종료" 페이지로 이동해요. 제한을 늘리거나 해제하면 코드가 다시 열려요.

## 대체 URL [#fallback-url]

일시 중지, 만료, 제한 초과된 코드가 사람들을 보내는 주소예요. 홈페이지나 다음 캠페인 등을 지정할 수 있어요. 지정하지 않으면 스캔한 사람에게 작은 중립 페이지가 표시돼요. 이 페이지에는 광고, QRdx 홍보, 가입 안내가 절대 표시되지 않고, 캠페인 상태와 "Report abuse" 링크만 표시돼요.

대체 URL도 코드의 대상 URL과 같은 안전 검사를 거쳐요.

## 플랜과 다운그레이드 [#plans-and-downgrades]

- 일시 중지는 모든 플랜에서 작동해요.
- 비밀번호, 날짜, 스캔 제한, 대체 URL을 설정하거나 변경하려면 Pro 또는 Business가 필요해요.
- **다운그레이드해도 코드가 종료되거나 잠기지 않아요.** Pro에서 설정한 제어는 설정한 그대로 계속 작동하며, 어떤 플랜에서든 언제든 삭제할 수 있어요.

## 링크 안전 검사 [#safety-checks-on-links]

QRdx는 대상 URL과 대체 URL을 저장할 때마다 검사해요.

- [Google Web Risk](https://cloud.google.com/web-risk)가 멀웨어, 피싱, 원치 않는 소프트웨어로 등록한 링크는 거부돼요(서버에 Web Risk 키가 있는 경우). 대량 처리 등으로 Web Risk가 제때 응답하지 못하면 코드는 일단 생성되고 잠시 후 링크를 다시 조회해요. 그때 Web Risk에 등록되어 있으면 코드가 꺼지고 검토자가 확인해요.
- `javascript:`, `data:` 등 웹이 아닌 링크는 거부돼요.
- 계정 생성 후 처음 7일 동안 URL 단축 서비스, IP 주소만 있는 주소, 비슷하게 생긴(동형 문자) 도메인을 가리키는 코드는 꺼진 상태로 저장되고 **검토 대기**로 전환돼요. 패널에 이 상태가 표시되며 사용자가 따로 할 일은 없어요. 확인이 끝나면 검토자가 코드를 켜 줘요. 새 계정은 시간당 동적 코드를 최대 30개까지 만들 수 있고, 유료 플랜 워크스페이스는 {facts.newPaidAccountHourlyCodes}개까지 만들 수 있어요. 이를 넘으면 오류 메시지에 몇 분 뒤에 더 만들 수 있는지 표시되고, 대시보드 가져오기는 그때까지 일시 중지돼요.

누구나 [qrdx.dev/report-abuse](/report-abuse)에서 코드를 신고할 수 있어요. 검토 후 꺼진 코드는 모든 사람에게 작동하지 않으며, 소유자가 다시 켤 수 없어요.

## 셀프 호스팅 [#self-hosting]

- `WEB_RISK_API_KEY`: Web Risk API가 활성화된 Google Cloud API 키예요. 없으면 링크는 위의 오프라인 규칙으로만 검사돼요.
- `NEXT_PUBLIC_TURNSTILE_SITE_KEY` 및 `TURNSTILE_SECRET_KEY`: 공개 신고 양식에 적용하는 Cloudflare Turnstile이에요(선택 사항).
- 잠금 해제 쿠키는 `BETTER_AUTH_SECRET`으로 서명돼요.
