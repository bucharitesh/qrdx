QRdx berlisensi AGPL-3.0, dan Anda dapat menjalankan aplikasi web (editor QR, akun, verifikasi dua langkah dan passkey, kode dinamis dan halaman yang di-hosting, tim, tema tersimpan, galeri komunitas, serta dokumentasi ini) di server Anda sendiri. Single sign-on workspace dan log audit workspace adalah pengecualian: keduanya berada di folder `ee/` yang berlisensi komersial dan tetap nonaktif kecuali Anda mengatur kunci lisensi (`QRDX_EE_LICENSE`). Menggunakannya di produksi memerlukan perjanjian tertulis dengan QRdx; lihat [LICENSING.md](https://github.com/bucharitesh/qrdx/blob/main/LICENSING.md). Anda tidak memerlukan semua ini untuk menggunakan [pustaka `qrdx` React](/docs/getting-started) atau CLI. Keduanya berjalan di mana saja tanpa backend, di bawah lisensi MIT. [Open source di QRdx](/open-source-qr-code-generator) mencantumkan setiap bagian repositori beserta lisensinya.

<Callout type="warn">
  Penyiapan Docker ini masih baru. Jika ada yang tidak berfungsi, silakan [buka issue](https://github.com/bucharitesh/qrdx/issues).
</Callout>

## Persyaratan [#requirements]

- Docker dengan Compose v2 dan BuildKit (Docker Desktop dan Docker Engine terbaru sudah menyertakan keduanya), atau Node.js 22 (22.22.3 atau lebih baru) dan [Bun](https://bun.com/docs/installation) 1.4 untuk penyiapan manual
- Memori minimal 8 GB untuk Docker saat image dibuild
- Cara untuk masuk agar akun dapat dibuat: aplikasi OAuth GitHub atau Google, atau [Resend](https://resend.com) untuk kode masuk lewat email. Kode dikirim lewat email hanya jika `NEXT_PUBLIC_APP_URL` bukan `localhost`. `bun run dev` mencetaknya di terminal, tetapi image Docker tidak melakukannya, sehingga pengujian Docker lokal memerlukan login GitHub atau Google.
- Postgres: container yang disertakan di `docker-compose.yml`, atau database [Neon](https://neon.tech)

### Cara kerja koneksi database [#how-the-database-connection-works]

Aplikasi berkomunikasi dengan Postgres melalui driver HTTP serverless Neon.

- **Neon:** langsung berfungsi. Atur `DATABASE_URL` ke connection string Neon Anda.
- **Postgres biasa:** memerlukan proxy HTTP yang kompatibel dengan Neon di depannya. `docker-compose.yml` menjalankannya ([local-neon-http-proxy](https://github.com/TimoWilhelm/local-neon-http-proxy)) dan mengatur `DATABASE_HTTP_ENDPOINT` agar aplikasi mengirim query ke sana.

Skema berasal dari `packages/database/schema.ts` dan diterapkan dengan `drizzle-kit push`.

## Mulai cepat dengan Docker Compose [#quick-start-with-docker-compose]

### 1. Clone repositori [#1-clone-the-repository]

```bash
git clone https://github.com/bucharitesh/qrdx.git
cd qrdx
```

### 2. Konfigurasikan environment [#2-configure-the-environment]

```bash
cp apps/docs/.env.example .env
```

Edit `.env`:

- `BETTER_AUTH_SECRET`: buat dengan `openssl rand -base64 32`
- `NEXT_PUBLIC_APP_URL`: URL publik instans Anda, misalnya `https://qr.example.com`. Gunakan `http://localhost:3000` untuk pengujian lokal.
- `BETTER_AUTH_URL`: hapus tanda komentarnya dan gunakan nilai yang sama
- `GITHUB_CLIENT_ID` / `GITHUB_CLIENT_SECRET`: dari [aplikasi OAuth GitHub](https://github.com/settings/developers) dengan callback URL `<your url>/api/auth/callback/github`
- atau `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET`: dari [klien OAuth Google](https://console.cloud.google.com/apis/credentials) dengan redirect URI `<your url>/api/auth/callback/google`

Anda tidak perlu mengatur `DATABASE_URL`. Compose mengarahkan aplikasi ke container Postgres miliknya sendiri. Untuk mengubah kata sandi database, atur `POSTGRES_PASSWORD` sebelum start pertama.

### 3. Jalankan stack [#3-start-the-stack]

```bash
docker compose up -d --build
```

Perintah ini membuild image, menjalankan Postgres dan proxy, menjalankan layanan sekali jalan `migrate` (`drizzle-kit push`), lalu menjalankan aplikasi di port 3000. Build pertama memakan waktu beberapa menit.

```bash
docker compose ps                    # migrate should show "exited (0)"
docker compose logs -f migrate app   # follow the schema sync and the app
```

### 4. Buat pengguna pertama Anda [#4-create-your-first-user]

Buka `NEXT_PUBLIC_APP_URL` di browser dan masuk dengan GitHub, Google, atau kode email. Akun Anda dibuat saat masuk pertama kali.

### 5. Buat admin pertama Anda [#5-create-your-first-admin]

Tambahkan alamat email akun yang baru Anda buat ke `.env`:

```bash
ADMIN_EMAILS=you@example.com
```

Buat ulang container aplikasi agar perubahan terbaca, lalu masuk dan buka `/admin`:

```bash
docker compose up -d app
```

`ADMIN_USER_IDS` bekerja dengan cara yang sama menggunakan ID pengguna.

## Menggunakan Neon atau database terkelola lainnya [#using-neon-or-another-managed-database]

Anda dapat melewati Postgres bawaan dan hanya menjalankan image aplikasi:

```bash
docker build -t qrdx --build-arg NEXT_PUBLIC_APP_URL=https://qr.example.com .
docker run -d --env-file .env -p 3000:3000 qrdx
```

Atur `DATABASE_URL` di `.env` ke connection string Neon Anda dan biarkan `DATABASE_HTTP_ENDPOINT` tidak diatur. Terapkan skema sekali (dan lagi setelah setiap pembaruan) dengan image migrator:

```bash
docker build --target migrator -t qrdx-migrate .
docker run --rm -e DATABASE_URL="<your connection string>" qrdx-migrate
```

## Penyiapan manual (Node.js) [#manual-setup-nodejs]

```bash
git clone https://github.com/bucharitesh/qrdx.git
cd qrdx
bun install

cp apps/docs/.env.example apps/docs/.env.local          # then edit it

bun run db:push                                          # apply the schema
bun run --filter docs dev                                # http://localhost:3000
```

Untuk produksi, build dan jalankan aplikasi:

```bash
bun x turbo build --filter=docs
bun run --filter docs start
```

`bun run db:push` terhubung dengan driver Neon, sehingga memerlukan database Neon. Untuk memakai Postgres Docker sebagai gantinya dalam pengembangan lokal, jalankan dengan `docker compose up -d db db-proxy`, terapkan skema dengan `docker compose run --rm migrate`, dan atur nilai berikut di `apps/docs/.env.local`:

```bash
DATABASE_URL=postgresql://postgres:postgres@localhost:5432/qrdx
DATABASE_HTTP_ENDPOINT=http://localhost:4444/sql
```

## Reverse proxy dan HTTPS [#reverse-proxy-and-https]

Letakkan aplikasi di belakang reverse proxy seperti Caddy, nginx, atau Traefik yang mengakhiri TLS, dan jangan membuka port 3000 langsung ke internet. Pembatasan laju, email keamanan, dan [log audit](/docs/help/teams/audit-log) membaca IP klien dari `X-Real-IP` lalu alamat pertama di `X-Forwarded-For`, jadi proxy harus mengatur header ini dan aplikasi hanya boleh dapat dijangkau melalui proxy. Atur proxy agar menetapkan `X-Real-IP` ke alamat tempat koneksi diterima (di nginx, `proxy_set_header X-Real-IP $remote_addr;`). Proxy yang hanya menambahkan ke `X-Forwarded-For` memungkinkan klien menaruh alamat apa pun di urutan pertama.

Setelah HTTPS siap, ubah `NEXT_PUBLIC_APP_URL` dan `BETTER_AUTH_URL` ke URL `https://`, perbarui URL callback OAuth, lalu build ulang.

### Content-Security-Policy [#content-security-policy]

Build produksi mengirim Content-Security-Policy pada halaman milik QRdx sendiri: halaman untuk pengguna yang sudah masuk mendapat nonce skrip baru untuk setiap permintaan, sedangkan halaman yang dirender sebelumnya mendapat daftar izin host skrip. Halaman yang di-hosting (`/p`) mendapat kebijakan yang longgar, karena halaman tersebut menjalankan piksel milik pemiliknya dan menyematkan media dari mana saja. Jika reverse proxy Anda juga mengatur `Content-Security-Policy`, browser akan menerapkan keduanya, jadi jangan atur di sana. Atur `CSP_REPORT_ONLY=1` (saat build dan saat dijalankan) untuk mengirim kebijakan sebagai report-only sambil Anda memeriksa pengaturan baru; pelanggaran dicatat oleh `/api/csp-report`. Tambahkan `CSP_HTTPS=1` jika Anda melayani lewat HTTPS di luar Vercel, agar browser meningkatkan setiap sumber daya `http://`.

## Memperbarui [#updating]

Cadangkan database terlebih dahulu:

```bash
docker compose exec db pg_dump -U postgres qrdx > qrdx-backup.sql
```

Lalu tarik pembaruan dan build ulang. Layanan `migrate` menyinkronkan skema lagi sebelum aplikasi dimulai.

```bash
git pull
docker compose up -d --build
```

Untuk pengaturan manual, jalankan `git pull`, `bun install`, dan `bun run db:push`, lalu build ulang.

Jika perubahan skema akan menghapus data, `drizzle-kit push` meminta konfirmasi. Dalam kasus itu, jalankan `docker compose run --rm migrate` di terminal untuk meninjau dan mengonfirmasi perubahan.

## Pemecahan masalah [#troubleshooting]

- **"Invalid environment variables" saat startup:** log menyebutkan setiap variabel yang hilang atau tidak valid. Variabel opsional harus dijadikan komentar, bukan diisi dengan nilai kosong.
- **"BETTER_AUTH_SECRET is missing" atau "You are using the default secret":** atur `BETTER_AUTH_SECRET` lalu buat ulang container.
- **`redirect_uri` OAuth tidak cocok:** URL callback di aplikasi OAuth Anda harus persis `<NEXT_PUBLIC_APP_URL>/api/auth/callback/<github|google>`. Atur `BETTER_AUTH_URL` ke URL dasar yang sama.
- **Aplikasi tidak dapat menjangkau database (`fetch failed`):** dengan Postgres biasa, `DATABASE_HTTP_ENDPOINT` harus mengarah ke proxy yang sedang berjalan. Periksa `docker compose ps db-proxy`.
- **`migrate` tidak pernah selesai:** `drizzle-kit push` sedang menunggu konfirmasi. Lihat [Memperbarui](#updating).
- **Perubahan nilai `NEXT_PUBLIC_*` tidak berpengaruh:** build ulang image.
- **Port 4444 sudah digunakan:** ubah pemetaan port `db-proxy` di `docker-compose.yml`. Port ini hanya dipakai untuk pengembangan lokal di host.
- **"the --mount option requires BuildKit":** Docker Anda tidak memiliki BuildKit. Pasang plugin `buildx`, atau perbarui Docker.
- **Build berhenti dengan `Killed` atau kode keluar 137:** Docker kehabisan memori. Berikan setidaknya 8 GB (Docker Desktop: Settings → Resources) lalu jalankan `docker compose up -d --build` lagi.
- **"sign-in code email is off for this deployment":** email kode tidak dikirim selama `NEXT_PUBLIC_APP_URL` adalah `localhost`. Gunakan masuk dengan GitHub atau Google untuk uji coba lokal.
