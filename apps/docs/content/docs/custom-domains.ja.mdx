デフォルトでは、[動的QRコード](/docs/dynamic-qr-codes)は `https://qrdx.dev/q/aB3dE5f` のような短縮リンクをエンコードします。カスタムドメインを使うと、代わりに `https://go.yourbrand.com/aB3dE5f` がエンコードされるため、スキャンする前からブランド名が相手に伝わります。リダイレクト、編集、スキャン分析は同じように使えます。

カスタムドメインは Pro(ワークスペースあたり最大5件)と Business(最大25件)で利用できます。

## ドメインを接続する [#connect-a-domain]

1. [設定 → ドメイン](/dashboard?to=settings/domains)を開き、`go.yourbrand.com` のようにドメインを入力します。メインのウェブサイトをそのまま使えるため、サブドメインがおすすめです。
2. DNSプロバイダ(ドメインを購入した会社、Cloudflare など)で、ドメインに表示されたDNSレコードを追加します。
   - サブドメインには `CNAME` レコードを追加します。
   - ルートドメイン(`yourbrand.com`)には `A` レコードを追加します。
   - 所有権の確認が必要な場合は、`TXT` レコードも表示されます。

   正確な値は、ダッシュボードからコピーしてください。多くのプロバイダでは、名前の欄にはドメインより前の部分のみ(`go`、ルートの場合は `@`)を入力します。
3. **確認** をクリックします。DNSの変更は通常数分で反映されますが、最大48時間かかることがあります。レコードがまだ見つからない場合は、しばらくしてからもう一度お試しください。

確認が完了すると、動的コードの作成時や編集時に、**短縮リンクのドメイン** の選択欄にそのドメインが表示されます。確認済みのドメインは、削除するまで確認済みのままです。**DNSを確認** を使うと、いつでもレコードを再読み込みできます。

<Callout type="info">
  3日以内に確認できなかったドメインは、別のアカウントが追加できるようになります。これにより、管理していないドメインを誰かが占有し続けることはありません。
</Callout>

<IfAvailable feature="domainConnect" id="one-click-dns-setup" title="ワンクリックDNS設定">

一部のDNSプロバイダは、サービスが代わりにレコードを追加できるオープン標準の [Domain Connect](https://www.domainconnect.org) に対応しています。お使いのプロバイダが対応しており、QRdxの設定を提供している場合、DNSの設定待ちのドメインには、プロバイダ名が入った **…で設定** ボタンが表示されます。

1. ボタンをクリックします。DNSプロバイダのページが開き、QRdxに必要なレコードが一覧表示されます。
2. 求められた場合はサインインし、変更を承認します。承認するまでは何も変更されません。
3. ドメインページに戻ると、すぐにDNSが確認され、その後30秒ほどの間にもう一度確認されます。

このボタンが表示されるのは `go.yourbrand.com` のようなサブドメインの場合のみで、しかも表示されたレコードをそのままプロバイダが追加できる場合に限ります。それ以外の場合は、上記のとおり表のレコードをご自身で追加してください。

</IfAvailable>

## コードで使う [#use-it-for-codes]

- **新しいコード:** **コードを作成** をクリックする前に、**短縮リンクのドメイン** でドメインを選びます。
- **既存のコード:** **リンクを編集** でドメインを選んで保存し、QRコードをもう一度ダウンロードしてください。エンコードされるリンクが変わるためです。

どのコードも、デフォルトの `https://qrdx.dev/q/<slug>` リンクでも引き続き動作します。そのため、コードをご自身のドメインに移す前に印刷したQRコードが使えなくなることはありません。一方、コードをあるカスタムドメインから別のカスタムドメイン(またはデフォルト)に移すと、古いカスタムドメインのリンクで印刷したQRコードは使えなくなります。保存の前に、ダイアログで警告が表示されます。

### 独自のバックハーフ [#your-own-back-halves]

Pro と Business では、`go.yourbrand.com/spring-menu` のように、ご自身のドメイン上でコードの[バックハーフ](/docs/dynamic-qr-codes#custom-back-halves)を選べます。バックハーフはそのドメイン内で一意であればよいため、他のQRdxユーザーが `spring-menu` を使っていても問題ありません。そのドメインで予約されているのは `api`、`p`、`q` のみです。ご自身のドメインで選んだバックハーフはそのドメインに属し、`qrdx.dev/q/` のリンクはありません。そのようなコードを別のドメインに移すと、移動先で空いていればバックハーフが維持されます。デフォルトのリンクに戻す場合も、`qrdx.dev` で空いていれば維持され、空いていなければ新しく生成されたものが割り当てられます。

ご自身のドメインでは、次のように動作します。

- `https://go.yourbrand.com/<slug>` は、そのドメインを使うコードに対してリダイレクトします。他のドメインのコードや、デフォルトリンクのみのコードでは「見つかりません」ページが表示されます。
- `https://go.yourbrand.com/` には、このドメインがQRコードのリンクをホストしていることを示す小さなページが表示されます。
- `https://go.yourbrand.com/01/<GTIN>`([GS1デジタルリンク](/docs/product-pages#gs1-digital-link))は、そのGTINを持ち、コードがこのドメインを使っている商品ページを開きます。
- それ以外のパスはすべて「見つかりません」を返します。このドメインから、QRdxのその他の部分が配信されることはありません。

変更(ドメインの新規確認や削除)がすべてのサーバーに反映されるまで、最大1分かかります。

## ワークスペースとロール [#workspaces-and-roles]

ドメインは、追加したワークスペースに属します。オーナーと管理者がドメインの追加、確認、削除を行えます。メンバーは全員、ワークスペースの確認済みドメインを自分のコードに使えます。

## プランとドメインの削除 [#plans-and-removing-domains]

- ダウングレードしても、何も壊れることはありません。確認済みのドメインは、それを使うコードを引き続き配信します。Pro または Business でない場合、ドメインの追加や確認、さらに多くのコードをドメインに移すことはできませんが、それらのコードの編集とドメインの削除は可能です。
- ドメインを削除すると、そのコードはデフォルトの `qrdx.dev/q/<slug>` リンクに戻ります。ドメインで選んだバックハーフは、`qrdx.dev` で空いていれば引き継がれ、空いていないものは新しく生成されます。カスタムドメインのリンクで印刷したQRコードは使えなくなるため、ダイアログにはまず、そのドメインを使っているコードの数が表示されます。

## REST API [#rest-api]

[コードAPI](/docs/dynamic-qr-codes#rest-api)は、`POST /v1/codes` と `PATCH /v1/codes/{id}` で `domainId`(同じワークスペース内の確認済みドメインのID)を受け付けます。デフォルトのリンクに戻すには、`PATCH` で `"domainId": null` を送信します。コードをドメインに移すには Pro が必要で、そうでない場合は `402 PLAN_REQUIRED` が返ります。

レスポンスの各コードには、次のフィールドが含まれます。

| フィールド | 説明 |
| --- | --- |
| `shortLink` | エンコードするリンク。確認済みであれば、カスタムドメインのもの |
| `defaultShortLink` | `https://qrdx.dev/q/<slug>`。常に動作します。カスタムドメインで選んだバックハーフの場合は `null` |
| `domain` | `{ "id", "hostname", "verified" }`、または `null` |

## セルフホスティング [#self-hosting]

ドメインの接続方法は、デプロイ環境によって異なります。

- **Vercel の場合:** `VERCEL_API_TOKEN`(プロジェクトにアクセスできるトークン)、`VERCEL_PROJECT_ID`、チームプロジェクトの場合は `VERCEL_TEAM_ID` を設定します。ドメインは Vercel Domains API を通じてプロジェクトに追加され、TLS証明書も発行されます。Vercel はプロジェクトに追加されたドメインのみをルーティングするため、これらの変数がないと、ドメインページにカスタムドメインが設定されていない旨が表示されます。
- **それ以外の環境**(Docker、Node.js): これらの変数は未設定のままにします。ドメインは手動で確認します。
  1. `CNAME`(アプリのホスト名宛て)または `A` レコード(サーバーのIP宛て)で、ドメインをサーバーに向けます。
  2. リバースプロキシがそのドメインを受け付け、HTTPS で配信し(たとえば Caddy のオンデマンドTLSや certbot の証明書を使用)、元の `Host` ヘッダーをアプリに転送するように設定します。nginx では `proxy_set_header Host $host;` です。Caddy ではデフォルトでそうなります。
  3. ドメインページでドメインを追加し、表示された `TXT` レコード(`_qrdx-challenge.<your-domain>`、値は `qrdx-verify=<token>`)を作成して、**確認** をクリックします。アプリはDNSルックアップでレコードを確認します。

**ワンクリックDNS設定**(任意)には [Domain Connect](https://www.domainconnect.org) を使います。対応したい各DNSプロバイダに承認された独自のテンプレートと、設定リンクに署名するRSA鍵が必要です。`DOMAIN_CONNECT_PROVIDER_ID`、`DOMAIN_CONNECT_SERVICE_ID`、`DOMAIN_CONNECT_PRIVATE_KEY`(PEM)を設定し、公開鍵を `_dck1.<provider id>` の `TXT` レコードとして公開してください。QRdx 独自のテンプレート(リポジトリの `domain-connect/`)は、プロバイダがその鍵で署名を検証するため、qrdx.dev でのみ動作します。公開した鍵が一致するまでは、ボタンは表示されず、アプリがその理由をログに記録します。

アプリは `Host` ヘッダーでカスタムドメインを判別します。ご自身のアプリのURL、`NEXT_PUBLIC_SHORT_LINK_BASE_URL`、`localhost`、`*.vercel.app` へのリクエストは、常にメインのアプリとして扱われます。
