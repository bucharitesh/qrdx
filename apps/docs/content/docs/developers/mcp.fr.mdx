QRdx exploite un serveur public [Model Context Protocol](https://modelcontextprotocol.io) à l'adresse suivante :

```txt
https://mcp.qrdx.dev/mcp
```

Utilisez cette URL dans tous les clients. Le même serveur répond aussi à l'adresse `https://qrdx.dev/api/mcp`, et la [page de connexion](/mcp) affiche l'URL publique sur qrdx.dev, sur les déploiements de prévisualisation et en développement local.

Il utilise le transport Streamable HTTP et ne conserve aucun état de session. Votre assistant IA peut l'appeler pour concevoir des QR codes pour tout type de contenu avec un score de scan vérifié, générer des QR codes, lister les styles disponibles, trouver des cadres et des thèmes de la communauté, et construire des données correctement formatées pour le Wi-Fi, les contacts, les e-mails, les SMS et les emplacements sur une carte. Rien de tout cela ne nécessite de compte ni de clé API. Avec une clé API QRdx sur la connexion, il peut aussi enregistrer un design dans vos thèmes et utiliser les logos que vous avez importés (voir [Utiliser une clé API](#use-an-api-key)).

[Essayer dans le Playground](/playground?open=code&lang=mcp) : stylisez-y un code, puis copiez-le sous forme d'arguments `design_qr` pour votre assistant.

## Configuration [#setup]

<Tabs items={["Claude Code", "Cursor", "VS Code", "Other clients"]}>
  <Tab value="Claude Code">
    ```bash
    claude mcp add --transport http qrdx https://mcp.qrdx.dev/mcp
    ```
  </Tab>
  <Tab value="Cursor">
    Ajoutez le serveur à `~/.cursor/mcp.json` (tous les projets) ou à `.cursor/mcp.json` (un seul projet) :

    ```json
    {
      "mcpServers": {
        "qrdx": {
          "url": "https://mcp.qrdx.dev/mcp"
        }
      }
    }
    ```
  </Tab>
  <Tab value="VS Code">
    Ajoutez le serveur à `.vscode/mcp.json` dans votre espace de travail :

    ```json
    {
      "servers": {
        "qrdx": {
          "type": "http",
          "url": "https://mcp.qrdx.dev/mcp"
        }
      }
    }
    ```
  </Tab>
  <Tab value="Other clients">
    Les clients qui prennent en charge les serveurs distants (Streamable HTTP) n'ont besoin que de l'URL `https://mcp.qrdx.dev/mcp`. Pour les clients qui n'exécutent que des serveurs stdio locaux, faites le lien avec [`mcp-remote`](https://www.npmjs.com/package/mcp-remote) :

    ```json
    {
      "mcpServers": {
        "qrdx": {
          "command": "npx",
          "args": ["-y", "mcp-remote", "https://mcp.qrdx.dev/mcp"]
        }
      }
    }
    ```
  </Tab>
</Tabs>

Demandez ensuite ce dont vous avez besoin, par exemple :

- « Crée un QR code pour https://example.com dans le bleu de notre marque, #155dfc, avec des modules arrondis. »
- « Crée un QR code Wi-Fi pour le réseau Office Guest avec le mot de passe correct-horse-battery. »
- « Génère un QR code de contact pour Ada Lovelace, ada@example.com, et ajoute-le au README. »
- « Conçois un QR code Wi-Fi pour Cafe Guest dans des tons bruns chaleureux avec un cadre Free Wi-Fi, et donne-moi son score de scan. »
- « Trouve un cadre de la communauté pour un menu de restaurant et utilise-le pour https://example.com/menu. »

## Outils [#tools]

| Outil | Fonction |
|------|--------------|
| `design_qr` | Conçoit un code pour n'importe quel type de contenu, avec le style choisi par votre assistant, ou à partir d'un thème intégré ou d'un élément de la communauté, vérifie son score de scan et répare le style jusqu'à obtenir Excellent. Renvoie le score, ce qui a été modifié, le JSON du style, un lien vers le Playground, un PNG et le SVG. |
| `list_options` | Liste toutes les valeurs acceptées par `design_qr` : types de contenu et leurs champs, couleurs et dégradés, formes, cadres (avec les identifiants des cadres officiels de QRdx), bordures, icônes de logo et logos de marque, thèmes intégrés, niveaux de correction d'erreur et limites. |
| `generate_qr_code` | Génère un QR code avec les styles de l'éditeur. Renvoie une image PNG et des URL publiques de l'[Image API](/docs/developers/image-api) (SVG, PNG, WebP sans perte et EPS vectoriel), prêtes pour Markdown, HTML ou l'impression, ainsi que le balisage SVG sur demande. |
| `list_qr_styles` | Liste les motifs de corps, les formes des yeux de coin et des points d'œil, les modèles de bordure, les cadres, les icônes de logo, les niveaux de correction d'erreur, les valeurs par défaut et les limites. |
| `search_community` | Recherche les cadres, thèmes et collections publiés de la [communauté](/community) par mots, type ou tag. |
| `get_community_item` | Renvoie un élément de la communauté avec le style qu'il applique, prêt pour `design_qr` ou `generate_qr_code`. |
| `save_template` | Enregistre un design comme thème dans votre espace de travail. Nécessite une [clé API](#use-an-api-key). |
| `generate_barcode` | Dessine un code-barres EAN-13, UPC-A, UPC-E, EAN-8, ITF-14, GS1-128, Code 128, Code 39, Data Matrix, PDF417 ou Aztec après avoir vérifié la valeur (chiffres de contrôle, longueurs, caractères). Renvoie un PNG et des URL publiques de l'[API de codes-barres](/docs/developers/barcode-api). |
| `save_barcode` | Enregistre un code-barres dans les codes-barres de votre espace de travail. Nécessite une [clé API](#use-an-api-key). |
| `qr_payload_wifi` | Construit une charge utile réseau `WIFI:` (WPA, WEP ou ouvert, éventuellement masqué) avec les caractères spéciaux échappés. |
| `qr_payload_vcard` | Construit un contact vCard 3.0 (RFC 2426) : nom, organisation, titre, téléphones, e-mail, site web, adresse et note. |
| `qr_payload_email` | Construit un lien `mailto:` (RFC 6068) avec cc, cci, objet et corps facultatifs. |
| `qr_payload_sms` | Construit un lien `sms:` (RFC 5724) avec un message facultatif, ou l'ancienne forme `SMSTO:`. |
| `qr_payload_geo` | Construit un emplacement `geo:` (RFC 5870) à partir d'une latitude et d'une longitude. |
| `qr_payload_payment` | Construit un code de paiement bancaire : un BR Code Pix, un virement SEPA (EPC069-12) ou un code PayNow, PromptPay ou VietQR (EMV, avec son CRC). Il vérifie les champs comme le font les formulaires du Playground. |

Les outils de charge utile renvoient une chaîne simple. Votre assistant la transmet ensuite comme `data` à `generate_qr_code`.

### design_qr [#design_qr]

`design_qr` prend le contenu sous la forme d'un type et de ses champs, avec les mêmes types et les mêmes vérifications que les formulaires de contenu de l'éditeur (`list_options` les liste), et un style facultatif :

```json
{
  "content": { "type": "wifi", "ssid": "Cafe Guest", "password": "sunshine123", "encryption": "WPA" },
  "style": {
    "bgColor": "#FFF7ED",
    "fgColor": "#9A3412",
    "bodyPattern": "rounded",
    "cornerEyePattern": "rounded",
    "frame": { "style": "banner-bottom", "text": "Free Wi-Fi" }
  }
}
```

Les options omises prennent des valeurs par défaut (les yeux suivent la couleur des points, formes carrées, marge 4, correction d'erreur Q, pas de cadre). QRdx exécute ensuite la vérification de scan de l'éditeur sur le design : il génère le code, le décode à 96, 160 et 320 px avec un modèle de caméra de téléphone, et vérifie le contraste, la zone de silence, les formes des yeux et les associations de formes. En dessous d'Excellent (85), il répare le style, jusqu'à trois fois, en changeant le moins possible (couleurs plus foncées qui gardent leur teinte, forme d'œil plus sûre, moins de correction d'erreur pour un contenu long). Si cela ne suffit pas, il se rabat sur un code classique noir sur blanc avec votre cadre. Le résultat indique ce qui a été modifié et pourquoi.

Aucun modèle d'IA ne s'exécute côté QRdx pour `design_qr` : votre assistant choisit le style, QRdx le valide, le vérifie et le répare. Un contenu invalide (un mot de passe WPA de moins de 8 caractères, une adresse e-mail mal formée) est refusé avec la raison. `design_qr` a sa propre limite de 20 appels par minute et par adresse IP.

Autres entrées :

- **`preset`** : partez d'un thème intégré à partir de son identifiant (`list_options` les liste). Les options de style que vous définissez l'emportent sur lui.
- **`community_item`** : partez d'un cadre ou d'un thème de la communauté à partir de son identifiant, par exemple `frame:wifi-card`. Un élément de type cadre repose sur un code classique ; vos options de style modifient le code qu'il contient.
- **Cadres officiels** : les cadres officiels de QRdx sont aussi des éléments de la communauté. `list_options` liste leurs identifiants par groupe (fêtes, saisons et usages), donc `frame:diwali-diya` ou `frame:menu-cutlery` fonctionnent comme `community_item`.
- **Un cadre personnalisé** : `style.frame` peut être `{ "style": "custom", "spec": … }` avec une spécification de cadre, comme celle d'un cadre de la communauté obtenue avec `get_community_item`. Il est dessiné et évalué tel quel ; les réparations modifient le code, jamais le cadre.
- **`style.logo`** : une icône de logo rapide (`wifi`, `location`, `phone`, `email`, `link`, `file`, `calendar`, `whatsapp` ou `instagram`), ou un logo de marque par son identifiant [Simple Icons](https://simpleicons.org) (`spotify`, `paypal:white`). `list_options` liste les identifiants des marques populaires.
- **Options du moteur** : `style.eyeColors` (couleurs `#RRGGBB` par œil), `moduleScale` (taille des points, de `0.5` à `1`), `shape` (`circle` pour un code rond), `autoLevel` et `logoOptions` (taille du logo, espace libre, position, recadrage et fond). Elles sont dessinées et évaluées telles quelles ; les réparations ne les modifient pas.

<IfAvailable feature="fileStorage">
`logo_file_id` dessine à la place un logo que vous avez téléversé sur QRdx, avec une [clé API](#use-an-api-key).
</IfAvailable>

Les logos sont évalués selon les modules qu'ils couvrent, comme dans l'éditeur ; une réparation peut donc porter la correction d'erreur à H ou retirer le logo. La marque QRdx que l'éditeur affiche par défaut n'est pas dessinée ici.

Le champ `qrdxStyle` du résultat est le design sous forme de JSON de style de l'éditeur. Transmettez-le à `save_template`, à `generate_qr_code` comme `style` pour générer le même design à une autre taille, ou au paramètre [`style`](/docs/developers/image-api#style) de l'Image API. `playground_url` ouvre le design dans le [Playground](/playground) : il ne contient que le style, jamais le logo ni le contenu, et `playgroundLeftOut` indique ce qu'il omet.

### Entrées de generate_qr_code [#generate_qr_code-inputs]

Les entrées correspondent aux [paramètres de l'Image API](/docs/developers/image-api#parameters) : `data` (obligatoire), `size`, `fg`, `bg`, `eyeColor`, `dotColor`, `body`, `eye`, `dot`, `level`, `margin`, `template`, `frame`, `frameText`, `logoIcon`, `logoFileId`, `item` (un identifiant d'élément de la communauté) et `style` (le JSON de style de l'éditeur : dégradés, cadres personnalisés et le reste, tel que `design_qr` le renvoie). Les options à plat l'emportent sur `style`, et `style` l'emporte sur `item`. Définissez `include_svg` sur `true` pour obtenir aussi le balisage SVG sous forme de texte, par exemple pour enregistrer un fichier `.svg`. Cette option est désactivée par défaut, car le balisage pèse souvent de 50 à 150 Ko, ce qui remplirait la conversation.

`generate_qr_code` ne vérifie pas le score de scan ; utilisez `design_qr` pour cela. Un code avec votre logo téléversé n'a pas d'URL d'image publique, car l'Image API ne dessine ce logo que pour les requêtes accompagnées de votre clé.

### La carte QR [#qr-card]

Dans les applications qui prennent en charge les [MCP Apps](https://modelcontextprotocol.io/extensions/apps/overview), `design_qr` et `generate_qr_code` affichent aussi une carte QR dans la conversation. Elle présente le code, ce qu'il encode (un code Wi-Fi affiche le nom du réseau, jamais le mot de passe), la taille et la correction d'erreur ou le score de scan, ainsi qu'un bouton **Ouvrir dans l'éditeur**. Le lien vers l'éditeur ne contient que le style, comme `playground_url`.

Les boutons PNG et SVG dépendent de ce que l'application autorise. Là où elle peut enregistrer des fichiers depuis une carte, ils les enregistrent. Sinon, ils ouvrent l'URL de l'Image API dans votre navigateur ; la carte de `design_qr` ne les affiche donc que dans les applications qui enregistrent des fichiers : son contenu ne figure jamais dans une URL d'image. Les applications peuvent vous demander de confirmer avant l'ouverture d'un lien.

Les applications sans MCP Apps reçoivent le même texte et la même image qu'auparavant. Pour les développeurs de clients :

- La carte est la ressource `ui://qrdx/qr-card` (`text/html;profile=mcp-app`), listée par `resources/list`. Les deux outils y renvoient avec `_meta.ui.resourceUri`.
- Ses données arrivent dans le `_meta` du résultat de l'outil, sous `dev.qrdx/qr-card`, destiné à la carte et non au modèle. Les outils ne renvoient aucun `structuredContent`.
- La carte est un seul fichier HTML avec ses styles et son script intégrés. La seule chose qu'elle charge est l'image du code depuis l'Image API (`https://api.qrdx.dev`, ou votre propre domaine en auto-hébergement), et sa politique de sécurité du contenu (`_meta.ui.csp.resourceDomains`) autorise cet hôte et aucun autre.

Si vous avez connecté QRdx avant l'existence de la carte, supprimez le connecteur puis ajoutez-le de nouveau, ou actualisez ses outils, afin que l'application récupère les nouvelles métadonnées des outils.

### Communauté [#community]

`search_community` trouve les cadres, thèmes et collections publiés de la [communauté](/community), gratuits sous CC0, par mots (`q`), `type` et `tag`. `get_community_item` renvoie un élément avec le style qu'il applique ; transmettez son identifiant à `design_qr` comme `community_item` ou à `generate_qr_code` comme `item`. Les mêmes données sont disponibles sur la REST API à [`/v1/community/items`](/docs/developers/api/list-community-items).

Le texte des éléments est rédigé par les membres de la communauté. Les noms, descriptions, pseudos, tags et libellés de cadre reviennent courts, sur une seule ligne et sans liens, e-mails ni balisage, et chaque résultat précise de les traiter comme des données, non comme des instructions.

## Utiliser une clé API [#use-an-api-key]

Certains outils nécessitent une [clé API](/docs/developers/api-keys) QRdx sur la connexion, envoyée sous la forme `Authorization: Bearer qrdx_…` :

- **`save_template`** enregistre un design comme thème, listé sous Thèmes dans le tableau de bord et proposé dans l'éditeur. Il nécessite une clé avec `codes:write`, ce qui est le cas des clés **Accès complet**. Une clé de votre propre espace de travail enregistre dans vos thèmes ; une clé d'équipe enregistre dans les thèmes partagés de l'équipe lorsque son créateur est propriétaire ou administrateur et que le forfait inclut les thèmes d'équipe. Les enregistrements comptent dans la limite de thèmes enregistrés du forfait (voir [Forfaits et limites](/docs/plans-and-limits)) ; au-delà, l'outil renvoie l'erreur `LIMIT_REACHED` (`402`) de l'API. Sans clé, il renvoie une erreur `401` qui indique comment en ajouter une.
- **`save_barcode`** enregistre un code-barres (format, valeur, un titre facultatif et des options de dessin) dans l'espace de travail de la clé, listé sous Codes-barres dans le tableau de bord. Il nécessite une clé avec `codes:write`. Tous les forfaits permettent d'enregistrer des codes-barres, jusqu'à 1,000 avec Gratuit ; au-delà de la limite, il renvoie `LIMIT_REACHED` (`402`).
<IfAvailable feature="fileStorage">
- **Logos que vous avez importés** dans [Tableau de bord → Fichiers](/docs/files), par identifiant de fichier (`logo_file_id` dans `design_qr`, `logoFileId` dans `generate_qr_code`) : un PNG ou JPEG de 1 Mo maximum. La clé doit appartenir à l'espace de travail propriétaire du fichier.
</IfAvailable>

## Confidentialité et limites [#privacy-and-limits]

- Les outils génèrent des images, vérifient des designs, mettent du texte en forme et lisent la communauté publique. Seuls `save_template` et `save_barcode` écrivent quelque chose : le thème ou le code-barres que vous leur demandez d'enregistrer, dans l'espace de travail de la clé API. Le serveur n'enregistre pas les codes que vous générez.
- Les URL d'image que renvoient `generate_qr_code` et `generate_barcode` contiennent les données encodées. Ne les partagez pas si les données sont privées, comme un mot de passe Wi-Fi.
- Les requêtes sont limitées à 120 par minute et par adresse IP, et `design_qr` à 20. Avec une clé, `save_template` est également limité à 30 par minute et par utilisateur.

## Auto-hébergement et développement local [#self-hosting-and-local-development]

Le serveur MCP fait partie de l'application web QRdx : chaque instance le sert donc à l'adresse `/api/mcp` :

- **Auto-hébergé.** Lorsque `NEXT_PUBLIC_APP_URL` correspond à votre propre domaine, la page de connexion, les extraits et les liens d'installation utilisent `https://<your-domain>/api/mcp`.
- **Développement local.** `bun run dev` le sert à l'adresse `http://localhost:3000/api/mcp`. La page de connexion affiche toujours l'URL publique et propose l'URL locale à titre d'indication, ce qui vous permet de pointer un client vers votre machine pour tester des modifications du serveur avant leur publication.

Ouvrir `/api/mcp` dans un navigateur redirige vers la page de connexion. Les clients MCP ne demandent jamais de HTML ; ils atteignent donc le serveur comme d'habitude.
