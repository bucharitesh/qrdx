Toute erreur de la REST API est un JSON de même forme, quel que soit le point de terminaison qui la renvoie :

```json
{
  "code": "INSUFFICIENT_SCOPE",
  "message": "This API key needs the 'codes:write' scope. Create a key that includes it at https://qrdx.dev/dashboard?to=settings/developers; a key's scopes can't be changed.",
  "status": 403,
  "docs": "https://qrdx.dev/docs/developers/api-keys"
}
```

| Champ | Description |
| --- | --- |
| `code` | Un code stable, lisible par une machine, tiré du tableau ci-dessous. C'est sur lui qu'il faut se baser pour votre logique. |
| `message` | Ce qui s'est mal passé et comment le corriger, à l'attention des humains. La formulation peut changer. |
| `status` | Le statut HTTP, répété. |
| `docs` | Une page qui explique la correction, lorsqu'il y en a une. |
| `data` | Détails supplémentaires, pour certaines erreurs. `VALIDATION_ERROR` liste chaque problème dans `data.details`. |

Une erreur de validation nomme chaque champ en échec :

```json
{
  "code": "VALIDATION_ERROR",
  "message": "Invalid request body",
  "status": 400,
  "data": {
    "details": [
      { "path": "destinationUrl", "message": "Enter a full URL, starting with https://" }
    ]
  }
}
```

L'Image API signale les paramètres de requête sous la forme `{ "param", "message" }` au lieu de `{ "path", "message" }`.

## Codes d'erreur [#error-codes]

| Statut | Code | Signification | Correction |
| --- | --- | --- | --- |
| 400 | `VALIDATION_ERROR` | Le corps, la requête ou le chemin n'a pas passé la validation. `data.details` liste chaque problème sous la forme `{ path, message }` (`{ param, message }` pour l'Image API), avec l'`index` de la ligne lorsque le corps est un tableau de codes. | Corrigez les champs listés dans `data.details` et renvoyez la requête. |
| 400 | `INVALID_SLUG` | La fin de lien personnalisée (`slug`) enfreint une règle : mot réservé, ou même fin de lien deux fois dans une requête. Pour un tableau, `data.details` liste chaque ligne par `index`. | Choisissez une autre fin de lien. Le message indique la règle. |
| 400 | `TOO_MANY_CODES` | Plus de 1 000 codes dans une même requête. Le schéma du corps la rejette normalement d'abord, en `VALIDATION_ERROR`. | Envoyez au maximum 1 000 codes par requête. |
| 400 | `DOMAIN_NOT_VERIFIED` | `domainId` désigne un domaine personnalisé qui n'est pas encore vérifié. | Terminez la vérification du domaine sur la page Domaines, ou omettez `domainId`. |
| 400 | `SID_REQUIRED` | Une conversion sans le `qrdx_sid` du scan (depuis le navigateur), ou sans `sid` ni `code` (depuis un serveur). | Envoyez le `qrdx_sid` que le lien court a ajouté à l'URL de votre page ou, avec une clé API ou un jeton, l'identifiant du code dans `code`. |
| 401 | `UNAUTHORIZED` | Aucun identifiant : la requête n'a pas d'en-tête `Authorization: Bearer` (ni de session de navigateur QRdx). | Envoyez une clé API sous la forme `Authorization: Bearer <key>` ; créez-en une dans Paramètres → Clés API et applications. Les jetons d'accès OAuth vont dans le même en-tête. |
| 401 | `INVALID_TOKEN` | La clé API ou le jeton d'accès est inconnu, révoqué ou expiré (les jetons d'accès durent une heure), ou le créateur de la clé a été banni ou a quitté l'espace de travail de la clé. | Vérifiez que vous avez envoyé la clé entière, ou créez-en une nouvelle. Pour un jeton d'accès, obtenez-en un nouveau avec votre jeton d'actualisation, ou renvoyez l'utilisateur vers l'autorisation. |
| 402 | `PLAN_REQUIRED` | La fonctionnalité n'est pas incluse dans le forfait de l'espace de travail : la création en lot, les fins de lien personnalisées et les domaines personnalisés nécessitent Pro ; les conversions et les hooks nécessitent Business. | Passez l'espace de travail à un forfait supérieur, ou retirez la fonctionnalité de la requête. |
| 402 | `LIMIT_REACHED` | L'espace de travail a autant de QR codes dynamiques actifs que son forfait en inclut (10 avec Gratuit). | Archivez un code (les codes archivés ne comptent pas) ou passez à Pro pour des codes illimités. |
| 403 | `INSUFFICIENT_SCOPE` | La clé API ou le jeton est valide, mais n'a pas la portée requise par ce point de terminaison. | Créez une clé avec la portée nommée dans le message (les portées d'une clé ne peuvent pas être modifiées). Pour une application OAuth, ajoutez la portée et demandez-la lors de l'autorisation par l'utilisateur. |
| 403 | `FORBIDDEN` | L'appelant n'a pas le droit d'effectuer cette action : un membre de l'espace de travail qui supprime un code créé par quelqu'un d'autre, un membre qui gère des hooks, ou une écriture depuis une session de navigateur provenant d'un autre site. Une clé API ne peut faire que ce que permet le rôle de son créateur dans son espace de travail. | Demandez à un propriétaire ou à un administrateur de l'espace de travail, ou appelez l'API avec une clé API depuis votre serveur. |
| 403 | `CONFIRMATION_REQUIRED` | La création d'un hook avec une session de navigateur connectée nécessite une confirmation « Confirmer que c'est vous » récente. Les clés API et les jetons OAuth ne sont pas concernés. | Confirmez votre identité dans QRdx, puis réessayez dans les 10 minutes, ou créez le hook avec une clé API depuis votre serveur. |
| 403 | `CONVERSIONS_OFF` | Une conversion depuis le navigateur pour un code dont le suivi des conversions n'est pas activé. | Activez le suivi des conversions pour le code, ou signalez la conversion depuis votre serveur avec une clé API. |
| 403 | `LIMIT_REACHED` | L'espace de travail compte déjà 20 points de terminaison de webhook et hooks. | Supprimez un point de terminaison ou un hook que vous n'utilisez plus. |
| 404 | `NOT_FOUND` | Ce point de terminaison n'existe pas, ou le code, le hook, le thème ou le domaine personnalisé n'existe pas dans l'espace de travail sur lequel agit la clé ou le jeton. | Vérifiez le chemin et l'identifiant. Une clé API agit sur l'espace de travail où elle a été créée ; un jeton OAuth agit sur l'espace de travail propre à son utilisateur. |
| 404 | `INVALID_SID` | Le `qrdx_sid` est inconnu ou date de plus de 30 jours, la fenêtre d'attribution. | Envoyez le `qrdx_sid` d'un scan récent, ou signalez la conversion par identifiant de code depuis votre serveur. |
| 409 | `SLUG_TAKEN` | Un autre code utilise déjà cette fin de lien sur ce domaine. Pour un tableau, `data.details` liste chaque fin de lien déjà prise par `index`, et rien n'est créé. | Choisissez une autre fin de lien. |
| 413 | `PAYLOAD_TOO_LARGE` | Le corps dépasse la limite du point de terminaison : 4 Mo pour les codes, 16 Ko pour les hooks, 8 Ko pour les conversions. Également un lot de codes dont la réponse (chaque code avec son design) dépasserait 4 Mo ; rien n'est créé. | Envoyez un corps plus petit. Pour les codes, un grand logo en ligne est la cause habituelle ; pour un lot, envoyez `Prefer: return=minimal` ou moins de codes. |
| 415 | `UNSUPPORTED_MEDIA_TYPE` | Une écriture sans `Content-Type: application/json`. | Envoyez un corps JSON avec `Content-Type: application/json`. |
| 422 | `UNSAFE_DESTINATION` | Google Web Risk signale l'URL de destination (logiciel malveillant, hameçonnage ou logiciel indésirable). Pour un tableau, `data.details` liste chaque ligne signalée par `index`, et rien n'est créé. | Utilisez une autre destination. Si le signalement est erroné, demandez à Google de réexaminer le site. |
| 429 | `RATE_LIMITED` | Trop de requêtes : une limite par minute (seul `Retry-After` est défini) ou le quota quotidien de l'espace de travail (`Retry-After` plus `X-RateLimit-*`). | Attendez `Retry-After` secondes. Pour le quota quotidien, attendez 00:00 UTC ou passez à un forfait supérieur. |
| 500 | `INTERNAL_ERROR` | Une défaillance est survenue du côté de QRdx. Elle a été consignée. | Réessayez dans un instant. Si cela persiste, signalez-le en indiquant l'heure de la requête. |
| 503 | `SLUG_UNAVAILABLE` | Aucun slug de lien court libre n'a pu être réservé à temps. | Renvoyez la même requête. |
| 503 | `UNAVAILABLE` | Les domaines personnalisés ne sont pas configurés sur ce déploiement (une instance auto-hébergée sans eux). | Omettez `domainId`, ou configurez les domaines personnalisés sur votre instance. |

## Nouvelles tentatives [#retrying]

- **`429` :** attendez le nombre de secondes indiqué dans `Retry-After`, puis renvoyez la même requête. Lorsque le quota quotidien est épuisé, les en-têtes `X-RateLimit-*` indiquent combien de requêtes le forfait autorise et quand le compteur est remis à zéro (00:00 UTC). Voir les [limites de débit](/docs/developers/rest-api#rate-limits).
- **`500` et `503` :** réessayez avec un backoff exponentiel, en commençant à environ une seconde.
- **Autres `4xx` :** la même requête échouera de la même façon. Corrigez-la d'abord.

La création de codes n'est pas idempotente : si un `POST /v1/codes` expire, listez vos codes avant de le renvoyer, sinon vous risquez de créer le code deux fois. Les conversions, elles, le sont : envoyez votre propre `id` et une répétition renvoie `200` avec `duplicate: true`.

## `/v1/me` et `/v1/themes` [#v1me-and-v1themes]

Ces deux points de terminaison envoient le même corps, plus les champs OAuth qu'ils ont toujours envoyés, `error` et `error_description` (le même texte que `message`), afin que les anciens clients continuent de fonctionner :

| `error` | `code` |
| --- | --- |
| `invalid_token` | UNAUTHORIZED ou INVALID_TOKEN |
| `insufficient_scope` | INSUFFICIENT_SCOPE |
| `rate_limited` | RATE_LIMITED (quota quotidien) |
| `not_found` | NOT_FOUND (thèmes) |

## Points de terminaison OAuth [#oauth-endpoints]

Les points de terminaison OAuth sous `https://qrdx.dev/api/oauth` (authorize, token, revoke, userinfo) suivent à la place la norme OAuth 2.0 : `{ "error", "error_description" }`, avec `error` valant `invalid_request`, `invalid_client`, `invalid_grant`, `unsupported_grant_type`, `invalid_token` ou `access_denied`. Recevoir `invalid_grant` lors d'une actualisation signifie que le jeton d'actualisation a déjà été utilisé (chaque actualisation en renvoie un nouveau), qu'il a expiré après 30 jours, ou que l'utilisateur a révoqué votre application : renvoyez l'utilisateur vers l'autorisation. Voir [REST API et OAuth](/docs/developers/rest-api#get-an-access-token).

## Points de terminaison inconnus [#unknown-endpoints]

Un chemin sous `/v1` qui n'existe pas renvoie `404 NOT_FOUND` au format JSON, jamais une page HTML. La [référence de l'API](/docs/developers/api) répertorie tous les points de terminaison.
