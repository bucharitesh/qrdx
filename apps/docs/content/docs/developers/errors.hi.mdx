हर REST API एरर JSON में आता है और उसका ढाँचा एक ही रहता है, चाहे उसे कोई भी endpoint लौटाए:

```json
{
  "code": "INSUFFICIENT_SCOPE",
  "message": "This API key needs the 'codes:write' scope. Create a key that includes it at https://qrdx.dev/dashboard?to=settings/developers; a key's scopes can't be changed.",
  "status": 403,
  "docs": "https://qrdx.dev/docs/developers/api-keys"
}
```

| फ़ील्ड | यह क्या है |
| --- | --- |
| `code` | नीचे दी गई टेबल का एक स्थिर, मशीन से पढ़ा जा सकने वाला कोड। अपने लॉजिक में इसी पर branch करें। |
| `message` | क्या गलत हुआ और उसे कैसे ठीक करें, लोगों के पढ़ने के लिए। शब्द बदल सकते हैं। |
| `status` | HTTP स्टेटस, दोबारा लिखा हुआ। |
| `docs` | वह पेज जो समाधान समझाता है, जहाँ कोई पेज हो। |
| `data` | कुछ एरर में अतिरिक्त जानकारी। `VALIDATION_ERROR` हर समस्या को `data.details` में सूचीबद्ध करता है। |

validation एरर हर उस फ़ील्ड का नाम बताता है जो फ़ेल हुआ:

```json
{
  "code": "VALIDATION_ERROR",
  "message": "Invalid request body",
  "status": 400,
  "data": {
    "details": [
      { "path": "destinationUrl", "message": "Enter a full URL, starting with https://" }
    ]
  }
}
```

image API query पैरामीटर को `{ "path", "message" }` की जगह `{ "param", "message" }` के रूप में बताती है।

| 400 | `VALIDATION_ERROR` | body, query या path validation में फ़ेल हो गया। `data.details` हर समस्या को `{ path, message }` के रूप में बताता है (image API पर `{ param, message }`), और जब body कोड की array हो तो उस पंक्ति का `index` भी देता है। | `data.details` में बताए गए फ़ील्ड ठीक करें और request दोबारा भेजें। |

| 402 | `LIMIT_REACHED` | workspace में उतने सक्रिय डायनेमिक कोड हैं जितने उसके प्लान में शामिल हैं (फ़्री पर 10)। | कोई कोड archive करें (archive किए गए कोड गिने नहीं जाते) या असीमित कोड के लिए Pro पर अपग्रेड करें। |
| 403 | `INSUFFICIENT_SCOPE` | API key या token वैध है, लेकिन इस endpoint के लिए ज़रूरी scope उसमें नहीं है। | message में बताए गए scope वाली key बनाएँ (key के scope बदले नहीं जा सकते)। OAuth app के लिए scope जोड़ें और यूज़र के authorize करते समय उसे माँगें। |

## दोबारा कोशिश करना [#retrying]

- **`429`:** `Retry-After` में दिए गए सेकंड तक रुकें, फिर वही request भेजें। जब दैनिक कोटा खत्म हो जाए, तो `X-RateLimit-*` headers बताते हैं कि प्लान कितनी request की अनुमति देता है और गिनती कब रीसेट होती है (00:00 UTC)। देखें [रेट लिमिट](/docs/developers/rest-api#rate-limits)।
- **`500` और `503`:** exponential backoff के साथ दोबारा कोशिश करें, लगभग एक सेकंड से शुरू करके।
- **बाकी `4xx`:** वही request हर बार उसी तरह फ़ेल होगी। पहले उसे ठीक करें।

कोड बनाना idempotent नहीं है: अगर `POST /v1/codes` का time out हो जाए, तो उसे दोबारा भेजने से पहले अपने कोड की सूची देखें, वरना कोड दो बार बन सकता है। कन्वर्ज़न idempotent हैं: अपना `id` भेजें और दोहराने पर `duplicate: true` के साथ `200` मिलेगा।

## `/v1/me` और `/v1/themes` [#v1me-and-v1themes]

ये दोनों endpoint वही body भेजते हैं, साथ में वे OAuth फ़ील्ड भी जो वे हमेशा से भेजते आए हैं, `error` और `error_description` (वही टेक्स्ट जो `message` में है), ताकि पुराने क्लाइंट चलते रहें:

| `error` | `code` |
| --- | --- |
| `invalid_token` | UNAUTHORIZED या INVALID_TOKEN |
| `insufficient_scope` | INSUFFICIENT_SCOPE |
| `rate_limited` | RATE_LIMITED (दैनिक कोटा) |
| `not_found` | NOT_FOUND (themes) |

## OAuth endpoints [#oauth-endpoints]

`https://qrdx.dev/api/oauth` के अंतर्गत OAuth endpoints (authorize, token, revoke, userinfo) इसकी जगह OAuth 2.0 मानक का पालन करते हैं: `{ "error", "error_description" }`, जहाँ `error` इनमें से एक होता है: `invalid_request`, `invalid_client`, `invalid_grant`, `unsupported_grant_type`, `invalid_token` या `access_denied`। refresh पर `invalid_grant` मिलने का मतलब है कि refresh token पहले ही इस्तेमाल हो चुका है (हर refresh नया token लौटाता है), 30 दिन बाद expire हो गया, या यूज़र ने आपका app रद्द कर दिया: यूज़र को दोबारा authorization से गुज़ारें। देखें [REST API और OAuth](/docs/developers/rest-api#get-an-access-token)।

## अज्ञात endpoints [#unknown-endpoints]

`/v1` के अंतर्गत ऐसा कोई पाथ जो मौजूद नहीं है, JSON में `404 NOT_FOUND` लौटाता है, कभी HTML पेज नहीं। हर endpoint की सूची [API reference](/docs/developers/api) में दी गई है।
