Todos los errores de la REST API son JSON con la misma estructura, sea cual sea el endpoint que los devuelva:

```json
{
  "code": "INSUFFICIENT_SCOPE",
  "message": "This API key needs the 'codes:write' scope. Create a key that includes it at https://qrdx.dev/dashboard?to=settings/developers; a key's scopes can't be changed.",
  "status": 403,
  "docs": "https://qrdx.dev/docs/developers/api-keys"
}
```

| Campo | Qué es |
| --- | --- |
| `code` | Un código estable y legible por máquinas, de la tabla de abajo. Basa tu lógica en este campo. |
| `message` | Qué salió mal y cómo solucionarlo, escrito para personas. El texto puede cambiar. |
| `status` | El estado HTTP, repetido. |
| `docs` | Una página que explica la solución, cuando la hay. |
| `data` | Detalles adicionales, en algunos errores. `VALIDATION_ERROR` enumera cada problema en `data.details`. |

Un error de validación nombra todos los campos que fallaron:

```json
{
  "code": "VALIDATION_ERROR",
  "message": "Invalid request body",
  "status": 400,
  "data": {
    "details": [
      { "path": "destinationUrl", "message": "Enter a full URL, starting with https://" }
    ]
  }
}
```

La Image API informa de los parámetros de consulta como `{ "param", "message" }` en lugar de `{ "path", "message" }`.

## Códigos de error [#error-codes]

| Estado | Código | Significado | Solución |
| --- | --- | --- | --- |
| 400 | `VALIDATION_ERROR` | El cuerpo, la consulta o la ruta no superaron la validación. `data.details` enumera cada problema como `{ path, message }` (`{ param, message }` en la Image API), con el `index` de la fila cuando el cuerpo es un array de códigos. | Corrige los campos indicados en `data.details` y vuelve a enviar la solicitud. |
| 400 | `INVALID_SLUG` | El final personalizado del enlace (`slug`) incumple una regla: es una palabra reservada, o el mismo final aparece dos veces en una solicitud. En un array, `data.details` enumera cada fila por `index`. | Elige otro final. El mensaje indica la regla. |
| 400 | `TOO_MANY_CODES` | Más de 1.000 códigos en una solicitud. Normalmente el esquema del cuerpo lo rechaza antes, como `VALIDATION_ERROR`. | Envía como máximo 1.000 códigos por solicitud. |
| 400 | `DOMAIN_NOT_VERIFIED` | `domainId` apunta a un dominio personalizado que aún no está verificado. | Termina de verificar el dominio en la página Dominios, o no incluyas `domainId`. |
| 400 | `SID_REQUIRED` | Una conversión sin el `qrdx_sid` del escaneo (desde el navegador), o sin `sid` ni `code` (desde un servidor). | Envía el `qrdx_sid` que el enlace corto añadió a la URL de tu página o, con una clave de API o un token, el id del código como `code`. |
| 401 | `UNAUTHORIZED` | Sin credenciales: la solicitud no tiene el encabezado `Authorization: Bearer` (ni sesión del navegador de QRdx). | Envía una clave de API como `Authorization: Bearer <key>`; crea una en Ajustes → Claves de API y apps. Los tokens de acceso de OAuth van en el mismo encabezado. |
| 401 | `INVALID_TOKEN` | La clave de API o el token de acceso es desconocido, fue revocado o ha caducado (los tokens de acceso duran una hora), o quien creó la clave fue bloqueado o dejó el espacio de trabajo de la clave. | Comprueba que enviaste la clave completa, o crea una nueva. Para un token de acceso, obtén uno nuevo con tu token de actualización, o vuelve a enviar al usuario por la autorización. |
| 402 | `PLAN_REQUIRED` | La función no está incluida en el plan del espacio de trabajo: la creación en lote, los finales personalizados y los dominios personalizados requieren Pro; las conversiones y los hooks requieren Business. | Mejora el plan del espacio de trabajo, o quita la función de la solicitud. |
| 402 | `LIMIT_REACHED` | El espacio de trabajo tiene tantos códigos dinámicos activos como incluye su plan (10 en Gratis). | Archiva un código (los archivados no cuentan) o mejora a Pro para tener códigos ilimitados. |
| 403 | `INSUFFICIENT_SCOPE` | La clave de API o el token es válido, pero no tiene el permiso (scope) que necesita este endpoint. | Crea una clave con el scope indicado en el mensaje (los scopes de una clave no se pueden cambiar). En una app OAuth, añade el scope y solicítalo cuando el usuario autorice. |
| 403 | `FORBIDDEN` | Quien llama no puede hacer esto: un miembro del espacio de trabajo que elimina un código creado por otra persona, un miembro que gestiona hooks, o una escritura con sesión del navegador desde otro sitio. Una clave de API solo puede hacer lo que permite el rol de su creador en su espacio de trabajo. | Pide ayuda a un propietario o administrador del espacio de trabajo, o llama a la API con una clave de API desde tu servidor. |
| 403 | `CONFIRMATION_REQUIRED` | Crear un hook con una sesión del navegador iniciada requiere una confirmación reciente de "Confirma que eres tú". A las claves de API y los tokens de OAuth no se les pide. | Confirma que eres tú en QRdx y vuelve a intentarlo en un plazo de 10 minutos, o crea el hook con una clave de API desde tu servidor. |
| 403 | `CONVERSIONS_OFF` | Una conversión del navegador para un código que no tiene activado el seguimiento de conversiones. | Activa el seguimiento de conversiones del código, o informa de la conversión desde tu servidor con una clave de API. |
| 403 | `LIMIT_REACHED` | El espacio de trabajo ya tiene 20 endpoints de webhook y hooks. | Elimina un endpoint o un hook que ya no uses. |
| 404 | `NOT_FOUND` | No existe ese endpoint, o el código, el hook, el tema o el dominio personalizado no existe en el espacio de trabajo en el que actúa la clave o el token. | Revisa la ruta y el id. Una clave de API actúa en el espacio de trabajo en el que se creó; un token de OAuth actúa en el espacio de trabajo propio de su usuario. |
| 404 | `INVALID_SID` | El `qrdx_sid` es desconocido o tiene más de 30 días, la ventana de atribución. | Envía el `qrdx_sid` de un escaneo reciente, o informa de la conversión por id de código desde tu servidor. |
| 409 | `SLUG_TAKEN` | Otro código ya usa ese final en ese dominio. En un array, `data.details` enumera cada uno de los ocupados por `index`, y no se crea nada. | Elige otro final. |
| 413 | `PAYLOAD_TOO_LARGE` | El cuerpo supera el límite del endpoint: 4 MB para códigos, 16 KB para hooks, 8 KB para conversiones. También un lote de códigos cuya respuesta (cada código con su diseño) superaría los 4 MB; no se crea nada. | Envía un cuerpo más pequeño. Con códigos, la causa habitual es un logo incrustado grande; con un lote, envía `Prefer: return=minimal` o menos códigos. |
| 415 | `UNSUPPORTED_MEDIA_TYPE` | Una escritura sin `Content-Type: application/json`. | Envía un cuerpo JSON con `Content-Type: application/json`. |
| 422 | `UNSAFE_DESTINATION` | Google Web Risk marca la URL de destino (malware, phishing o software no deseado). En un array, `data.details` enumera cada fila marcada por `index`, y no se crea nada. | Usa otro destino. Si la marca es errónea, pide a Google que revise el sitio. |
| 429 | `RATE_LIMITED` | Demasiadas solicitudes: un límite por minuto (solo se establece `Retry-After`) o la cuota diaria del espacio de trabajo (`Retry-After` más `X-RateLimit-*`). | Espera los segundos indicados en `Retry-After`. Con la cuota diaria, espera hasta las 00:00 UTC o mejora el plan. |
| 500 | `INTERNAL_ERROR` | Algo falló en el lado de QRdx. Se ha registrado. | Inténtalo de nuevo en un momento. Si sigue ocurriendo, infórmalo indicando la hora de la solicitud. |
| 503 | `SLUG_UNAVAILABLE` | No se pudo reservar a tiempo ningún slug libre para el enlace corto. | Envía la misma solicitud otra vez. |
| 503 | `UNAVAILABLE` | Los dominios personalizados no están configurados en este despliegue (una instancia autoalojada sin ellos). | No incluyas `domainId`, o configura los dominios personalizados en tu instancia. |

## Reintentos [#retrying]

- **`429`:** espera el número de segundos de `Retry-After` y luego envía la misma solicitud. Cuando se agota la cuota diaria, los encabezados `X-RateLimit-*` indican cuántas solicitudes permite el plan y cuándo se reinicia el recuento (00:00 UTC). Consulta los [límites de uso](/docs/developers/rest-api#rate-limits).
- **`500` y `503`:** reintenta con retroceso exponencial, empezando por aproximadamente un segundo.
- **Otros `4xx`:** la misma solicitud fallará de la misma manera. Corrígela primero.

Crear códigos no es idempotente: si un `POST /v1/codes` agota el tiempo de espera, consulta la lista de tus códigos antes de volver a enviarlo, o podrías crear el código dos veces. Las conversiones sí lo son: envía tu propio `id` y una repetición devuelve `200` con `duplicate: true`.

## `/v1/me` y `/v1/themes` [#v1me-and-v1themes]

Estos dos endpoints envían el mismo cuerpo más los campos de OAuth que siempre han enviado, `error` y `error_description` (el mismo texto que `message`), para que los clientes antiguos sigan funcionando:

| `error` | `code` |
| --- | --- |
| `invalid_token` | UNAUTHORIZED o INVALID_TOKEN |
| `insufficient_scope` | INSUFFICIENT_SCOPE |
| `rate_limited` | RATE_LIMITED (cuota diaria) |
| `not_found` | NOT_FOUND (temas) |

## Endpoints de OAuth [#oauth-endpoints]

Los endpoints de OAuth bajo `https://qrdx.dev/api/oauth` (authorize, token, revoke, userinfo) siguen en cambio el estándar OAuth 2.0: `{ "error", "error_description" }`, donde `error` es uno de `invalid_request`, `invalid_client`, `invalid_grant`, `unsupported_grant_type`, `invalid_token` o `access_denied`. Recibir `invalid_grant` al renovar significa que el token de actualización ya se usó (cada renovación devuelve uno nuevo), caducó a los 30 días o el usuario revocó tu app: vuelve a enviar al usuario por la autorización. Consulta [REST API y OAuth](/docs/developers/rest-api#get-an-access-token).

## Endpoints desconocidos [#unknown-endpoints]

Una ruta bajo `/v1` que no existe devuelve `404 NOT_FOUND` como JSON, nunca una página HTML. La [referencia de la API](/docs/developers/api) enumera todos los endpoints.
