QRdx एक पब्लिक [Model Context Protocol](https://modelcontextprotocol.io) सर्वर चलाता है, जो इस पते पर उपलब्ध है:

```txt
https://mcp.qrdx.dev/mcp
```

हर क्लाइंट में यही URL इस्तेमाल करें। यही सर्वर `https://qrdx.dev/api/mcp` पर भी जवाब देता है, और [कनेक्ट पेज](/mcp) qrdx.dev, प्रीव्यू डिप्लॉयमेंट और लोकल डेवलपमेंट में पब्लिक URL दिखाता है।

यह Streamable HTTP ट्रांसपोर्ट इस्तेमाल करता है और कोई सेशन स्टेट नहीं रखता। आपका AI असिस्टेंट इसे कॉल करके किसी भी कंटेंट टाइप के लिए जाँचे हुए स्कैन स्कोर वाले QR कोड डिज़ाइन कर सकता है, QR कोड रेंडर कर सकता है, उपलब्ध स्टाइल की सूची देख सकता है, कम्युनिटी के फ़्रेम और थीम खोज सकता है, और Wi-Fi, कॉन्टैक्ट, ईमेल, SMS और मैप लोकेशन के लिए सही फ़ॉर्मैट वाले पेलोड बना सकता है। इनमें से किसी के लिए अकाउंट या API key की ज़रूरत नहीं है। कनेक्शन पर QRdx API key लगाने से आप डिज़ाइन को अपनी थीम में सेव भी कर सकते हैं और अपने अपलोड किए हुए लोगो इस्तेमाल कर सकते हैं (देखें [API key इस्तेमाल करें](#use-an-api-key))।

[Playground में आज़माएँ](/playground?open=code&lang=mcp): वहाँ कोड को स्टाइल करें, फिर उसे `design_qr` आर्ग्युमेंट के रूप में कॉपी करके अपने असिस्टेंट को दें।

## टूल [#tools]

| टूल | क्या करता है |
|------|--------------|
| `design_qr` | किसी भी कंटेंट टाइप के लिए कोड डिज़ाइन करता है। स्टाइल आपका असिस्टेंट चुनता है, या किसी बिल्ट-इन थीम या कम्युनिटी आइटम से शुरू करता है। यह उसका स्कैन स्कोर जाँचता है और स्टाइल को तब तक ठीक करता है जब तक वह Great न हो जाए। नतीजे में स्कोर, क्या बदला गया, स्टाइल JSON, playground लिंक, PNG और SVG मिलते हैं। |
| `list_options` | `design_qr` जो भी वैल्यू मानता है, उन सबकी सूची देता है: कंटेंट टाइप और उनके फ़ील्ड, रंग और ग्रेडिएंट, शेप, फ़्रेम (QRdx के आधिकारिक फ़्रेम के id सहित), बॉर्डर, लोगो आइकन और ब्रांड लोगो, बिल्ट-इन थीम, एरर करेक्शन लेवल और सीमाएँ। |
| `generate_qr_code` | एडिटर की स्टाइल के साथ QR कोड बनाता है। नतीजे में PNG इमेज और सार्वजनिक [image API](/docs/developers/image-api) URL (SVG, PNG, लॉसलेस WebP और वेक्टर EPS) मिलते हैं, जो Markdown, HTML या प्रिंट में सीधे इस्तेमाल हो सकते हैं। माँगने पर SVG मार्कअप भी मिलता है। |
| `list_qr_styles` | बॉडी पैटर्न, कॉर्नर आई और आई डॉट शेप, बॉर्डर टेम्पलेट, फ़्रेम, लोगो आइकन, एरर करेक्शन लेवल, डिफ़ॉल्ट और सीमाओं की सूची देता है। |
| `search_community` | प्रकाशित [कम्युनिटी](/community) फ़्रेम, थीम और कलेक्शन शब्दों, टाइप या टैग से खोजता है। |
| `get_community_item` | एक कम्युनिटी आइटम और उसकी लागू होने वाली स्टाइल देता है, जो `design_qr` या `generate_qr_code` के लिए तैयार होती है। |
| `save_template` | किसी डिज़ाइन को आपके वर्कस्पेस में थीम के रूप में सेव करता है। इसके लिए [API key](#use-an-api-key) चाहिए। |
| `generate_barcode` | वैल्यू जाँचने (चेक डिजिट, लंबाई, अक्षर) के बाद EAN-13, UPC-A, UPC-E, EAN-8, ITF-14, GS1-128, Code 128, Code 39, Data Matrix, PDF417 या Aztec बारकोड बनाता है। नतीजे में PNG और सार्वजनिक [barcode API](/docs/developers/barcode-api) URL मिलते हैं। |
| `save_barcode` | बारकोड को आपके वर्कस्पेस के Barcodes में सेव करता है। इसके लिए [API key](#use-an-api-key) चाहिए। |
| `qr_payload_wifi` | `WIFI:` नेटवर्क पेलोड बनाता है (WPA, WEP या ओपन, चाहें तो हिडन), विशेष अक्षरों को एस्केप करके। |
| `qr_payload_vcard` | vCard 3.0 कॉन्टैक्ट (RFC 2426) बनाता है: नाम, संगठन, पद, फ़ोन, ईमेल, वेबसाइट, पता और नोट। |
| `qr_payload_email` | वैकल्पिक cc, bcc, विषय और मैसेज बॉडी के साथ `mailto:` लिंक (RFC 6068) बनाता है। |
| `qr_payload_sms` | वैकल्पिक मैसेज के साथ `sms:` लिंक (RFC 5724) बनाता है, या पुराना `SMSTO:` रूप। |
| `qr_payload_geo` | अक्षांश और देशांतर से `geo:` लोकेशन (RFC 5870) बनाता है। |
| `qr_payload_payment` | बैंक पेमेंट कोड बनाता है: Pix BR Code, SEPA क्रेडिट ट्रांसफ़र (EPC069-12), या PayNow, PromptPay या VietQR कोड (EMV, CRC सहित)। यह फ़ील्ड को वैसे ही जाँचता है जैसे playground के फ़ॉर्म जाँचते हैं। |

पेलोड टूल एक सादी स्ट्रिंग लौटाते हैं। आपका असिस्टेंट फिर उसे `data` के रूप में `generate_qr_code` को देता है।

### design_qr [#design_qr]

`design_qr` कंटेंट को टाइप और उसके फ़ील्ड के रूप में लेता है (एडिटर के कंटेंट फ़ॉर्म जैसे ही टाइप और जाँच, जिन्हें `list_options` सूचीबद्ध करता है), और साथ में एक वैकल्पिक स्टाइल:

```json
{
  "content": { "type": "wifi", "ssid": "Cafe Guest", "password": "sunshine123", "encryption": "WPA" },
  "style": {
    "bgColor": "#FFF7ED",
    "fgColor": "#9A3412",
    "bodyPattern": "rounded",
    "cornerEyePattern": "rounded",
    "frame": { "style": "banner-bottom", "text": "Free Wi-Fi" }
  }
}
```

जो विकल्प आप छोड़ देते हैं उनके डिफ़ॉल्ट लगते हैं (आई डॉट के रंग का अनुसरण करती हैं, चौकोर शेप, मार्जिन 4, एरर करेक्शन Q, कोई फ़्रेम नहीं)। फिर QRdx डिज़ाइन पर एडिटर की स्कैन जाँच चलाता है: वह कोड रेंडर करता है, उसे फ़ोन-कैमरा मॉडल के ज़रिए 96, 160 और 320 px पर डिकोड करता है, और कंट्रास्ट, क्वाइट ज़ोन, आई शेप और शेप जोड़ियाँ जाँचता है। Great (85) से नीचे होने पर वह स्टाइल को ज़्यादा से ज़्यादा तीन बार ठीक करता है, और जितना हो सके कम बदलता है (वही रंगत रखने वाले गहरे रंग, ज़्यादा सुरक्षित आई शेप, लंबे कंटेंट के लिए कम एरर करेक्शन)। इससे भी काम न बने तो वह आपके फ़्रेम के साथ क्लासिक सफ़ेद पर काले कोड पर लौट आता है। नतीजा बताता है कि क्या बदला गया और क्यों।

`design_qr` के लिए QRdx की तरफ़ कोई AI मॉडल नहीं चलता: स्टाइल आपका असिस्टेंट चुनता है, और QRdx उसे वैलिडेट करता है, जाँचता है और ठीक करता है। अमान्य कंटेंट (8 अक्षर से छोटा WPA पासवर्ड, गलत बना ईमेल पता) कारण बताकर मना कर दिया जाता है। `design_qr` की अपनी सीमा है: प्रति IP पता प्रति मिनट 20 कॉल।

और इनपुट:

- **`preset`**: id से किसी बिल्ट-इन थीम से शुरू करें (`list_options` उन्हें सूचीबद्ध करता है)। आपके सेट किए गए स्टाइल विकल्प उस पर भारी पड़ते हैं।
- **`community_item`**: id से किसी कम्युनिटी फ़्रेम या थीम से शुरू करें, जैसे `frame:wifi-card`। फ़्रेम आइटम क्लासिक कोड पर लगता है; आपके स्टाइल विकल्प उसके नीचे का कोड बदलते हैं।
- **आधिकारिक फ़्रेम**: QRdx के आधिकारिक फ़्रेम भी कम्युनिटी आइटम हैं। `list_options` उनके id समूह के अनुसार सूचीबद्ध करता है (त्योहार, मौसम और उपयोग), इसलिए `frame:diwali-diya` या `frame:menu-cutlery` को `community_item` के रूप में दिया जा सकता है।
- **कस्टम फ़्रेम**: `style.frame` `{ "style": "custom", "spec": … }` हो सकता है, जिसमें फ़्रेम स्पेक हो, जैसे `get_community_item` से मिला किसी कम्युनिटी फ़्रेम का स्पेक। वह जैसा है वैसा ही बनाया और स्कोर किया जाता है; सुधार कोड को बदलते हैं, फ़्रेम को कभी नहीं।
- **`style.logo`**: एक क्विक लोगो आइकन (`wifi`, `location`, `phone`, `email`, `link`, `file`, `calendar`, `whatsapp` या `instagram`), या [Simple Icons](https://simpleicons.org) स्लग से कोई ब्रांड लोगो (`spotify`, `paypal:white`)। `list_options` लोकप्रिय ब्रांड स्लग सूचीबद्ध करता है।
- **इंजन विकल्प**: `style.eyeColors` (हर आई के `#RRGGBB` रंग), `moduleScale` (डॉट का आकार, `0.5` से `1`), `shape` (गोल कोड के लिए `circle`), `autoLevel` और `logoOptions` (लोगो का आकार, खाली जगह, पोज़िशन, क्रॉप और प्लेट)। इन्हें जैसा दिया गया वैसा ही बनाया और स्कोर किया जाता है; सुधार इन्हें नहीं बदलते।

<IfAvailable feature="fileStorage">
`logo_file_id` इसकी जगह वह लोगो बनाता है जो आपने QRdx पर अपलोड किया है, इसके लिए [API key](#use-an-api-key) चाहिए।
</IfAvailable>

लोगो को एडिटर की तरह उन मॉड्यूल के हिसाब से स्कोर किया जाता है जिन्हें वह ढकता है, इसलिए सुधार में एरर करेक्शन H तक बढ़ सकता है या लोगो हट सकता है। एडिटर में डिफ़ॉल्ट रूप से दिखने वाला QRdx मार्क यहाँ नहीं बनाया जाता।

नतीजे का `qrdxStyle` एडिटर के स्टाइल JSON के रूप में डिज़ाइन है। इसे `save_template` को दें, या `generate_qr_code` को `style` के रूप में दें ताकि वही डिज़ाइन किसी और साइज़ में बने, या image API के [`style`](/docs/developers/image-api#style) को दें। `playground_url` डिज़ाइन को [playground](/playground) में खोलता है: उसमें सिर्फ़ स्टाइल होती है, लोगो या कंटेंट कभी नहीं, और `playgroundLeftOut` बताता है कि क्या छोड़ा गया है।

### generate_qr_code के इनपुट [#generate_qr_code-inputs]

इनपुट [image API पैरामीटर](/docs/developers/image-api#parameters) से मेल खाते हैं: `data` (ज़रूरी), `size`, `fg`, `bg`, `eyeColor`, `dotColor`, `body`, `eye`, `dot`, `level`, `margin`, `template`, `frame`, `frameText`, `logoIcon`, `logoFileId`, `item` (कम्युनिटी आइटम id) और `style` (एडिटर का स्टाइल JSON: ग्रेडिएंट, कस्टम फ़्रेम और बाकी सब, जैसा `design_qr` लौटाता है)। अलग-अलग विकल्प `style` पर भारी पड़ते हैं, और `style` `item` पर। SVG मार्कअप भी टेक्स्ट के रूप में पाने के लिए `include_svg` को `true` करें, जैसे `.svg` फ़ाइल सेव करने के लिए। यह डिफ़ॉल्ट रूप से बंद है क्योंकि मार्कअप अक्सर 50 से 150 KB का होता है, जो बातचीत को भर देगा।

`generate_qr_code` स्कैन स्कोर नहीं जाँचता; उसके लिए `design_qr` इस्तेमाल करें। आपके अपलोड किए लोगो वाले कोड का कोई सार्वजनिक इमेज URL नहीं होता, क्योंकि image API वह लोगो सिर्फ़ आपकी key वाले रिक्वेस्ट के लिए बनाता है।

### QR कार्ड [#qr-card]

जो ऐप [MCP Apps](https://modelcontextprotocol.io/extensions/apps/overview) सपोर्ट करते हैं, उनमें `design_qr` और `generate_qr_code` चैट में एक QR कार्ड भी दिखाते हैं। उसमें कोड, वह क्या एन्कोड करता है (Wi-Fi कोड में नेटवर्क का नाम दिखता है, पासवर्ड कभी नहीं), साइज़ और एरर करेक्शन या स्कैन स्कोर, और एक **Open in editor** बटन होता है। एडिटर लिंक में `playground_url` की तरह सिर्फ़ स्टाइल होती है।

PNG और SVG बटन इस पर निर्भर करते हैं कि ऐप क्या अनुमति देता है। जहाँ ऐप कार्ड से फ़ाइलें सेव कर सकता है, वहाँ वे फ़ाइलें सेव करते हैं। नहीं तो वे image API URL को आपके ब्राउज़र में खोलते हैं, इसलिए `design_qr` के कार्ड में वे सिर्फ़ उन ऐप में दिखते हैं जो फ़ाइलें सेव करते हैं: उसका कंटेंट कभी इमेज URL में नहीं जाता। लिंक खुलने से पहले ऐप आपसे पुष्टि माँग सकते हैं।

जिन ऐप में MCP Apps नहीं है, उन्हें पहले जैसा ही टेक्स्ट और इमेज मिलता है। क्लाइंट डेवलपर के लिए:

- कार्ड रिसोर्स `ui://qrdx/qr-card` (`text/html;profile=mcp-app`) है, जो `resources/list` में दिखता है। दोनों टूल `_meta.ui.resourceUri` से उसकी ओर इशारा करते हैं।
- उसका डेटा टूल नतीजे के `_meta` में `dev.qrdx/qr-card` के अंतर्गत आता है, जो कार्ड के लिए है, मॉडल के लिए नहीं। टूल कोई `structuredContent` नहीं लौटाते।
- कार्ड एक अकेली HTML फ़ाइल है जिसकी स्टाइल और स्क्रिप्ट उसी के अंदर हैं। वह सिर्फ़ image API से कोड की इमेज लोड करता है (`https://api.qrdx.dev`, या सेल्फ़-होस्ट करने पर आपका अपना डोमेन), और उसकी कंटेंट सिक्योरिटी पॉलिसी (`_meta.ui.csp.resourceDomains`) सिर्फ़ उसी होस्ट को अनुमति देती है, किसी और को नहीं।

अगर आपने कार्ड आने से पहले QRdx कनेक्ट किया था, तो कनेक्टर हटाकर दोबारा जोड़ें, या उसके टूल रिफ़्रेश करें, ताकि ऐप नया टूल मेटाडेटा ले ले।

### कम्युनिटी [#community]

`search_community` प्रकाशित [कम्युनिटी](/community) फ़्रेम, थीम और कलेक्शन खोजता है, जो CC0 के तहत फ़्री हैं, शब्दों (`q`), `type` और `tag` से। `get_community_item` एक आइटम और उसकी लागू होने वाली स्टाइल लौटाता है; उसका id `design_qr` को `community_item` के रूप में या `generate_qr_code` को `item` के रूप में दें। यही डेटा REST API पर [`/v1/community/items`](/docs/developers/api/list-community-items) पर मिलता है।

आइटम का टेक्स्ट कम्युनिटी के सदस्य लिखते हैं। नाम, विवरण, हैंडल, टैग और फ़्रेम लेबल छोटे, एक लाइन में और लिंक, ईमेल या मार्कअप के बिना लौटते हैं, और हर नतीजा कहता है कि इन्हें डेटा मानें, निर्देश नहीं।

## API key का उपयोग करें [#use-an-api-key]

कुछ tools को कनेक्शन पर QRdx [API key](/docs/developers/api-keys) की ज़रूरत होती है, जिसे `Authorization: Bearer qrdx_…` के रूप में भेजा जाता है:

- **`save_template`** किसी डिज़ाइन को थीम के रूप में सेव करता है। यह डैशबोर्ड में Themes के अंतर्गत दिखती है और एडिटर में उपलब्ध होती है। इसके लिए `codes:write` वाली key चाहिए, जो **Full access** keys में होती है। आपके अपने workspace की key से थीम आपकी थीम में सेव होती है; टीम की key से थीम टीम की साझा थीम में सेव होती है, बशर्ते उसे बनाने वाला owner या admin हो और प्लान में टीम थीम हों। सेव करने पर प्लान की सेव्ड-थीम सीमा गिनी जाती है ([प्लान और सीमाएँ](/docs/plans-and-limits) देखें); सीमा पार होने पर tool API की `LIMIT_REACHED` एरर (`402`) लौटाता है। key न हो तो यह `401` एरर लौटाता है, जिसमें बताया जाता है कि key कैसे जोड़ें।
- **`save_barcode`** एक barcode (फ़ॉर्मैट, वैल्यू, वैकल्पिक टाइटल और ड्रॉइंग विकल्प) key के workspace में सेव करता है, जो डैशबोर्ड में Barcodes के अंतर्गत दिखता है। इसके लिए `codes:write` वाली key चाहिए। हर प्लान में barcode सेव किए जा सकते हैं, फ़्री में 1,000 तक; सीमा पार होने पर यह `LIMIT_REACHED` (`402`) लौटाता है।
<IfAvailable feature="fileStorage">

## प्राइवेसी और सीमाएँ [#privacy-and-limits]

- ये tools इमेज रेंडर करते हैं, डिज़ाइन जाँचते हैं, टेक्स्ट फ़ॉर्मैट करते हैं और पब्लिक कम्युनिटी पढ़ते हैं। सिर्फ़ `save_template` और `save_barcode` कुछ लिखते हैं: वही थीम या barcode जिसे आप सेव करने को कहें, API key के workspace में। सर्वर आपके बनाए QR कोड सेव नहीं करता।
- `generate_qr_code` और `generate_barcode` जो इमेज URL लौटाते हैं, उनमें एन्कोड किया गया डेटा होता है। अगर डेटा निजी है, जैसे Wi-Fi पासवर्ड, तो उन्हें साझा न करें।
- रिक्वेस्ट प्रति IP एड्रेस 120 प्रति मिनट तक सीमित हैं, और `design_qr` के लिए 20। key के साथ `save_template` प्रति यूज़र 30 प्रति मिनट तक भी सीमित है।

## सेल्फ़-होस्टिंग और लोकल डेवलपमेंट [#self-hosting-and-local-development]

MCP सर्वर QRdx वेब app का हिस्सा है, इसलिए हर instance इसे `/api/mcp` पर चलाता है:

- **सेल्फ़-होस्टेड।** जब `NEXT_PUBLIC_APP_URL` आपका अपना डोमेन हो, तो connect पेज, snippets और install links `https://<your-domain>/api/mcp` इस्तेमाल करते हैं।
- **लोकल डेवलपमेंट।** `bun run dev` इसे `http://localhost:3000/api/mcp` पर चलाता है। connect पेज अब भी पब्लिक URL दिखाता है और लोकल URL को संकेत के रूप में देता है, ताकि आप सर्वर में बदलाव रिलीज़ होने से पहले टेस्ट करने के लिए किसी client को अपनी मशीन की ओर पॉइंट कर सकें।

ब्राउज़र में `/api/mcp` खोलने पर आप connect पेज पर पहुँच जाते हैं। MCP clients कभी HTML नहीं माँगते, इसलिए वे सर्वर तक सामान्य रूप से पहुँचते हैं।
