QRdx runs a public [Model Context Protocol](https://modelcontextprotocol.io) server at:

```txt
https://mcp.qrdx.dev/mcp
```

Use this URL in every client. The same server also answers at `https://qrdx.dev/api/mcp`, and the [connect page](/mcp) shows the public URL on qrdx.dev, on preview deployments and in local development.

It uses the Streamable HTTP transport, needs no account or API key, and keeps no session state. Your AI assistant can call it to design QR codes for any content type with a checked scan score, render QR codes, list the available styles, and build correctly formatted payloads for Wi-Fi, contacts, email, SMS and map locations.

## Setup

<Tabs items={["Claude Code", "Cursor", "VS Code", "Other clients"]}>
  <Tab value="Claude Code">
    ```bash
    claude mcp add --transport http qrdx https://mcp.qrdx.dev/mcp
    ```
  </Tab>
  <Tab value="Cursor">
    Add the server to `~/.cursor/mcp.json` (all projects) or `.cursor/mcp.json` (one project):

    ```json
    {
      "mcpServers": {
        "qrdx": {
          "url": "https://mcp.qrdx.dev/mcp"
        }
      }
    }
    ```
  </Tab>
  <Tab value="VS Code">
    Add the server to `.vscode/mcp.json` in your workspace:

    ```json
    {
      "servers": {
        "qrdx": {
          "type": "http",
          "url": "https://mcp.qrdx.dev/mcp"
        }
      }
    }
    ```
  </Tab>
  <Tab value="Other clients">
    Clients that support remote (Streamable HTTP) servers only need the URL `https://mcp.qrdx.dev/mcp`. For clients that only run local stdio servers, bridge it with [`mcp-remote`](https://www.npmjs.com/package/mcp-remote):

    ```json
    {
      "mcpServers": {
        "qrdx": {
          "command": "npx",
          "args": ["-y", "mcp-remote", "https://mcp.qrdx.dev/mcp"]
        }
      }
    }
    ```
  </Tab>
</Tabs>

Then ask for what you need, for example:

- "Make a QR code for https://example.com in our brand blue, #155dfc, with rounded modules."
- "Create a Wi-Fi QR code for the network Office Guest with password correct-horse-battery."
- "Generate a contact QR code for Ada Lovelace, ada@example.com, and add it to the README."
- "Design a Wi-Fi QR code for Cafe Guest in warm browns with a Free Wi-Fi frame, and tell me its scan score."

## Tools

| Tool | What it does |
|------|--------------|
| `design_qr` | Designs a code for any content type with the style your assistant chooses, checks its scan score and repairs the style until it is Great. Returns the score, what it changed, the style JSON, a PNG and the SVG. |
| `list_options` | Lists every value `design_qr` accepts: content types and their fields, colours and gradients, shapes, frames, borders, error correction levels and limits. |
| `generate_qr_code` | Renders a QR code. Returns a PNG image and public [image API](/docs/developers/image-api) URLs (SVG and PNG) ready for Markdown or HTML, plus the SVG markup on request. |
| `list_qr_styles` | Lists body patterns, corner eye and eye dot shapes, frame templates, error correction levels, defaults and limits. |
| `qr_payload_wifi` | Builds a `WIFI:` network payload (WPA, WEP or open, optionally hidden) with special characters escaped. |
| `qr_payload_vcard` | Builds a vCard 3.0 contact (RFC 2426): name, organization, title, phones, email, website, address and note. |
| `qr_payload_email` | Builds a `mailto:` link (RFC 6068) with optional cc, bcc, subject and body. |
| `qr_payload_sms` | Builds an `sms:` link (RFC 5724) with an optional message, or the older `SMSTO:` form. |
| `qr_payload_geo` | Builds a `geo:` location (RFC 5870) from latitude and longitude. |

The payload tools return a plain string. Your assistant then passes it as `data` to `generate_qr_code`.

### design_qr

`design_qr` takes the content as a type and its fields, the same types and checks as the editor's content forms (`list_options` lists them), and an optional style:

```json
{
  "content": { "type": "wifi", "ssid": "Cafe Guest", "password": "sunshine123", "encryption": "WPA" },
  "style": {
    "bgColor": "#FFF7ED",
    "fgColor": "#9A3412",
    "bodyPattern": "rounded",
    "cornerEyePattern": "rounded",
    "frame": { "style": "banner-bottom", "text": "Free Wi-Fi" }
  }
}
```

Options you leave out get defaults (eyes follow the dot colour, square shapes, margin 4, error correction Q, no frame). QRdx then runs the editor's scan check on the design: it renders the code, decodes it at 96, 160 and 320 px through a phone-camera model, and checks contrast, quiet zone, eye shapes and shape pairs. Below Great (85), it repairs the style, up to three times, changing as little as it can (darker colours that keep their hue, a safer eye shape, less error correction for long content). If that isn't enough, it falls back to a classic black-on-white code with your frame. The result says what was changed and why.

No AI model runs on QRdx's side for `design_qr`: your assistant picks the style, QRdx validates, checks and repairs it. Content that isn't valid (a WPA password under 8 characters, a malformed email address) is refused with the reason. Logos aren't available over MCP. `design_qr` has its own limit of 20 calls per minute per IP address.

Saving a design to a QRdx account isn't available over MCP. In the editor, the AI chat can save a design as a template to your themes.

### generate_qr_code inputs

The inputs match the [image API parameters](/docs/developers/image-api#parameters): `data` (required), `size`, `fg`, `bg`, `eyeColor`, `dotColor`, `body`, `eye`, `dot`, `level`, `margin` and `template`. Set `include_svg` to `true` to also get the SVG markup as text, for example to save an `.svg` file. It is off by default because the markup is often 50 to 150 KB, which would fill the conversation.

Like the image API, the MCP server renders solid colors only. It doesn't support logos or gradients.

## Privacy and limits

- The tools only render images, check designs and format text. They don't read or change any QRdx account data, and the server doesn't save the codes you generate.
- The image URLs that `generate_qr_code` returns contain the encoded data. Don't share them if the data is private, such as a Wi-Fi password.
- Requests are limited to 120 per minute per IP address, and `design_qr` to 20.

## Self-hosting and local development

The MCP server is part of the QRdx web app, so every instance serves it at `/api/mcp`:

- **Self-hosted.** When `NEXT_PUBLIC_APP_URL` is your own domain, the connect page, snippets and install links use `https://<your-domain>/api/mcp`.
- **Local development.** `pnpm dev` serves it at `http://localhost:3000/api/mcp`. The connect page still shows the public URL and offers the local one as a hint, so you can point a client at your machine to test changes to the server before they ship.

Opening `/api/mcp` in a browser redirects to the connect page. MCP clients never ask for HTML, so they reach the server as usual.
