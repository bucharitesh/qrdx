QRdx REST APIは `https://api.qrdx.dev/v1` で提供されています。JSONを使用し、キー不要の[Image API](/docs/developers/image-api)を除き、Bearer認証情報でリクエストを認証します。

```bash
curl https://api.qrdx.dev/v1/codes -H "Authorization: Bearer $QRDX_API_KEY"
```

- **[APIキー](/docs/developers/api-keys)**（`qrdx_…`）：ご自身のサーバーやスクリプト向けです。作成したワークスペースに対して、そのワークスペースでのあなたのロールで動作します。
- **OAuth 2.0アクセストークン**：他のQRdxユーザーに代わって動作するアプリ向けです（[後述](#get-an-access-token)）。トークンを使ったリクエストは、トークン所有者自身のワークスペースに対して動作します。

コード、コンバージョン、フックのエンドポイントは、QRdxにサインインしているユーザーのブラウザセッションでも利用できます。その場合のリクエストは、そのブラウザセッションで最後に開いた[ワークスペース](/docs/teams)に対して動作します。

同じエンドポイントは `https://qrdx.dev/api/v1` でも応答します。サインイン用のCookieはqrdx.devに属するため、ブラウザセッションのリクエストにはこのパスを使います。[セルフホスト](/docs/self-hosting)したインスタンスでは、自身のドメインの `/api/v1` でAPIが提供されます。

はじめての方は、[クイックスタート](/docs/developers/quickstart)で最初のリクエストまで進められます。各エンドポイントには専用のページがあり、リクエストとレスポンスのスキーマ、curl・JavaScript・Pythonのサンプル、Try itパネルを[APIリファレンス](/docs/developers/api)に用意しています。これは[OpenAPIドキュメント](/openapi.json)から生成されています。

[Playgroundで試す](/playground?open=code&lang=api)：Playgroundでコードをスタイル設定し、それを動的QRコードとして作成する `POST /v1/codes` リクエストをコピーできます。

## エンドポイント [#endpoints]

| エンドポイント | スコープ | 内容 |
| --- | --- | --- |
| `GET /v1/qr` | なし | エディタのスタイルを反映したQRコード画像（SVG、PNG、WebP、EPS）。[Image API](/docs/developers/image-api)を参照 |
| `GET /v1/community/items`, `GET /v1/community/items/{id}` | なし | 公開されているコミュニティのフレーム、テーマ、コレクションと、それぞれが適用するスタイル。読み取り専用でキャッシュされます。[コミュニティアイテム](#community-items)を参照 |
| `/v1/codes` | `codes:read`, `codes:write` | 動的QRコードの一覧表示、作成（1件、または一度に最大{facts.apiBatchCodes}件。`slug` で任意のカスタムバックハーフを指定可能）、更新（`kind` をウェブサイトのリンクとホスト型ページの間で切り替える操作を含む）、削除。[動的QRコード](/docs/dynamic-qr-codes#rest-api)を参照 |
| `GET /v1/codes/{id}/scans` | `codes:read` | コードのスキャン分析、または個々のスキャンをページ単位で取得 |
| `POST /v1/conversions` | `codes:write` | 売上やサインアップを、その起点となったスキャンに紐付けます（Business）。[トラッキングとコンバージョン](/docs/tracking-and-conversions)を参照 |
| `/v1/hooks` | `codes:read`, `codes:write` | REST Hooks方式でURLをイベントに購読登録します。Zapier、Make、n8n向けです。[Webhook](/docs/webhooks)を参照 |
| `GET /v1/themes`, `GET /v1/themes/{id}` | `themes:read` | OAuthトークンでは、保存したQRテーマ（名前とスタイル）を取得します。APIキーでは、そのワークスペースのテーマを取得します |
| `GET /v1/me` | `profile:read` | キーの作成者またはトークンのユーザーのID、名前、メールアドレス、アバター |

`codes:write` には、`codes:read` でできることがすべて含まれます。

### コミュニティアイテム [#community-items]

`GET /v1/community/items` は、公開されている[コミュニティ](/community)のアイテムを、人気順に一覧表示します。CC0で自由に利用できます。`type`（`frame`、`theme`、`collection`）、`q`（名前、説明、タグ、作成者のすべてに含まれる必要がある語）、`tag` で絞り込めます。ページ送りには `limit`（最大50）と `offset` を使います。`GET /v1/community/items/{id}` は1件のアイテムを返し、`style` には、保存済みテーマと同じJSON形式で、適用されるデザインが含まれます。IDは種類とスラッグを組み合わせたもの（例：`frame:wifi-card`）で、Image APIには[`item`](/docs/developers/image-api#community-items)として渡します。

```bash
curl "https://api.qrdx.dev/v1/community/items?type=frame&q=wifi"
```

どちらもキー不要で、クォータを消費しません。レスポンスは1分間キャッシュされ（CDNでは5分）、IPアドレスごとに1分あたり120リクエストに制限されます。アイテムのテキストはコミュニティのメンバーが書いたものです。名前、説明、ハンドル、タグは短く、リンクなしで返されますが、指示ではなくデータとして扱ってください。

### コードのスタイル内のロゴ [#code-logos]

エディタが保存する画像データURLのほかに、コードの `style` では `logoIcon` を指定できます。エディタのクイックアイコン（`wifi`、`location`、`phone`、`email`、`link`、`file`、`calendar`、`whatsapp`、`instagram`）のいずれか、または[Simple Icons](https://simpleicons.org)のスラッグによるブランドロゴです。ブランドロゴには `:black` または `:white` を付けることもできます（`spotify`、`paypal:white`）。これはエディタでの保存時と同様に `customLogo` に保存されます。

<IfAvailable feature="fileStorage">
`logoFileId` も指定できます。これは[ダッシュボード → ファイル](/docs/files)でワークスペースにアップロードしたPNGまたはJPEGを、ファイルIDで指定するものです。ファイルのリンクとして保存されます。
</IfAvailable>

他のサイトを指す `customLogo` のリンクは、QRdxが他のサイトからロゴを取得しないため、`400` で拒否されます。`PATCH` では、コードにすでに設定されているロゴをそのまま送り返しても構いません。

## アクセストークンを取得する [#get-an-access-token]

ご自身のスクリプトには、[APIキー](/docs/developers/api-keys)のほうが簡単です。アプリが他のユーザーに代わって動作する場合、QRdxはOAuth 2.0プロバイダーとして機能します。アプリがユーザーをQRdxへ誘導してサインインさせ、付与されたスコープで許可された操作のみ可能なアクセストークンを受け取ります。APIキーも同じスコープを使います。

| スコープ | 許可される操作 |
| --- | --- |
| `profile:read` | ユーザーの名前、メールアドレス、アバターの読み取り |
| `themes:read` | ユーザーが保存したQRテーマの読み取り |
| `codes:read` | 動的コードとそのスキャン分析の読み取り |
| `codes:write` | 動的コードの作成、編集、削除、コンバージョンの報告、Webhook購読の管理 |

### 1. アプリを登録する [#1-register-an-app]

[設定 → APIキーとアプリ](/dashboard?to=settings/developers)でOAuthアプリを自分で作成します。名前、リダイレクトURI、必要なスコープを指定すると、クライアントIDとクライアントシークレットが発行されます。シークレットは一度だけ表示されるので、サーバー上で安全に保管してください。フリーのワークスペースでは1個、Proでは5個、Businessでは25個のアプリを作成できます。アプリの作成から連携ディレクトリへの掲載まで、一連の流れは[連携を構築する](/docs/developers/build-an-integration)で説明しています。

[セルフホスト](/docs/self-hosting)したインスタンスでは、`apps/docs` からファーストパーティのアプリを作成することもできます。

```bash
bun x tsx scripts/create-oauth-app.ts \
  --name "My app" \
  --redirect-uris "https://myapp.example/callback" \
  --scopes "codes:read,codes:write"
```

### 2. ユーザーをQRdxへ誘導する [#2-send-the-user-to-qrdx]

```txt
https://qrdx.dev/api/oauth/authorize
  ?response_type=code
  &client_id=<client id>
  &redirect_uri=https://myapp.example/callback
  &scope=codes:read codes:write
  &state=<random value>
  &code_challenge=<PKCE challenge>
  &code_challenge_method=S256
```

`redirect_uri` は登録済みのURLと完全に一致する必要があり、`scope`（スペースまたはカンマ区切り）にはアプリのスコープのみを指定できます。PKCEは推奨で、**Require PKCE** を有効にしたアプリでは必須です。使えるメソッドは `S256` のみで、`plain` のチャレンジは `invalid_request` になります。ユーザーは必要に応じてサインインし、QRdxの同意画面でアプリを承認します。同意画面にはアプリの名前、ロゴ、ウェブサイト、開発者、要求された権限が表示され、本人であることを確認します。その後QRdxは、`code` と `state` を付けて `redirect_uri` にリダイレクトします。キャンセルされた場合は `error=access_denied` が付きます。コードの有効期間は10分で、1回のみ使用できます。

### 3. コードをトークンに交換する [#3-exchange-the-code-for-tokens]

```bash
curl -X POST https://qrdx.dev/api/oauth/token \
  -d grant_type=authorization_code \
  -d client_id=$CLIENT_ID \
  -d client_secret=$CLIENT_SECRET \
  -d code=$CODE \
  -d redirect_uri=https://myapp.example/callback \
  -d code_verifier=$CODE_VERIFIER
```

```json
{
  "access_token": "...",
  "token_type": "Bearer",
  "expires_in": 3600,
  "refresh_token": "...",
  "scope": "codes:read codes:write"
}
```

トークンエンドポイントは、フォームエンコードされた本文を受け付けます。アクセストークンの有効期間は1時間、リフレッシュトークンは30日です。

### 4. 更新と取り消し [#4-refresh-and-revoke]

```bash
# New access and refresh tokens; the old refresh token stops working
curl -X POST https://qrdx.dev/api/oauth/token \
  -d grant_type=refresh_token \
  -d client_id=$CLIENT_ID \
  -d client_secret=$CLIENT_SECRET \
  -d refresh_token=$REFRESH_TOKEN

# Revoke an access or refresh token
curl -X POST https://qrdx.dev/api/oauth/revoke -d token=$TOKEN
```

`GET /api/oauth/userinfo` は、`profile:read` を持つトークンに対して、ユーザー情報を `sub`、`name`、`email`、`picture` として返します。

ユーザーは **設定 → 承認済みアプリ** で、アプリのアクセス権を自分で取り消せます。取り消されると、そのアカウントに対するアプリのトークンは `invalid_token`（API呼び出し）や `invalid_grant`（更新）で失敗し、アプリは改めて許可を求める必要があります。

## エラーと制限 [#errors-and-limits]

すべての `/v1` エンドポイントは、エラーを `{ "code": "...", "message": "...", "status": 400 }` の形式で返します。修正方法を説明するページがある場合は `docs` リンクも含まれます。すべてのコードと修正方法は[エラーのページ](/docs/developers/errors)にまとめています。存在しないパスには `404 NOT_FOUND` が返ります。`/v1/me` と `/v1/themes` には、従来から送っている OAuth のフィールド `"error": "invalid_token"` と `"error_description"` も含まれます。OAuth エンドポイント(`/api/oauth/*`)では OAuth 形式のみを使います。

1 回のリクエストで複数のコードを作成する、コードの `slug` を指定する、コードをカスタムドメインに移すには、Pro または Business が必要です(それ以外では `402 PLAN_REQUIRED` になります)。スキャンが制限されることはありません。

### レート制限 [#rate-limits]

制限は 2 種類あります。どちらも `429 RATE_LIMITED` を返し、待機する秒数を示す `Retry-After` ヘッダーが付きます。

- **1 日あたりのクォータ。** ワークスペースが 1 日に行える API リクエストは、フリーで 1,000 件、Pro で 10,000 件、Business で 100,000 件です([プランと制限](/docs/plans-and-limits)を参照)。1 日は UTC の 00:00 から 24:00 までです。認証済みのリクエストはすべてカウントされます。API キーによるリクエストは、キーのワークスペースとそのプランに対してカウントされます。アクセストークンによるリクエストは、トークンの所有者自身のワークスペースに対してカウントされます。ブラウザーセッションによるリクエストは、そのセッションで最後に開いたワークスペースに対してカウントされます。
- **1 分あたりの制限。** codes、conversions、hooks の各エンドポイントでは、ユーザーごとに 1 分あたり読み取り 120 件、書き込み 30 件、IP アドレスごとに 1 分あたり 300 件まで許可されます。

1 日のクォータの確認より前に拒否されたリクエストはカウントされません。無効なキーまたはトークン(`401`)、必要なスコープがないもの(`403`)、1 分あたりの制限による `429` が該当します。カウントされるリクエストへのレスポンスには、成功時もエラー時も、1 日のクォータを示す 3 つのヘッダーが付きます。

| ヘッダー | 値 |
| --- | --- |
| `X-RateLimit-Limit` | ワークスペースのプランでの 1 日あたりのリクエスト数 |
| `X-RateLimit-Remaining` | 本日の残りリクエスト数 |
| `X-RateLimit-Reset` | カウントがリセットされる時刻(次の UTC 00:00)、Unix 秒 |

`X-RateLimit-*` ヘッダーは常に 1 日のクォータを表します。1 分あたりの制限による `429` には `Retry-After` ヘッダーのみが付きます。1 日のクォータを超えると、次のレスポンスになります。

```http
HTTP/1.1 429 Too Many Requests
Retry-After: 43200
X-RateLimit-Limit: 1000
X-RateLimit-Remaining: 0
X-RateLimit-Reset: 1793577600
```

```json
{
  "code": "RATE_LIMITED",
  "message": "Daily API limit reached: the Free plan allows 1,000 requests a day. It resets at 00:00 UTC. Upgrade your plan for a higher limit.",
  "status": 429
}
```

`/v1/me` と `/v1/themes` も同じヘッダーと本文を送り、さらに `"error": "rate_limited"` と `"error_description"` を含みます。

[Image API](/docs/developers/image-api)、[MCP サーバー](/docs/developers/mcp)、ブラウザーから `qrdx_sid` 付きで報告されるコンバージョンにはトークンが不要なので、1 日のクォータは使用しません。これらには独自の IP ごとの制限があります。[セルフホスト](/docs/self-hosting)したインスタンスでは、Upstash Redis を設定した場合にのみレート制限が適用されます。
