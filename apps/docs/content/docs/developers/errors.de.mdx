Jeder Fehler der REST API ist JSON mit derselben Struktur, egal welcher Endpunkt ihn zurückgibt:

```json
{
  "code": "INSUFFICIENT_SCOPE",
  "message": "This API key needs the 'codes:write' scope. Create a key that includes it at https://qrdx.dev/dashboard?to=settings/developers; a key's scopes can't be changed.",
  "status": 403,
  "docs": "https://qrdx.dev/docs/developers/api-keys"
}
```

| Feld | Bedeutung |
| --- | --- |
| `code` | Ein stabiler, maschinenlesbarer Code aus der Tabelle unten. Verzweige anhand dieses Felds. |
| `message` | Was schiefgelaufen ist und wie du es behebst, für Menschen geschrieben. Der Wortlaut kann sich ändern. |
| `status` | Der HTTP-Status, wiederholt. |
| `docs` | Eine Seite, die die Lösung erklärt, falls es eine gibt. |
| `data` | Zusätzliche Details bei manchen Fehlern. `VALIDATION_ERROR` listet jedes Problem in `data.details` auf. |

Ein Validierungsfehler nennt jedes Feld, das fehlgeschlagen ist:

```json
{
  "code": "VALIDATION_ERROR",
  "message": "Invalid request body",
  "status": 400,
  "data": {
    "details": [
      { "path": "destinationUrl", "message": "Enter a full URL, starting with https://" }
    ]
  }
}
```

Die Image API meldet Query-Parameter als `{ "param", "message" }` statt als `{ "path", "message" }`.

## Fehlercodes [#error-codes]

| Status | Code | Bedeutung | Lösung |
| --- | --- | --- | --- |
| 400 | `VALIDATION_ERROR` | Body, Query oder Pfad haben die Validierung nicht bestanden. `data.details` listet jedes Problem als `{ path, message }` auf (bei der Image API als `{ param, message }`). Ist der Body ein Array von Codes, steht zusätzlich der `index` der Zeile dabei. | Korrigiere die Felder in `data.details` und sende die Anfrage erneut. |
| 400 | `INVALID_SLUG` | Der benutzerdefinierte Back-Half (`slug`) verstößt gegen eine Regel: Es ist ein reserviertes Wort, oder derselbe Back-Half kommt in einer Anfrage zweimal vor. Bei einem Array listet `data.details` jede Zeile mit `index` auf. | Wähle einen anderen Back-Half. Die Meldung nennt die Regel. |
| 400 | `TOO_MANY_CODES` | Mehr als 1.000 Codes in einer Anfrage. Normalerweise lehnt das Body-Schema das zuerst ab, und zwar als `VALIDATION_ERROR`. | Sende höchstens 1.000 Codes pro Anfrage. |
| 400 | `DOMAIN_NOT_VERIFIED` | `domainId` verweist auf eine eigene Domain, die noch nicht verifiziert ist. | Schließe die Verifizierung der Domain auf der Seite „Domains" ab oder lass `domainId` weg. |
| 400 | `SID_REQUIRED` | Eine Conversion ohne die `qrdx_sid` des Scans (aus dem Browser) oder ohne `sid` bzw. `code` (von einem Server). | Sende die `qrdx_sid`, die der Kurzlink an deine Seiten-URL angehängt hat, oder sende mit einem API-Schlüssel oder Token die Code-ID als `code`. |
| 400 | `AI_ART_TEXT_TOO_LONG` | `text` ist zu lang für KI-Art (mehr als 300 Zeichen). | Sende stattdessen die ID eines dynamischen Codes als `code`: Die Art kodiert dessen Kurzlink, der kurz und weiterhin bearbeitbar ist. |
| 401 | `UNAUTHORIZED` | Keine Zugangsdaten: Die Anfrage hat keinen `Authorization: Bearer`-Header (und keine QRdx-Browser-Sitzung). | Sende einen API-Schlüssel als `Authorization: Bearer <key>`. Du erstellst ihn unter Einstellungen → API-Schlüssel & Apps. OAuth-Zugriffstokens kommen in denselben Header. |
| 401 | `INVALID_TOKEN` | Der API-Schlüssel oder das Zugriffstoken ist unbekannt, widerrufen oder abgelaufen (Zugriffstokens gelten eine Stunde), oder die Person, die den Schlüssel erstellt hat, wurde gesperrt oder hat den Workspace des Schlüssels verlassen. | Prüfe, ob du den ganzen Schlüssel gesendet hast, oder erstelle einen neuen. Hol dir für ein Zugriffstoken mit deinem Refresh-Token ein neues oder schick die Nutzer erneut durch die Autorisierung. |
| 402 | `PLAN_REQUIRED` | Die Funktion ist im Tarif des Workspace nicht enthalten: Massenerstellung, benutzerdefinierte Back-Halves und eigene Domains brauchen Pro, Conversions und Hooks brauchen Business. | Upgrade den Workspace oder lass die Funktion in der Anfrage weg. |
| 402 | `LIMIT_REACHED` | Der Workspace hat so viele aktive dynamische QR-Codes, wie sein Tarif enthält (10 bei Kostenlos). | Archiviere einen Code (archivierte Codes zählen nicht mit) oder wechsle zu Pro für unbegrenzt viele Codes. |
| 402 | `AI_ART_CREDITS_EXHAUSTED` | Der Workspace hat die KI-Art-Bilder dieses Monats aufgebraucht (Kostenlos und Pro). Für die Anfrage wurde nichts berechnet. | Warte, bis sich das Kontingent am 1. des Monats (UTC) zurücksetzt, oder upgrade für mehr Bilder. |
| 403 | `INSUFFICIENT_SCOPE` | Der API-Schlüssel oder das Token ist gültig, hat aber nicht den Scope, den dieser Endpoint braucht. | Erstelle einen Schlüssel mit dem Scope aus der Meldung (die Scopes eines Schlüssels lassen sich nicht ändern). Füge bei einer OAuth-App den Scope hinzu und fordere ihn an, wenn die Nutzer autorisieren. |
| 403 | `FORBIDDEN` | Der Aufrufer darf das nicht tun: ein Workspace-Mitglied löscht einen Code, den jemand anderes erstellt hat, ein Mitglied verwaltet Hooks oder ein Schreibzugriff über eine Browser-Sitzung kommt von einer anderen Website. Ein API-Schlüssel darf nur das, was die Rolle seines Erstellers im Workspace erlaubt. | Frag einen Owner oder Admin des Workspace oder rufe die API von deinem Server aus mit einem API-Schlüssel auf. |
| 403 | `CONFIRMATION_REQUIRED` | Zum Erstellen eines Hooks mit einer angemeldeten Browser-Sitzung ist eine kürzlich erfolgte Bestätigung „Du bist es" nötig. API-Schlüssel und OAuth-Tokens werden nicht danach gefragt. | Bestätige in QRdx, dass du es bist, und versuche es innerhalb von 10 Minuten erneut, oder erstelle den Hook mit einem API-Schlüssel von deinem Server aus. |
| 403 | `CONVERSIONS_OFF` | Eine Browser-Conversion für einen Code, bei dem das Conversion-Tracking nicht aktiviert ist. | Aktiviere das Conversion-Tracking für den Code oder melde die Conversion mit einem API-Schlüssel von deinem Server aus. |
| 403 | `LIMIT_REACHED` | Der Workspace hat bereits 20 Webhook-Endpoints und Hooks. | Lösche einen Endpoint oder Hook, den du nicht mehr brauchst. |
| 404 | `NOT_FOUND` | Es gibt keinen solchen Endpoint, oder der Code, Hook, das Theme oder die eigene Domain existiert nicht in dem Workspace, in dem der Schlüssel oder das Token handelt. | Prüfe Pfad und ID. Ein API-Schlüssel handelt im Workspace, in dem er erstellt wurde. Ein OAuth-Token handelt im eigenen Workspace seines Nutzers. |
| 404 | `INVALID_SID` | Die `qrdx_sid` ist unbekannt oder älter als 30 Tage, das Attributionsfenster. | Sende die `qrdx_sid` eines aktuellen Scans oder melde die Conversion von deinem Server aus per Code-ID. |
| 409 | `SLUG_TAKEN` | Ein anderer Code verwendet diesen Back-Half bereits auf dieser Domain. Bei einem Array listet `data.details` jeden vergebenen per `index` auf, und es wird nichts erstellt. | Wähle einen anderen Back-Half. |
| 413 | `PAYLOAD_TOO_LARGE` | Der Body überschreitet das Limit des Endpoints: 4 MB für Codes, 16 KB für Hooks, 8 KB für Conversions. Gilt auch für einen Batch von Codes, dessen Antwort (jeder Code mit seinem Design) über 4 MB läge. Es wird nichts erstellt. | Sende einen kleineren Body. Bei Codes ist meist ein großes Inline-Logo die Ursache. Bei einem Batch sende `Prefer: return=minimal` oder weniger Codes. |
| 413 | `AI_ART_IMAGE_TOO_LARGE` | Das Bild `photo` oder `reference` überschreitet das Größenlimit für KI-Art (die Meldung nennt, welches). | Verkleinere das Bild (eine `reference` auf etwa 512 px an der längsten Seite, ein `photo` auf etwa 1024 px im Quadrat) und sende es erneut als PNG- oder JPEG-Data-URL. |
| 415 | `UNSUPPORTED_MEDIA_TYPE` | Ein Schreibzugriff ohne `Content-Type: application/json`. | Sende einen JSON-Body mit `Content-Type: application/json`. |
| 422 | `UNSAFE_DESTINATION` | Google Web Risk markiert die Ziel-URL (Malware, Phishing oder unerwünschte Software). Bei einem Array listet `data.details` jede markierte Zeile per `index` auf, und es wird nichts erstellt. | Verwende ein anderes Ziel. Wenn die Markierung falsch ist, bitte Google, die Website zu prüfen. |
| 429 | `RATE_LIMITED` | Zu viele Anfragen: ein Limit pro Minute (nur `Retry-After` ist gesetzt) oder das Tageskontingent des Workspace (`Retry-After` plus `X-RateLimit-*`). | Warte `Retry-After` Sekunden. Beim Tageskontingent warte bis 00:00 UTC oder wechsle den Tarif. |
| 429 | `AI_ART_CREDITS_EXHAUSTED` | Ein Business-Workspace hat die KI-Art-Bilder dieses Monats aufgebraucht, die sich das ganze Team teilt. | Warte, bis sich das Kontingent am 1. des Monats (UTC) zurücksetzt. |
| 429 | `AI_ART_DAILY_LIMIT` | Der Ersteller des Schlüssels hat heute (UTC) 25 KI-Art-Bilder erzeugt. Das ist eine Sicherheitsgrenze zusätzlich zum Monatskontingent. | Versuche es morgen (UTC) erneut. |
| 500 | `INTERNAL_ERROR` | Auf Seiten von QRdx ist etwas fehlgeschlagen. Der Fehler wurde protokolliert. | Versuche es gleich noch einmal. Tritt der Fehler weiterhin auf, melde ihn mit dem Zeitpunkt der Anfrage. |
| 502 | `AI_ART_FAILED` | Das Bildmodell ist fehlgeschlagen, hat den Prompt abgelehnt oder ein Bild geliefert, das QRdx nicht lesen konnte. Es wurde kein KI-Art-Guthaben verbraucht. | Versuche es erneut oder formuliere den Prompt um. Die Meldung sagt, was passiert ist. |
| 502 | `AI_ART_UNSCANNABLE` | Das Bild des Modells ließ sich mit der gewählten QR-Sichtbarkeit nicht scanbar machen. Es wurde kein KI-Art-Guthaben verbraucht. | Versuche es mit einer höheren `visibility` oder einem anderen Seed erneut. |
| 502 | `AI_ART_DESCRIBE_FAILED` | Du hast `prompt` weggelassen, und das Textmodell, das einen für dich schreibt, ist fehlgeschlagen. Es wurde kein KI-Art-Guthaben verbraucht. | Versuche es erneut oder sende deinen eigenen `prompt`. |
| 503 | `SLUG_UNAVAILABLE` | Es konnte nicht rechtzeitig ein freier Kurzlink-Slug reserviert werden. | Sende dieselbe Anfrage noch einmal. |
| 503 | `AI_ART_BUSY` | Das Bildmodell ist gerade überlastet. Es wurde kein KI-Art-Guthaben verbraucht. | Warte eine Minute und versuche es erneut. |
| 503 | `AI_NOT_CONFIGURED` | KI-Art ist in dieser Bereitstellung nicht eingerichtet (eine selbst gehostete Instanz ohne `AI_GATEWAY_API_KEY`). | Nutze die gehostete QRdx API oder richte Vercel AI Gateway auf deiner Instanz ein. |
| 503 | `UNAVAILABLE` | Eigene Domains sind in dieser Bereitstellung nicht eingerichtet (eine selbst gehostete Instanz ohne sie). | Lass `domainId` weg oder konfiguriere eigene Domains auf deiner Instanz. |
| 504 | `AI_ART_TIMEOUT` | Das Bildmodell hat zu lange gebraucht, und QRdx hat vor dem Ein-Minuten-Limit der Anfrage aufgehört zu warten. Es wurde kein KI-Art-Guthaben verbraucht. | Versuche es erneut. Aufrufe dauern meist 15 bis 45 Sekunden. |

## Wiederholungen [#retrying]

- **`429`:** Warte die Anzahl an Sekunden aus `Retry-After` und sende dann dieselbe Anfrage erneut. Wenn das Tageskontingent aufgebraucht ist, zeigen die `X-RateLimit-*`-Header, wie viele Anfragen dein Plan erlaubt und wann der Zähler zurückgesetzt wird (00:00 UTC). Siehe [Rate Limits](/docs/developers/rest-api#rate-limits).
- **`500` und `503`:** Versuche es mit exponentiellem Backoff erneut, beginnend bei etwa einer Sekunde.
- **Andere `4xx`:** Dieselbe Anfrage schlägt immer auf dieselbe Weise fehl. Behebe zuerst den Fehler.

Das Erstellen von Codes ist nicht idempotent: Wenn bei einem `POST /v1/codes` ein Timeout auftritt, liste deine Codes auf, bevor du die Anfrage erneut sendest. Sonst erstellst du den Code möglicherweise zweimal. Konvertierungen sind idempotent: Sende deine eigene `id`, und eine Wiederholung liefert `200` mit `duplicate: true`.

## `/v1/me` und `/v1/themes` [#v1me-and-v1themes]

Diese beiden Endpunkte senden denselben Body plus die OAuth-Felder, die sie schon immer gesendet haben, `error` und `error_description` (derselbe Text wie `message`), damit ältere Clients weiter funktionieren:

| `error` | `code` |
| --- | --- |
| `invalid_token` | UNAUTHORIZED oder INVALID_TOKEN |
| `insufficient_scope` | INSUFFICIENT_SCOPE |
| `rate_limited` | RATE_LIMITED (Tageskontingent) |
| `not_found` | NOT_FOUND (Themes) |

## OAuth-Endpunkte [#oauth-endpoints]

Die OAuth-Endpunkte unter `https://qrdx.dev/api/oauth` (authorize, token, revoke, userinfo) folgen stattdessen dem OAuth-2.0-Standard: `{ "error", "error_description" }`, wobei `error` einer der Werte `invalid_request`, `invalid_client`, `invalid_grant`, `unsupported_grant_type`, `invalid_token` oder `access_denied` ist. Wenn du bei einem Refresh `invalid_grant` erhältst, wurde das Refresh-Token bereits verwendet (jeder Refresh liefert ein neues), ist nach 30 Tagen abgelaufen oder der Nutzer hat den Zugriff deiner App widerrufen: Schicke den Nutzer erneut durch die Autorisierung. Siehe [REST API und OAuth](/docs/developers/rest-api#get-an-access-token).

## Unbekannte Endpunkte [#unknown-endpoints]

Ein nicht vorhandener Pfad unter `/v1` liefert `404 NOT_FOUND` als JSON, nie eine HTML-Seite. Die [API-Referenz](/docs/developers/api) listet jeden Endpunkt auf.
