Setiap kesalahan REST API berupa JSON dengan bentuk yang sama, apa pun endpoint yang mengembalikannya:

```json
{
  "code": "INSUFFICIENT_SCOPE",
  "message": "This API key needs the 'codes:write' scope. Create a key that includes it at https://qrdx.dev/dashboard?to=settings/developers; a key's scopes can't be changed.",
  "status": 403,
  "docs": "https://qrdx.dev/docs/developers/api-keys"
}
```

| Kolom | Keterangan |
| --- | --- |
| `code` | Kode stabil yang dapat dibaca mesin dari tabel di bawah. Gunakan kode ini untuk percabangan logika. |
| `message` | Penjelasan untuk manusia tentang apa yang salah dan cara memperbaikinya. Kalimatnya dapat berubah. |
| `status` | Status HTTP, diulang di sini. |
| `docs` | Halaman yang menjelaskan cara memperbaikinya, jika ada. |
| `data` | Rincian tambahan pada beberapa kesalahan. `VALIDATION_ERROR` mencantumkan setiap masalah di `data.details`. |

Kesalahan validasi menyebutkan setiap kolom yang gagal:

```json
{
  "code": "VALIDATION_ERROR",
  "message": "Invalid request body",
  "status": 400,
  "data": {
    "details": [
      { "path": "destinationUrl", "message": "Enter a full URL, starting with https://" }
    ]
  }
}
```

Image API melaporkan parameter kueri sebagai `{ "param", "message" }`, bukan `{ "path", "message" }`.

## Kode kesalahan [#error-codes]

| Status | Kode | Arti | Perbaikan |
| --- | --- | --- | --- |
| 400 | `VALIDATION_ERROR` | Isi permintaan, kueri, atau path gagal validasi. `data.details` mencantumkan setiap masalah sebagai `{ path, message }` (`{ param, message }` pada Image API), dengan `index` baris tersebut jika isi permintaan berupa larik kode. | Perbaiki kolom yang tercantum di `data.details`, lalu kirim permintaan lagi. |
| 400 | `INVALID_SLUG` | Back-half kustom (`slug`) melanggar aturan: kata yang dicadangkan, atau back-half yang sama dua kali dalam satu permintaan. Untuk larik, `data.details` mencantumkan setiap baris berdasarkan `index`. | Pilih back-half lain. Pesan kesalahan menyebutkan aturannya. |
| 400 | `TOO_MANY_CODES` | Lebih dari 1.000 kode dalam satu permintaan. Skema isi permintaan biasanya menolaknya lebih dulu sebagai `VALIDATION_ERROR`. | Kirim paling banyak 1.000 kode per permintaan. |
| 400 | `DOMAIN_NOT_VERIFIED` | `domainId` mengarah ke domain kustom yang belum terverifikasi. | Selesaikan verifikasi domain di halaman Domain, atau hapus `domainId`. |
| 400 | `SID_REQUIRED` | Konversi tanpa `qrdx_sid` dari pemindaian (dari browser), atau tanpa `sid` maupun `code` (dari server). | Kirim `qrdx_sid` yang ditambahkan tautan pendek ke URL halaman Anda, atau, dengan kunci API atau token, kirim id kode sebagai `code`. |
| 401 | `UNAUTHORIZED` | Tanpa kredensial: permintaan tidak memiliki header `Authorization: Bearer` (dan tidak ada sesi browser QRdx). | Kirim kunci API sebagai `Authorization: Bearer <key>`; buat kunci di Pengaturan → Kunci API & aplikasi. Token akses OAuth dikirim di header yang sama. |
| 401 | `INVALID_TOKEN` | Kunci API atau token akses tidak dikenal, dicabut, atau kedaluwarsa (token akses berlaku satu jam), atau pembuat kunci diblokir atau keluar dari workspace kunci tersebut. | Pastikan Anda mengirim seluruh kunci, atau buat yang baru. Untuk token akses, dapatkan yang baru dengan token refresh Anda, atau arahkan pengguna melalui otorisasi lagi. |
| 402 | `PLAN_REQUIRED` | Fitur tidak tersedia di paket workspace: pembuatan massal, back-half kustom, dan domain kustom memerlukan Pro; konversi dan hook memerlukan Business. | Tingkatkan paket workspace, atau hapus fitur tersebut dari permintaan. |
| 402 | `LIMIT_REACHED` | Workspace sudah memiliki kode dinamis aktif sebanyak yang disertakan paketnya (10 pada Gratis). | Arsipkan sebuah kode (kode yang diarsipkan tidak dihitung) atau tingkatkan ke Pro untuk kode tanpa batas. |
| 403 | `INSUFFICIENT_SCOPE` | Kunci API atau token valid tetapi tidak memiliki scope yang dibutuhkan endpoint ini. | Buat kunci dengan scope yang disebutkan di pesan (scope kunci tidak dapat diubah). Untuk aplikasi OAuth, tambahkan scope dan minta saat pengguna memberi otorisasi. |
| 403 | `FORBIDDEN` | Pemanggil tidak diizinkan melakukan ini: anggota workspace menghapus kode yang dibuat orang lain, anggota mengelola hook, atau penulisan sesi browser dari situs lain. Kunci API hanya dapat melakukan apa yang diizinkan oleh peran pembuatnya di workspace tersebut. | Minta pemilik atau admin workspace, atau panggil API dengan kunci API dari server Anda. |
| 403 | `CONFIRMATION_REQUIRED` | Membuat hook dengan sesi browser yang sedang masuk memerlukan "Konfirmasi bahwa ini Anda" yang baru. Kunci API dan token OAuth tidak dimintai. | Konfirmasi bahwa ini Anda di QRdx, lalu coba lagi dalam 10 menit, atau buat hook dengan kunci API dari server Anda. |
| 403 | `CONVERSIONS_OFF` | Konversi browser untuk kode yang pelacakan konversinya tidak diaktifkan. | Aktifkan pelacakan konversi untuk kode tersebut, atau laporkan konversi dari server Anda dengan kunci API. |
| 403 | `LIMIT_REACHED` | Workspace sudah memiliki 20 endpoint webhook dan hook. | Hapus endpoint atau hook yang tidak lagi Anda gunakan. |
| 404 | `NOT_FOUND` | Endpoint tidak ada, atau kode, hook, tema, atau domain kustom tidak ada di workspace tempat kunci atau token bertindak. | Periksa path dan id. Kunci API bertindak di workspace tempat kunci itu dibuat; token OAuth bertindak di workspace milik penggunanya. |
| 404 | `INVALID_SID` | `qrdx_sid` tidak dikenal atau lebih lama dari 30 hari, yaitu jendela atribusi. | Kirim `qrdx_sid` dari pemindaian terbaru, atau laporkan konversi berdasarkan id kode dari server Anda. |
| 409 | `SLUG_TAKEN` | Kode lain sudah memakai back-half itu di domain tersebut. Untuk larik, `data.details` mencantumkan setiap back-half yang sudah dipakai berdasarkan `index`, dan tidak ada yang dibuat. | Pilih back-half lain. |
| 413 | `PAYLOAD_TOO_LARGE` | Isi permintaan melebihi batas endpoint: 4 MB untuk kode, 16 KB untuk hook, 8 KB untuk konversi. Juga untuk kumpulan kode yang responsnya (setiap kode beserta desainnya) akan melebihi 4 MB; tidak ada yang dibuat. | Kirim isi permintaan yang lebih kecil. Untuk kode, penyebab yang umum adalah logo inline yang besar; untuk kumpulan kode, kirim `Prefer: return=minimal` atau kurangi jumlah kodenya. |
| 415 | `UNSUPPORTED_MEDIA_TYPE` | Permintaan tulis tanpa `Content-Type: application/json`. | Kirim isi JSON dengan `Content-Type: application/json`. |
| 422 | `UNSAFE_DESTINATION` | Google Web Risk menandai URL tujuan (malware, phishing, atau perangkat lunak yang tidak diinginkan). Untuk larik, `data.details` mencantumkan setiap baris yang ditandai berdasarkan `index`, dan tidak ada yang dibuat. | Gunakan tujuan lain. Jika penandaan itu keliru, minta Google meninjau situs tersebut. |
| 429 | `RATE_LIMITED` | Terlalu banyak permintaan: batas per menit (hanya `Retry-After` yang diatur) atau kuota harian workspace (`Retry-After` ditambah `X-RateLimit-*`). | Tunggu selama `Retry-After` detik. Untuk kuota harian, tunggu hingga 00:00 UTC atau tingkatkan paket. |
| 500 | `INTERNAL_ERROR` | Terjadi kegagalan di sisi QRdx. Kesalahan ini sudah dicatat. | Coba lagi sebentar lagi. Jika terus terjadi, laporkan dengan waktu permintaan. |
| 503 | `SLUG_UNAVAILABLE` | Tidak ada slug tautan pendek yang bebas yang dapat dicadangkan tepat waktu. | Kirim permintaan yang sama lagi. |
| 503 | `UNAVAILABLE` | Domain kustom tidak disiapkan pada deployment ini (instans self-hosted tanpa domain kustom). | Hapus `domainId`, atau konfigurasikan domain kustom di instans Anda. |

## Mencoba ulang [#retrying]

- **`429`:** tunggu selama jumlah detik di `Retry-After`, lalu kirim permintaan yang sama. Saat kuota harian habis, header `X-RateLimit-*` menunjukkan berapa banyak permintaan yang diizinkan paket dan kapan hitungan diatur ulang (00:00 UTC). Lihat [batas laju](/docs/developers/rest-api#rate-limits).
- **`500` dan `503`:** coba ulang dengan exponential backoff, mulai dari sekitar satu detik.
- **`4xx` lainnya:** permintaan yang sama akan gagal dengan cara yang sama. Perbaiki dulu.

Pembuatan kode tidak idempoten: jika `POST /v1/codes` mengalami batas waktu, lihat daftar kode Anda sebelum mengirimnya lagi, atau kode bisa terbuat dua kali. Konversi bersifat idempoten: kirim `id` Anda sendiri dan pengulangan akan mengembalikan `200` dengan `duplicate: true`.

## `/v1/me` dan `/v1/themes` [#v1me-and-v1themes]

Kedua endpoint ini mengirim isi yang sama ditambah kolom OAuth yang selama ini mereka kirim, `error` dan `error_description` (teksnya sama dengan `message`), sehingga klien lama tetap berfungsi:

| `error` | `code` |
| --- | --- |
| `invalid_token` | UNAUTHORIZED atau INVALID_TOKEN |
| `insufficient_scope` | INSUFFICIENT_SCOPE |
| `rate_limited` | RATE_LIMITED (kuota harian) |
| `not_found` | NOT_FOUND (tema) |

## Endpoint OAuth [#oauth-endpoints]

Endpoint OAuth di bawah `https://qrdx.dev/api/oauth` (authorize, token, revoke, userinfo) mengikuti standar OAuth 2.0: `{ "error", "error_description" }`, dengan `error` berupa salah satu dari `invalid_request`, `invalid_client`, `invalid_grant`, `unsupported_grant_type`, `invalid_token`, atau `access_denied`. Menerima `invalid_grant` saat refresh berarti token refresh sudah dipakai (setiap refresh mengembalikan yang baru), kedaluwarsa setelah 30 hari, atau pengguna mencabut aplikasi Anda: arahkan pengguna melalui otorisasi lagi. Lihat [REST API dan OAuth](/docs/developers/rest-api#get-an-access-token).

## Endpoint yang tidak dikenal [#unknown-endpoints]

Path di bawah `/v1` yang tidak ada akan mengembalikan `404 NOT_FOUND` dalam format JSON, bukan halaman HTML. [Referensi API](/docs/developers/api) memuat daftar semua endpoint.
