AI assistants and coding agents can use QRdx in three ways. Pick by what the agent has to do:

| The agent needs to | Use | Key or account |
| --- | --- | --- |
| Make a QR code in a chat or an agent run | [MCP server](#connect-the-mcp-server) | None |
| Put a QR code in Markdown, HTML, an email or a build | [Image API](#give-agents-qr-image-urls) | None |
| Create or change dynamic codes, read scans | [REST API](#call-the-rest-api-for-a-user) | API key, or OAuth access token |
| Read the QRdx docs | [Markdown and llms.txt](#read-qrdx-as-markdown) | None |

## Connect the MCP server

The QRdx MCP server lives at:

```txt
https://mcp.qrdx.dev/mcp
```

It uses the Streamable HTTP transport and needs no account, sign-in or API key. The [connect page](/mcp) has one-click buttons for Claude, Cursor and VS Code. The tools and their inputs are listed in [MCP server](/docs/developers/mcp).

### Discovery for MCP clients

Clients and registries that discover servers on their own can read:

- the **MCP Server Card** at `https://mcp.qrdx.dev/mcp/server-card`, in the format of the MCP [Server Card extension](https://modelcontextprotocol.io/seps/2127-mcp-server-cards): name, version, transport and supported protocol versions;
- the **AI Catalog** at [`/.well-known/ai-catalog.json`](/.well-known/ai-catalog.json), which points to the server card;
- the **API catalog** at [`/.well-known/api-catalog`](/.well-known/api-catalog) ([RFC 9727](https://www.rfc-editor.org/rfc/rfc9727)), which lists the REST API with its [OpenAPI document](/openapi.json) and the MCP server.

## Give agents QR image URLs

The [image API](/docs/developers/image-api) turns a URL into a QR code image with no key, so an agent can write the image straight into Markdown, HTML or an email:

```txt
https://api.qrdx.dev/v1/qr?data=<encoded text>&format=svg|png|eps
```

```md
![QR code for qrdx.dev](https://api.qrdx.dev/v1/qr?data=https%3A%2F%2Fqrdx.dev&format=png&size=512)
```

- **Encode `data`** with `encodeURIComponent`, or `&`, `#`, `+` and spaces split it.
- **Pick the format for the destination.** PNG works in chat apps and email clients that don't show SVG; SVG is sharpest on the web; EPS is for print shops.
- **Style with query parameters** (`fg`, `bg`, `body`, `eye`, `dot`, `level`, `margin`, `template`). The values are listed in [Image API](/docs/developers/image-api#parameters), and the MCP tool `list_qr_styles` returns them too.
- **The same URL always returns the same image**, so it's safe to cache and embed.

## Call the REST API for a user

To create or change [dynamic codes](/docs/dynamic-qr-codes), read scans or subscribe to [webhooks](/docs/webhooks), an agent calls the [REST API](/docs/developers/rest-api) at `https://api.qrdx.dev/v1` with a Bearer credential. The [OpenAPI document](/openapi.json) describes every endpoint, schema and error, and the [API reference](/docs/developers/api) has a page for each.

**An agent working for you** uses an [API key](/docs/developers/api-keys):

1. **Create a key** in [Settings → API keys & apps](/dashboard?to=settings/developers&new=1) of the workspace the agent should work in (change workspace with the workspace switcher). The key acts with your role in that workspace.
2. **Give it the least access.** **Read only** is enough to report on codes and scans; choose **Full access**, or a custom set with `codes:write`, only when the agent creates or edits codes. Set an expiry for short-lived agents.
3. **Keep the key in a secret store or an environment variable**, never in a prompt, a log or the repository. Send it as `Authorization: Bearer $QRDX_API_KEY`.
4. **Respect the quota.** Each workspace has a daily request quota by plan (see [Plans and limits](/docs/plans-and-limits)). On `429 RATE_LIMITED`, wait for the seconds in `Retry-After`.

Revoke the key in Settings → API keys & apps when the agent no longer needs it.

**An agent that works for other people** uses OAuth, so each person approves it: register an app, run the authorization code flow with PKCE once per person, and keep their refresh tokens in a secret store. Access tokens last an hour, and each refresh returns a new refresh token. The steps are in [Get an access token](/docs/developers/rest-api#get-an-access-token). Requests made with a token act on that person's own workspace.

## Read QRdx as Markdown

- [`/llms.txt`](/llms.txt): an index of the whole site for LLMs, with the product, developer tools, docs, help center, pricing and legal pages.
- [`/llms-full.txt`](/llms-full.txt): every docs page in one file, in sidebar order.
- Add `.md` to any docs URL for that page alone, for example [`/docs/developers/mcp.md`](/docs/developers/mcp.md). [`/pricing.md`](/pricing.md) and [`/mcp.md`](/mcp.md) work too.
- Requests to the home page, `/pricing`, `/mcp` or any docs page with `Accept: text/markdown` get the Markdown version at the same URL.

## Limits

- **The MCP tools make static QR codes.** They render images and build payloads (Wi-Fi, contacts, email, SMS, map locations). They can't create dynamic codes or read anything from a QRdx account; use the REST API for that.
- **No logos or gradients** from the MCP server or the image API: they draw solid colors. Use the [playground](/playground?tab=design) or the [React library](/docs/getting-started) for logos and gradients.
- **Image URLs contain the encoded data.** Don't put passwords or other secrets in them, such as a private Wi-Fi password in a public README.
- **Rate limits apply per IP address** to the MCP server and the image API; the numbers are on the [MCP server](/docs/developers/mcp#privacy-and-limits) and [Image API](/docs/developers/image-api#limits) pages.
- **OAuth tokens act on the person's own workspace only.** To work in another workspace, use an API key created in it. There's no client-credentials grant.
