无论由哪个端点返回，REST API 的每个错误都是结构相同的 JSON：

```json
{
  "code": "INSUFFICIENT_SCOPE",
  "message": "This API key needs the 'codes:write' scope. Create a key that includes it at https://qrdx.dev/dashboard?to=settings/developers; a key's scopes can't be changed.",
  "status": 403,
  "docs": "https://qrdx.dev/docs/developers/api-keys"
}
```

| 字段 | 说明 |
| --- | --- |
| `code` | 来自下表的稳定、可供机器读取的错误码。请根据它进行分支处理。 |
| `message` | 面向人的说明，指出出了什么问题以及如何解决。措辞可能会变化。 |
| `status` | HTTP 状态码，在此重复给出。 |
| `docs` | 说明解决方法的页面（如有）。 |
| `data` | 部分错误附带的额外信息。`VALIDATION_ERROR` 会在 `data.details` 中列出每一个问题。 |

校验错误会指出每一个未通过校验的字段：

```json
{
  "code": "VALIDATION_ERROR",
  "message": "Invalid request body",
  "status": 400,
  "data": {
    "details": [
      { "path": "destinationUrl", "message": "Enter a full URL, starting with https://" }
    ]
  }
}
```

Image API 以 `{ "param", "message" }` 的形式报告查询参数，而不是 `{ "path", "message" }`。

## 错误码 [#error-codes]

| 状态码 | 错误码 | 含义 | 解决办法 |
| --- | --- | --- | --- |
| 400 | `VALIDATION_ERROR` | 请求体、查询参数或路径未通过校验。`data.details` 以 `{ path, message }` 的形式列出每个问题（Image API 中为 `{ param, message }`）；当请求体是二维码数组时，还会附上对应行的 `index`。 | 修正 `data.details` 中列出的字段，然后重新发送请求。 |
| 400 | `INVALID_SLUG` | 自定义后缀（`slug`）违反了某条规则：使用了保留词，或同一请求中出现了两个相同的后缀。对于数组，`data.details` 会按 `index` 列出每一行。 | 换一个后缀。错误信息会指出具体规则。 |
| 400 | `TOO_MANY_CODES` | 单个请求中的二维码超过 1,000 个。通常请求体的 schema 会先拒绝，并返回 `VALIDATION_ERROR`。 | 每个请求最多发送 1,000 个二维码。 |
| 400 | `DOMAIN_NOT_VERIFIED` | `domainId` 指向的自定义域名尚未通过验证。 | 在“域名”页面完成域名验证，或者不要传 `domainId`。 |
| 400 | `SID_REQUIRED` | 转化请求缺少该次扫描的 `qrdx_sid`（来自浏览器），或缺少 `sid` 或 `code`（来自服务器）。 | 发送短链接添加到你页面 URL 中的 `qrdx_sid`；如果使用 API 密钥或令牌，则将二维码 id 作为 `code` 发送。 |
| 400 | `AI_ART_TEXT_TOO_LONG` | `text` 对 AI 艺术二维码来说太长（超过 300 个字符）。 | 改为将动态二维码的 id 作为 `code` 发送：艺术二维码会编码它的短链接，短链接很短，而且仍可编辑。 |
| 401 | `UNAUTHORIZED` | 没有凭据：请求中没有 `Authorization: Bearer` 请求头（也没有 QRdx 浏览器会话）。 | 以 `Authorization: Bearer <key>` 的形式发送 API 密钥；可在 设置 → API 密钥与应用 中创建。OAuth 访问令牌放在同一个请求头中。 |
| 401 | `INVALID_TOKEN` | API 密钥或访问令牌未知、已被撤销或已过期（访问令牌有效期为一小时），或者该密钥的创建者已被封禁或已离开该密钥所属的工作区。 | 检查你发送的是否为完整的密钥，或者新建一个。对于访问令牌，请用刷新令牌获取新的令牌，或让用户重新走一遍授权流程。 |
| 402 | `PLAN_REQUIRED` | 工作区的套餐不包含该功能：批量创建、自定义后缀和自定义域名需要 Pro；转化和钩子需要 Business。 | 升级工作区，或在请求中去掉该功能。 |
| 402 | `LIMIT_REACHED` | 工作区的活跃动态二维码数量已达到套餐包含的上限（免费版为 10 个）。 | 归档一个二维码（已归档的不计入），或升级到 Pro 以获得不限数量的二维码。 |
| 402 | `AI_ART_CREDITS_EXHAUSTED` | 工作区已用完本月的 AI 艺术图片额度（免费版和 Pro）。此次请求未扣费。 | 等待额度在每月 1 日（UTC）重置，或升级以获得更多图片。 |
| 403 | `INSUFFICIENT_SCOPE` | API 密钥或令牌有效，但缺少该端点所需的权限范围。 | 创建一个带有错误信息中所指权限范围的密钥（密钥的权限范围无法修改）。对于 OAuth 应用，请添加该权限范围，并在用户授权时请求它。 |
| 403 | `FORBIDDEN` | 调用方无权执行此操作：例如工作区成员删除他人创建的二维码、成员管理钩子，或来自其他站点的浏览器会话写入。API 密钥只能执行其创建者在所属工作区中的角色所允许的操作。 | 请工作区所有者或管理员操作，或在你的服务器上使用 API 密钥调用 API。 |
| 403 | `CONFIRMATION_REQUIRED` | 使用已登录的浏览器会话创建钩子时，需要最近完成过“确认是你本人”。API 密钥和 OAuth 令牌无需此确认。 | 在 QRdx 中确认是你本人，然后在 10 分钟内重试，或在你的服务器上使用 API 密钥创建该钩子。 |
| 403 | `CONVERSIONS_OFF` | 浏览器针对未开启转化跟踪的二维码上报了转化。 | 为该二维码开启转化跟踪，或在你的服务器上使用 API 密钥上报该转化。 |
| 403 | `LIMIT_REACHED` | 工作区已有 20 个 webhook 端点和钩子。 | 删除一个不再使用的端点或钩子。 |
| 404 | `NOT_FOUND` | 没有这个端点，或者二维码、钩子、主题或自定义域名不存在于该密钥或令牌所操作的工作区中。 | 检查路径和 id。API 密钥作用于创建它的工作区；OAuth 令牌作用于其用户自己的工作区。 |
| 404 | `INVALID_SID` | `qrdx_sid` 未知，或已超过 30 天的归因窗口期。 | 发送最近一次扫描的 `qrdx_sid`，或在你的服务器上按二维码 id 上报该转化。 |
| 409 | `SLUG_TAKEN` | 同一域名下已有另一个二维码使用了该后缀。对于数组，`data.details` 会按 `index` 列出每个已被占用的后缀，且不会创建任何二维码。 | 换一个后缀。 |
| 413 | `PAYLOAD_TOO_LARGE` | 请求体超过了该端点的限制：二维码为 4 MB，钩子为 16 KB，转化为 8 KB。此外，如果一批二维码的响应（每个二维码连同其设计）将超过 4 MB，也会返回此错误；不会创建任何二维码。 | 发送更小的请求体。对于二维码，通常是内联的大尺寸 logo 所致；对于批量请求，请发送 `Prefer: return=minimal`，或减少二维码数量。 |
| 413 | `AI_ART_IMAGE_TOO_LARGE` | `photo` 或 `reference` 图片超过了 AI 艺术的大小限制（错误信息会说明是哪一个）。 | 缩小图片（`reference` 最长边缩到约 512 px，`photo` 缩到约 1024 px 见方），然后以 PNG 或 JPEG 的 data URL 形式重新发送。 |
| 415 | `UNSUPPORTED_MEDIA_TYPE` | 写入请求没有带 `Content-Type: application/json`。 | 发送 JSON 请求体，并带上 `Content-Type: application/json`。 |
| 422 | `UNSAFE_DESTINATION` | Google Web Risk 将目标 URL 标记为有风险（恶意软件、网络钓鱼或不受欢迎的软件）。对于数组，`data.details` 会按 `index` 列出每个被标记的行，且不会创建任何二维码。 | 改用其他目标地址。如果标记有误，请向 Google 申请重新审核该站点。 |
| 429 | `RATE_LIMITED` | 请求过多：触发了每分钟限制（仅设置 `Retry-After`），或工作区的每日配额（设置 `Retry-After` 和 `X-RateLimit-*`）。 | 等待 `Retry-After` 秒。若是每日配额，请等到 UTC 00:00，或升级套餐。 |
| 429 | `AI_ART_CREDITS_EXHAUSTED` | Business 工作区已用完本月的 AI 艺术图片额度，该额度由整个团队共享。 | 等待额度在每月 1 日（UTC）重置。 |
| 429 | `AI_ART_DAILY_LIMIT` | 该密钥的创建者今天（UTC）已生成 25 张 AI 艺术图片，这是在月度额度之外的安全上限。 | 明天（UTC）再试。 |
| 500 | `INTERNAL_ERROR` | QRdx 一侧出现故障，已记录日志。 | 稍后重试。如果持续出现，请连同请求时间一起反馈。 |
| 502 | `AI_ART_FAILED` | 图像模型失败、拒绝了提示词，或返回了 QRdx 无法读取的图片。未消耗 AI 艺术额度。 | 重试，或改写提示词。错误信息会说明发生了什么。 |
| 502 | `AI_ART_UNSCANNABLE` | 在你选择的二维码可见度下，无法让模型生成的图片被扫描识别。未消耗 AI 艺术额度。 | 提高 `visibility` 后重试，或换一个种子。 |
| 502 | `AI_ART_DESCRIBE_FAILED` | 你没有传 `prompt`，而替你撰写提示词的文本模型失败了。未消耗 AI 艺术额度。 | 重试，或自行发送 `prompt`。 |
| 503 | `SLUG_UNAVAILABLE` | 未能在限定时间内预留到可用的短链接后缀。 | 重新发送同一请求。 |
| 503 | `AI_ART_BUSY` | 图像模型当前超出负载能力。未消耗 AI 艺术额度。 | 等待一分钟后重试。 |
| 503 | `AI_NOT_CONFIGURED` | 此部署未配置 AI 艺术功能（未设置 `AI_GATEWAY_API_KEY` 的自托管实例）。 | 使用托管的 QRdx API，或在你的实例上配置 Vercel AI Gateway。 |
| 503 | `UNAVAILABLE` | 此部署未配置自定义域名（没有配置的自托管实例）。 | 不要传 `domainId`，或在你的实例上配置自定义域名。 |
| 504 | `AI_ART_TIMEOUT` | 图像模型耗时过长，QRdx 在请求一分钟的限制到期之前就停止了等待。未消耗 AI 艺术额度。 | 重试。调用通常需要 15 到 45 秒。 |

## 重试 [#retrying]

- **`429`：** 等待 `Retry-After` 中给出的秒数，然后重新发送同一请求。当日配额用完时，`X-RateLimit-*` 响应头会说明当前套餐允许的请求数，以及计数重置的时间（UTC 00:00）。参见[速率限制](/docs/developers/rest-api#rate-limits)。
- **`500` 和 `503`：** 使用指数退避重试，起始间隔约为一秒。
- **其他 `4xx`：** 同样的请求还会以同样的方式失败，请先修正请求。

创建二维码不是幂等操作：如果 `POST /v1/codes` 超时，请先列出你的二维码，再决定是否重新发送，否则可能会创建出两个相同的二维码。转换操作则是幂等的：发送你自己的 `id`，重复请求会返回 `200` 和 `duplicate: true`。

## `/v1/me` 和 `/v1/themes` [#v1me-and-v1themes]

这两个端点返回相同的响应体，同时保留它们一直以来发送的 OAuth 字段 `error` 和 `error_description`（内容与 `message` 相同），因此旧版客户端仍可正常工作：

| `error` | `code` |
| --- | --- |
| `invalid_token` | UNAUTHORIZED 或 INVALID_TOKEN |
| `insufficient_scope` | INSUFFICIENT_SCOPE |
| `rate_limited` | RATE_LIMITED（每日配额） |
| `not_found` | NOT_FOUND（themes） |

## OAuth 端点 [#oauth-endpoints]

`https://qrdx.dev/api/oauth` 下的 OAuth 端点（authorize、token、revoke、userinfo）遵循 OAuth 2.0 标准：`{ "error", "error_description" }`，其中 `error` 为 `invalid_request`、`invalid_client`、`invalid_grant`、`unsupported_grant_type`、`invalid_token` 或 `access_denied` 之一。刷新令牌时收到 `invalid_grant`，表示该刷新令牌已被使用过（每次刷新都会返回新的令牌）、已在 30 天后过期，或用户已撤销对你的应用的授权：请让用户重新走一遍授权流程。参见 [REST API 与 OAuth](/docs/developers/rest-api#get-an-access-token)。

## 未知端点 [#unknown-endpoints]

`/v1` 下不存在的路径会以 JSON 形式返回 `404 NOT_FOUND`，绝不会返回 HTML 页面。[API 参考](/docs/developers/api)列出了所有端点。
