无论由哪个端点返回,每个 REST API 错误都是结构相同的 JSON:

```json
{
  "code": "INSUFFICIENT_SCOPE",
  "message": "This API key needs the 'codes:write' scope. Create a key that includes it at https://qrdx.dev/dashboard?to=settings/developers; a key's scopes can't be changed.",
  "status": 403,
  "docs": "https://qrdx.dev/docs/developers/api-keys"
}
```

| 字段 | 说明 |
| --- | --- |
| `code` | 来自下表的稳定、机器可读的错误码。请根据它进行分支处理。 |
| `message` | 面向人的说明,告诉你出了什么问题以及如何修复。措辞可能会变化。 |
| `status` | HTTP 状态码,重复给出。 |
| `docs` | 解释修复方法的页面(如果有)。 |
| `data` | 部分错误附带的额外信息。`VALIDATION_ERROR` 会在 `data.details` 中列出每个问题。 |

验证错误会指出每个未通过验证的字段:

```json
{
  "code": "VALIDATION_ERROR",
  "message": "Invalid request body",
  "status": 400,
  "data": {
    "details": [
      { "path": "destinationUrl", "message": "Enter a full URL, starting with https://" }
    ]
  }
}
```

Image API 以 `{ "param", "message" }` 的形式报告查询参数,而不是 `{ "path", "message" }`。

## 错误码 [#error-codes]

| 状态码 | 错误码 | 含义 | 修复方法 |
| --- | --- | --- | --- |
| 400 | `VALIDATION_ERROR` | 请求体、查询参数或路径未通过验证。`data.details` 以 `{ path, message }` 的形式列出每个问题(Image API 上为 `{ param, message }`);当请求体是二维码数组时,还会带上对应行的 `index`。 | 修正 `data.details` 中列出的字段,然后重新发送请求。 |
| 400 | `INVALID_SLUG` | 自定义后缀(`slug`)违反了规则:使用了保留字,或同一请求中重复使用了相同的后缀。对于数组,`data.details` 会按 `index` 列出每一行。 | 选择其他后缀。错误信息会指明违反的规则。 |
| 400 | `TOO_MANY_CODES` | 单次请求中的二维码超过 1,000 个。通常请求体 schema 会先拦截,返回 `VALIDATION_ERROR`。 | 每次请求最多发送 1,000 个二维码。 |
| 400 | `DOMAIN_NOT_VERIFIED` | `domainId` 指向的自定义域名尚未通过验证。 | 在域名页面完成域名验证,或省略 `domainId`。 |
| 400 | `SID_REQUIRED` | 转化事件缺少该次扫描的 `qrdx_sid`(来自浏览器),或缺少 `sid` 或 `code`(来自服务器)。 | 发送短链接添加到你页面 URL 中的 `qrdx_sid`;如果使用 API 密钥或令牌,则以 `code` 发送二维码 ID。 |
| 401 | `UNAUTHORIZED` | 没有凭据:请求中没有 `Authorization: Bearer` 请求头(也没有 QRdx 浏览器会话)。 | 以 `Authorization: Bearer <key>` 的形式发送 API 密钥;可在设置 → API 密钥和应用中创建。OAuth 访问令牌也放在同一个请求头中。 |
| 401 | `INVALID_TOKEN` | API 密钥或访问令牌未知、已被撤销或已过期(访问令牌有效期为一小时),或者该密钥的创建者已被封禁或已离开该密钥所属的工作区。 | 检查是否发送了完整的密钥,或创建新的密钥。对于访问令牌,请使用刷新令牌获取新的令牌,或让用户重新走一遍授权流程。 |
| 402 | `PLAN_REQUIRED` | 工作区的套餐不包含该功能:批量创建、自定义后缀和自定义域名需要 Pro;转化和钩子需要 Business。 | 升级工作区套餐,或在请求中去掉该功能。 |
| 402 | `LIMIT_REACHED` | 工作区的活跃动态二维码数量已达到套餐上限(免费版为 10 个)。 | 归档一个二维码(已归档的二维码不计入数量),或升级到 Pro 以获得不限数量的二维码。 |
| 403 | `INSUFFICIENT_SCOPE` | API 密钥或令牌有效,但缺少该端点所需的权限范围。 | 创建带有错误信息中所指权限范围的密钥(密钥的权限范围无法修改)。对于 OAuth 应用,请添加该权限范围,并在用户授权时请求它。 |
| 403 | `FORBIDDEN` | 调用方无权执行此操作:工作区成员删除他人创建的二维码、成员管理钩子,或来自其他站点的浏览器会话写入。API 密钥只能执行其创建者在所属工作区中的角色所允许的操作。 | 请工作区所有者或管理员操作,或在你的服务器上使用 API 密钥调用 API。 |
| 403 | `CONFIRMATION_REQUIRED` | 使用已登录的浏览器会话创建钩子,需要近期完成“确认是你本人”。API 密钥和 OAuth 令牌不会被要求确认。 | 在 QRdx 中确认是你本人,然后在 10 分钟内重试,或在你的服务器上使用 API 密钥创建钩子。 |
| 403 | `CONVERSIONS_OFF` | 浏览器针对未开启转化追踪的二维码上报了转化。 | 为该二维码开启转化追踪,或在你的服务器上使用 API 密钥上报转化。 |
| 403 | `LIMIT_REACHED` | 工作区已有 20 个 webhook 端点和钩子。 | 删除不再使用的端点或钩子。 |
| 404 | `NOT_FOUND` | 没有这个端点,或者二维码、钩子、主题或自定义域名在该密钥或令牌所操作的工作区中不存在。 | 检查路径和 ID。API 密钥作用于其创建时所在的工作区;OAuth 令牌作用于其用户自己的工作区。 |
| 404 | `INVALID_SID` | `qrdx_sid` 未知,或已超过 30 天的归因窗口。 | 发送近期一次扫描的 `qrdx_sid`,或在你的服务器上按二维码 ID 上报转化。 |
| 409 | `SLUG_TAKEN` | 该域名下已有其他二维码使用了这个后缀。对于数组,`data.details` 会按 `index` 列出每个被占用的后缀,且不会创建任何内容。 | 选择其他后缀。 |
| 413 | `PAYLOAD_TOO_LARGE` | 请求体超出了端点的限制:二维码为 4 MB,钩子为 16 KB,转化为 8 KB。此外,如果一批二维码的响应(每个二维码连同其设计)将超过 4 MB,也会返回此错误;不会创建任何内容。 | 发送更小的请求体。对于二维码,通常是内嵌的大尺寸标志导致的;对于批量请求,请发送 `Prefer: return=minimal` 或减少二维码数量。 |
| 415 | `UNSUPPORTED_MEDIA_TYPE` | 写入请求没有 `Content-Type: application/json`。 | 发送 JSON 请求体,并带上 `Content-Type: application/json`。 |
| 422 | `UNSAFE_DESTINATION` | Google Web Risk 将目标 URL 标记为危险(恶意软件、网络钓鱼或不受欢迎的软件)。对于数组,`data.details` 会按 `index` 列出每个被标记的行,且不会创建任何内容。 | 使用其他目标地址。如果标记有误,请向 Google 申请重新审核该网站。 |
| 429 | `RATE_LIMITED` | 请求过多:触发了每分钟限制(只设置 `Retry-After`),或工作区的每日配额(设置 `Retry-After` 及 `X-RateLimit-*`)。 | 等待 `Retry-After` 秒。若是每日配额,请等到 UTC 00:00,或升级套餐。 |
| 500 | `INTERNAL_ERROR` | QRdx 一侧出现故障,已记录日志。 | 稍后重试。如果问题持续出现,请连同请求时间一起反馈。 |
| 503 | `SLUG_UNAVAILABLE` | 未能在规定时间内预留到可用的短链接后缀。 | 重新发送同一请求。 |
| 503 | `UNAVAILABLE` | 此部署未配置自定义域名(未配置该功能的自托管实例)。 | 省略 `domainId`,或在你的实例上配置自定义域名。 |

## 重试 [#retrying]

- **`429`:** 等待 `Retry-After` 中给出的秒数,然后重新发送同一请求。当每日配额用完时,`X-RateLimit-*` 响应头会说明套餐允许的请求数以及计数重置的时间(UTC 00:00)。参见[速率限制](/docs/developers/rest-api#rate-limits)。
- **`500` 和 `503`:** 使用指数退避重试,起始间隔约一秒。
- **其他 `4xx`:** 相同的请求只会以相同的方式失败。请先修复问题。

创建二维码不是幂等操作:如果 `POST /v1/codes` 超时,请先列出你的二维码再决定是否重新发送,否则可能会重复创建。转化事件则是幂等的:发送你自己的 `id`,重复请求会返回 `200` 和 `duplicate: true`。

## `/v1/me` 和 `/v1/themes` [#v1me-and-v1themes]

这两个端点返回相同的响应体,并附带它们一直以来发送的 OAuth 字段 `error` 和 `error_description`(内容与 `message` 相同),因此旧版客户端仍可正常工作:

| `error` | `code` |
| --- | --- |
| `invalid_token` | UNAUTHORIZED 或 INVALID_TOKEN |
| `insufficient_scope` | INSUFFICIENT_SCOPE |
| `rate_limited` | RATE_LIMITED(每日配额) |
| `not_found` | NOT_FOUND(themes) |

## OAuth 端点 [#oauth-endpoints]

`https://qrdx.dev/api/oauth` 下的 OAuth 端点(authorize、token、revoke、userinfo)遵循 OAuth 2.0 标准,返回 `{ "error", "error_description" }`,其中 `error` 为 `invalid_request`、`invalid_client`、`invalid_grant`、`unsupported_grant_type`、`invalid_token` 或 `access_denied` 之一。刷新时收到 `invalid_grant`,表示该刷新令牌已被使用过(每次刷新都会返回新的刷新令牌)、已在 30 天后过期,或用户已撤销你的应用:请让用户重新走一遍授权流程。参见 [REST API 和 OAuth](/docs/developers/rest-api#get-an-access-token)。

## 未知端点 [#unknown-endpoints]

访问 `/v1` 下不存在的路径时，会返回 JSON 格式的 `404 NOT_FOUND`，绝不会返回 HTML 页面。[API 参考](/docs/developers/api)列出了所有端点。
