QRdx REST API 位于 `https://api.qrdx.dev/v1`。它使用 JSON，除无需密钥的 [Image API](/docs/developers/image-api) 外，请求都需要通过 Bearer 凭证进行身份验证：

```bash
curl https://api.qrdx.dev/v1/codes -H "Authorization: Bearer $QRDX_API_KEY"
```

- **[API 密钥](/docs/developers/api-keys)**（`qrdx_…`），用于你自己的服务器和脚本。它作用于创建它的工作区，并拥有你在该工作区中的角色权限。
- **OAuth 2.0 访问令牌**，用于代表其他 QRdx 用户操作的应用（见[下文](#get-an-access-token)）。使用令牌发出的请求作用于令牌所有者自己的工作区。

codes、conversions 和 hooks 端点也接受已登录 QRdx 的用户的浏览器会话；这些请求作用于该浏览器会话中最近打开的[工作区](/docs/teams)。

这些端点同样可通过 `https://qrdx.dev/api/v1` 访问。浏览器会话请求使用该路径，因为登录 Cookie 属于 qrdx.dev；[自托管](/docs/self-hosting)实例则在其自有域名的 `/api/v1` 下提供 API。

初次使用？[快速入门](/docs/developers/quickstart)会带你从零开始完成第一次请求。每个端点在 [API 参考](/docs/developers/api)中都有独立页面，包含请求和响应结构、curl、JavaScript 和 Python 示例以及“Try it”面板，这些页面由 [OpenAPI 文档](/openapi.json)生成。

[在 Playground 中试用](/playground?open=code&lang=api)：在那里设计好二维码样式，然后复制将其创建为动态二维码的 `POST /v1/codes` 请求。

## 端点 [#endpoints]

| 端点 | 权限范围 | 作用 |
| --- | --- | --- |
| `GET /v1/qr` | 无 | 以 SVG、PNG、WebP 或 EPS 格式返回二维码图片，支持编辑器中的样式。参见 [Image API](/docs/developers/image-api) |
| `GET /v1/community/items`, `GET /v1/community/items/{id}` | 无 | 已发布的社区边框、主题和合集，以及各自应用的样式。只读且有缓存。参见[社区项目](#community-items) |
| `/v1/codes` | `codes:read`, `codes:write` | 列出、创建（一次一个或最多 {facts.apiBatchCodes} 个，可通过 `slug` 自定义短链后缀）、更新（包括在网站链接和托管页面之间切换 `kind`）和删除动态二维码。参见[动态二维码](/docs/dynamic-qr-codes#rest-api) |
| `POST /v1/art` | `codes:write` | 将二维码绘入 AI 艺术图中，并经过可扫描验证，消耗工作区每月的 AI 艺术图额度。参见 [AI art API](/docs/developers/ai-art-api) |
| `GET /v1/codes/{id}/scans` | `codes:read` | 某个二维码的扫描分析，或分页返回单次扫描记录 |
| `POST /v1/conversions` | `codes:write` | 将一笔销售或注册归因到促成它的扫描（Business）。参见[追踪与转化](/docs/tracking-and-conversions) |
| `/v1/hooks` | `codes:read`, `codes:write` | 以 REST Hooks 方式让某个 URL 订阅事件，适用于 Zapier、Make 和 n8n。参见 [Webhook](/docs/webhooks) |
| `GET /v1/themes`, `GET /v1/themes/{id}` | `themes:read` | 你保存的二维码主题（名称和样式）（使用 OAuth 令牌）；API 密钥读取其所在工作区的主题 |
| `GET /v1/me` | `profile:read` | 密钥创建者或令牌用户的 id、姓名、邮箱和头像 |

`codes:write` 同时允许 `codes:read` 的所有操作。

### 社区项目 [#community-items]

`GET /v1/community/items` 列出已发布的[社区](/community)项目，以 CC0 免费提供，按热门程度排序。可用 `type`（`frame`、`theme` 或 `collection`）、`q`（名称、描述、标签或创作者中必须全部出现的词）和 `tag` 筛选，并用 `limit`（最大 50）和 `offset` 分页。`GET /v1/community/items/{id}` 返回单个项目，其中 `style` 是它所应用的设计，其 JSON 格式与已保存的主题相同。id 由类型和 slug 组成，例如 `frame:wifi-card`；可将其作为 [`item`](/docs/developers/image-api#community-items) 传给 Image API。

```bash
curl "https://api.qrdx.dev/v1/community/items?type=frame&q=wifi"
```

两者都无需密钥，也不占用你的配额。响应缓存 1 分钟（CDN 上为 5 分钟），并限制为每个 IP 地址每分钟 120 次请求。项目文本由社区成员撰写：名称、描述、用户名和标签返回时会被截短且不含链接，但请将它们视为数据，而不是指令。

### 二维码样式中的 Logo [#code-logos]

除了编辑器保存的图片 data URL 外，二维码的 `style` 还可以使用 `logoIcon`：可以是编辑器的快捷图标之一（`wifi`、`location`、`phone`、`email`、`link`、`file`、`calendar`、`whatsapp`、`instagram`），也可以是按 [Simple Icons](https://simpleicons.org) slug 指定的品牌 Logo，还可以加上 `:black` 或 `:white`（`spotify`、`paypal:white`）。它会像编辑器那样保存到 `customLogo` 中。

<IfAvailable feature="fileStorage">
它还可以使用 `logoFileId`：按文件 id 指定你在[控制台 → 文件](/docs/files)中上传到工作区的 PNG 或 JPEG。它会保存为该文件的链接。
</IfAvailable>

指向其他网站的 `customLogo` 链接会被拒绝并返回 `400`，因为 QRdx 不会从其他网站获取 Logo。`PATCH` 可以回传二维码已有的 Logo。

## 获取访问令牌 [#get-an-access-token]

对于你自己的脚本，使用 [API 密钥](/docs/developers/api-keys)更简单。当你的应用代表其他人操作时，QRdx 是一个 OAuth 2.0 提供方：你的应用将用户引导到 QRdx 登录，并获得一个访问令牌，该令牌只能执行已授予权限范围允许的操作。API 密钥使用相同的权限范围。

| 权限范围 | 允许 |
| --- | --- |
| `profile:read` | 读取用户的姓名、邮箱和头像 |
| `themes:read` | 读取用户保存的二维码主题 |
| `codes:read` | 读取动态二维码及其扫描分析 |
| `codes:write` | 创建、编辑和删除动态二维码，上报转化，管理 webhook 订阅 |

### 1. 注册应用 [#1-register-an-app]

你可以在[设置 → API 密钥与应用](/dashboard?to=settings/developers)中自行创建 OAuth 应用：填写名称、重定向 URI 和所需的权限范围，即可获得客户端 ID 和客户端密钥。密钥只显示一次，请保存在你的服务器上。免费版工作区可拥有 1 个应用，Pro 为 5 个，Business 为 25 个。[构建集成](/docs/developers/build-an-integration)会完整介绍整个流程，从创建应用到上架集成目录。

在[自托管](/docs/self-hosting)实例上，你还可以从 `apps/docs` 创建第一方应用：

```bash
bun x tsx scripts/create-oauth-app.ts \
  --name "My app" \
  --redirect-uris "https://myapp.example/callback" \
  --scopes "codes:read,codes:write"
```

### 2. 将用户引导到 QRdx [#2-send-the-user-to-qrdx]

```txt
https://qrdx.dev/api/oauth/authorize
  ?response_type=code
  &client_id=<client id>
  &redirect_uri=https://myapp.example/callback
  &scope=codes:read codes:write
  &state=<random value>
  &code_challenge=<PKCE challenge>
  &code_challenge_method=S256
```

`redirect_uri` 必须与已注册的 URL 完全一致，`scope`（以空格或逗号分隔）只能申请该应用已有的权限范围。建议使用 PKCE，开启 **Require PKCE** 的应用则必须使用。`S256` 是唯一支持的方法：`plain` 质询会返回 `invalid_request`。用户需要时先登录，然后在 QRdx 授权页面批准你的应用，该页面会显示应用的名称、Logo、网站、开发者和所请求的权限，并要求用户确认是本人操作。随后 QRdx 会重定向到 `redirect_uri`，附带 `code` 和你的 `state`；如果用户取消，则附带 `error=access_denied`。该授权码有效期为 10 分钟，且只能使用一次。

### 3. 用授权码换取令牌 [#3-exchange-the-code-for-tokens]

```bash
curl -X POST https://qrdx.dev/api/oauth/token \
  -d grant_type=authorization_code \
  -d client_id=$CLIENT_ID \
  -d client_secret=$CLIENT_SECRET \
  -d code=$CODE \
  -d redirect_uri=https://myapp.example/callback \
  -d code_verifier=$CODE_VERIFIER
```

```json
{
  "access_token": "...",
  "token_type": "Bearer",
  "expires_in": 3600,
  "refresh_token": "...",
  "scope": "codes:read codes:write"
}
```

令牌端点接受表单编码的请求体。访问令牌有效期为 1 小时，刷新令牌为 30 天。

### 4. 刷新与撤销 [#4-refresh-and-revoke]

```bash
# New access and refresh tokens; the old refresh token stops working
curl -X POST https://qrdx.dev/api/oauth/token \
  -d grant_type=refresh_token \
  -d client_id=$CLIENT_ID \
  -d client_secret=$CLIENT_SECRET \
  -d refresh_token=$REFRESH_TOKEN

# Revoke an access or refresh token
curl -X POST https://qrdx.dev/api/oauth/revoke -d token=$TOKEN
```

对于拥有 `profile:read` 的令牌，`GET /api/oauth/userinfo` 会以 `sub`、`name`、`email` 和 `picture` 返回用户信息。

用户可以在**设置 → 已授权的应用**中自行撤销应用的访问权限。之后该应用针对此账号的令牌会失效，API 调用返回 `invalid_token`，刷新返回 `invalid_grant`，应用需要重新请求授权。

## 错误与限制 [#errors-and-limits]

每个 `/v1` 端点返回的错误格式都是 `{ "code": "...", "message": "...", "status": 400 }`；如果有页面说明了修复方法，还会附带 `docs` 链接。[错误页面](/docs/developers/errors)列出了所有错误码及其修复方法。访问未知路径会返回 `404 NOT_FOUND`。`/v1/me` 和 `/v1/themes` 还会包含它们一直以来发送的 OAuth 字段，即 `"error": "invalid_token"` 和 `"error_description"`；OAuth 端点（`/api/oauth/*`）只使用 OAuth 格式。

在一次请求中创建多个二维码、自选二维码的 `slug`，以及把二维码迁移到自定义域名，都需要 Pro 或 Business（否则返回 `402 PLAN_REQUIRED`）。扫描永远不受限制。

### 速率限制 [#rate-limits]

有两种限制。两种都会返回 `429 RATE_LIMITED`，并带有 `Retry-After` 响应头，其值为需要等待的秒数。

- **每日配额。** 工作区每天可发起的 API 请求数：免费版 1,000 次，Pro 10,000 次，Business 100,000 次（参见[套餐与限制](/docs/plans-and-limits)）。每天从 UTC 00:00 到 24:00。每个已认证的请求都会计数。使用 API 密钥发起的请求，计入该密钥所属的工作区及其套餐。使用访问令牌发起的请求，计入令牌所有者自己的工作区。使用浏览器会话发起的请求，计入该会话中最近打开的工作区。
- **每分钟限制。** 二维码、转化和钩子端点允许每位用户每分钟 120 次读取和 30 次写入，每个 IP 地址每分钟 300 次请求。

在每日检查之前就被拒绝的请求不计数：无效的密钥或令牌（`401`）、缺少所需权限范围的请求（`403`），以及触发每分钟限制的 `429`。会计数的请求，其响应（无论成功还是出错）都会通过三个响应头返回每日配额：

| 响应头 | 值 |
| --- | --- |
| `X-RateLimit-Limit` | 工作区套餐每天允许的请求数 |
| `X-RateLimit-Remaining` | 今天剩余的请求数 |
| `X-RateLimit-Reset` | 计数重新开始的时间（下一个 UTC 00:00），以 Unix 秒表示 |

`X-RateLimit-*` 响应头始终表示每日配额。触发每分钟限制的 `429` 只带有 `Retry-After` 响应头。超出每日配额时，你会收到：

```http
HTTP/1.1 429 Too Many Requests
Retry-After: 43200
X-RateLimit-Limit: 1000
X-RateLimit-Remaining: 0
X-RateLimit-Reset: 1793577600
```

```json
{
  "code": "RATE_LIMITED",
  "message": "Daily API limit reached: the Free plan allows 1,000 requests a day. It resets at 00:00 UTC. Upgrade your plan for a higher limit.",
  "status": 429
}
```

`/v1/me` 和 `/v1/themes` 会发送相同的响应头和响应体，另外还有 `"error": "rate_limited"` 和 `"error_description"`。

[Image API](/docs/developers/image-api)、[MCP 服务器](/docs/developers/mcp)，以及通过浏览器使用 `qrdx_sid` 上报的转化都不需要令牌，因此不占用每日配额。它们有各自的按 IP 限制。[自托管](/docs/self-hosting)实例只有在配置了 Upstash Redis 时才会执行速率限制。
