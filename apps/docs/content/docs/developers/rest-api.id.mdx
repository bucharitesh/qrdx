REST API QRdx berada di bawah `https://api.qrdx.dev/v1`. API ini menggunakan JSON dan, kecuali [Image API](/docs/developers/image-api) yang tanpa kunci, mengautentikasi permintaan dengan kredensial Bearer:

```bash
curl https://api.qrdx.dev/v1/codes -H "Authorization: Bearer $QRDX_API_KEY"
```

- **Sebuah [kunci API](/docs/developers/api-keys)** (`qrdx_…`) untuk server dan skrip Anda sendiri. Kunci ini bekerja pada workspace tempat kunci dibuat, dengan peran Anda di sana.
- **Token akses OAuth 2.0** untuk aplikasi yang bertindak atas nama pengguna QRdx lain ([di bawah](#get-an-access-token)). Permintaan yang dibuat dengan token bekerja pada workspace milik pemilik token.

Endpoint codes, conversions, dan hooks juga menerima sesi browser dari orang yang masuk ke QRdx; permintaan tersebut bekerja pada [workspace](/docs/teams) yang terakhir dibuka di sesi browser itu.

Endpoint yang sama juga dapat diakses di `https://qrdx.dev/api/v1`. Permintaan sesi browser menggunakan path ini, karena cookie masuk milik qrdx.dev, dan instance [self-hosted](/docs/self-hosting) menyajikan API di `/api/v1` pada domainnya sendiri.

Baru di sini? [Panduan memulai](/docs/developers/quickstart) membawa Anda dari nol hingga permintaan pertama. Setiap endpoint memiliki halamannya sendiri, lengkap dengan skema permintaan dan respons, contoh dalam curl, JavaScript, dan Python, serta panel Try it, di [referensi API](/docs/developers/api), yang dihasilkan dari [dokumen OpenAPI](/openapi.json).

[Coba di Playground](/playground?open=code&lang=api): atur gaya kode di sana, lalu salin permintaan `POST /v1/codes` yang membuatnya sebagai kode dinamis.

## Endpoint [#endpoints]

| Endpoint | Cakupan | Fungsi |
| --- | --- | --- |
| `GET /v1/qr` | Tidak ada | Gambar kode QR sebagai SVG, PNG, WebP, atau EPS, dengan gaya dari editor. Lihat [Image API](/docs/developers/image-api) |
| `GET /v1/community/items`, `GET /v1/community/items/{id}` | Tidak ada | Bingkai, tema, dan koleksi komunitas yang dipublikasikan, beserta gaya yang diterapkannya. Hanya baca dan di-cache. Lihat [Item komunitas](#community-items) |
| `/v1/codes` | `codes:read`, `codes:write` | Menampilkan daftar, membuat (satu atau hingga {facts.apiBatchCodes} sekaligus, dengan back-half kustom opsional di `slug`), memperbarui (termasuk mengalihkan `kind` antara tautan situs web dan halaman yang di-hosting), dan menghapus kode dinamis. Lihat [Kode QR dinamis](/docs/dynamic-qr-codes#rest-api) |
| `POST /v1/art` | `codes:write` | Kode QR yang dilukis ke dalam karya seni AI, diperiksa agar dapat dipindai, dengan kuota gambar seni AI bulanan workspace. Lihat [API seni AI](/docs/developers/ai-art-api) |
| `GET /v1/codes/{id}/scans` | `codes:read` | Analitik pemindaian untuk sebuah kode, atau setiap pemindaian per halaman |
| `POST /v1/conversions` | `codes:write` | Mengaitkan penjualan atau pendaftaran dengan pemindaian yang mengarah kepadanya (Business). Lihat [Pelacakan dan konversi](/docs/tracking-and-conversions) |
| `/v1/hooks` | `codes:read`, `codes:write` | Berlangganan URL ke event, gaya REST Hooks, untuk Zapier, Make, dan n8n. Lihat [Webhook](/docs/webhooks) |
| `GET /v1/themes`, `GET /v1/themes/{id}` | `themes:read` | Tema QR tersimpan Anda (nama dan gaya) untuk token OAuth; kunci API membaca tema milik workspace-nya |
| `GET /v1/me` | `profile:read` | Id, nama, email, dan avatar pembuat kunci atau pengguna token |

`codes:write` juga mengizinkan semua yang diizinkan oleh `codes:read`.

### Item komunitas [#community-items]

`GET /v1/community/items` menampilkan daftar item [komunitas](/community) yang dipublikasikan, gratis di bawah CC0, dari yang paling populer. Saring dengan `type` (`frame`, `theme`, atau `collection`), `q` (kata-kata yang semuanya harus muncul di nama, deskripsi, tag, atau pembuat), dan `tag`, lalu bagi per halaman dengan `limit` (hingga 50) dan `offset`. `GET /v1/community/items/{id}` mengembalikan satu item beserta `style`, yaitu desain yang diterapkannya dalam JSON yang sama dengan tema tersimpan. Id berupa tipe dan slug, seperti `frame:wifi-card`; teruskan ke Image API sebagai [`item`](/docs/developers/image-api#community-items).

```bash
curl "https://api.qrdx.dev/v1/community/items?type=frame&q=wifi"
```

Keduanya tanpa kunci dan tidak memakai kuota Anda. Respons di-cache selama satu menit (5 menit di CDN), dan dibatasi 120 permintaan per menit per alamat IP. Teks item ditulis oleh anggota komunitas: nama, deskripsi, handle, dan tag dikembalikan singkat dan tanpa tautan, tetapi perlakukan sebagai data, bukan instruksi.

### Logo dalam gaya kode [#code-logos]

Selain data URL gambar seperti yang disimpan editor, `style` sebuah kode dapat menerima `logoIcon`: salah satu ikon cepat editor (`wifi`, `location`, `phone`, `email`, `link`, `file`, `calendar`, `whatsapp`, `instagram`), atau logo merek berdasarkan slug [Simple Icons](https://simpleicons.org), opsional dengan `:black` atau `:white` (`spotify`, `paypal:white`). Nilainya disimpan di `customLogo` seperti yang disimpan editor.

<IfAvailable feature="fileStorage">
Gaya ini juga dapat menerima `logoFileId`: PNG atau JPEG yang Anda unggah ke workspace di [Dasbor → File](/docs/files), berdasarkan id file. Nilainya disimpan sebagai tautan file.
</IfAvailable>

Tautan `customLogo` ke situs lain ditolak dengan `400`, karena QRdx tidak mengambil logo dari situs lain. `PATCH` boleh mengirim kembali logo yang sudah dimiliki kode.

## Dapatkan token akses [#get-an-access-token]

Untuk skrip Anda sendiri, [kunci API](/docs/developers/api-keys) lebih sederhana. Saat aplikasi Anda bertindak atas nama orang lain, QRdx adalah penyedia OAuth 2.0: aplikasi Anda mengarahkan orang ke QRdx untuk masuk, lalu menerima token akses yang hanya dapat melakukan apa yang diizinkan oleh cakupan yang diberikan. Kunci API menggunakan cakupan yang sama.

| Cakupan | Mengizinkan |
| --- | --- |
| `profile:read` | Membaca nama, email, dan avatar pengguna |
| `themes:read` | Membaca tema QR tersimpan milik pengguna |
| `codes:read` | Membaca kode dinamis beserta analitik pemindaiannya |
| `codes:write` | Membuat, mengedit, dan menghapus kode dinamis, melaporkan konversi, mengelola langganan webhook |

### 1. Daftarkan aplikasi [#1-register-an-app]

Buat sendiri aplikasi OAuth di [Pengaturan → Kunci API & aplikasi](/dashboard?to=settings/developers): beri nama, URI pengalihan, dan cakupan yang dibutuhkan, lalu Anda mendapatkan client ID dan client secret. Secret hanya ditampilkan sekali; simpan di server Anda. Workspace Gratis dapat memiliki 1 aplikasi, Pro 5, dan Business 25. [Membangun integrasi](/docs/developers/build-an-integration) menjelaskan seluruh alurnya, dari membuat aplikasi hingga mendaftarkannya di direktori integrasi.

Pada instance [self-hosted](/docs/self-hosting), Anda juga dapat membuat aplikasi first-party dari `apps/docs`:

```bash
bun x tsx scripts/create-oauth-app.ts \
  --name "My app" \
  --redirect-uris "https://myapp.example/callback" \
  --scopes "codes:read,codes:write"
```

### 2. Arahkan pengguna ke QRdx [#2-send-the-user-to-qrdx]

```txt
https://qrdx.dev/api/oauth/authorize
  ?response_type=code
  &client_id=<client id>
  &redirect_uri=https://myapp.example/callback
  &scope=codes:read codes:write
  &state=<random value>
  &code_challenge=<PKCE challenge>
  &code_challenge_method=S256
```

`redirect_uri` harus sama persis dengan URL yang terdaftar, dan `scope` (dipisahkan spasi atau koma) hanya boleh meminta cakupan milik aplikasi. PKCE direkomendasikan, dan wajib untuk aplikasi yang mengaktifkan **Require PKCE**. `S256` adalah satu-satunya metode: tantangan `plain` menghasilkan `invalid_request`. Orang masuk jika perlu, lalu menyetujui aplikasi Anda di layar persetujuan QRdx, yang menampilkan nama, logo, situs web, pembuat, dan izin yang diminta, serta mengonfirmasi bahwa itu memang mereka. QRdx kemudian mengalihkan ke `redirect_uri` dengan `code` dan `state` Anda, atau dengan `error=access_denied` jika mereka membatalkan. Kode berlaku selama 10 menit dan hanya dapat digunakan sekali.

### 3. Tukarkan kode dengan token [#3-exchange-the-code-for-tokens]

```bash
curl -X POST https://qrdx.dev/api/oauth/token \
  -d grant_type=authorization_code \
  -d client_id=$CLIENT_ID \
  -d client_secret=$CLIENT_SECRET \
  -d code=$CODE \
  -d redirect_uri=https://myapp.example/callback \
  -d code_verifier=$CODE_VERIFIER
```

```json
{
  "access_token": "...",
  "token_type": "Bearer",
  "expires_in": 3600,
  "refresh_token": "...",
  "scope": "codes:read codes:write"
}
```

Endpoint token menerima isi permintaan berformat form-encoded. Token akses berlaku 1 jam dan token refresh 30 hari.

### 4. Segarkan dan cabut [#4-refresh-and-revoke]

```bash
# New access and refresh tokens; the old refresh token stops working
curl -X POST https://qrdx.dev/api/oauth/token \
  -d grant_type=refresh_token \
  -d client_id=$CLIENT_ID \
  -d client_secret=$CLIENT_SECRET \
  -d refresh_token=$REFRESH_TOKEN

# Revoke an access or refresh token
curl -X POST https://qrdx.dev/api/oauth/revoke -d token=$TOKEN
```

`GET /api/oauth/userinfo` mengembalikan pengguna sebagai `sub`, `name`, `email`, dan `picture` untuk token dengan `profile:read`.

Orang dapat mencabut akses aplikasi sendiri di **Pengaturan → Aplikasi yang diotorisasi**. Token aplikasi untuk akun tersebut kemudian gagal dengan `invalid_token` (panggilan API) dan `invalid_grant` (refresh), dan aplikasi harus meminta izin lagi.

## Error dan batas [#errors-and-limits]

Setiap endpoint `/v1` mengembalikan error dalam bentuk `{ "code": "...", "message": "...", "status": 400 }`, disertai tautan `docs` bila ada halaman yang menjelaskan cara memperbaikinya; [halaman error](/docs/developers/errors) mencantumkan setiap kode beserta solusinya. Path yang tidak dikenal mendapat `404 NOT_FOUND`. `/v1/me` dan `/v1/themes` juga menyertakan kolom OAuth yang sejak dulu mereka kirim, yaitu `"error": "invalid_token"` dan `"error_description"`, sedangkan endpoint OAuth (`/api/oauth/*`) hanya memakai format OAuth.

Membuat beberapa kode dalam satu permintaan, memilih `slug` sebuah kode, dan memindahkan kode ke domain kustom memerlukan Pro atau Business (jika tidak, hasilnya `402 PLAN_REQUIRED`). Pemindaian tidak pernah dibatasi.

### Batas laju [#rate-limits]

Ada dua jenis batas. Keduanya menjawab `429 RATE_LIMITED` dengan header `Retry-After`, yaitu jumlah detik yang harus ditunggu.

- **Kuota harian.** Sebuah workspace dapat membuat 1.000 permintaan API per hari di paket Gratis, 10.000 di Pro, dan 100.000 di Business (lihat [Paket dan batas](/docs/plans-and-limits)). Hari dihitung dari 00:00 hingga 24:00 UTC. Setiap permintaan terautentikasi dihitung. Permintaan dengan kunci API dihitung terhadap workspace milik kunci tersebut dan paketnya. Permintaan dengan access token dihitung terhadap workspace milik pemilik token itu sendiri. Permintaan dengan sesi browser dihitung terhadap workspace yang terakhir dibuka dalam sesi tersebut.
- **Batas per menit.** Endpoint codes, conversions, dan hooks mengizinkan 120 pembacaan dan 30 penulisan per menit untuk setiap pengguna, serta 300 permintaan per menit untuk setiap alamat IP.

Permintaan yang ditolak sebelum pemeriksaan harian tidak dihitung: kunci atau token yang tidak valid (`401`), permintaan tanpa scope yang diperlukan (`403`), atau `429` per menit. Respons untuk permintaan yang dihitung membawa kuota harian dalam tiga header, baik pada respons berhasil maupun error:

| Header | Nilai |
| --- | --- |
| `X-RateLimit-Limit` | Jumlah permintaan per hari pada paket workspace |
| `X-RateLimit-Remaining` | Sisa permintaan hari ini |
| `X-RateLimit-Reset` | Kapan hitungan dimulai ulang (00:00 UTC berikutnya), dalam detik Unix |

Header `X-RateLimit-*` selalu menggambarkan kuota harian. `429` per menit hanya memiliki header `Retry-After`. Jika melewati kuota harian, Anda mendapat:

```http
HTTP/1.1 429 Too Many Requests
Retry-After: 43200
X-RateLimit-Limit: 1000
X-RateLimit-Remaining: 0
X-RateLimit-Reset: 1793577600
```

```json
{
  "code": "RATE_LIMITED",
  "message": "Daily API limit reached: the Free plan allows 1,000 requests a day. It resets at 00:00 UTC. Upgrade your plan for a higher limit.",
  "status": 429
}
```

`/v1/me` dan `/v1/themes` mengirim header dan isi yang sama, ditambah `"error": "rate_limited"` dan `"error_description"`.

[Image API](/docs/developers/image-api), [server MCP](/docs/developers/mcp), dan konversi yang dilaporkan dari browser dengan `qrdx_sid` tidak memerlukan token, sehingga tidak memakai kuota harian. Keduanya memiliki batas per IP sendiri. Instans [self-hosted](/docs/self-hosting) hanya menerapkan batas laju jika Upstash Redis dikonfigurasi.
