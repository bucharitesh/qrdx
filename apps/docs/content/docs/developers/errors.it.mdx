Ogni errore della REST API è un JSON con la stessa struttura, qualunque endpoint lo restituisca:

```json
{
  "code": "INSUFFICIENT_SCOPE",
  "message": "This API key needs the 'codes:write' scope. Create a key that includes it at https://qrdx.dev/dashboard?to=settings/developers; a key's scopes can't be changed.",
  "status": 403,
  "docs": "https://qrdx.dev/docs/developers/api-keys"
}
```

| Campo | Che cos'è |
| --- | --- |
| `code` | Un codice stabile e leggibile da una macchina, preso dalla tabella qui sotto. Usa questo per gestire i casi. |
| `message` | Che cosa è andato storto e come risolverlo, scritto per le persone. La formulazione può cambiare. |
| `status` | Lo stato HTTP, ripetuto. |
| `docs` | Una pagina che spiega come risolvere, quando c'è. |
| `data` | Dettagli aggiuntivi, per alcuni errori. `VALIDATION_ERROR` elenca ogni problema in `data.details`. |

Un errore di validazione indica ogni campo che non è valido:

```json
{
  "code": "VALIDATION_ERROR",
  "message": "Invalid request body",
  "status": 400,
  "data": {
    "details": [
      { "path": "destinationUrl", "message": "Enter a full URL, starting with https://" }
    ]
  }
}
```

L'Image API segnala i parametri della query come `{ "param", "message" }` invece di `{ "path", "message" }`.

## Codici di errore [#error-codes]

| Stato | Codice | Significato | Soluzione |
| --- | --- | --- | --- |
| 400 | `VALIDATION_ERROR` | Il body, la query o il percorso non hanno superato la validazione. `data.details` elenca ogni problema come `{ path, message }` (`{ param, message }` nell'Image API), con l'`index` della riga quando il body è un array di codici. | Correggi i campi elencati in `data.details` e invia di nuovo la richiesta. |
| 400 | `INVALID_SLUG` | Il back-half personalizzato (`slug`) viola una regola: una parola riservata, oppure lo stesso back-half due volte nella stessa richiesta. Per un array, `data.details` elenca ogni riga per `index`. | Scegli un altro back-half. Il messaggio indica la regola. |
| 400 | `TOO_MANY_CODES` | Più di 1.000 codici in una sola richiesta. Di solito lo schema del body lo rifiuta prima, come `VALIDATION_ERROR`. | Invia al massimo 1.000 codici per richiesta. |
| 400 | `DOMAIN_NOT_VERIFIED` | `domainId` punta a un dominio personalizzato non ancora verificato. | Completa la verifica del dominio nella pagina Domini, oppure ometti `domainId`. |
| 400 | `SID_REQUIRED` | Una conversione senza il `qrdx_sid` della scansione (dal browser), oppure senza `sid` o `code` (da un server). | Invia il `qrdx_sid` che il link breve ha aggiunto all'URL della tua pagina oppure, con una chiave API o un token, l'id del codice come `code`. |
| 401 | `UNAUTHORIZED` | Nessuna credenziale: la richiesta non ha l'header `Authorization: Bearer` (e nessuna sessione del browser di QRdx). | Invia una chiave API come `Authorization: Bearer <key>`; creane una in Impostazioni → Chiavi API e app. I token di accesso OAuth vanno nello stesso header. |
| 401 | `INVALID_TOKEN` | La chiave API o il token di accesso è sconosciuto, revocato o scaduto (i token di accesso durano un'ora), oppure chi ha creato la chiave è stato bannato o ha lasciato il workspace della chiave. | Controlla di aver inviato la chiave completa, oppure creane una nuova. Per un token di accesso, ottienine uno nuovo con il tuo refresh token, oppure fai ripetere l'autorizzazione all'utente. |
| 402 | `PLAN_REQUIRED` | La funzione non è inclusa nel piano del workspace: la creazione in blocco, i back-half personalizzati e i domini personalizzati richiedono Pro; le conversioni e gli hook richiedono Business. | Passa a un piano superiore per il workspace, oppure ometti la funzione dalla richiesta. |
| 402 | `LIMIT_REACHED` | Il workspace ha già tutti i codici dinamici attivi inclusi nel suo piano (10 con Gratuito). | Archivia un codice (i codici archiviati non vengono contati) oppure passa a Pro per avere codici illimitati. |
| 403 | `INSUFFICIENT_SCOPE` | La chiave API o il token è valido ma non ha lo scope richiesto da questo endpoint. | Crea una chiave con lo scope indicato nel messaggio (gli scope di una chiave non si possono modificare). Per un'app OAuth, aggiungi lo scope e richiedilo quando l'utente autorizza. |
| 403 | `FORBIDDEN` | Chi chiama non può eseguire questa azione: un membro del workspace che elimina un codice creato da qualcun altro, un membro che gestisce gli hook, oppure una scrittura da sessione del browser proveniente da un altro sito. Una chiave API può fare solo ciò che il ruolo di chi l'ha creata consente nel suo workspace. | Chiedi a un proprietario o a un amministratore del workspace, oppure chiama l'API con una chiave API dal tuo server. |
| 403 | `CONFIRMATION_REQUIRED` | Creare un hook con una sessione del browser autenticata richiede un "Conferma la tua identità" recente. Alle chiavi API e ai token OAuth non viene chiesto. | Conferma la tua identità in QRdx, poi riprova entro 10 minuti, oppure crea l'hook con una chiave API dal tuo server. |
| 403 | `CONVERSIONS_OFF` | Una conversione dal browser per un codice che non ha il tracciamento delle conversioni attivo. | Attiva il tracciamento delle conversioni per il codice, oppure registra la conversione dal tuo server con una chiave API. |
| 403 | `LIMIT_REACHED` | Il workspace ha già 20 endpoint webhook e hook. | Elimina un endpoint o un hook che non usi più. |
| 404 | `NOT_FOUND` | L'endpoint non esiste, oppure il codice, l'hook, il tema o il dominio personalizzato non esiste nel workspace su cui agisce la chiave o il token. | Controlla il percorso e l'id. Una chiave API agisce sul workspace in cui è stata creata; un token OAuth agisce sul workspace personale del suo utente. |
| 404 | `INVALID_SID` | Il `qrdx_sid` è sconosciuto o più vecchio di 30 giorni, la finestra di attribuzione. | Invia il `qrdx_sid` di una scansione recente, oppure registra la conversione tramite l'id del codice dal tuo server. |
| 409 | `SLUG_TAKEN` | Un altro codice usa già quel back-half su quel dominio. Per un array, `data.details` elenca ogni back-half già in uso per `index`, e non viene creato nulla. | Scegli un altro back-half. |
| 413 | `PAYLOAD_TOO_LARGE` | Il body supera il limite dell'endpoint: 4 MB per i codici, 16 KB per gli hook, 8 KB per le conversioni. Vale anche per un lotto di codici la cui risposta (ogni codice con il suo design) supererebbe 4 MB; non viene creato nulla. | Invia un body più piccolo. Per i codici, la causa abituale è un logo inline di grandi dimensioni; per un lotto, invia `Prefer: return=minimal` oppure meno codici. |
| 415 | `UNSUPPORTED_MEDIA_TYPE` | Una scrittura senza `Content-Type: application/json`. | Invia un body JSON con `Content-Type: application/json`. |
| 422 | `UNSAFE_DESTINATION` | Google Web Risk segnala l'URL di destinazione (malware, phishing o software indesiderato). Per un array, `data.details` elenca ogni riga segnalata per `index`, e non viene creato nulla. | Usa un'altra destinazione. Se la segnalazione è sbagliata, chiedi a Google di riesaminare il sito. |
| 429 | `RATE_LIMITED` | Troppe richieste: un limite al minuto (viene impostato solo `Retry-After`) oppure la quota giornaliera del workspace (`Retry-After` più `X-RateLimit-*`). | Attendi i secondi indicati in `Retry-After`. Per la quota giornaliera, aspetta le 00:00 UTC oppure passa a un piano superiore. |
| 500 | `INTERNAL_ERROR` | Qualcosa è andato storto dal lato di QRdx. L'errore è stato registrato. | Riprova fra un momento. Se continua a succedere, segnalalo indicando l'ora della richiesta. |
| 503 | `SLUG_UNAVAILABLE` | Non è stato possibile riservare in tempo uno slug libero per il link breve. | Invia di nuovo la stessa richiesta. |
| 503 | `UNAVAILABLE` | I domini personalizzati non sono configurati in questa installazione (un'istanza self-hosted senza di essi). | Ometti `domainId`, oppure configura i domini personalizzati sulla tua istanza. |

## Nuovi tentativi [#retrying]

- **`429`:** attendi il numero di secondi indicato in `Retry-After`, poi invia di nuovo la stessa richiesta. Quando la quota giornaliera si esaurisce, gli header `X-RateLimit-*` indicano quante richieste consente il piano e quando il conteggio si azzera (00:00 UTC). Vedi [limiti di frequenza](/docs/developers/rest-api#rate-limits).
- **`500` e `503`:** riprova con backoff esponenziale, partendo da circa un secondo.
- **Altri `4xx`:** la stessa richiesta fallirà allo stesso modo. Correggila prima.

La creazione dei codici non è idempotente: se un `POST /v1/codes` va in timeout, elenca i tuoi codici prima di inviarlo di nuovo, altrimenti potresti creare il codice due volte. Le conversioni invece lo sono: invia un tuo `id` e una ripetizione restituisce `200` con `duplicate: true`.

## `/v1/me` e `/v1/themes` [#v1me-and-v1themes]

Questi due endpoint inviano lo stesso body più i campi OAuth che hanno sempre inviato, `error` e `error_description` (lo stesso testo di `message`), così i client più vecchi continuano a funzionare:

| `error` | `code` |
| --- | --- |
| `invalid_token` | UNAUTHORIZED o INVALID_TOKEN |
| `insufficient_scope` | INSUFFICIENT_SCOPE |
| `rate_limited` | RATE_LIMITED (quota giornaliera) |
| `not_found` | NOT_FOUND (temi) |

## Endpoint OAuth [#oauth-endpoints]

Gli endpoint OAuth sotto `https://qrdx.dev/api/oauth` (authorize, token, revoke, userinfo) seguono invece lo standard OAuth 2.0: `{ "error", "error_description" }`, con `error` uno tra `invalid_request`, `invalid_client`, `invalid_grant`, `unsupported_grant_type`, `invalid_token` o `access_denied`. Ricevere `invalid_grant` durante un refresh significa che il refresh token è già stato usato (ogni refresh ne restituisce uno nuovo), è scaduto dopo 30 giorni, oppure l'utente ha revocato la tua app: fai ripetere l'autorizzazione all'utente. Vedi [REST API e OAuth](/docs/developers/rest-api#get-an-access-token).

## Endpoint sconosciuti [#unknown-endpoints]

Un percorso sotto `/v1` che non esiste restituisce `404 NOT_FOUND` come JSON, mai una pagina HTML. Il [riferimento API](/docs/developers/api) elenca tutti gli endpoint.
