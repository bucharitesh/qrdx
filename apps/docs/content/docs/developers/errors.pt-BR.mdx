Todo erro da REST API é um JSON com o mesmo formato, seja qual for o endpoint que o retorna:

```json
{
  "code": "INSUFFICIENT_SCOPE",
  "message": "This API key needs the 'codes:write' scope. Create a key that includes it at https://qrdx.dev/dashboard?to=settings/developers; a key's scopes can't be changed.",
  "status": 403,
  "docs": "https://qrdx.dev/docs/developers/api-keys"
}
```

| Campo | O que é |
| --- | --- |
| `code` | Um código estável, legível por máquina, da tabela abaixo. Use este campo para tratar o erro. |
| `message` | O que deu errado e como corrigir, escrito para pessoas. O texto pode mudar. |
| `status` | O status HTTP, repetido. |
| `docs` | Uma página que explica a correção, quando existe. |
| `data` | Detalhes extras, em alguns erros. `VALIDATION_ERROR` lista cada problema em `data.details`. |

Um erro de validação indica todos os campos que falharam:

```json
{
  "code": "VALIDATION_ERROR",
  "message": "Invalid request body",
  "status": 400,
  "data": {
    "details": [
      { "path": "destinationUrl", "message": "Enter a full URL, starting with https://" }
    ]
  }
}
```

A Image API informa os parâmetros de consulta como `{ "param", "message" }` em vez de `{ "path", "message" }`.

## Códigos de erro [#error-codes]

| Status | Código | Significado | Correção |
| --- | --- | --- | --- |
| 400 | `VALIDATION_ERROR` | O corpo, a query ou o caminho não passou na validação. `data.details` lista cada problema como `{ path, message }` (`{ param, message }` na Image API), com o `index` da linha quando o corpo é um array de códigos. | Corrija os campos listados em `data.details` e envie a requisição de novo. |
| 400 | `INVALID_SLUG` | O final personalizado do link (`slug`) quebra uma regra: é uma palavra reservada, ou o mesmo final aparece duas vezes na mesma requisição. Em um array, `data.details` lista cada linha por `index`. | Escolha outro final de link. A mensagem indica a regra. |
| 400 | `TOO_MANY_CODES` | Mais de 1.000 códigos em uma única requisição. Normalmente o schema do corpo rejeita isso antes, como `VALIDATION_ERROR`. | Envie no máximo 1.000 códigos por requisição. |
| 400 | `DOMAIN_NOT_VERIFIED` | `domainId` aponta para um domínio personalizado que ainda não foi verificado. | Conclua a verificação do domínio na página Domínios ou deixe `domainId` de fora. |
| 400 | `SID_REQUIRED` | Uma conversão sem o `qrdx_sid` da leitura (vinda do navegador), ou sem `sid` ou `code` (vinda de um servidor). | Envie o `qrdx_sid` que o link curto adicionou à URL da sua página ou, com uma chave de API ou token, o id do código como `code`. |
| 401 | `UNAUTHORIZED` | Sem credenciais: a requisição não tem o header `Authorization: Bearer` (nem sessão de navegador do QRdx). | Envie uma chave de API como `Authorization: Bearer <key>`; crie uma em Configurações → Chaves de API e apps. Os tokens de acesso OAuth vão no mesmo header. |
| 401 | `INVALID_TOKEN` | A chave de API ou o token de acesso é desconhecido, foi revogado ou expirou (os tokens de acesso duram uma hora), ou quem criou a chave foi banido ou saiu do workspace da chave. | Confira se você enviou a chave inteira ou crie uma nova. No caso de um token de acesso, obtenha um novo com o refresh token ou leve o usuário pela autorização de novo. |
| 402 | `PLAN_REQUIRED` | O recurso não está no plano do workspace: criação em massa, finais de link personalizados e domínios personalizados exigem Pro; conversões e hooks exigem Business. | Faça upgrade do workspace ou tire o recurso da requisição. |
| 402 | `LIMIT_REACHED` | O workspace já tem o máximo de QR codes dinâmicos ativos que o plano inclui (10 no Grátis). | Arquive um código (códigos arquivados não contam) ou faça upgrade para o Pro e tenha códigos ilimitados. |
| 403 | `INSUFFICIENT_SCOPE` | A chave de API ou o token é válido, mas não tem o escopo que este endpoint exige. | Crie uma chave com o escopo indicado na mensagem (não dá para alterar os escopos de uma chave). Em um app OAuth, adicione o escopo e peça-o quando o usuário autorizar. |
| 403 | `FORBIDDEN` | Quem fez a chamada não pode fazer isso: um membro do workspace excluindo um código criado por outra pessoa, um membro gerenciando hooks, ou uma escrita com sessão de navegador vinda de outro site. Uma chave de API só pode fazer o que o papel de quem a criou permite no workspace. | Peça a um proprietário ou administrador do workspace, ou chame a API com uma chave de API a partir do seu servidor. |
| 403 | `CONFIRMATION_REQUIRED` | Criar um hook com uma sessão de navegador autenticada exige um "Confirme que é você" recente. Chaves de API e tokens OAuth não passam por essa confirmação. | Confirme que é você no QRdx e tente de novo em até 10 minutos, ou crie o hook com uma chave de API a partir do seu servidor. |
| 403 | `CONVERSIONS_OFF` | Uma conversão do navegador para um código que não tem o rastreamento de conversões ativado. | Ative o rastreamento de conversões do código, ou registre a conversão a partir do seu servidor com uma chave de API. |
| 403 | `LIMIT_REACHED` | O workspace já tem 20 endpoints de webhook e hooks. | Exclua um endpoint ou hook que você não usa mais. |
| 404 | `NOT_FOUND` | O endpoint não existe, ou o código, hook, tema ou domínio personalizado não existe no workspace em que a chave ou o token atua. | Confira o caminho e o id. Uma chave de API atua no workspace em que foi criada; um token OAuth atua no workspace do próprio usuário. |
| 404 | `INVALID_SID` | O `qrdx_sid` é desconhecido ou tem mais de 30 dias, a janela de atribuição. | Envie o `qrdx_sid` de uma leitura recente ou registre a conversão pelo id do código a partir do seu servidor. |
| 409 | `SLUG_TAKEN` | Outro código já usa esse final de link nesse domínio. Em um array, `data.details` lista cada final já em uso por `index`, e nada é criado. | Escolha outro final de link. |
| 413 | `PAYLOAD_TOO_LARGE` | O corpo passa do limite do endpoint: 4 MB para códigos, 16 KB para hooks, 8 KB para conversões. Também vale para um lote de códigos cuja resposta (cada código com seu design) passaria de 4 MB; nada é criado. | Envie um corpo menor. Para códigos, a causa mais comum é um logo inline grande; para um lote, envie `Prefer: return=minimal` ou menos códigos. |
| 415 | `UNSUPPORTED_MEDIA_TYPE` | Uma escrita sem `Content-Type: application/json`. | Envie um corpo JSON com `Content-Type: application/json`. |
| 422 | `UNSAFE_DESTINATION` | O Google Web Risk sinaliza a URL de destino (malware, phishing ou software indesejado). Em um array, `data.details` lista cada linha sinalizada por `index`, e nada é criado. | Use outro destino. Se a sinalização estiver errada, peça ao Google para revisar o site. |
| 429 | `RATE_LIMITED` | Requisições demais: um limite por minuto (só `Retry-After` é definido) ou a cota diária do workspace (`Retry-After` mais `X-RateLimit-*`). | Espere os segundos indicados em `Retry-After`. Para a cota diária, espere até 00:00 UTC ou faça upgrade do plano. |
| 500 | `INTERNAL_ERROR` | Algo falhou do lado do QRdx. O erro foi registrado. | Tente de novo em instantes. Se continuar acontecendo, relate o problema informando o horário da requisição. |
| 503 | `SLUG_UNAVAILABLE` | Não foi possível reservar a tempo um slug de link curto livre. | Envie a mesma requisição de novo. |
| 503 | `UNAVAILABLE` | Os domínios personalizados não estão configurados nesta instalação (uma instância auto-hospedada sem eles). | Deixe `domainId` de fora ou configure os domínios personalizados na sua instância. |

## Tentar de novo [#retrying]

- **`429`:** espere o número de segundos de `Retry-After` e envie a mesma requisição. Quando a cota diária acaba, os headers `X-RateLimit-*` indicam quantas requisições o plano permite e quando a contagem é zerada (00:00 UTC). Veja os [limites de uso](/docs/developers/rest-api#rate-limits).
- **`500` e `503`:** tente de novo com backoff exponencial, começando em cerca de um segundo.
- **Outros `4xx`:** a mesma requisição vai falhar do mesmo jeito. Corrija-a primeiro.

Criar códigos não é idempotente: se um `POST /v1/codes` der timeout, liste seus códigos antes de enviá-lo de novo, senão você pode criar o código duas vezes. Conversões são idempotentes: envie seu próprio `id` e uma repetição retorna `200` com `duplicate: true`.

## `/v1/me` e `/v1/themes` [#v1me-and-v1themes]

Esses dois endpoints enviam o mesmo corpo, mais os campos OAuth que sempre enviaram, `error` e `error_description` (o mesmo texto de `message`), para que clientes mais antigos continuem funcionando:

| `error` | `code` |
| --- | --- |
| `invalid_token` | UNAUTHORIZED ou INVALID_TOKEN |
| `insufficient_scope` | INSUFFICIENT_SCOPE |
| `rate_limited` | RATE_LIMITED (cota diária) |
| `not_found` | NOT_FOUND (temas) |

## Endpoints OAuth [#oauth-endpoints]

Os endpoints OAuth em `https://qrdx.dev/api/oauth` (authorize, token, revoke, userinfo) seguem o padrão OAuth 2.0: `{ "error", "error_description" }`, com `error` sendo `invalid_request`, `invalid_client`, `invalid_grant`, `unsupported_grant_type`, `invalid_token` ou `access_denied`. Receber `invalid_grant` ao renovar significa que o refresh token já foi usado (cada renovação retorna um novo), expirou após 30 dias, ou o usuário revogou seu app: leve o usuário pela autorização de novo. Veja [REST API e OAuth](/docs/developers/rest-api#get-an-access-token).

## Endpoints desconhecidos [#unknown-endpoints]

Um caminho em `/v1` que não existe retorna `404 NOT_FOUND` em JSON, nunca uma página HTML. A [referência da API](/docs/developers/api) lista todos os endpoints.
