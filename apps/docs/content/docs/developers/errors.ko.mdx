모든 REST API 오류는 어느 엔드포인트에서 반환되든 같은 형태의 JSON입니다.

```json
{
  "code": "INSUFFICIENT_SCOPE",
  "message": "This API key needs the 'codes:write' scope. Create a key that includes it at https://qrdx.dev/dashboard?to=settings/developers; a key's scopes can't be changed.",
  "status": 403,
  "docs": "https://qrdx.dev/docs/developers/api-keys"
}
```

| 필드 | 설명 |
| --- | --- |
| `code` | 아래 표에 있는 안정적인 기계 판독용 코드입니다. 이 값으로 분기하세요. |
| `message` | 무엇이 잘못되었는지, 어떻게 해결하는지를 사람이 읽도록 설명한 문장입니다. 문구는 바뀔 수 있습니다. |
| `status` | HTTP 상태를 그대로 한 번 더 담습니다. |
| `docs` | 해결 방법을 설명하는 페이지입니다. 있는 경우에만 포함됩니다. |
| `data` | 일부 오류에 담기는 추가 정보입니다. `VALIDATION_ERROR`는 각 문제를 `data.details`에 나열합니다. |

검증 오류는 실패한 모든 필드를 알려 줍니다.

```json
{
  "code": "VALIDATION_ERROR",
  "message": "Invalid request body",
  "status": 400,
  "data": {
    "details": [
      { "path": "destinationUrl", "message": "Enter a full URL, starting with https://" }
    ]
  }
}
```

Image API는 쿼리 매개변수를 `{ "path", "message" }` 대신 `{ "param", "message" }` 형태로 알려 줍니다.

## 오류 코드 [#error-codes]

| 상태 | 코드 | 의미 | 해결 방법 |
| --- | --- | --- | --- |
| 400 | `VALIDATION_ERROR` | 본문, 쿼리 또는 경로가 검증에 실패했습니다. `data.details`에 각 문제가 `{ path, message }` 형태로 나열됩니다(Image API는 `{ param, message }`). 본문이 코드 배열이면 해당 행의 `index`도 함께 표시됩니다. | `data.details`에 나열된 필드를 고친 뒤 요청을 다시 보내세요. |
| 400 | `INVALID_SLUG` | 사용자 지정 back-half(`slug`)가 규칙에 어긋납니다. 예약어이거나, 한 요청에서 같은 back-half를 두 번 썼습니다. 배열이면 `data.details`에 각 행이 `index`로 나열됩니다. | 다른 back-half를 고르세요. 메시지에 어떤 규칙인지 나와 있습니다. |
| 400 | `TOO_MANY_CODES` | 한 요청에 코드가 1,000개를 넘었습니다. 보통은 본문 스키마가 먼저 `VALIDATION_ERROR`로 거부합니다. | 요청당 코드를 최대 1,000개까지만 보내세요. |
| 400 | `DOMAIN_NOT_VERIFIED` | `domainId`가 아직 확인되지 않은 사용자 지정 도메인을 가리킵니다. | 도메인 페이지에서 도메인 확인을 마치거나, `domainId`를 빼세요. |
| 400 | `SID_REQUIRED` | 전환을 보냈는데 스캔의 `qrdx_sid`가 없거나(브라우저에서), `sid` 또는 `code`가 없습니다(서버에서). | 짧은 링크가 페이지 URL에 붙여 준 `qrdx_sid`를 보내세요. API 키나 토큰을 쓸 때는 코드 id를 `code`로 보내세요. |
| 401 | `UNAUTHORIZED` | 자격 증명이 없습니다. 요청에 `Authorization: Bearer` 헤더가 없습니다(QRdx 브라우저 세션도 없음). | API 키를 `Authorization: Bearer <key>` 형식으로 보내세요. 키는 설정 → API 키 및 앱에서 만들 수 있습니다. OAuth 액세스 토큰도 같은 헤더에 넣습니다. |
| 401 | `INVALID_TOKEN` | API 키나 액세스 토큰을 알 수 없거나, 폐기되었거나, 만료되었습니다(액세스 토큰은 1시간 동안 유효). 또는 키를 만든 사람이 차단되었거나 키의 워크스페이스를 떠났습니다. | 키 전체를 보냈는지 확인하거나 새 키를 만드세요. 액세스 토큰이면 리프레시 토큰으로 새로 받거나, 사용자가 다시 인증하도록 하세요. |
| 402 | `PLAN_REQUIRED` | 워크스페이스 요금제에 없는 기능입니다. 대량 생성, 사용자 지정 back-half, 사용자 지정 도메인은 Pro가 필요하고, 전환과 훅은 Business가 필요합니다. | 워크스페이스를 업그레이드하거나, 요청에서 해당 기능을 빼세요. |
| 402 | `LIMIT_REACHED` | 워크스페이스의 활성 동적 코드 수가 요금제에 포함된 개수에 도달했습니다(무료는 10개). | 코드를 보관하거나(보관된 코드는 세지 않습니다) Pro로 업그레이드해 무제한으로 사용하세요. |
| 403 | `INSUFFICIENT_SCOPE` | API 키나 토큰은 유효하지만 이 엔드포인트에 필요한 스코프가 없습니다. | 메시지에 나온 스코프로 키를 새로 만드세요(키의 스코프는 바꿀 수 없습니다). OAuth 앱이면 스코프를 추가하고 사용자가 인증할 때 요청하세요. |
| 403 | `FORBIDDEN` | 호출한 주체에게 이 작업의 권한이 없습니다. 예를 들어 워크스페이스 멤버가 다른 사람이 만든 코드를 삭제하거나, 멤버가 훅을 관리하거나, 다른 사이트에서 브라우저 세션으로 쓰기를 시도한 경우입니다. API 키는 워크스페이스에서 키를 만든 사람의 역할이 허용하는 작업만 할 수 있습니다. | 워크스페이스 소유자나 관리자에게 요청하거나, 서버에서 API 키로 API를 호출하세요. |
| 403 | `CONFIRMATION_REQUIRED` | 로그인한 브라우저 세션으로 훅을 만들려면 최근의 "본인 확인"이 필요합니다. API 키와 OAuth 토큰은 확인을 요구하지 않습니다. | QRdx에서 본인 확인을 한 뒤 10분 안에 다시 시도하거나, 서버에서 API 키로 훅을 만드세요. |
| 403 | `CONVERSIONS_OFF` | 전환 추적이 켜져 있지 않은 코드에 대해 브라우저에서 전환을 보냈습니다. | 코드의 전환 추적을 켜거나, 서버에서 API 키로 전환을 보고하세요. |
| 403 | `LIMIT_REACHED` | 워크스페이스에 웹훅 엔드포인트와 훅이 이미 20개 있습니다. | 더 이상 쓰지 않는 엔드포인트나 훅을 삭제하세요. |
| 404 | `NOT_FOUND` | 해당 엔드포인트가 없거나, 키 또는 토큰이 작동하는 워크스페이스에 그 코드, 훅, 테마, 사용자 지정 도메인이 없습니다. | 경로와 id를 확인하세요. API 키는 만들어진 워크스페이스에서 작동하고, OAuth 토큰은 해당 사용자의 워크스페이스에서 작동합니다. |
| 404 | `INVALID_SID` | `qrdx_sid`를 알 수 없거나, 기여 기간인 30일보다 오래되었습니다. | 최근 스캔의 `qrdx_sid`를 보내거나, 서버에서 코드 id로 전환을 보고하세요. |
| 409 | `SLUG_TAKEN` | 같은 도메인에서 다른 코드가 이미 그 back-half를 쓰고 있습니다. 배열이면 `data.details`에 사용 중인 각 행이 `index`로 나열되며, 아무것도 생성되지 않습니다. | 다른 back-half를 고르세요. |
| 413 | `PAYLOAD_TOO_LARGE` | 본문이 엔드포인트의 제한을 넘었습니다. 코드는 4 MB, 훅은 16 KB, 전환은 8 KB입니다. 각 코드와 디자인을 포함한 응답이 4 MB를 넘는 코드 배치도 해당하며, 아무것도 생성되지 않습니다. | 본문을 줄여서 보내세요. 코드는 큰 인라인 로고가 흔한 원인이고, 배치는 `Prefer: return=minimal`을 보내거나 코드 수를 줄이세요. |
| 415 | `UNSUPPORTED_MEDIA_TYPE` | `Content-Type: application/json` 없이 쓰기 요청을 보냈습니다. | `Content-Type: application/json`과 함께 JSON 본문을 보내세요. |
| 422 | `UNSAFE_DESTINATION` | Google Web Risk가 대상 URL을 위험으로 표시했습니다(악성코드, 피싱 또는 원치 않는 소프트웨어). 배열이면 `data.details`에 표시된 각 행이 `index`로 나열되며, 아무것도 생성되지 않습니다. | 다른 대상을 사용하세요. 잘못 표시된 경우 Google에 사이트 검토를 요청하세요. |
| 429 | `RATE_LIMITED` | 요청이 너무 많습니다. 분당 제한(`Retry-After`만 설정됨) 또는 워크스페이스의 일일 할당량(`Retry-After`와 `X-RateLimit-*`)에 걸렸습니다. | `Retry-After`에 적힌 초만큼 기다리세요. 일일 할당량이면 00:00 UTC까지 기다리거나 요금제를 업그레이드하세요. |
| 500 | `INTERNAL_ERROR` | QRdx 쪽에서 문제가 발생했습니다. 로그에는 기록되었습니다. | 잠시 후 다시 시도하세요. 계속 발생하면 요청 시각과 함께 알려 주세요. |
| 503 | `SLUG_UNAVAILABLE` | 제때 예약할 수 있는 빈 짧은 링크 슬러그가 없었습니다. | 같은 요청을 다시 보내세요. |
| 503 | `UNAVAILABLE` | 이 배포에는 사용자 지정 도메인이 설정되어 있지 않습니다(이를 갖추지 않은 셀프 호스팅 인스턴스). | `domainId`를 빼거나, 인스턴스에서 사용자 지정 도메인을 설정하세요. |

## 재시도 [#retrying]

- **`429`:** `Retry-After`에 적힌 초만큼 기다린 뒤 같은 요청을 보내세요. 일일 할당량이 소진되면 `X-RateLimit-*` 헤더가 요금제에서 허용하는 요청 수와 카운트가 초기화되는 시각(00:00 UTC)을 알려 줍니다. [속도 제한](/docs/developers/rest-api#rate-limits)을 참고하세요.
- **`500` 및 `503`:** 약 1초에서 시작해 지수 백오프로 재시도하세요.
- **그 밖의 `4xx`:** 같은 요청은 같은 방식으로 실패합니다. 먼저 문제를 고치세요.

코드 생성은 멱등이 아닙니다. `POST /v1/codes`가 시간 초과되면 다시 보내기 전에 코드 목록을 먼저 확인하세요. 그렇지 않으면 코드가 두 번 만들어질 수 있습니다. 전환은 멱등입니다. 직접 정한 `id`를 보내면 반복 요청에 `duplicate: true`와 함께 `200`을 반환합니다.

## `/v1/me` 및 `/v1/themes` [#v1me-and-v1themes]

이 두 엔드포인트는 같은 본문에 더해, 예전부터 보내던 OAuth 필드인 `error`와 `error_description`(`message`와 같은 텍스트)을 함께 보내므로 이전 클라이언트도 계속 작동합니다.

| `error` | `code` |
| --- | --- |
| `invalid_token` | UNAUTHORIZED 또는 INVALID_TOKEN |
| `insufficient_scope` | INSUFFICIENT_SCOPE |
| `rate_limited` | RATE_LIMITED (일일 할당량) |
| `not_found` | NOT_FOUND (테마) |

## OAuth 엔드포인트 [#oauth-endpoints]

`https://qrdx.dev/api/oauth` 아래의 OAuth 엔드포인트(authorize, token, revoke, userinfo)는 대신 OAuth 2.0 표준인 `{ "error", "error_description" }` 형태를 따르며, `error`는 `invalid_request`, `invalid_client`, `invalid_grant`, `unsupported_grant_type`, `invalid_token`, `access_denied` 중 하나입니다. 토큰 갱신에서 `invalid_grant`가 나오면 리프레시 토큰이 이미 사용되었거나(갱신할 때마다 새 토큰이 반환됩니다), 30일이 지나 만료되었거나, 사용자가 앱을 해제했다는 뜻입니다. 사용자가 다시 인증하도록 하세요. [REST API 및 OAuth](/docs/developers/rest-api#get-an-access-token)를 참고하세요.

## 알 수 없는 엔드포인트 [#unknown-endpoints]

`/v1` 아래에 존재하지 않는 경로를 요청하면 HTML 페이지가 아니라 JSON 형식의 `404 NOT_FOUND`가 반환돼요. 모든 엔드포인트는 [API 레퍼런스](/docs/developers/api)에서 확인할 수 있어요.
