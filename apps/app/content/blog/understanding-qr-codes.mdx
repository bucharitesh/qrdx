Scanning a QR code takes a second: aim a camera, tap a link. The code itself is a carefully standardized binary barcode, a grid of black and white modules that stores bits, protects them with error correction, and lays them out so a decoder can read them from almost any angle.

This post explains how each of those parts works, for anyone who builds or designs with QR codes.

## QR codes vs. traditional barcodes

A 1D barcode, such as a UPC, stores data in stripes of varying width along a single line. It is dense in one direction and fragile in the other: a smudge or a bad angle can wipe out a whole scan line.

A QR (Quick Response) code is two-dimensional: the data sits in a square matrix of modules, usually black on white. That gives you more capacity in the same printed area, and the code can be read in any orientation, because the decoder works out which way is up from the pattern itself.

The same three bullseye squares appear in every QR code because they make that possible: they are how the decoder finds the code and aligns it.

A QR symbol is a square of modules, the printed equivalent of pixels. The smallest standard version, Version 1, is 21×21 modules, and each version up adds 4 modules per side:

- Version 1: 21×21
- Version 2: 25×25
- Version 40: 177×177 (the largest defined in the common standard)

Larger versions carry more data and more error-correction redundancy.

### Finder patterns

Three finder patterns sit in the top-left, top-right and bottom-left corners. Each is 7×7 modules: a 3×3 dark core inside a one-module light ring, inside a one-module dark ring. A one-module light separator keeps each finder apart from the data around it.

Scanners look for these shapes first. With three of them, software can work out the code's scale, rotation and perspective, which is how your phone still reads a sticker skewed on a curved cup.

### Timing patterns

Timing patterns are runs of alternating black and white modules between the finder patterns. They work like a ruler printed into the code: the decoder uses them to count modules and stay synchronized as it walks the grid.

### Alignment patterns (larger versions)

From Version 2 up, smaller alignment patterns appear inside the code. They refine the position when the surface is curved or the image is distorted, as on bottle labels and flexible packaging.

### Quiet zone

The standard expects a margin of light modules around the symbol, called the quiet zone. Without it, nearby graphics can blend into the code and confuse the edge detector. Always leave that blank space around a QR code; your design tool should enforce it.

## What gets encoded: bit streams and segments

At the lowest level, a QR code stores a bit stream made of:

1. Mode indicators: how to interpret the next chunk
2. Character count: how long that chunk is
3. Payload: the data itself
4. Terminator and padding: fill out to a byte boundary
5. Error correction codewords: Reed-Solomon redundancy

### Data modes

The encoder picks the mode that stores the payload most efficiently:

| Mode | Typical use | Idea |
|------|-------------|------|
| **Numeric** | Digits only | Packs triples of digits into 10 bits |
| **Alphanumeric** | `0–9`, `A–Z`, space, `$%*+-./:` | 5.5 bits per character (pairs) |
| **Byte** | Arbitrary bytes (URLs, UTF-8) | 8 bits per byte |
| **Kanji** | Shift JIS kanji | Compact for Japanese text |

One QR code can mix several segments in different modes, for example an optimized numeric chunk followed by a byte-mode URL.

### Capacity vs. error correction

A QR code's "maximum characters" depends on its error-correction level. Error correction takes up a large share of the codewords, so the same Version 5 symbol holds more data at level L (low recovery) than at level H (high recovery).

Roughly:

- Level L: about 7% recovery, the largest payload and the least robust
- Level M: about 15%
- Level Q: about 25%
- Level H: about 30%, the smallest payload, and it survives the most damage (partial occlusion, dirt)

Marketing codes on outdoor signs often use M or Q. Tiny codes on screens can sometimes use L if the conditions are clean.

## Error correction: why a torn code still scans

<Figure

  width={1600}

  caption="This code uses level H. The missing patch covers about 9% of it and it still decodes: Reed-Solomon parity rebuilds the lost codewords, up to the level's limit."
/>

QR codes use Reed-Solomon codes over GF(256). The encoder computes extra parity-like bytes from your message, and the decoder uses them to rebuild missing or wrong modules, up to a limit.

That's why a code with a scuffed edge, a fingertip over part of the data area or a logo (within the standard's limits) still gives a readable payload: the decoder reconstructs the original bit stream exactly. Error correction can't fix a hidden finder pattern, though. If the decoder can't locate the code, it never gets as far as the math.

A logo in the center is the same kind of damage, so it's safe only if enough redundancy is left to cover the modules it blocks. That means storing less data, or raising the version or error-correction level.

## Mask patterns: making the code easier to read

Once the data and error-correction bytes are placed on the grid by the standard's placement rules, the encoder XORs the data area with one of eight mask patterns. This breaks up large areas of one color and patterns that look like parts of a finder.

The standard defines a penalty score for each mask, and the encoder picks the mask with the lowest score. With the same URL and the same error-correction level, the black and white arrangement can still change if a different mask wins.

In normal tools you don't pick the mask; the generator does it for you.

## What happens when you scan

A modern scanner works roughly like this:

1. Image capture: a camera frame, possibly HDR
2. Find the finder patterns: locate the three squares
3. Homography (perspective warp): flatten the grid
4. Sample modules: decide black or white for each cell, with a threshold that adapts to the lighting
5. Read the format info: error-correction level and mask pattern (plus version info from Version 7 up)
6. Extract and correct codewords: Reed-Solomon recovery
7. Parse segments: modes and payload
8. Hand off: a URL, Wi-Fi settings, a vCard and so on

Apps implement these steps with different heuristics, so contrast, the quiet zone and module size still matter in the real world, even though the error correction is forgiving.

## What this means for design

Taste still decides the look, but the format limits what is safe:

- The quiet zone is part of the spec. Don't trim it.
- Decoders threshold brightness, so contrast is what they measure. Keep dark modules on a light background and avoid light gray on white. The current standard allows inverted (light-on-dark) codes, but some older scanners still fail on them.
- A logo costs payload capacity, so a generator should check that the code still scans, as well as how it looks.
