Un QR code dynamique encode un lien court, comme `https://qrdx.dev/q/aB3dE5f`, au lieu de votre URL finale. Le scan ouvre le lien court, qui redirige vers la destination que vous avez définie. Vous pouvez modifier la destination à tout moment, de sorte que les codes imprimés ne deviennent jamais obsolètes, et chaque scan est comptabilisé.

Les QR codes statiques créés depuis le Playground et depuis la bibliothèque `qrdx` restent gratuits et illimités. Les QR codes dynamiques nécessitent un compte QRdx.

## Créer un code dynamique [#create-a-dynamic-code]

- **Tableau de bord :** ouvrez [tableau de bord](/dashboard), cliquez sur **Nouveau code**, saisissez l'URL de destination et un titre facultatif. Téléchargez le code au format PNG, WebP ou SVG.
- **Playground :** choisissez le type de contenu **URL**, saisissez votre lien et activez **Rendre dynamique**. Le QR code passe à un lien court et conserve votre design. Si vous modifiez ensuite l'URL, cliquez sur **Rediriger vers la nouvelle URL** pour mettre à jour la destination. **Enregistrer le design dans le code** enregistre le design actuel avec le code.

Les destinations doivent être des liens `http://` ou `https://`. Les liens contenant un nom d'utilisateur ou un mot de passe, ainsi que les liens vers d'autres liens courts QRdx, sont refusés.

## Suffixes personnalisés [#custom-back-halves]

Chaque code reçoit un suffixe aléatoire de 7 caractères, la partie qui suit `/q/`. Avec les offres Pro et Business, vous pouvez choisir le vôtre, par exemple `https://qrdx.dev/q/spring-menu` : renseignez **Suffixe personnalisé** lors de la création ou de la modification d'un code, et la boîte de dialogue vous indique, pendant la saisie, si le suffixe est disponible.

- De 3 à 64 caractères : lettres, chiffres, `-` et `_`, sans commencer ni finir par `-`.
- Les suffixes sont sensibles à la casse, comme les suffixes générés : `Spring-Menu` et `spring-menu` sont deux liens différents.
- Sur `qrdx.dev`, un suffixe est unique dans l'ensemble de QRdx, et les mots qui correspondent à des pages de QRdx (`admin`, `api`, `docs`, `login`, `pricing`, `settings`, ...) sont réservés.
- Sur votre propre [domaine personnalisé](/docs/custom-domains), il doit seulement être unique sur ce domaine, et seuls `api`, `p` et `q` sont réservés. Ainsi, `go.yourbrand.com/pricing` fonctionne. Un tel suffixe appartient au domaine : il n'a pas de lien `qrdx.dev/q/`.
- Modifier le suffixe d'un code change son lien : les QR codes imprimés avec l'ancien ne fonctionnent plus. Téléchargez donc à nouveau le code.

## Gérer les codes [#manage-codes]

Depuis le tableau de bord, vous pouvez :

- **Modifier le lien :** changer la destination ou le titre. Le code imprimé continue de fonctionner et ouvre la nouvelle destination au prochain scan.
- **Changer le type :** transformer un lien vers un site web en [page hébergée](/docs/landing-pages), une page en lien, ou une page en un autre type de page. Le lien court et les scans sont conservés. Voir [Modifier la destination d'un code imprimé](/docs/help/dynamic-codes/change-the-type).
- **Modifier le design dans le Playground :** ouvre le code dans l'éditeur, toujours lié à son lien court.
- **Archiver :** le lien court affiche une page « plus active » jusqu'à ce que vous restauriez le code. Les codes archivés ne comptent pas dans la limite de votre offre.
- **Déplacer dans la corbeille :** le lien court affiche une page « plus active » (HTTP 410) et le code ne compte plus dans votre offre. Restaurez-le depuis la **Corbeille**, ou supprimez-le définitivement depuis cet endroit, ce qui efface aussi son historique de scans ; le lien court affiche alors une page « QR code introuvable ». Une suppression via l'API (`DELETE /v1/codes/{id}`) est définitive immédiatement.
- **Dupliquer :** copie la destination, le design, le dossier, les étiquettes et les notes dans un nouveau code, avec un nouveau lien court et aucun scan.
- **Historique des versions :** chaque modification est enregistrée sur la page du code ; restaurer une version enregistre d'abord les paramètres actuels, de sorte qu'une restauration peut être annulée.

## Organiser les codes [#organize-codes]

- **Dossiers :** imbriquez-les jusqu'à 5 niveaux. Faites glisser les codes sur un dossier ou utilisez **Déplacer vers un dossier**. Supprimer un dossier remonte ses codes et sous-dossiers d'un niveau.
- **Étiquettes :** filtrez par plusieurs étiquettes pour voir les codes qui les possèdent toutes.
- **Favoris et notes :** ajoutez des codes en favori et gardez des notes privées ; les notes sont consultables par la recherche.
- **Recherche :** couvre les titres, les destinations, les notes, les étiquettes et les suffixes (collez un lien court pour retrouver son code).
- **Actions groupées :** sélectionnez des codes pour les déplacer, les étiqueter, les suspendre, les archiver, les ajouter aux favoris, les mettre à la corbeille ou les télécharger dans une archive ZIP de fichiers PNG, WebP ou SVG.
- **Import CSV :** **Codes → Importer** crée jusqu'à {facts.importRows} codes dynamiques à partir d'un seul CSV (destination, titre, dossier, étiquettes, suffixe personnalisé facultatif dans la colonne `slug`), et peut classer tous les codes dans un même dossier et ajouter des étiquettes à tous. Un import long peut être mis en pause et reprend après un rechargement de la page ou une coupure de connexion, sans créer deux fois le même code. Il se termine par un CSV de résultats (le lien court de chaque ligne) et par une archive ZIP des codes au format PNG ou SVG. Importer plus d'une ligne, ainsi que les suffixes personnalisés, nécessite l'offre Pro.

Les codes appartiennent à l'espace de travail dans lequel ils sont créés. Chaque membre de l'espace de travail peut créer et modifier des codes ; les membres peuvent supprimer leurs propres codes, et les propriétaires et administrateurs peuvent supprimer tout code de l'espace de travail.

<Callout type="info">
  Les codes ne expirent jamais : passer à une offre inférieure ne désactive jamais les codes existants. Au-delà de la limite, vous pouvez toujours modifier et archiver des codes ; vous ne pouvez simplement pas en créer ou en restaurer d'autres tant que vous n'êtes pas repassé sous la limite.
</Callout>

## Statistiques des scans [#scan-analytics]

Chaque code dispose d'une page de statistiques avec les scans dans le temps, les visiteurs uniques, les principaux pays et villes, les appareils, les systèmes d'exploitation, les navigateurs et les sources de trafic, pour les 7, 30 ou 90 derniers jours, 1 an ou 3 ans, ou depuis le premier scan du code (limité par l'historique de votre offre : toute la période est disponible avec Pro et Business). Vous pouvez exporter les scans de la période sélectionnée au format CSV.

Pour chaque scan, sont enregistrés :

- L'heure (UTC), ainsi que le pays, la région et la ville lorsque la plateforme d'hébergement les fournit (en-têtes géographiques de Vercel sur qrdx.dev)
- Le type d'appareil, le système d'exploitation et le navigateur, détectés à partir du user agent
- Uniquement le nom d'hôte de la source du trafic, jamais l'URL complète. La plupart des scans de QR codes n'ont pas de source.
- Un hachage du visiteur : un SHA-256 salé de l'adresse IP, du user agent et du jour. Il permet de compter les visiteurs uniques par jour ; l'adresse IP elle-même n'est jamais stockée.
- Avec Pro et Business, lorsque le code [demande la position précise](/docs/precise-location) et que la personne qui scanne l'autorise : sa position arrondie à 3 décimales (environ 100 m) et la précision signalée par son navigateur

Les robots connus, les aperçus de liens et les préchargements du navigateur ne sont pas comptabilisés.

## API REST [#rest-api]

Gérez vos codes par programmation sous `https://api.qrdx.dev/v1/codes`. Les requêtes sont authentifiées avec une [clé API](/docs/developers/api-keys) ou un jeton d'accès OAuth (`Authorization: Bearer <key or token>`) disposant de la portée `codes:read` ou `codes:write` ; consultez [API REST](/docs/developers/rest-api) pour savoir comment en obtenir un. Une clé agit sur l'espace de travail dans lequel elle a été créée, tandis que les requêtes faites avec un jeton agissent sur votre propre espace de travail. Les requêtes émises depuis une session de navigateur connectée fonctionnent aussi et agissent sur l'espace de travail que vous avez ouvert en dernier dans le tableau de bord.

| Méthode | Chemin | Description |
| --- | --- | --- |
| `GET` | `/v1/codes` | Lister les codes. Paramètres de requête : `status` (`active`, `archived`, `all`), `q`, `limit` (≤ 100), `offset` |
| `POST` | `/v1/codes` | Créer un code, ou un tableau de jusqu'à {facts.apiBatchCodes} codes (les tableaux nécessitent Pro). Corps : `destinationUrl`, `title`, `style`, `domainId` et `slug` en option |
| `GET` | `/v1/codes/{id}` | Obtenir un code |
| `PATCH` | `/v1/codes/{id}` | Mettre à jour `destinationUrl`, `title`, `style`, `domainId` ([domaines personnalisés](/docs/custom-domains)), `slug` ou `archived`, ou faire passer `kind` de `redirect` à `page` (ou inversement) |
| `DELETE` | `/v1/codes/{id}` | Supprimer un code et ses scans |
| `GET` | `/v1/codes/{id}/scans` | Statistiques pour `range` (`7d`, `30d`, `90d`, `365d`, `1095d`, ou `all` avec Pro et Business ; limité par l'historique de votre forfait). Ajoutez `limit` (≤ 500) pour les scans individuels, et `before` (le dernier `scannedAt`) pour la page suivante |

Créer un code :

```bash
curl https://api.qrdx.dev/v1/codes \
  -H "Authorization: Bearer $QRDX_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"destinationUrl": "https://example.com/menu", "title": "Spring menu"}'
```

```json
{
  "data": {
    "id": "cm3x...",
    "slug": "aB3dE5f",
    "shortLink": "https://qrdx.dev/q/aB3dE5f",
    "defaultShortLink": "https://qrdx.dev/q/aB3dE5f",
    "domain": null,
    "destinationUrl": "https://example.com/menu",
    "title": "Spring menu",
    "contentType": "url",
    "kind": "redirect",
    "pageId": null,
    "status": "active",
    "style": null,
    "scanCount": 0,
    "lastScannedAt": null,
    "archivedAt": null,
    "createdAt": "2026-10-31T12:00:00.000Z",
    "updatedAt": "2026-10-31T12:00:00.000Z",
    "organizationId": null
  }
}
```

Transmettez `slug` pour choisir la seconde moitié de l'URL (Pro et Business ; consultez [secondes moitiés personnalisées](#custom-back-halves) pour les règles). Avec un `domainId`, il est vérifié sur ce domaine, sinon sur `qrdx.dev` :

```bash
curl https://api.qrdx.dev/v1/codes \
  -H "Authorization: Bearer $QRDX_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"destinationUrl": "https://example.com/menu", "slug": "spring-menu"}'
```

La réponse contient alors `"slug": "spring-menu"` et `"shortLink": "https://qrdx.dev/q/spring-menu"`. Une seconde moitié choisie sur un domaine personnalisé renvoie `"defaultShortLink": null`, car elle n'existe que sur ce domaine. Dans un tableau, chaque `slug` doit être différent.

### Plusieurs codes en une seule requête [#many-codes-in-one-request]

Avec Pro et Business, envoyez un tableau de jusqu'à {facts.apiBatchCodes} codes. Les secondes moitiés générées ne se répètent jamais au sein du lot et n'entrent pas en conflit avec les codes existants. Les liens que Google Web Risk ne peut pas vérifier à temps sont à nouveau contrôlés peu après la création du lot, et un code dont le lien figure dans sa liste est désactivé ([contrôles de sécurité](/docs/code-controls#safety-checks-on-links)). Un lot est tout ou rien : si une ligne pose problème (une destination invalide, un `slug` déjà pris ou réservé, un lien dangereux), rien n'est créé et `data.details` de l'erreur répertorie chaque problème par `index`, c'est-à-dire la position de la ligne dans le tableau (à partir de 0).

Envoyez un en-tête `Idempotency-Key` avec une valeur unique pour le lot, comme un UUID. Si la requête expire ou si la connexion est coupée, renvoyez la même requête avec la même clé : vous recevez les codes créés par la première tentative, avec un en-tête `Idempotent-Replayed: true`, et une tentative interrompue en cours de route est achevée sans créer deux fois le même code.

```bash
curl https://api.qrdx.dev/v1/codes \
  -H "Authorization: Bearer $QRDX_TOKEN" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: 6f1c2a9e-spring-tables" \
  -H "Prefer: return=minimal" \
  -d '[{"destinationUrl": "https://example.com/table/1", "title": "Table 1"},
       {"destinationUrl": "https://example.com/table/2", "title": "Table 2"}]'
```

Chaque code est renvoyé avec son design. Lorsque le thème par défaut de votre espace de travail intègre un logo, cela s'ajoute sur un lot important : envoyez `Prefer: return=minimal` pour obtenir chaque code sans `style` (son id, son slug, ses liens, sa destination, son titre, son statut et sa date de création). Un lot dont la réponse dépasserait 4 Mo est refusé avec `PAYLOAD_TOO_LARGE` avant toute création.

Modifier la destination :

```bash
curl -X PATCH https://api.qrdx.dev/v1/codes/cm3x... \
  -H "Authorization: Bearer $QRDX_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"destinationUrl": "https://example.com/summer-menu"}'
```

`style` accepte les mêmes champs de design que le playground (`fgColor`, `bgColor`, `bodyPattern`, `cornerEyePattern`, `level`, ...). Pour un logo, envoyez `logoIcon`<IfAvailable feature="fileStorage"> ou le `logoFileId` d'un fichier téléversé</IfAvailable> ([logos dans le style d'un code](/docs/developers/rest-api#code-logos)). Encodez `shortLink` dans votre QR code, par exemple avec la [bibliothèque `qrdx`](/docs/getting-started) ou l'[API d'images](/docs/developers/image-api).

Les erreurs suivent un seul format JSON, `{ "code": "...", "message": "...", "status": 400 }`, auquel s'ajoute un lien `docs` lorsqu'une page explique la correction :

| Statut | Code | Quand |
| --- | --- | --- |
| 400 | `VALIDATION_ERROR`, `INVALID_SLUG` | Corps ou paramètres de requête invalides (détails dans `data`, par `index` dans un lot), ou un `slug` qui ne respecte pas les règles ou qui est réservé |
| 401 | `UNAUTHORIZED`, `INVALID_TOKEN` | Aucun jeton `Authorization: Bearer`, ou jeton invalide, expiré ou révoqué ([obtenir un jeton](/docs/developers/rest-api#get-an-access-token)) |
| 402 | `LIMIT_REACHED`, `PLAN_REQUIRED` | Limite de codes actifs de votre forfait dépassée, ou création en masse ou `slug` personnalisé sans Pro |
| 403 | `INSUFFICIENT_SCOPE`, `FORBIDDEN` | Jeton sans la portée nécessaire, ou rôle dans l'espace de travail ne permettant pas cette action |
| 404 | `NOT_FOUND` | Le code n'existe pas ou ne vous appartient pas, ou le point de terminaison n'existe pas |
| 409 | `SLUG_TAKEN` | Un autre code utilise déjà ce `slug` (sur `qrdx.dev`, ou sur le domaine personnalisé) |
| 429 | `RATE_LIMITED` | Trop de requêtes ; réessayez après l'en-tête `Retry-After` |

## Auto-hébergement [#self-hosting]

Les codes dynamiques fonctionnent également sur les instances auto-hébergées :

- `NEXT_PUBLIC_SHORT_LINK_BASE_URL` définit l'origine des liens courts. Par défaut, il s'agit de l'URL de votre application.
- `SCAN_HASH_SALT` définit le sel secret des empreintes des visiteurs. Sans lui, il est dérivé de `BETTER_AUTH_SECRET`.
- Le pays, la région et la ville proviennent des en-têtes géographiques de Vercel. Derrière Cloudflare, seul le pays est disponible (`CF-IPCountry`) ; ailleurs, les localisations apparaissent comme inconnues.
- Les règles de zone utilisent les coordonnées IP de Vercel (`x-vercel-ip-latitude`, `x-vercel-ip-longitude`) lorsqu'un scanneur n'a pas partagé sa localisation. Ailleurs, elles ne correspondent qu'aux scans avec une localisation partagée.
- Les limites de débit s'appliquent lorsque Upstash Redis est configuré.
