동적 QR 코드는 최종 URL 대신 `https://qrdx.dev/q/aB3dE5f`와 같은 짧은 링크를 담습니다. 스캔하면 짧은 링크가 열리고, 설정한 대상 주소로 리디렉션됩니다. 대상 주소는 언제든지 바꿀 수 있어서 인쇄한 코드가 오래되지 않으며, 모든 스캔이 집계됩니다.

Playground와 `qrdx` 라이브러리에서 만든 정적 QR 코드는 계속 무료이며 사용 횟수에도 제한이 없습니다. 동적 코드는 QRdx 계정이 필요합니다.

## 동적 코드 만들기 [#create-a-dynamic-code]

- **대시보드:** [대시보드](/dashboard)를 열고 **새 코드**를 클릭한 다음, 대상 URL과 선택 사항인 제목을 입력합니다. 코드를 PNG, WebP 또는 SVG로 다운로드할 수 있습니다.
- **Playground:** 콘텐츠 유형으로 **URL**을 선택하고 링크를 입력한 다음 **동적으로 만들기**를 켭니다. QR 코드가 짧은 링크로 바뀌고 디자인은 그대로 유지됩니다. 나중에 URL을 수정하면 **새 URL로 연결**을 클릭해 대상 주소를 업데이트합니다. **디자인을 코드에 저장**을 누르면 현재 디자인이 코드와 함께 저장됩니다.

대상 주소는 `http://` 또는 `https://` 링크여야 합니다. 사용자 이름이나 비밀번호가 포함된 링크와 다른 QRdx 짧은 링크는 허용되지 않습니다.

## 사용자 지정 back-half [#custom-back-halves]

모든 코드에는 `/q/` 뒤에 붙는 7자리 무작위 back-half가 자동으로 생성됩니다. Pro와 Business에서는 `https://qrdx.dev/q/spring-menu`처럼 원하는 back-half를 직접 지정할 수 있습니다. 코드를 만들거나 수정할 때 **사용자 지정 back-half**를 입력하면, 입력하는 동안 대화상자에서 사용 가능 여부를 알려 줍니다.

- 3자 이상 64자 이하이며, 영문자, 숫자, `-`, `_`만 사용할 수 있습니다. `-`로 시작하거나 끝날 수 없습니다.
- 생성된 back-half와 마찬가지로 대소문자를 구분합니다. `Spring-Menu`와 `spring-menu`는 서로 다른 링크입니다.
- `qrdx.dev`에서는 back-half가 QRdx 전체에서 고유해야 하며, `admin`, `api`, `docs`, `login`, `pricing`, `settings` 등 QRdx 페이지로 읽히는 단어는 예약되어 있습니다.
- 직접 소유한 [사용자 지정 도메인](/docs/custom-domains)에서는 해당 도메인 안에서만 고유하면 되고, `api`, `p`, `q`만 예약되어 있으므로 `go.yourbrand.com/pricing`을 사용할 수 있습니다. 이런 back-half는 도메인에 속하며 `qrdx.dev/q/` 링크는 생성되지 않습니다.
- 코드의 back-half를 바꾸면 링크도 바뀝니다. 이전 back-half로 인쇄한 QR 코드는 더 이상 작동하지 않으므로 코드를 다시 다운로드해야 합니다.

## 코드 관리 [#manage-codes]

대시보드에서 다음 작업을 할 수 있습니다.

- **링크 수정:** 대상 주소나 제목을 바꿉니다. 인쇄한 코드는 계속 작동하며, 다음 스캔부터 새 대상 주소가 열립니다.
- **유형 변경:** 웹사이트 링크를 [호스팅 페이지](/docs/landing-pages)로, 페이지를 다시 링크로, 또는 페이지를 다른 페이지 유형으로 바꿉니다. 짧은 링크와 스캔 기록은 유지됩니다. 자세한 내용은 [인쇄한 코드가 여는 대상 바꾸기](/docs/help/dynamic-codes/change-the-type)를 참고하세요.
- **Playground에서 디자인 수정:** 코드를 편집기에서 열며, 여전히 같은 짧은 링크에 연결되어 있습니다.
- **보관:** 코드를 복원하기 전까지 짧은 링크는 "더 이상 활성 상태가 아님" 페이지를 표시합니다. 보관된 코드는 요금제 한도에 포함되지 않습니다.
- **휴지통으로 이동:** 짧은 링크는 "더 이상 활성 상태가 아님" 페이지(HTTP 410)를 표시하고, 코드는 요금제 한도에서 제외됩니다. **휴지통**에서 복원하거나 그곳에서 영구 삭제할 수 있습니다. 영구 삭제하면 스캔 기록도 함께 삭제되며, 이후 짧은 링크는 "QR 코드를 찾을 수 없음" 페이지를 표시합니다. API(`DELETE /v1/codes/{id}`)로 삭제하면 즉시 영구 삭제됩니다.
- **복제:** 대상 주소, 디자인, 폴더, 태그, 메모를 복사해 새 짧은 링크를 가진 새 코드를 만듭니다. 스캔 기록은 복사되지 않습니다.
- **버전 기록:** 모든 변경 사항이 코드 페이지에 기록됩니다. 버전을 복원하면 먼저 현재 설정이 저장되므로, 복원 작업도 되돌릴 수 있습니다.

## 코드 정리 [#organize-codes]

- **폴더:** 최대 5단계까지 중첩할 수 있습니다. 코드를 폴더로 끌어 놓거나 **폴더로 이동**을 사용합니다. 폴더를 삭제하면 그 안의 코드와 하위 폴더가 한 단계 위로 이동합니다.
- **태그:** 여러 태그로 필터링하여 해당 태그를 모두 가진 코드만 볼 수 있습니다.
- **즐겨찾기와 메모:** 코드에 별표를 하고 비공개 메모를 남길 수 있습니다. 메모도 검색됩니다.
- **검색:** 제목, 대상 주소, 메모, 태그, back-half를 검색합니다. 짧은 링크를 붙여 넣으면 해당 코드를 찾을 수 있습니다.
- **일괄 작업:** 여러 코드를 선택해 폴더로 이동, 태그 지정, 일시 중지, 보관, 즐겨찾기, 휴지통 이동을 하거나, PNG, WebP 또는 SVG 파일을 담은 ZIP으로 다운로드할 수 있습니다.
- **CSV 가져오기:** **코드 → 가져오기**에서 CSV 한 개로 동적 코드를 최대 {facts.importRows}개까지 만들 수 있습니다. CSV에는 대상 주소, 제목, 폴더, 태그, 그리고 `slug` 열에 선택 사항인 사용자 지정 back-half를 넣습니다. 모든 코드를 하나의 폴더에 넣고 모든 코드에 태그를 추가할 수도 있습니다. 오래 걸리는 가져오기는 일시 중지할 수 있으며, 새로 고침이나 연결이 끊긴 뒤에도 이어서 진행되고 같은 코드를 두 번 만들지 않습니다. 완료되면 각 행의 짧은 링크가 담긴 결과 CSV와 PNG 또는 SVG 코드를 담은 ZIP 파일이 제공됩니다. 한 행보다 많이 가져오거나 사용자 지정 back-half를 사용하려면 Pro가 필요합니다.

코드는 생성된 워크스페이스에 속합니다. 워크스페이스의 모든 구성원은 코드를 만들고 수정할 수 있습니다. 구성원은 자신이 만든 코드를 삭제할 수 있고, 소유자와 관리자는 워크스페이스의 모든 코드를 삭제할 수 있습니다.

<Callout type="info">
  코드는 만료되지 않습니다. 요금제를 낮춰도 기존 코드는 꺼지지 않습니다. 한도를 넘더라도 코드를 계속 수정하고 보관할 수 있으며, 한도 아래로 내려가기 전까지는 새 코드를 만들거나 복원할 수만 없습니다.
</Callout>

워크스페이스의 코드는 소유자들 중 가장 좋은 요금제를 적용받습니다. 각 요금제에 포함된 나머지 항목은 [요금제와 한도](/docs/plans-and-limits)를 참고하세요.

## 스캔 분석 [#scan-analytics]

각 코드에는 분석 페이지가 있습니다. 여기에서 시간에 따른 스캔 수, 고유 방문자, 상위 국가와 도시, 기기, 운영체제, 브라우저, 유입 경로를 확인할 수 있습니다. 기간은 최근 7일, 30일, 90일, 1년, 3년 또는 코드의 첫 스캔 이후 전체 기간 중에서 선택할 수 있습니다. 전체 기간은 요금제의 기록 보관 한도에 따라 제한됩니다. 전체 기간은 Pro와 Business에서만 사용할 수 있습니다. 선택한 기간의 스캔은 CSV로 내보낼 수 있습니다.

각 스캔에서 기록되는 항목은 다음과 같습니다.

- 시간(UTC), 그리고 호스팅 플랫폼이 제공하는 경우 국가, 지역, 도시(qrdx.dev에서는 Vercel 지리 정보 헤더 사용)
- 사용자 에이전트에서 감지한 기기 유형, 운영체제, 브라우저
- 유입 경로의 호스트 이름만 기록하며 전체 URL은 기록하지 않습니다. 대부분의 QR 스캔에는 유입 경로가 없습니다.
- 방문자 해시: IP 주소, 사용자 에이전트, 날짜에 솔트를 더한 SHA-256 값입니다. 하루 기준으로 고유 방문자를 집계하는 데 쓰이며, IP 주소 자체는 저장되지 않습니다.
- Pro와 Business에서, 코드가 [정확한 위치를 요청](/docs/precise-location)하고 스캔하는 사람이 허용한 경우에만 소수점 3자리(약 100m)로 반올림한 위치와 브라우저가 보고한 정확도

알려진 봇, 링크 미리보기, 브라우저 사전 로드는 집계되지 않습니다.

## REST API [#rest-api]

`https://api.qrdx.dev/v1/codes`에서 코드를 프로그래밍 방식으로 관리합니다. 요청은 `codes:read` 또는 `codes:write` 범위를 가진 [API 키](/docs/developers/api-keys) 또는 OAuth 액세스 토큰(`Authorization: Bearer <key or token>`)으로 인증합니다. 발급 방법은 [REST API](/docs/developers/rest-api)를 참고하세요. API 키는 만들어진 워크스페이스에서 동작하고, 토큰 요청은 본인의 워크스페이스에서 동작합니다. 로그인한 브라우저 세션의 요청도 가능하며, 이 경우 대시보드에서 마지막으로 연 워크스페이스에서 동작합니다.

| 메서드 | 경로 | 설명 |
| --- | --- | --- |
| `GET` | `/v1/codes` | 코드 목록을 조회합니다. 쿼리: `status`(`active`, `archived`, `all`), `q`, `limit`(≤ 100), `offset` |
| `POST` | `/v1/codes` | 코드 하나 또는 최대 {facts.apiBatchCodes}개의 배열을 만듭니다(배열은 Pro가 필요합니다). 본문: `destinationUrl`, 선택 항목 `title`, `style`, `domainId`, `slug` |
| `GET` | `/v1/codes/{id}` | 코드 하나를 조회합니다. |
| `PATCH` | `/v1/codes/{id}` | `destinationUrl`, `title`, `style`, `domainId`([사용자 지정 도메인](/docs/custom-domains)), `slug` 또는 `archived`를 수정하거나, `kind`를 `redirect`와 `page` 사이에서 전환합니다. |
| `DELETE` | `/v1/codes/{id}` | 코드와 그 스캔 기록을 삭제합니다. |
| `GET` | `/v1/codes/{id}/scans` | `range`(`7d`, `30d`, `90d`, `365d`, `1095d`, Pro 및 Business에서는 `all`; 요금제의 기록 보관 기간에 따라 제한됩니다)에 대한 분석을 조회합니다. 개별 스캔을 보려면 `limit`(≤ 500)을, 다음 페이지를 보려면 `before`(마지막 `scannedAt` 값)를 추가합니다. |

코드를 만들려면:

```bash
curl https://api.qrdx.dev/v1/codes \
  -H "Authorization: Bearer $QRDX_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"destinationUrl": "https://example.com/menu", "title": "Spring menu"}'
```

```json
{
  "data": {
    "id": "cm3x...",
    "slug": "aB3dE5f",
    "shortLink": "https://qrdx.dev/q/aB3dE5f",
    "defaultShortLink": "https://qrdx.dev/q/aB3dE5f",
    "domain": null,
    "destinationUrl": "https://example.com/menu",
    "title": "Spring menu",
    "contentType": "url",
    "kind": "redirect",
    "pageId": null,
    "status": "active",
    "style": null,
    "scanCount": 0,
    "lastScannedAt": null,
    "archivedAt": null,
    "createdAt": "2026-10-31T12:00:00.000Z",
    "updatedAt": "2026-10-31T12:00:00.000Z",
    "organizationId": null
  }
}
```

back-half를 직접 고르려면 `slug`를 전달합니다(Pro 및 Business 전용이며, 규칙은 [사용자 지정 back-half](#custom-back-halves)를 참고하세요). `domainId`를 함께 보내면 해당 도메인에서 확인하고, 그렇지 않으면 `qrdx.dev`에서 확인합니다.

```bash
curl https://api.qrdx.dev/v1/codes \
  -H "Authorization: Bearer $QRDX_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"destinationUrl": "https://example.com/menu", "slug": "spring-menu"}'
```

응답에는 `"slug": "spring-menu"`와 `"shortLink": "https://qrdx.dev/q/spring-menu"`가 포함됩니다. 사용자 지정 도메인에서 고른 back-half는 해당 도메인에만 존재하므로 `"defaultShortLink": null`이 됩니다. 배열에서는 모든 `slug`가 서로 달라야 합니다.

### 한 요청으로 여러 코드 만들기 [#many-codes-in-one-request]

Pro 및 Business에서는 최대 {facts.apiBatchCodes}개 코드의 배열을 보낼 수 있습니다. 자동 생성되는 back-half는 배치 안에서 중복되지 않으며, 기존 코드와도 충돌하지 않습니다. Google Web Risk가 제때 확인하지 못한 링크는 배치 생성 직후 다시 조회하며, 이 링크가 목록에 있으면 해당 코드는 꺼집니다([링크 안전 확인](/docs/code-controls#safety-checks-on-links)). 배치는 전부 성공하거나 전부 실패합니다. 어떤 행이라도 문제가 있으면(잘못된 대상, 이미 사용 중이거나 예약된 `slug`, 안전하지 않은 링크) 아무것도 만들어지지 않으며, 오류의 `data.details`에 모든 문제가 `index`와 함께 나열됩니다. `index`는 배열에서 행의 위치(0부터 시작)입니다.

배치마다 고유한 값(예: UUID)을 담은 `Idempotency-Key` 헤더를 보내세요. 요청이 시간 초과되거나 연결이 끊기면 같은 키로 같은 요청을 다시 보내세요. 그러면 첫 시도에서 만들어진 코드들이 `Idempotent-Replayed: true` 헤더와 함께 반환되며, 중간에 끊긴 시도는 어떤 코드도 두 번 만들지 않고 마무리됩니다.

```bash
curl https://api.qrdx.dev/v1/codes \
  -H "Authorization: Bearer $QRDX_TOKEN" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: 6f1c2a9e-spring-tables" \
  -H "Prefer: return=minimal" \
  -d '[{"destinationUrl": "https://example.com/table/1", "title": "Table 1"},
       {"destinationUrl": "https://example.com/table/2", "title": "Table 2"}]'
```

각 코드는 디자인과 함께 반환됩니다. 워크스페이스의 기본 테마에 로고가 포함되어 있으면 큰 배치에서는 응답이 크게 늘어납니다. 이때 `Prefer: return=minimal` 헤더를 보내면 각 코드를 `style` 없이 받을 수 있습니다(id, slug, 링크, 대상, 제목, 상태, 생성 시각만 포함). 응답이 4 MB를 넘는 배치는 아무것도 만들기 전에 `PAYLOAD_TOO_LARGE`로 거부됩니다.

대상 URL을 바꾸려면:

```bash
curl -X PATCH https://api.qrdx.dev/v1/codes/cm3x... \
  -H "Authorization: Bearer $QRDX_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"destinationUrl": "https://example.com/summer-menu"}'
```

`style`에는 플레이그라운드와 같은 디자인 필드(`fgColor`, `bgColor`, `bodyPattern`, `cornerEyePattern`, `level` 등)를 사용합니다. 로고를 넣으려면 `logoIcon`<IfAvailable feature="fileStorage">이나 업로드한 파일의 `logoFileId`</IfAvailable>를 보내세요([코드 스타일의 로고](/docs/developers/rest-api#code-logos)). `shortLink`는 [`qrdx` 라이브러리](/docs/getting-started)나 [이미지 API](/docs/developers/image-api)를 사용하는 등의 방법으로 QR 코드에 인코딩하세요.

오류는 하나의 JSON 형식을 사용합니다. `{ "code": "...", "message": "...", "status": 400 }` 형태이며, 해결 방법을 설명하는 문서가 있으면 `docs` 링크가 함께 포함됩니다.

| 상태 | 코드 | 발생 조건 |
| --- | --- | --- |
| 400 | `VALIDATION_ERROR`, `INVALID_SLUG` | 잘못된 본문 또는 쿼리(배치에서는 `data`에 `index`별 세부 정보가 있음), 또는 규칙에 맞지 않거나 예약된 `slug` |
| 401 | `UNAUTHORIZED`, `INVALID_TOKEN` | `Authorization: Bearer` 토큰이 없거나, 토큰이 잘못되었거나 만료되었거나 취소됨([토큰 발급](/docs/developers/rest-api#get-an-access-token)) |
| 402 | `LIMIT_REACHED`, `PLAN_REQUIRED` | 요금제의 활성 코드 한도를 초과했거나, Pro 없이 대량 생성 또는 사용자 지정 `slug`를 사용함 |
| 403 | `INSUFFICIENT_SCOPE`, `FORBIDDEN` | 필요한 범위가 없는 토큰이거나, 이 작업을 할 수 없는 워크스페이스 역할 |
| 404 | `NOT_FOUND` | 코드가 없거나 본인의 코드가 아니거나, 해당 엔드포인트가 없음 |
| 409 | `SLUG_TAKEN` | 다른 코드가 이미 그 `slug`를 사용 중임(`qrdx.dev` 또는 사용자 지정 도메인에서) |
| 429 | `RATE_LIMITED` | 요청이 너무 많음. `Retry-After` 헤더에 표시된 시간 이후에 다시 시도하세요. |

## 셀프 호스팅 [#self-hosting]

동적 코드는 셀프 호스팅 인스턴스에서도 동작합니다.

- `NEXT_PUBLIC_SHORT_LINK_BASE_URL`은 짧은 링크의 출처를 설정합니다. 기본값은 앱 URL입니다.
- `SCAN_HASH_SALT`는 방문자 해시에 쓰는 비밀 salt를 설정합니다. 설정하지 않으면 `BETTER_AUTH_SECRET`에서 생성됩니다.
- 국가, 지역, 도시는 Vercel의 geo 헤더에서 가져옵니다. Cloudflare 뒤에서는 국가만 사용할 수 있습니다(`CF-IPCountry`). 그 외의 환경에서는 위치가 알 수 없음으로 표시됩니다.
- 스캐너가 위치를 공유하지 않은 경우, 지역 규칙은 Vercel의 IP 좌표(`x-vercel-ip-latitude`, `x-vercel-ip-longitude`)를 사용합니다. 그 외의 환경에서는 위치를 공유한 스캔에만 일치합니다.
- Upstash Redis가 설정되어 있으면 요청 제한이 적용됩니다.
