Um QR code dinâmico codifica um link curto, como `https://qrdx.dev/q/aB3dE5f`, em vez da sua URL final. Ao ler o código, o link curto é aberto e redireciona para o destino que você definiu. Você pode mudar o destino a qualquer momento, então os códigos impressos nunca ficam desatualizados, e cada leitura é contabilizada.

Os QR codes estáticos do Playground e da biblioteca `qrdx` continuam grátis e ilimitados. Os códigos dinâmicos exigem uma conta QRdx.

## Criar um código dinâmico [#create-a-dynamic-code]

- **Painel:** abra o [Painel](/dashboard), clique em **New code**, informe a URL de destino e, se quiser, um título. Baixe o código em PNG, WebP ou SVG.
- **Playground:** escolha o tipo de conteúdo **URL**, informe seu link e ative **Make it dynamic**. O QR code passa a usar um link curto e mantém seu design. Se você editar a URL depois, clique em **Point it to the new URL** para atualizar o destino. **Save design to code** guarda o design atual junto com o código.

Os destinos precisam ser links `http://` ou `https://`. Links com nome de usuário ou senha, e links para outros links curtos do QRdx, são rejeitados.

## Back-halves personalizados [#custom-back-halves]

Cada código recebe um back-half aleatório de 7 caracteres, a parte depois de `/q/`. Nos planos Pro e Business, você pode escolher o seu, como `https://qrdx.dev/q/spring-menu`: preencha **Custom back-half** ao criar ou editar um código, e a caixa de diálogo avisa enquanto você digita se o nome está livre.

- De 3 a 64 caracteres: letras, dígitos, `-` e `_`, sem começar nem terminar com `-`.
- Os back-halves diferenciam maiúsculas de minúsculas, como os gerados automaticamente: `Spring-Menu` e `spring-menu` são dois links diferentes.
- Em `qrdx.dev`, um back-half é único em todo o QRdx, e palavras que parecem páginas do QRdx (`admin`, `api`, `docs`, `login`, `pricing`, `settings`, ...) são reservadas.
- No seu próprio [domínio personalizado](/docs/custom-domains), ele só precisa ser único naquele domínio, e apenas `api`, `p` e `q` são reservados, então `go.yourbrand.com/pricing` funciona. Esse back-half pertence ao domínio: não existe um link `qrdx.dev/q/` para ele.
- Mudar o back-half de um código muda o link dele: os QR codes impressos com o antigo deixam de funcionar, então baixe o código de novo.

## Gerenciar códigos [#manage-codes]

No painel você pode:

- **Edit link:** mudar o destino ou o título. O código impresso continua funcionando e abre o novo destino na próxima leitura.
- **Change type:** transformar um link de site em uma [página hospedada](/docs/landing-pages), uma página de volta em link, ou uma página em outro tipo de página. O link curto e as leituras continuam. Veja [Mude o que um código impresso abre](/docs/help/dynamic-codes/change-the-type).
- **Edit design in playground:** abre o código no editor, ainda vinculado ao link curto dele.
- **Archive:** o link curto mostra uma página de "não está mais ativo" até você restaurar o código. Códigos arquivados não contam para o limite do seu plano.
- **Move to trash:** o link curto mostra uma página de "não está mais ativo" (HTTP 410) e o código deixa de contar para o seu plano. Restaure-o em **Trash** ou exclua-o definitivamente por lá, o que também remove o histórico de leituras; o link curto passa então a mostrar uma página de "QR code não encontrado". Excluir pela API (`DELETE /v1/codes/{id}`) é permanente imediatamente.
- **Duplicate:** copia o destino, o design, a pasta, as tags e as notas para um novo código, com um novo link curto e sem leituras.
- **Version history:** cada alteração fica registrada na página do código; ao restaurar uma versão, as configurações atuais são salvas antes, então a restauração pode ser desfeita.

## Organizar códigos [#organize-codes]

- **Pastas:** aninhe até 5 níveis. Arraste códigos para uma pasta ou use **Move to folder**. Excluir uma pasta move seus códigos e subpastas um nível acima.
- **Tags:** filtre por várias tags para ver os códigos que têm todas elas.
- **Favoritos e notas:** marque códigos com estrela e guarde notas privadas; as notas são pesquisáveis.
- **A busca** abrange títulos, destinos, notas, tags e back-halves (cole um link curto para encontrar o código dele).
- **Ações em massa:** selecione códigos para mover, adicionar tags, pausar, arquivar, favoritar, enviar para a lixeira ou baixar como um ZIP de arquivos PNG, WebP ou SVG.
- **Importação de CSV:** **Codes → Import** cria até {facts.importRows} códigos dinâmicos a partir de um CSV (destino, título, pasta, tags e, opcionalmente, um back-half personalizado na coluna `slug`), e pode colocar todos os códigos em uma pasta e adicionar tags a todos. Uma importação longa pode ser pausada e continua depois de um recarregamento ou de uma queda de conexão sem criar nenhum código duas vezes. Ela termina com um CSV de resultados (o link curto de cada linha) e um ZIP dos códigos em PNG ou SVG. Importar mais de uma linha e usar back-halves personalizados exigem o plano Pro.

Os códigos pertencem ao workspace em que são criados. Todos os membros do workspace podem criá-los e editá-los; os membros podem excluir os próprios códigos, e proprietários e administradores podem excluir qualquer código do workspace.

<Callout type="info">
  Os códigos nunca morrem: rebaixar seu plano nunca desativa os códigos existentes. Acima do limite, você ainda pode editar e arquivar códigos, mas não pode criar nem restaurar mais até ficar abaixo dele.
</Callout>

## Análises de leitura [#scan-analytics]

Cada código tem uma página de análises com leituras ao longo do tempo, visitantes únicos, principais países e cidades, dispositivos, sistemas operacionais, navegadores e referenciadores dos últimos 7, 30 ou 90 dias, 1 ano ou 3 anos, ou de todo o período desde a primeira leitura do código (limitado pelo histórico do seu plano: todo o período está disponível no Pro e no Business). Você pode exportar em CSV as leituras do intervalo selecionado.

O que é registrado em cada leitura:

- Horário (UTC) e país, região e cidade quando a plataforma de hospedagem os fornece (cabeçalhos de geolocalização da Vercel em qrdx.dev)
- Tipo de dispositivo, sistema operacional e navegador, detectados a partir do user agent
- Apenas o nome do host do referenciador, nunca a URL completa. A maioria das leituras de QR code não tem referenciador.
- Um hash de visitante: um SHA-256 com salt do endereço IP, do user agent e do dia. Ele conta visitantes únicos por dia; o endereço IP em si nunca é armazenado.
- Nos planos Pro e Business, quando o código [pede a localização precisa](/docs/precise-location) e a pessoa permite: a localização dela arredondada para 3 casas decimais (cerca de 100 m) e a precisão informada pelo navegador

Bots conhecidos, pré-visualizações de links e pré-carregamentos do navegador não são contabilizados.

## REST API [#rest-api]

Gerencie os códigos programaticamente em `https://api.qrdx.dev/v1/codes`. As requisições são autenticadas com uma [chave de API](/docs/developers/api-keys) ou um token de acesso OAuth (`Authorization: Bearer <key or token>`) que tenha o escopo `codes:read` ou `codes:write`; veja [REST API](/docs/developers/rest-api) para saber como obter um. Uma chave atua no workspace em que foi criada; as requisições com token atuam no seu próprio workspace. Requisições de uma sessão de navegador autenticada também funcionam e atuam no workspace que você abriu por último no painel.

| Método | Caminho | Descrição |
| --- | --- | --- |
| `GET` | `/v1/codes` | Lista os códigos. Query: `status` (`active`, `archived`, `all`), `q`, `limit` (≤ 100), `offset` |
| `POST` | `/v1/codes` | Cria um código ou um array de até {facts.apiBatchCodes} (arrays exigem Pro). Body: `destinationUrl`, e opcionais `title`, `style`, `domainId` e `slug` |
| `GET` | `/v1/codes/{id}` | Busca um código |
| `PATCH` | `/v1/codes/{id}` | Atualiza `destinationUrl`, `title`, `style`, `domainId` ([domínios personalizados](/docs/custom-domains)), `slug` ou `archived`, ou alterna `kind` entre `redirect` e `page` |
| `DELETE` | `/v1/codes/{id}` | Exclui um código e suas leituras |
| `GET` | `/v1/codes/{id}/scans` | Análises de `range` (`7d`, `30d`, `90d`, `365d`, `1095d`, ou `all` no Pro e no Business; limitado pelo histórico do seu plano). Adicione `limit` (≤ 500) para obter leituras individuais e `before` (o último `scannedAt`) para a próxima página |

Crie um código:

```bash
curl https://api.qrdx.dev/v1/codes \
  -H "Authorization: Bearer $QRDX_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"destinationUrl": "https://example.com/menu", "title": "Spring menu"}'
```

```json
{
  "data": {
    "id": "cm3x...",
    "slug": "aB3dE5f",
    "shortLink": "https://qrdx.dev/q/aB3dE5f",
    "defaultShortLink": "https://qrdx.dev/q/aB3dE5f",
    "domain": null,
    "destinationUrl": "https://example.com/menu",
    "title": "Spring menu",
    "contentType": "url",
    "kind": "redirect",
    "pageId": null,
    "status": "active",
    "style": null,
    "scanCount": 0,
    "lastScannedAt": null,
    "archivedAt": null,
    "createdAt": "2026-10-31T12:00:00.000Z",
    "updatedAt": "2026-10-31T12:00:00.000Z",
    "organizationId": null
  }
}
```

Passe `slug` para escolher o final do link (Pro e Business; veja [finais de link personalizados](#custom-back-halves) para as regras). Com um `domainId`, ele é verificado nesse domínio; caso contrário, em `qrdx.dev`:

```bash
curl https://api.qrdx.dev/v1/codes \
  -H "Authorization: Bearer $QRDX_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"destinationUrl": "https://example.com/menu", "slug": "spring-menu"}'
```

A resposta então traz `"slug": "spring-menu"` e `"shortLink": "https://qrdx.dev/q/spring-menu"`. Um final de link escolhido em um domínio personalizado tem `"defaultShortLink": null`, porque ele só existe nesse domínio. Em um array, cada `slug` precisa ser diferente.

### Vários códigos em uma requisição [#many-codes-in-one-request]

No Pro e no Business, envie um array de até {facts.apiBatchCodes} códigos. Os finais de link gerados nunca se repetem dentro do lote nem conflitam com códigos existentes. Links que o Google Web Risk não consegue verificar a tempo são consultados de novo logo após a criação do lote, e um código cujo link ele listar é desativado ([verificações de segurança nos links](/docs/code-controls#safety-checks-on-links)). Um lote é tudo ou nada: se qualquer linha tiver um problema (um destino inválido, um `slug` já usado ou reservado, um link inseguro), nada é criado e o `data.details` do erro lista todos os problemas por `index`, a posição da linha no array (a partir de 0).

Envie um header `Idempotency-Key` com um valor único para o lote, como um UUID. Se a requisição der timeout ou a conexão cair, envie a mesma requisição com a mesma chave de novo: você recebe de volta os códigos que a primeira tentativa criou, com um header `Idempotent-Replayed: true`, e uma tentativa interrompida no meio é concluída sem criar nenhum código duas vezes.

```bash
curl https://api.qrdx.dev/v1/codes \
  -H "Authorization: Bearer $QRDX_TOKEN" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: 6f1c2a9e-spring-tables" \
  -H "Prefer: return=minimal" \
  -d '[{"destinationUrl": "https://example.com/table/1", "title": "Table 1"},
       {"destinationUrl": "https://example.com/table/2", "title": "Table 2"}]'
```

Cada código volta com o seu design. Quando o tema padrão do seu workspace incorpora um logo, isso pesa em um lote grande: envie `Prefer: return=minimal` para receber cada código sem `style` (com id, slug, links, destino, título, status e data de criação). Um lote cuja resposta não caberia em 4 MB é recusado com `PAYLOAD_TOO_LARGE` antes de qualquer coisa ser criada.

Altere o destino:

```bash
curl -X PATCH https://api.qrdx.dev/v1/codes/cm3x... \
  -H "Authorization: Bearer $QRDX_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"destinationUrl": "https://example.com/summer-menu"}'
```

`style` aceita os mesmos campos de design do Playground (`fgColor`, `bgColor`, `bodyPattern`, `cornerEyePattern`, `level`, ...). Para um logo, envie `logoIcon`<IfAvailable feature="fileStorage"> ou o `logoFileId` de um arquivo enviado</IfAvailable> ([logos no style de um código](/docs/developers/rest-api#code-logos)). Codifique o `shortLink` no seu QR code, por exemplo com a [biblioteca `qrdx`](/docs/getting-started) ou a [Image API](/docs/developers/image-api).

Os erros usam um único formato JSON, `{ "code": "...", "message": "...", "status": 400 }`, mais um link `docs` quando uma página explica a solução:

| Status | Código | Quando |
| --- | --- | --- |
| 400 | `VALIDATION_ERROR`, `INVALID_SLUG` | Body ou query inválido (detalhes em `data`, por `index` em um lote), ou um `slug` que viola as regras ou é reservado |
| 401 | `UNAUTHORIZED`, `INVALID_TOKEN` | Sem token `Authorization: Bearer`, ou token inválido, expirado ou revogado ([obtenha um token](/docs/developers/rest-api#get-an-access-token)) |
| 402 | `LIMIT_REACHED`, `PLAN_REQUIRED` | Acima do limite de códigos ativos do seu plano, ou criação em massa ou `slug` personalizado sem Pro |
| 403 | `INSUFFICIENT_SCOPE`, `FORBIDDEN` | Token sem o escopo necessário, ou uma função no workspace que não pode fazer isso |
| 404 | `NOT_FOUND` | O código não existe ou não é seu, ou o endpoint não existe |
| 409 | `SLUG_TAKEN` | Outro código já usa esse `slug` (em `qrdx.dev` ou no domínio personalizado) |
| 429 | `RATE_LIMITED` | Requisições demais; tente de novo depois do tempo indicado no header `Retry-After` |

## Hospedagem própria [#self-hosting]

Os QR codes dinâmicos também funcionam em instâncias de hospedagem própria:

- `NEXT_PUBLIC_SHORT_LINK_BASE_URL` define a origem dos links curtos. O padrão é a URL do seu app.
- `SCAN_HASH_SALT` define o salt secreto dos hashes de visitantes. Sem ele, um é derivado de `BETTER_AUTH_SECRET`.
- País, região e cidade vêm dos headers de geolocalização da Vercel. Atrás da Cloudflare, só o país está disponível (`CF-IPCountry`); em outros ambientes, as localizações aparecem como desconhecidas.
- As regras de área usam as coordenadas de IP da Vercel (`x-vercel-ip-latitude`, `x-vercel-ip-longitude`) quando quem fez a leitura não compartilhou a localização. Em outros ambientes, elas só correspondem a leituras com localização compartilhada.
- Os limites de requisições se aplicam quando o Upstash Redis está configurado.
