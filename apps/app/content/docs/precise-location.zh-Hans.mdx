每个[动态二维码](/docs/dynamic-qr-codes)都会根据网络记录每次扫描所在的国家、地区和城市。在 Pro 和 Business 上，你还可以请扫描者分享精确位置。允许分享的用户会以四舍五入到约 100 米的点位显示在二维码的分析数据中，[智能路由](/docs/smart-routing)也可以根据他们所在的位置，把他们送到不同的目的地。

所有二维码默认关闭此功能，需要你手动开启；每位扫描者都在自己的浏览器中自行决定是否分享。

## 开启方式 [#turn-it-on]

在[控制台](/dashboard?to=codes)中打开该二维码，进入 **设置** 标签页，在 **精确位置** 面板中打开 **请扫描者分享精确位置**。此功能适用于打开网站链接的二维码，也适用于打开托管页面的二维码。

使用 [REST API](/docs/developers/rest-api) 时，发送 `PATCH /v1/codes/{id}`，请求体为 `{"preciseLocation": true}`。二维码会在其 `preciseLocation` 字段中返回该设置。

## 扫描者会看到什么 [#what-scanners-see]

**打开网站链接的二维码**会在链接打开前显示一个简短的“分享你的位置？”步骤，带有 **允许** 和 **跳过** 两个选项。点击允许会弹出浏览器自带的位置授权提示。这个步骤不会妨碍任何人访问你的链接：

- 点击跳过会立即打开链接。
- 如果扫描者在浏览器中拒绝，或浏览器无法获取位置，链接会照常打开。
- 如果在点击允许后 8 秒内仍未获取到位置，链接也会打开。
- 如果浏览器已对该站点选择过拒绝，会自动跳过此步骤；如果已选择过允许，则无需再次点击即可直接分享。
- 在没有 JavaScript 的情况下，链接会立即打开。

此步骤会写明扫描者将要访问的站点，并附有隐私政策的链接。

**打开托管页面的二维码**会像往常一样立即打开页面。页面加载完成后，浏览器会在页面上请求位置；页面从不等待回应。它只会在扫描之后立即请求，直接打开页面地址时不会请求。

关闭该设置后，一切照旧：扫描会直接跳转到目的地，没有额外步骤。

## 存储的内容 [#whats-stored]

用户允许后，浏览器会在发送前把位置四舍五入到小数点后 3 位（约 100 米），QRdx 在存储前会再次取整，并与该次扫描一起保存，同时保存浏览器报告的精度。精确的位置永远不会到达 QRdx。

用户跳过或拒绝时不会存储任何位置。该次扫描仍会被计数，并像往常一样记录来自网络的国家、地区和城市。

精确位置的保留时间与该二维码其他扫描数据相同，你的套餐决定了可以回看多久以前的数据。参见[QRdx 在扫描时会记录什么](/docs/help/privacy-and-security/scan-data)。

## 在分析数据中 [#in-analytics]

二维码的 **分析** 标签页中有一张 **精确位置** 卡片，与基于 IP 的国家和城市数据分开显示。它会显示被询问的扫描者人数、分享了位置的人数及占比，然后列出每个已分享的点位，包括扫描次数、平均精度和最近一次扫描。你可以按其中任意一项对表格排序，并在 OpenStreetMap 中打开某个点位查看它的位置。

CSV 导出包含 `latitude`、`longitude`、`location_accuracy_m` 和 `location_source` 列。`location_source` 的值为：已分享位置时是 `gps`；二维码请求了位置但扫描者未分享时是 `ip`；二维码未请求位置时为空。[`GET /v1/codes/{id}/scans`](/docs/developers/api/get-code-scans) 会按每次扫描返回相同的字段，另外还有 `preciseLocations` 汇总。

共享的分析链接（二维码菜单中的 **分享分析**）从不显示精确位置，只显示到国家层级。

## 按区域路由扫描 [#route-scans-by-area]

在二维码的 **智能路由** 面板中，添加带有 **区域** 条件的规则：设定一个中心点，以及 100 米到 500 公里之间的半径。获取中心点时，可以在地图应用中右键点击某个地点并复制其坐标（例如 `40.7580, -73.9855`），或者人在现场时使用 **使用我的位置**。**在地图上查看** 会在 OpenStreetMap 中打开该点。

QRdx 会使用它为该次扫描掌握的最佳位置来判断区域：

1. 在该步骤中扫描者分享的位置（前提是已开启精确位置且扫描者允许）。
2. 否则使用其 IP 地址的大致位置。在 qrdx.dev 上，这来自 Vercel 的 IP 地理定位，通常是扫描者所在城市或区域的中心，因此适合几公里以上的半径。它只用于路由该次扫描，不会被存储。

两者都不可用时，区域条件不匹配，而“不在”该区域的条件则会匹配。未在 Vercel 上运行的自托管副本没有 IP 坐标，因此那里的区域规则只对已分享的位置生效。

**测试你的规则** 中有一个 **位置** 字段，你可以检查从任意一点发起的扫描会跳转到哪里。

### 仅限区域内 [#only-inside-an-area]

如果只想向身处某个地点（如活动场地或门店）的人展示内容：

1. 添加一条规则，使用围绕该地点的区域条件，并把它的 URL 设为面向现场人员的内容。
2. 把二维码的主目的地设为面向其他所有人的页面，例如说明该优惠仅限现场使用的页面。

同时开启精确位置，这样由扫描者分享的位置来决定，精度可达约 100 米。不开启的话，就由 IP 位置决定，只能精确到城市级别。

浏览器允许用户伪造位置，因此区域规则不是访问控制。对于必须保密的内容，请使用[密码](/docs/code-controls)。

## 须知 [#good-to-know]

- 机器人、链接预览和 HEAD 请求不会看到该步骤，它们得到的是常规重定向。
- 设置了密码的二维码不会显示该步骤：输入正确密码后，扫描会直接跳转到目的地。
- 位于区域条件之后的分流的 A/B 测试计数只是估算值，因为扫描记录中不会保存规则使用的是哪个位置。
- 如果你的工作区降级为免费版，QRdx 会停止请求精确位置。已保存的区域规则会继续使用 IP 位置生效，而关闭该设置无需任何套餐。
