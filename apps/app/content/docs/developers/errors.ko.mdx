모든 REST API 오류는 어떤 엔드포인트에서 반환되든 같은 형태의 JSON입니다.

```json
{
  "code": "INSUFFICIENT_SCOPE",
  "message": "This API key needs the 'codes:write' scope. Create a key that includes it at https://qrdx.dev/dashboard?to=settings/developers; a key's scopes can't be changed.",
  "status": 403,
  "docs": "https://qrdx.dev/docs/developers/api-keys"
}
```

| 필드 | 설명 |
| --- | --- |
| `code` | 아래 표에 있는 안정적인 기계 판독용 코드입니다. 이 값으로 분기하세요. |
| `message` | 무엇이 잘못되었는지, 어떻게 해결하는지를 사람에게 알려 주는 설명입니다. 문구는 바뀔 수 있습니다. |
| `status` | HTTP 상태를 그대로 한 번 더 담습니다. |
| `docs` | 해결 방법을 설명하는 페이지입니다. 해당 페이지가 있을 때만 포함됩니다. |
| `data` | 일부 오류에 포함되는 추가 정보입니다. `VALIDATION_ERROR`는 각 문제를 `data.details`에 나열합니다. |

검증 오류는 실패한 모든 필드를 알려 줍니다.

```json
{
  "code": "VALIDATION_ERROR",
  "message": "Invalid request body",
  "status": 400,
  "data": {
    "details": [
      { "path": "destinationUrl", "message": "Enter a full URL, starting with https://" }
    ]
  }
}
```

Image API는 쿼리 매개변수를 `{ "path", "message" }` 대신 `{ "param", "message" }` 형태로 보고합니다.

## 오류 코드 [#error-codes]

| 상태 | 코드 | 의미 | 해결 방법 |
| --- | --- | --- | --- |
| 400 | `VALIDATION_ERROR` | 본문, 쿼리 또는 경로가 유효성 검사를 통과하지 못했어요. `data.details`에 각 문제가 `{ path, message }` 형태로 나열돼요(이미지 API에서는 `{ param, message }`). 본문이 코드 배열이면 해당 행의 `index`도 함께 표시돼요. | `data.details`에 나열된 필드를 수정한 뒤 요청을 다시 보내세요. |
| 400 | `INVALID_SLUG` | 사용자 지정 back-half(`slug`)가 규칙을 어겼어요. 예약어이거나, 한 요청에서 같은 back-half를 두 번 사용한 경우예요. 배열이면 `data.details`에 각 행이 `index`별로 나열돼요. | 다른 back-half를 선택하세요. 메시지에 어떤 규칙인지 나와 있어요. |
| 400 | `TOO_MANY_CODES` | 한 요청에 코드가 1,000개를 넘었어요. 보통은 본문 스키마가 먼저 `VALIDATION_ERROR`로 거부해요. | 요청당 코드를 최대 1,000개까지만 보내세요. |
| 400 | `DOMAIN_NOT_VERIFIED` | `domainId`가 아직 인증되지 않은 사용자 지정 도메인을 가리켜요. | 도메인 페이지에서 도메인 인증을 마치거나 `domainId`를 빼세요. |
| 400 | `SID_REQUIRED` | (브라우저에서) 스캔의 `qrdx_sid` 없이 전환을 보냈거나, (서버에서) `sid` 또는 `code` 없이 보냈어요. | 짧은 링크가 페이지 URL에 추가한 `qrdx_sid`를 보내세요. API 키나 토큰을 쓸 때는 코드 id를 `code`로 보내세요. |
| 400 | `AI_ART_TEXT_TOO_LONG` | `text`가 AI 아트에 쓰기에는 너무 길어요(300자 초과). | 대신 동적 코드의 id를 `code`로 보내세요. 아트는 짧고 계속 수정할 수 있는 해당 짧은 링크를 인코딩해요. |
| 401 | `UNAUTHORIZED` | 자격 증명이 없어요. 요청에 `Authorization: Bearer` 헤더가 없고 QRdx 브라우저 세션도 없어요. | API 키를 `Authorization: Bearer <key>`로 보내세요. 키는 설정 → API 키 및 앱에서 만들 수 있어요. OAuth 액세스 토큰도 같은 헤더에 넣어요. |
| 401 | `INVALID_TOKEN` | API 키 또는 액세스 토큰이 알 수 없거나, 폐기되었거나, 만료되었어요(액세스 토큰은 1시간 유지돼요). 또는 키를 만든 사람이 차단되었거나 키의 워크스페이스를 떠났어요. | 키 전체를 보냈는지 확인하거나 새 키를 만드세요. 액세스 토큰이라면 리프레시 토큰으로 새로 받거나 사용자가 다시 인증하도록 하세요. |
| 402 | `PLAN_REQUIRED` | 워크스페이스 요금제에 없는 기능이에요. 일괄 생성, 사용자 지정 back-half, 사용자 지정 도메인은 Pro가 필요하고, 전환과 훅은 Business가 필요해요. | 워크스페이스를 업그레이드하거나 요청에서 해당 기능을 빼세요. |
| 402 | `LIMIT_REACHED` | 워크스페이스의 활성 동적 코드 수가 요금제에 포함된 한도에 도달했어요(무료는 10개). | 코드를 보관하거나(보관된 코드는 세지 않아요) Pro로 업그레이드해 무제한 코드를 사용하세요. |
| 402 | `AI_ART_CREDITS_EXHAUSTED` | 워크스페이스가 이번 달 AI 아트 이미지를 모두 사용했어요(무료와 Pro). 이 요청에는 요금이 부과되지 않았어요. | 매월 1일(UTC)에 한도가 초기화될 때까지 기다리거나, 더 많은 이미지를 위해 업그레이드하세요. |
| 403 | `INSUFFICIENT_SCOPE` | API 키 또는 토큰은 유효하지만 이 엔드포인트에 필요한 스코프가 없어요. | 메시지에 나온 스코프로 키를 새로 만드세요(키의 스코프는 변경할 수 없어요). OAuth 앱은 스코프를 추가하고 사용자가 승인할 때 요청하세요. |
| 403 | `FORBIDDEN` | 호출자가 이 작업을 할 수 없어요. 워크스페이스 멤버가 다른 사람이 만든 코드를 삭제하거나, 멤버가 훅을 관리하거나, 다른 사이트에서 브라우저 세션으로 쓰기를 시도한 경우예요. API 키는 해당 워크스페이스에서 키 생성자의 역할이 허용하는 작업만 할 수 있어요. | 워크스페이스 소유자나 관리자에게 요청하거나, 서버에서 API 키로 API를 호출하세요. |
| 403 | `CONFIRMATION_REQUIRED` | 로그인한 브라우저 세션으로 훅을 만들려면 최근의 "본인 확인"이 필요해요. API 키와 OAuth 토큰은 요구하지 않아요. | QRdx에서 본인 확인을 한 뒤 10분 이내에 다시 시도하거나, 서버에서 API 키로 훅을 만드세요. |

## 재시도 [#retrying]

- **`429`:** `Retry-After`에 적힌 시간(초)만큼 기다린 다음 같은 요청을 다시 보내세요. 일일 할당량을 모두 사용했다면 `X-RateLimit-*` 헤더에서 요금제가 허용하는 요청 수와 카운트가 초기화되는 시각(00:00 UTC)을 확인할 수 있어요. [요청 제한](/docs/developers/rest-api#rate-limits)을 참고하세요.
- **`500` 및 `503`:** 약 1초부터 시작해 지수 백오프로 재시도하세요.
- **그 외 `4xx`:** 같은 요청은 같은 방식으로 실패합니다. 먼저 요청을 수정하세요.

코드 생성은 멱등성이 없습니다. `POST /v1/codes` 요청이 시간 초과되면 다시 보내기 전에 코드 목록을 먼저 조회하세요. 그렇지 않으면 같은 코드가 두 번 생성될 수 있습니다. 변환 요청은 멱등성이 있습니다. 직접 지정한 `id`를 보내면, 같은 요청을 반복했을 때 `200`과 `duplicate: true`가 반환됩니다.

## `/v1/me` 및 `/v1/themes` [#v1me-and-v1themes]

이 두 엔드포인트는 동일한 본문에 더해, 예전부터 보내던 OAuth 필드인 `error`와 `error_description`(`message`와 같은 텍스트)도 함께 보냅니다. 따라서 이전 클라이언트도 계속 동작합니다.

| `error` | `code` |
| --- | --- |
| `invalid_token` | UNAUTHORIZED 또는 INVALID_TOKEN |
| `insufficient_scope` | INSUFFICIENT_SCOPE |
| `rate_limited` | RATE_LIMITED (일일 할당량) |
| `not_found` | NOT_FOUND (테마) |

## OAuth 엔드포인트 [#oauth-endpoints]

`https://qrdx.dev/api/oauth` 아래의 OAuth 엔드포인트(authorize, token, revoke, userinfo)는 대신 OAuth 2.0 표준을 따릅니다. 형식은 `{ "error", "error_description" }`이며, `error`는 `invalid_request`, `invalid_client`, `invalid_grant`, `unsupported_grant_type`, `invalid_token`, `access_denied` 중 하나입니다. 토큰 갱신 시 `invalid_grant`가 반환된다면 갱신 토큰을 이미 사용했거나(갱신할 때마다 새 토큰이 반환돼요), 30일이 지나 만료됐거나, 사용자가 앱 권한을 취소했다는 뜻입니다. 이 경우 사용자가 인증 과정을 처음부터 다시 거치도록 하세요. [REST API와 OAuth](/docs/developers/rest-api#get-an-access-token)를 참고하세요.

## 알 수 없는 엔드포인트 [#unknown-endpoints]

`/v1` 아래에 존재하지 않는 경로로 요청하면 HTML 페이지가 아닌 JSON 형식의 `404 NOT_FOUND`가 반환됩니다. 모든 엔드포인트는 [API 레퍼런스](/docs/developers/api)에서 확인할 수 있습니다.
