हर REST API एरर JSON में आता है और उसका ढाँचा हमेशा एक जैसा रहता है, चाहे वह किसी भी endpoint से आए:

```json
{
  "code": "INSUFFICIENT_SCOPE",
  "message": "This API key needs the 'codes:write' scope. Create a key that includes it at https://qrdx.dev/dashboard?to=settings/developers; a key's scopes can't be changed.",
  "status": 403,
  "docs": "https://qrdx.dev/docs/developers/api-keys"
}
```

| फ़ील्ड | यह क्या है |
| --- | --- |
| `code` | नीचे दी गई तालिका का एक स्थिर, मशीन से पढ़ने लायक कोड। अपना लॉजिक इसी पर आधारित रखें। |
| `message` | क्या गलत हुआ और उसे कैसे ठीक करें, यह लोगों के लिए लिखा गया है। शब्द बदल सकते हैं। |
| `status` | HTTP status, जो यहाँ दोबारा दिया गया है। |
| `docs` | वह पेज जो समाधान समझाता है, जब कोई पेज उपलब्ध हो। |
| `data` | कुछ एरर में अतिरिक्त जानकारी। `VALIDATION_ERROR` हर समस्या को `data.details` में सूचीबद्ध करता है। |

वैलिडेशन एरर में हर उस फ़ील्ड का नाम होता है जो फ़ेल हुआ:

```json
{
  "code": "VALIDATION_ERROR",
  "message": "Invalid request body",
  "status": 400,
  "data": {
    "details": [
      { "path": "destinationUrl", "message": "Enter a full URL, starting with https://" }
    ]
  }
}
```

Image API क्वेरी पैरामीटर को `{ "path", "message" }` की जगह `{ "param", "message" }` के रूप में बताता है।

## दोबारा कोशिश करना [#retrying]

- **`429`:** `Retry-After` में दिए गए सेकंड तक रुकें, फिर वही request दोबारा भेजें। जब रोज़ का कोटा खत्म हो जाता है, तो `X-RateLimit-*` हेडर बताते हैं कि आपके प्लान में कितनी requests की अनुमति है और गिनती कब रीसेट होगी (00:00 UTC)। देखें [रेट लिमिट](/docs/developers/rest-api#rate-limits)।
- **`500` और `503`:** exponential backoff के साथ दोबारा कोशिश करें, लगभग एक सेकंड से शुरू करें।
- **दूसरे `4xx`:** वही request हर बार उसी तरह फ़ेल होगी। पहले उसे ठीक करें।

कोड बनाना idempotent नहीं है: अगर `POST /v1/codes` टाइमआउट हो जाए, तो उसे दोबारा भेजने से पहले अपने कोड की सूची देखें, वरना एक ही कोड दो बार बन सकता है। Conversions idempotent हैं: अपना `id` भेजें, और दोहराने पर `200` के साथ `duplicate: true` मिलेगा।

## `/v1/me` और `/v1/themes` [#v1me-and-v1themes]

ये दोनों endpoints वही body भेजते हैं, साथ में वे OAuth फ़ील्ड भी जो ये हमेशा से भेजते आए हैं, यानी `error` और `error_description` (वही टेक्स्ट जो `message` में है), ताकि पुराने क्लाइंट चलते रहें:

| `error` | `code` |
| --- | --- |
| `invalid_token` | UNAUTHORIZED या INVALID_TOKEN |
| `insufficient_scope` | INSUFFICIENT_SCOPE |
| `rate_limited` | RATE_LIMITED (रोज़ का कोटा) |

## OAuth endpoints [#oauth-endpoints]

`https://qrdx.dev/api/oauth` के तहत आने वाले OAuth endpoints (authorize, token, revoke, userinfo) इसके बजाय OAuth 2.0 स्टैंडर्ड का पालन करते हैं: `{ "error", "error_description" }`, जहाँ `error` इनमें से एक होता है: `invalid_request`, `invalid_client`, `invalid_grant`, `unsupported_grant_type`, `invalid_token` या `access_denied`। refresh के समय `invalid_grant` मिलने का मतलब है कि refresh token पहले ही इस्तेमाल हो चुका है (हर refresh नया token देता है), 30 दिन बाद expire हो गया है, या यूज़र ने आपका app revoke कर दिया है: यूज़र को दोबारा authorization के लिए भेजें। देखें [REST API और OAuth](/docs/developers/rest-api#get-an-access-token)।

## अनजान endpoints [#unknown-endpoints]

`/v1` के तहत ऐसा कोई path जो मौजूद नहीं है, JSON में `404 NOT_FOUND` लौटाता है, कभी HTML पेज नहीं। [API रेफ़रेंस](/docs/developers/api) में हर endpoint की सूची है।
