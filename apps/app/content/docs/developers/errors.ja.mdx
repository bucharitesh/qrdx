REST APIのエラーは、どのエンドポイントが返す場合でも、同じ形式のJSONです。

```json
{
  "code": "INSUFFICIENT_SCOPE",
  "message": "This API key needs the 'codes:write' scope. Create a key that includes it at https://qrdx.dev/dashboard?to=settings/developers; a key's scopes can't be changed.",
  "status": 403,
  "docs": "https://qrdx.dev/docs/developers/api-keys"
}
```

| フィールド | 内容 |
| --- | --- |
| `code` | 下の表にある、安定した機械可読のコードです。処理の分岐にはこの値を使ってください。 |
| `message` | 何が問題だったか、どう修正すればよいかを人向けに説明する文です。文言は変更される場合があります。 |
| `status` | HTTPステータスです（重複して返されます）。 |
| `docs` | 修正方法を説明するページです。該当するページがある場合のみ含まれます。 |
| `data` | 一部のエラーに含まれる追加情報です。`VALIDATION_ERROR` では、問題点が `data.details` に1件ずつ一覧で入ります。 |

バリデーションエラーでは、失敗したすべてのフィールドが示されます。

```json
{
  "code": "VALIDATION_ERROR",
  "message": "Invalid request body",
  "status": 400,
  "data": {
    "details": [
      { "path": "destinationUrl", "message": "Enter a full URL, starting with https://" }
    ]
  }
}
```

Image APIでは、クエリパラメータは `{ "path", "message" }` ではなく `{ "param", "message" }` の形式で報告されます。

## エラーコード [#error-codes]

| ステータス | コード | 意味 | 対処方法 |
| --- | --- | --- | --- |
| 400 | `VALIDATION_ERROR` | ボディ、クエリ、またはパスの検証に失敗しました。`data.details` に各問題が `{ path, message }` の形式（Image API では `{ param, message }`）で一覧表示されます。ボディがコードの配列の場合は、その行の `index` も含まれます。 | `data.details` に記載されたフィールドを修正し、リクエストを再送してください。 |
| 400 | `INVALID_SLUG` | カスタムバックハーフ（`slug`）がルールに違反しています。予約語である場合や、1回のリクエスト内で同じバックハーフが重複している場合が該当します。配列の場合、`data.details` に各行が `index` 付きで一覧表示されます。 | 別のバックハーフを選んでください。メッセージに違反したルールが示されます。 |
| 400 | `TOO_MANY_CODES` | 1回のリクエストに含まれるコードが1,000件を超えています。通常は、ボディスキーマが先にこれを `VALIDATION_ERROR` として拒否します。 | 1回のリクエストで送信するコードは最大1,000件にしてください。 |
| 400 | `DOMAIN_NOT_VERIFIED` | `domainId` が、まだ認証されていないカスタムドメインを指しています。 | ドメインページでドメインの認証を完了するか、`domainId` を指定しないでください。 |
| 400 | `SID_REQUIRED` | コンバージョンに、スキャンの `qrdx_sid`（ブラウザから送信する場合）、または `sid` もしくは `code`（サーバーから送信する場合）がありません。 | 短縮リンクがページURLに付加した `qrdx_sid` を送信してください。APIキーまたはトークンを使う場合は、コードIDを `code` として送信してください。 |
| 400 | `AI_ART_TEXT_TOO_LONG` | `text` がAIアートには長すぎます（300文字を超えています）。 | 代わりに、動的QRコードのIDを `code` として送信してください。アートには短縮リンクがエンコードされるため、短く、編集も可能なままです。 |
| 401 | `UNAUTHORIZED` | 認証情報がありません。リクエストに `Authorization: Bearer` ヘッダーがなく、QRdxのブラウザセッションもありません。 | APIキーを `Authorization: Bearer <key>` として送信してください。キーは「設定」→「APIキーとアプリ」で作成できます。OAuthアクセストークンも同じヘッダーで送信します。 |
| 401 | `INVALID_TOKEN` | APIキーまたはアクセストークンが不明、失効済み、または期限切れです（アクセストークンの有効期間は1時間です）。または、キーの作成者が凍結されたか、キーのワークスペースから退出しています。 | キー全体を送信したか確認するか、新しいキーを作成してください。アクセストークンの場合は、リフレッシュトークンで新しいトークンを取得するか、ユーザーに再度認可を行ってもらってください。 |
| 402 | `PLAN_REQUIRED` | この機能はワークスペースのプランに含まれていません。一括作成、カスタムバックハーフ、カスタムドメインには Pro が、コンバージョンとフックには Business が必要です。 | ワークスペースのプランをアップグレードするか、リクエストからその機能を外してください。 |
| 402 | `LIMIT_REACHED` | ワークスペースの有効な動的QRコードが、プランに含まれる数に達しています（フリーでは10件）。 | コードをアーカイブするか（アーカイブ済みのコードは数えられません）、Pro にアップグレードしてコードを無制限にしてください。 |
| 402 | `AI_ART_CREDITS_EXHAUSTED` | ワークスペースが今月分のAIアート画像をすべて使用しました（フリーと Pro）。このリクエストには課金されていません。 | 毎月1日（UTC）に利用枠がリセットされるまでお待ちいただくか、アップグレードして画像枠を増やしてください。 |
| 403 | `INSUFFICIENT_SCOPE` | APIキーまたはトークンは有効ですが、このエンドポイントに必要なスコープがありません。 | メッセージに示されたスコープを持つキーを作成してください（キーのスコープは変更できません）。OAuthアプリの場合は、スコープを追加し、ユーザーが認可する際にそのスコープを要求してください。 |
| 403 | `FORBIDDEN` | 呼び出し元にはこの操作を行う権限がありません。たとえば、ワークスペースのメンバーが他の人が作成したコードを削除する場合、メンバーがフックを管理する場合、別のサイトからブラウザセッションで書き込みを行う場合です。APIキーでは、ワークスペースにおける作成者のロールで許可されている操作のみ実行できます。 | ワークスペースのオーナーまたは管理者に依頼するか、サーバーからAPIキーを使ってAPIを呼び出してください。 |
| 403 | `CONFIRMATION_REQUIRED` | ログイン中のブラウザセッションでフックを作成するには、直近の「本人確認」が必要です。APIキーとOAuthトークンでは求められません。 | QRdxで本人確認を行い、10分以内にもう一度お試しください。または、サーバーからAPIキーを使ってフックを作成してください。 |
| 403 | `CONVERSIONS_OFF` | コンバージョントラッキングがオンになっていないコードに対して、ブラウザからコンバージョンが送信されました。 | そのコードのコンバージョントラッキングをオンにするか、サーバーからAPIキーを使ってコンバージョンを報告してください。 |
| 403 | `LIMIT_REACHED` | ワークスペースにすでにWebhookエンドポイントとフックが合わせて20件あります。 | 使用していないエンドポイントまたはフックを削除してください。 |
| 404 | `NOT_FOUND` | そのようなエンドポイントがないか、キーまたはトークンが操作対象とするワークスペースにコード、フック、テーマ、カスタムドメインが存在しません。 | パスとIDを確認してください。APIキーは作成されたワークスペースを対象に動作し、OAuthトークンはユーザー自身のワークスペースを対象に動作します。 |
| 404 | `INVALID_SID` | `qrdx_sid` が不明であるか、帰属期間である30日より古くなっています。 | 最近のスキャンの `qrdx_sid` を送信するか、サーバーからコードIDでコンバージョンを報告してください。 |
| 409 | `SLUG_TAKEN` | そのドメインでは、別のコードがすでにそのバックハーフを使用しています。配列の場合、`data.details` に使用済みのものが `index` 付きで一覧表示され、何も作成されません。 | 別のバックハーフを選んでください。 |
| 413 | `PAYLOAD_TOO_LARGE` | ボディがエンドポイントの上限を超えています。コードは4 MB、フックは16 KB、コンバージョンは8 KBです。また、レスポンス（各コードとそのデザイン）が4 MBを超えるコードのバッチも対象で、この場合は何も作成されません。 | ボディを小さくして送信してください。コードの場合は、大きなインラインロゴが原因であることが多く、バッチの場合は `Prefer: return=minimal` を送信するか、コードの数を減らしてください。 |
| 413 | `AI_ART_IMAGE_TOO_LARGE` | `photo` または `reference` の画像が、AIアートのサイズ上限を超えています（どちらかはメッセージに示されます）。 | 画像を縮小し（`reference` は長辺を約512 px、`photo` は約1024 px四方に）、PNGまたはJPEGのデータURLとして再送信してください。 |
| 415 | `UNSUPPORTED_MEDIA_TYPE` | `Content-Type: application/json` なしで書き込みが行われました。 | `Content-Type: application/json` を付けて、JSONのボディを送信してください。 |
| 422 | `UNSAFE_DESTINATION` | Google Web Risk が遷移先URLにフラグを立てました（マルウェア、フィッシング、または不要なソフトウェア）。配列の場合、`data.details` にフラグが立った各行が `index` 付きで一覧表示され、何も作成されません。 | 別の遷移先を使用してください。フラグが誤っている場合は、Googleにサイトの再審査を依頼してください。 |
| 429 | `RATE_LIMITED` | リクエストが多すぎます。1分あたりの制限（`Retry-After` のみ設定されます）、またはワークスペースの1日あたりのクォータ（`Retry-After` と `X-RateLimit-*`）に達しました。 | `Retry-After` の秒数だけお待ちください。1日あたりのクォータの場合は、00:00 UTCまで待つか、プランをアップグレードしてください。 |
| 429 | `AI_ART_CREDITS_EXHAUSTED` | Business のワークスペースが、チーム全体で共有する今月分のAIアート画像をすべて使用しました。 | 毎月1日（UTC）に利用枠がリセットされるまでお待ちください。 |
| 429 | `AI_ART_DAILY_LIMIT` | キーの作成者が、本日（UTC）すでに25枚のAIアート画像を作成しました。これは月間の利用枠に加えた安全上の上限です。 | 明日（UTC）もう一度お試しください。 |
| 500 | `INTERNAL_ERROR` | QRdx側で何らかの障害が発生しました。記録されています。 | しばらくしてからもう一度お試しください。繰り返し発生する場合は、リクエストの時刻を添えてご報告ください。 |
| 502 | `AI_ART_FAILED` | 画像モデルが失敗した、プロンプトを拒否した、またはQRdxが読み取れない画像を返しました。AIアートのクレジットは使用されていません。 | もう一度お試しいただくか、プロンプトの表現を変えてください。メッセージに状況が示されます。 |
| 502 | `AI_ART_UNSCANNABLE` | 指定したQRの視認性の範囲では、モデルが生成した画像をスキャンできる状態にできませんでした。AIアートのクレジットは使用されていません。 | `visibility` を高くするか、別のシードでもう一度お試しください。 |
| 502 | `AI_ART_DESCRIBE_FAILED` | `prompt` が指定されておらず、代わりにプロンプトを作成するテキストモデルが失敗しました。AIアートのクレジットは使用されていません。 | もう一度お試しいただくか、独自の `prompt` を送信してください。 |
| 503 | `SLUG_UNAVAILABLE` | 時間内に、空いている短縮リンクのスラッグを確保できませんでした。 | 同じリクエストをもう一度送信してください。 |
| 503 | `AI_ART_BUSY` | 画像モデルが現在、処理能力の上限に達しています。AIアートのクレジットは使用されていません。 | 1分ほど待ってから、もう一度お試しください。 |
| 503 | `AI_NOT_CONFIGURED` | このデプロイ環境ではAIアートが設定されていません（`AI_GATEWAY_API_KEY` のないセルフホストのインスタンス）。 | ホスト版のQRdx APIを使用するか、お使いのインスタンスにVercel AI Gatewayを設定してください。 |
| 503 | `UNAVAILABLE` | このデプロイ環境ではカスタムドメインが設定されていません（カスタムドメインのないセルフホストのインスタンス）。 | `domainId` を指定しないか、お使いのインスタンスでカスタムドメインを設定してください。 |
| 504 | `AI_ART_TIMEOUT` | 画像モデルの処理に時間がかかりすぎたため、QRdxはリクエストの1分の制限より前に待機を打ち切りました。AIアートのクレジットは使用されていません。 | もう一度お試しください。通常、呼び出しには15〜45秒かかります。 |

## リトライ [#retrying]

- **`429`:** `Retry-After` に指定された秒数だけ待ってから、同じリクエストを送信してください。1日のクォータを使い切った場合は、`X-RateLimit-*` ヘッダーで、プランで許可されているリクエスト数とカウントがリセットされる時刻（00:00 UTC）を確認できます。[レート制限](/docs/developers/rest-api#rate-limits)を参照してください。
- **`500` と `503`:** 約1秒から始めて、指数バックオフでリトライしてください。
- **その他の `4xx`:** 同じリクエストは同じように失敗します。まずリクエストを修正してください。

コードの作成は冪等ではありません。`POST /v1/codes` がタイムアウトした場合は、再送する前にコードの一覧を取得して確認してください。そうしないと、同じコードが2つ作成されるおそれがあります。変換は冪等です。独自の `id` を送信すると、再送時には `200` と `duplicate: true` が返されます。

## `/v1/me` と `/v1/themes` [#v1me-and-v1themes]

この2つのエンドポイントは、共通のボディに加えて、従来から返しているOAuthのフィールド `error` と `error_description`（`message` と同じテキスト）も返します。これにより、古いクライアントも引き続き動作します。

| `error` | `code` |
| --- | --- |
| `invalid_token` | UNAUTHORIZED または INVALID_TOKEN |
| `insufficient_scope` | INSUFFICIENT_SCOPE |
| `rate_limited` | RATE_LIMITED（1日のクォータ） |
| `not_found` | NOT_FOUND（テーマ） |

## OAuthエンドポイント [#oauth-endpoints]

`https://qrdx.dev/api/oauth` 配下のOAuthエンドポイント（authorize、token、revoke、userinfo）は、代わりにOAuth 2.0標準に従い、`{ "error", "error_description" }` を返します。`error` は `invalid_request`、`invalid_client`、`invalid_grant`、`unsupported_grant_type`、`invalid_token`、`access_denied` のいずれかです。リフレッシュ時に `invalid_grant` が返された場合は、リフレッシュトークンがすでに使用された（リフレッシュのたびに新しいトークンが返されます）、30日後に期限切れになった、またはユーザーがアプリを取り消したことを意味します。ユーザーに再度認可を行ってもらってください。[REST APIとOAuth](/docs/developers/rest-api#get-an-access-token)を参照してください。

## 不明なエンドポイント [#unknown-endpoints]

`/v1` 配下に存在しないパスにアクセスすると、HTMLページではなく、JSONで `404 NOT_FOUND` が返されます。すべてのエンドポイントは[APIリファレンス](/docs/developers/api)で確認できます。
