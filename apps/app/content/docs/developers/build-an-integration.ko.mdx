통합은 곧 OAuth 앱입니다. 사용자가 여러분의 제품에서 **Connect QRdx**를 클릭하고 QRdx 동의 화면에서 앱을 승인하면, 서버는 액세스 토큰을 받아 사용자를 대신해 `https://api.qrdx.dev/v1`을 호출합니다. 호출은 사용자가 승인한 스코프 범위 안에서만 가능합니다.

이 가이드는 앱 만들기, 사용자를 QRdx로 보내기, 코드를 토큰으로 교환하기, API 호출, 이벤트 수신, 등록까지 전체 흐름을 다룹니다.

## 1. OAuth 앱 만들기 [#1-create-an-oauth-app]

[설정 → API 키 및 앱](/dashboard?to=settings/developers)을 열고 **새 앱**을 클릭하세요. 앱은 현재 열려 있는 워크스페이스, 즉 워크스페이스 전환기에서 선택한 워크스페이스에 속합니다. 앱을 만들고 변경할 수 있는 사람은 워크스페이스 소유자뿐이며, 관리자와 멤버는 앱을 볼 수만 있습니다.

| 필드 | 용도 |
| --- | --- |
| 이름, 설명, 로고, 웹사이트 | 동의 화면에 표시됩니다. 정사각형 로고를 업로드하거나 로고의 `https://` 링크를 붙여 넣으세요 |
| 리디렉션 URI | QRdx가 사용자를 다시 보낼 주소이며, 최대 10개까지 등록할 수 있습니다. `https://`만 가능하고, 개발용으로 `http://localhost`(또는 `127.0.0.1`)도 허용됩니다. 와일드카드와 `#fragments`는 사용할 수 없으며, 모든 요청은 등록된 URI 중 하나와 정확히 일치해야 합니다 |
| 스코프 | 앱이 요청할 수 있는 최대 범위입니다. 각 승인 요청에서는 이 중 일부 또는 전부를 요청합니다 |
| PKCE 필수 | 모든 승인 요청에 `S256` 코드 챌린지를 보내야 합니다. 권장하며 기본으로 켜져 있어요 |

앱을 만들면 QRdx가 **클라이언트 ID**와 **클라이언트 시크릿**을 보여 줍니다. 시크릿은 이때 꼭 복사해 두세요. QRdx는 해시만 보관하므로 다시 보여 줄 수 없습니다. 시크릿을 잃어버렸거나 유출되었다면 앱 페이지에서 **시크릿 재생성**을 클릭하세요. 이전 시크릿은 즉시 작동하지 않지만, 이미 연결한 사용자는 연결이 유지됩니다. 앱을 만들 때와 시크릿을 재생성할 때는 먼저 [본인 확인](/docs/help/privacy-and-security/two-step-verification#confirm-its-you)을 요구합니다. 해당 브라우저에서 최근 10분 이내에 확인했다면 생략됩니다.

| 요금제 | 워크스페이스당 OAuth 앱 수 |
| --- | --- |
| 무료 | 1 |
| Pro | 5 |
| Business | 25 |

다른 [한도](/docs/plans-and-limits)와 마찬가지로, 워크스페이스는 소유자들 중 가장 높은 요금제를 적용받습니다.

## 2. 사용자를 QRdx로 보내기 [#2-send-people-to-qrdx]

무작위 `state`와 PKCE `code_verifier`를 생성해 둘 다 사용자 세션에 보관한 다음, 승인 URL로 리디렉션하세요.

```txt
https://qrdx.dev/api/oauth/authorize
  ?response_type=code
  &client_id=<client id>
  &redirect_uri=https://acme.example/oauth/qrdx/callback
  &scope=profile:read codes:read codes:write
  &state=<random value>
  &code_challenge=<BASE64URL(SHA256(code_verifier))>
  &code_challenge_method=S256
```

| 매개변수 | 필수 여부 | 값 |
| --- | --- | --- |
| `response_type` | 예 | `code` |
| `client_id` | 예 | 앱의 클라이언트 ID |
| `redirect_uri` | 예 | 앱의 리디렉션 URI 중 하나, 글자 하나까지 동일해야 함 |
| `scope` | 예 | 공백 또는 쉼표로 구분하며, 앱이 가진 스코프만 가능 |
| `state` | 권장 | 임의의 값이며 QRdx가 그대로 돌려보냅니다. CSRF를 막으려면 이 값을 확인하세요 |
| `code_challenge` | 앱이 PKCE를 요구하는 경우 | 43~128자: `code_verifier`의 SHA-256을 base64url로 인코딩한 값 |
| `code_challenge_method` | 아니요 | `S256`이며 기본값이자 유일하게 허용되는 방식입니다. `plain`은 `invalid_request`로 거부됩니다 |
| `prompt` | 아니요 | `consent`를 지정하면 사용자가 이전에 같은 스코프를 승인했더라도 동의 화면을 표시합니다 |

```ts title="lib/qrdx-oauth.ts"
import { createHash, randomBytes } from "node:crypto";

export const QRDX_AUTHORIZE_URL = "https://qrdx.dev/api/oauth/authorize";

export function createPkce() {
  const verifier = randomBytes(32).toString("base64url"); // 43 characters
  const challenge = createHash("sha256").update(verifier).digest("base64url");
  return { verifier, challenge };
}

export function authorizeUrl({
  state,
  challenge,
}: {
  state: string;
  challenge: string;
}) {
  const url = new URL(QRDX_AUTHORIZE_URL);
  url.search = new URLSearchParams({
    response_type: "code",
    client_id: process.env.QRDX_CLIENT_ID!,
    redirect_uri: "https://acme.example/oauth/qrdx/callback",
    scope: "profile:read codes:read codes:write",
    state,
    code_challenge: challenge,
    code_challenge_method: "S256",
  }).toString();
  return url.toString();
}
```

QRdx에 로그인하지 않은 사용자는 먼저 로그인합니다. 그다음 동의 화면이 나타나며, 여기에는 앱의 로고, 이름, 웹사이트, 만든 사람, 요청한 권한, 로그인한 계정이 표시됩니다. QRdx가 확인하지 않은 앱에는 **확인되지 않은 앱** 안내가 붙습니다. **승인**을 누르면 [본인 확인](/docs/help/privacy-and-security/two-step-verification#confirm-its-you)을 요구하지만, 최근 10분 이내에 확인했다면 생략됩니다(방금 로그인한 경우는 보통 해당됩니다). 같은 스코프를 이미 앱에 승인한 사용자는 곧바로 앱으로 돌아갑니다.

그다음 QRdx는 `redirect_uri`로 리디렉션합니다.

- 승인한 경우: `?code=<authorization code>&state=<your state>`. 코드는 10분 이내에 한 번만 사용할 수 있습니다.
- 취소한 경우: `?error=access_denied&error_description=...&state=<your state>`.

잘못된 요청(알 수 없는 `client_id`, 등록되지 않은 `redirect_uri`, 앱에 없는 스코프, PKCE가 필수인데 챌린지가 없는 경우, `code_challenge_method=plain`)은 리디렉션하지 않습니다. 대신 `{ "error": "invalid_scope", "error_description": "..." }` 같은 JSON 오류를 반환합니다.

## 3. 코드를 토큰으로 교환하기 [#3-exchange-the-code-for-tokens]

서버에서 코드를 토큰 엔드포인트로 POST하세요. 본문은 form 인코딩이어야 하며, `redirect_uri`는 2단계에서 사용한 값과 같아야 합니다.

```bash
curl -X POST https://qrdx.dev/api/oauth/token \
  -d grant_type=authorization_code \
  -d client_id=$QRDX_CLIENT_ID \
  -d client_secret=$QRDX_CLIENT_SECRET \
  -d code=$CODE \
  -d redirect_uri=https://acme.example/oauth/qrdx/callback \
  -d code_verifier=$CODE_VERIFIER
```

```ts title="app/oauth/qrdx/callback/route.ts"
export async function GET(req: Request) {
  const params = new URL(req.url).searchParams;
  const session = await getSession(req); // your own session store
  if (params.get("state") !== session.qrdxState) {
    return new Response("Invalid state", { status: 400 });
  }
  if (params.get("error")) {
    return Response.redirect("https://acme.example/settings?qrdx=cancelled");
  }

  const response = await fetch("https://qrdx.dev/api/oauth/token", {
    method: "POST",
    body: new URLSearchParams({
      grant_type: "authorization_code",
      client_id: process.env.QRDX_CLIENT_ID!,
      client_secret: process.env.QRDX_CLIENT_SECRET!,
      code: params.get("code") ?? "",
      redirect_uri: "https://acme.example/oauth/qrdx/callback",
      code_verifier: session.qrdxVerifier,
    }),
  });
  if (!response.ok) {
    const { error, error_description } = await response.json();
    throw new Error(`QRdx token exchange failed: ${error} ${error_description}`);
  }

  const tokens: {
    access_token: string;
    token_type: "Bearer";
    expires_in: number;
    refresh_token: string;
    scope: string;
  } = await response.json();
  await saveQrdxTokens(session.userId, tokens); // encrypt at rest
  return Response.redirect("https://acme.example/settings?qrdx=connected");
}
```

```json
{
  "access_token": "...",
  "token_type": "Bearer",
  "expires_in": 3600,
  "refresh_token": "...",
  "scope": "profile:read codes:read codes:write"
}
```

`scope`는 부여된 스코프를 공백으로 구분해 나열합니다. 액세스 토큰은 1시간, 리프레시 토큰은 30일 동안 유효합니다. `code_verifier`는 승인 요청에 `code_challenge`가 있었을 때만 보내세요. `code_challenge` 없이 발급된 코드에 verifier를 보내면 거부됩니다.

### 리프레시 토큰 [#refresh-tokens]

액세스 토큰이 만료되기 전에 리프레시 토큰을 새 토큰 쌍으로 교환하세요. 리프레시 토큰은 순환됩니다. 각 토큰은 한 번만 사용할 수 있으므로 매번 새 토큰을 저장하세요.

```bash
curl -X POST https://qrdx.dev/api/oauth/token \
  -d grant_type=refresh_token \
  -d client_id=$QRDX_CLIENT_ID \
  -d client_secret=$QRDX_CLIENT_SECRET \
  -d refresh_token=$REFRESH_TOKEN
```

```ts
export async function refreshQrdxTokens(refreshToken: string) {
  const response = await fetch("https://qrdx.dev/api/oauth/token", {
    method: "POST",
    body: new URLSearchParams({
      grant_type: "refresh_token",
      client_id: process.env.QRDX_CLIENT_ID!,
      client_secret: process.env.QRDX_CLIENT_SECRET!,
      refresh_token: refreshToken,
    }),
  });
  // invalid_grant: revoked, expired or already used. Ask the person to reconnect.
  if (!response.ok) throw new Error((await response.json()).error);
  return response.json();
}
```

토큰 엔드포인트는 IP 주소당 분당 30건의 요청을 허용합니다.

## 4. 스코프 [#4-scopes]

| 스코프 | 허용 범위 |
| --- | --- |
| `profile:read` | 사용자의 ID, 이름, 이메일, 아바타: `GET /v1/me` 및 `GET /api/oauth/userinfo` |
| `themes:read` | 저장된 QR 테마: `GET /v1/themes`, `GET /v1/themes/{id}` |
| `codes:read` | 동적 코드와 스캔 분석, 웹훅 구독 목록 조회 |
| `codes:write` | `codes:read`로 가능한 모든 작업에 더해 코드 생성, 편집, 삭제, 전환 보고, 웹훅 구독 |

통합에 필요한 최소한의 스코프만 요청하세요. 사용자는 동의 화면에서 각 스코프를 확인합니다.

## 5. API 호출하기 [#5-call-the-api]

액세스 토큰을 Bearer 토큰으로 `https://api.qrdx.dev/v1`에 보내세요. 토큰 요청은 앱을 승인한 사용자의 개인 워크스페이스(모든 계정에 하나씩 있습니다)에서 그 워크스페이스의 요금제에 따라 실행됩니다.

```bash
curl https://api.qrdx.dev/v1/codes \
  -H "Authorization: Bearer $ACCESS_TOKEN"
```

```ts
const response = await fetch("https://api.qrdx.dev/v1/codes", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${accessToken}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    destinationUrl: "https://acme.example/menu",
    title: "Spring menu",
  }),
});
const { data: code } = await response.json(); // code.shortLink is what the QR encodes
```

`401`과 `invalid_token`은 토큰이 만료되었거나 취소되었다는 뜻입니다. 토큰을 갱신하거나 사용자에게 다시 연결해 달라고 요청하세요. `403`과 `insufficient_scope`는 토큰에 해당 스코프가 없다는 뜻입니다. 모든 엔드포인트와 필요한 스코프, 오류는 [REST API와 OAuth](/docs/developers/rest-api)에 정리되어 있습니다.

## 6. 웹훅으로 이벤트 받기 [#6-receive-events-with-webhooks]

사용자에게 URL을 붙여 넣게 하는 대신 REST Hooks API로 사용자를 대신해 구독하세요. `codes:write`가 필요하며, 사용자의 요금제에 [웹훅](/docs/webhooks)(Business)이 포함되어 있어야 합니다. 그렇지 않으면 `402 PLAN_REQUIRED`가 반환됩니다.

```bash
curl https://api.qrdx.dev/v1/hooks \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"target_url": "https://acme.example/webhooks/qrdx", "events": ["scan.created", "form.submitted"]}'
```

`201` 응답에는 구독 `id`와 서명용 `secret`이 들어 있으며, 시크릿은 한 번만 표시됩니다. 모든 전송은 이 시크릿으로 서명되어 `X-QRdx-Signature`에 담깁니다. 자세한 내용은 [서명 확인](/docs/webhooks#verify-signatures)을 참고하세요. 사용자가 연결을 해제하면 `DELETE /v1/hooks/{id}`로 구독을 해지하세요. 구독은 사용자 본인 워크스페이스의 설정 → 웹훅에도 표시되며, 거기서 직접 삭제할 수도 있어요.

## 7. 취소와 userinfo [#7-revoke-and-userinfo]

사용자가 여러분의 제품에서 QRdx 연결을 해제하면 해당 토큰을 취소하세요. 한 쌍의 토큰 중 하나를 취소하면 쌍 전체가 취소되며, 엔드포인트는 알 수 없는 토큰에도 `200`으로 응답합니다.

```bash
curl -X POST https://qrdx.dev/api/oauth/revoke -d token=$REFRESH_TOKEN
```

```ts
await fetch("https://qrdx.dev/api/oauth/revoke", {
  method: "POST",
  body: new URLSearchParams({ token: refreshToken }),
});
```

### 액세스 취소 [#revoking-access]

사용자는 언제든 QRdx의 **설정 → 승인된 앱**에서 직접 액세스를 회수할 수 있습니다. 그러면 앱이 해당 계정에 대해 가진 모든 토큰이 즉시 작동하지 않습니다. API 호출은 `401`과 `invalid_token`으로, 갱신은 `invalid_grant`로 응답합니다. 두 경우 모두 "연결 해제됨"으로 처리하고 다시 연결하도록 안내하세요. 사용자에게 동의 화면이 다시 표시됩니다.

누가 연결했는지 확인하려면 `profile:read` 토큰으로 `GET /api/oauth/userinfo`를 호출하세요. OpenID 방식의 클레임을 반환합니다.

```bash
curl https://qrdx.dev/api/oauth/userinfo -H "Authorization: Bearer $ACCESS_TOKEN"
```

```json
{
  "sub": "user id",
  "name": "Ada Lovelace",
  "email": "ada@example.com",
  "picture": "https://..."
}
```

이메일은 바뀔 수 있으므로 `sub`를 변하지 않는 계정 ID로 사용하세요.

## 8. 등록하기 [#8-get-listed]

통합이 처음부터 끝까지 제대로 작동하면 [통합 디렉터리](/integrations)에 추가해 달라고 요청하세요. 여러분이 만든 **커뮤니티** 통합으로 표시됩니다. 아래 내용을 담아 [support@qrdx.dev](mailto:support@qrdx.dev?subject=List%20my%20integration)로 이메일을 보내세요(앱 페이지의 **등록 요청** 버튼을 누르면 세부 내용이 자동으로 채워집니다).

- 앱 이름과 클라이언트 ID
- 앱이 하는 일과 대상 사용자에 대한 한 줄 설명
- 설정 단계 또는 그 링크
- 지원 연락처

QRdx 팀은 등록된 앱을 검토해 **확인됨**으로 표시하며, 그러면 동의 화면에서 "확인되지 않은 앱" 안내가 사라집니다. 확인된 앱의 이름, 로고, 웹사이트를 변경하면 다시 검토를 받을 때까지 배지가 제거됩니다.

## 보안 체크리스트 [#security-checklist]

- 클라이언트 시크릿은 서버에만 보관하세요. 브라우저와 모바일 코드에는 절대 노출하면 안 됩니다.
- 모든 승인 요청에 PKCE(`S256`)와 새 `state`를 사용하고, 돌아왔을 때 `state`를 확인하세요.
- 리디렉션 URI는 정확히 등록하세요. QRdx는 글자 하나까지 비교합니다.

- 사용자가 연결을 해제하면 토큰을 취소하세요. 설정 → API 키 및 앱에서 앱을 삭제하면 발급된 모든 토큰이 취소되고, 앱을 일시 중지하면 다시 시작할 때까지 토큰이 거부됩니다.
