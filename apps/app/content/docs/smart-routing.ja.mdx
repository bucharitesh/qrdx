通常、[動的QRコード](/docs/dynamic-qr-codes)はすべてのスキャンを1つの宛先に送ります。スマートルーティングを使うと、印刷した1つのコードで、iPhoneではApp Store、AndroidではGoogle Playを開いたり、スペイン語圏の訪問者にはスペイン語のページを表示したり、営業時間外には別のオファーを表示したりできます。設定は、[ダッシュボード](/dashboard?to=codes)にあるコードのページの**スマートルーティング**パネルで行います（コードを開き、**設定**タブを開いてください）。

スマートルーティングとUTMパラメータは、ProとBusinessでご利用いただけます。対象は、ウェブサイトのリンクを開くコードです。[ホスト型ページ](/docs/landing-pages)はリダイレクトを行わないため、ルーティングはありません。

## ルールの仕組み [#how-rules-work]

- 1つのコードには、最大20個の**ルール**を設定できます。各ルールには、条件（「いつ」）とアクション（「どうする」）があります。
- ルールはスキャンのたびに**上から順に**チェックされます。**すべての条件に一致した最初のルール**が、スキャンの送り先を決定します。矢印を使ってルールの順序を変更できます。
- どのルールにも一致しない場合、スキャンはコードのメインの宛先に送られます。
- 条件のないルールはすべてのスキャンに一致するため、その下にあるルールは実行されません。
- ルールを**オフ**にすると、削除せずに無効にしておけます。
- 変更は次のスキャンから反映されます。コードを再印刷する必要はありません。

何らかの理由でルールを評価できなかった場合でも、スキャンはメインの宛先に送られます。ルーティングが原因でコードが動作しなくなることはありません。

## 条件 [#conditions]

各条件は**ではない**で反転できます（例：「国が US ではない」）。

| 条件 | 一致する場合 | 備考 |
| --- | --- | --- |
| デバイス | スキャンした人がスマートフォン、タブレット、デスクトップ、その他のデバイスを使っている | ブラウザのユーザーエージェントから判定します |
| オペレーティングシステム | iOS、Android、Windows、macOS、Linux、ChromeOS、HarmonyOS など | iPhoneとiPadはどちらもiOSとして扱われます |
| 国 | スキャンが指定した国のいずれかから行われた | `US, CA, GB` のような2文字のコード |
| 地域 | スキャンが指定した地域のいずれかから行われた | `US-CA, US-NY` のようなコード（国＋行政区画） |
| 言語 | 訪問者のブラウザの優先言語が指定した言語のいずれかである | `es` はスペイン語のすべてのバリエーション（`es-MX`、`es-ES`）に一致し、`pt-BR` はブラジルのポルトガル語のみに一致します |
| 時間帯 | 選択した曜日の、指定したタイムゾーンでの2つの時刻の間にスキャンが行われた | 22:00～02:00 のような時間帯は日付をまたぎ、開始した日の枠として扱われます |
| 期間 | スキャンが2つの日付の間に行われた | 片方を空にすると「まで」または「から」になります。日付はブラウザのタイムゾーンで扱われます |
| スキャン数 | 最初のN回のスキャンのいずれか、またはN回より後のスキャンである | 記録されたスキャン数を数えます（ボットは含まれません）。多くの人が同時にスキャンした場合は概算になります |
| エリア | スキャンした人が、ある地点から半径（100 m～500 km）以内にいる | [精密な位置情報](/docs/precise-location)がオンの場合はスキャンした人が共有した位置情報を使い、そうでない場合はIPアドレスからのおおよその位置を使います |

国、地域、およびエリア判定に使うIPベースの位置情報は、スキャンした人のIPアドレスから取得されます。QRdxがIPアドレスを保存することはありません。位置が不明な場合、位置に関する条件は一致しません（「ではない」条件は一致します）。エリアの詳細や、特定のエリア内でのみ動作するコードの作り方については、[精密な位置情報とジオフェンシング](/docs/precise-location)をご覧ください。

## スマートアプリリンク [#smart-app-links]

**ルールを追加 → スマートアプリリンク**を選ぶと、2つのルールが一度に作成されます。iOSはApp Storeのリンクへ、AndroidはGoogle Playのリンクへ送られます。それ以外（デスクトップやその他のスマートフォン）は、たとえば自社のウェブサイトなど、メインの宛先に送られます。

## A/Bテスト [#ab-tests]

ルールのアクションを**URLに振り分け（A/B）**に設定し、2～5個のバリアントを追加します。各バリアントにはURLと重みを指定します。70と30で振り分けると、訪問者の約70%が最初のURLに送られます。

- 割り当ては**固定**されます。同じ日にもう一度スキャンした訪問者には、同じバリアントが表示されます。これは匿名の日次訪問者ハッシュに基づいており、Cookieは使いません。
- コードのアナリティクスには、振り分けのバリアントまたは重みを最後に変更して以降の**バリアントごとのスキャン数**が表示されます。各スキャンには、表示されたバリアントが保存されます。QRdxがバリアントを保存する前に記録されたスキャンは、現在のルールで再計算され、カードには推定値と表示されます。
- 振り分けにも条件を設定できます（例：「ドイツの訪問者のみを対象としたA/Bテスト」）。

## ルールをテストする [#test-your-rules]

パネル下部の**ルールをテスト**では、デバイス、オペレーティングシステム、国、地域、言語、日時、スキャン番号、訪問者を指定して、スキャンがどこに送られるかを確認できます。保存前の変更内容が反映されます。どのルールに一致したか、ほかのルールが一致しなかった理由、UTMパラメータを含む最終的なURLが表示されます。

## UTMパラメータ [#utm-parameters]

**UTMパラメータ**パネルでは、`utm_source`、`utm_medium`、`utm_campaign`、`utm_term`、`utm_content` と、最大10個の独自パラメータを、各スキャンが開くURLに追加できます。これにより、分析ツールでQRコード経由のトラフィックを区別できます。

- パラメータはルーティングの後に、スキャンの送り先となるURLに追加されます。
- URLにすでに存在するパラメータが置き換えられることはなく、URLのそれ以外の部分は入力したままの状態で保持されます。
- `qrdx_` で始まる名前は、[コンバージョントラッキング](/docs/tracking-and-conversions)用に予約されています。

## プランとダウングレード [#plans-and-downgrades]

Proで保存したルールとUTMパラメータは、ダウングレードしても引き続き動作します。制限されるのは、新規作成のみです。Proでなくなった後も、ルールのオフへの切り替えと削除、UTMパラメータの削除は可能です。変更するには、再びProが必要です。
