QRdx 采用 AGPL-3.0 许可，你可以在自己的服务器上运行 Web 应用（二维码编辑器、账户、两步验证和通行密钥、动态码和托管页面、团队、已保存的主题、社区图库以及本文档）。工作区单点登录和工作区审计日志除外：它们位于商业许可的 `ee/` 文件夹中，除非设置许可证密钥（`QRDX_EE_LICENSE`），否则保持关闭。在生产环境中使用它们需要与 QRdx 签订书面协议，详见 [LICENSING.md](https://github.com/bucharitesh/qrdx/blob/main/LICENSING.md)。使用 [`qrdx` React 库](/docs/getting-started)或 CLI 不需要这些。它们采用 MIT 许可，无需后端即可在任何地方运行。[QRdx 开源](/open-source-qr-code-generator)列出了代码仓库的各个部分及其许可证。

<Callout type="warn">
  Docker 部署方式是新推出的。如果遇到问题，请[提交 issue](https://github.com/bucharitesh/qrdx/issues)。
</Callout>

## 环境要求 [#requirements]

- 带有 Compose v2 和 BuildKit 的 Docker（Docker Desktop 和最新的 Docker Engine 均已包含），或者手动部署所需的 Node.js 22（22.22.3 或更高版本）和 [Bun](https://bun.com/docs/installation) 1.4
- 构建镜像时，Docker 至少需要 8 GB 内存
- 一种登录方式，以便创建账户：GitHub 或 Google OAuth 应用，或用于邮件登录验证码的 [Resend](https://resend.com)。只有当 `NEXT_PUBLIC_APP_URL` 不是 `localhost` 时才会通过邮件发送验证码。`bun run dev` 会改为在终端中打印验证码，但 Docker 镜像不会，因此在本地用 Docker 测试时需要使用 GitHub 或 Google 登录。
- Postgres：`docker-compose.yml` 中自带的容器，或 [Neon](https://neon.tech) 数据库

### 数据库连接的工作方式 [#how-the-database-connection-works]

应用通过 Neon 的无服务器 HTTP 驱动连接 Postgres。

- **Neon：** 可直接使用。将 `DATABASE_URL` 设置为你的 Neon 连接字符串。
- **普通 Postgres：** 前面需要一个与 Neon 兼容的 HTTP 代理。`docker-compose.yml` 会运行一个（[local-neon-http-proxy](https://github.com/TimoWilhelm/local-neon-http-proxy)），并设置 `DATABASE_HTTP_ENDPOINT`，让应用把查询发送到该代理。

数据库架构来自 `packages/database/schema.ts`，通过 `drizzle-kit push` 应用。

## 使用 Docker Compose 快速开始 [#quick-start-with-docker-compose]

### 1. 克隆代码仓库 [#1-clone-the-repository]

```bash
git clone https://github.com/bucharitesh/qrdx.git
cd qrdx
```

### 2. 配置环境 [#2-configure-the-environment]

```bash
cp apps/app/.env.example .env
```

编辑 `.env`：

- `BETTER_AUTH_SECRET`：用 `openssl rand -base64 32` 生成
- `NEXT_PUBLIC_APP_URL`：你的实例的公开 URL，例如 `https://qr.example.com`。本地测试请保持 `http://localhost:3000`。
- `BETTER_AUTH_URL`：取消注释，并使用相同的值
- `GITHUB_CLIENT_ID` / `GITHUB_CLIENT_SECRET`：来自 [GitHub OAuth 应用](https://github.com/settings/developers)，回调 URL 为 `<your url>/api/auth/callback/github`
- 或 `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET`：来自 [Google OAuth 客户端](https://console.cloud.google.com/apis/credentials)，重定向 URI 为 `<your url>/api/auth/callback/google`

你不需要设置 `DATABASE_URL`。Compose 会让应用连接到它自己的 Postgres 容器。如需更改数据库密码，请在首次启动前设置 `POSTGRES_PASSWORD`。

### 3. 启动服务 [#3-start-the-stack]

```bash
docker compose up -d --build
```

这会构建镜像，启动 Postgres 和代理，运行一次性的 `migrate` 服务（`drizzle-kit push`），然后在 3000 端口启动应用。首次构建需要几分钟。

```bash
docker compose ps                    # migrate should show "exited (0)"
docker compose logs -f migrate app   # follow the schema sync and the app
```

### 4. 创建第一个用户 [#4-create-your-first-user]

在浏览器中打开 `NEXT_PUBLIC_APP_URL`，使用 GitHub、Google 或邮件验证码登录。你的账户会在首次登录时创建。

### 5. 创建第一个管理员 [#5-create-your-first-admin]

将你刚创建的账户的邮箱地址添加到 `.env`：

```bash
ADMIN_EMAILS=you@example.com
```

重新创建应用容器以使更改生效，然后登录并打开 `/admin`：

```bash
docker compose up -d app
```

`ADMIN_USER_IDS` 的用法相同，只是填写用户 ID。

## 使用 Neon 或其他托管数据库 [#using-neon-or-another-managed-database]

你可以跳过自带的 Postgres，只运行应用镜像：

```bash
docker build -t qrdx --build-arg NEXT_PUBLIC_APP_URL=https://qr.example.com .
docker run -d --env-file .env -p 3000:3000 qrdx
```

在 `.env` 中将 `DATABASE_URL` 设置为你的 Neon 连接字符串，并保持 `DATABASE_HTTP_ENDPOINT` 不设置。使用迁移镜像应用一次数据库架构（之后每次更新后再应用一次）：

```bash
docker build --target migrator -t qrdx-migrate .
docker run --rm -e DATABASE_URL="<your connection string>" qrdx-migrate
```

## 手动部署（Node.js） [#manual-setup-nodejs]

```bash
git clone https://github.com/bucharitesh/qrdx.git
cd qrdx
bun install

cp apps/app/.env.example apps/app/.env.local            # then edit it

bun run db:push                                          # apply the schema
bun run --filter app dev                                 # http://localhost:3000
```

对于生产环境，构建并启动应用：

```bash
bun x turbo build --filter=app
bun run --filter app start
```

`bun run db:push` 使用 Neon 的驱动连接，因此需要 Neon 数据库。如果想改用 Docker 中的 Postgres 进行本地开发，请用 `docker compose up -d db db-proxy` 启动它，用 `docker compose run --rm migrate` 应用数据库架构，并在 `apps/app/.env.local` 中设置以下内容：

```bash
DATABASE_URL=postgresql://postgres:postgres@localhost:5432/qrdx
DATABASE_HTTP_ENDPOINT=http://localhost:4444/sql
```

## 反向代理与 HTTPS [#reverse-proxy-and-https]

请将应用放在反向代理（如 Caddy、nginx 或 Traefik）之后，由代理终止 TLS，且不要将 3000 端口直接暴露到互联网。速率限制、安全邮件和[审计日志](/docs/help/teams/audit-log)会先读取 `X-Real-IP`，再读取 `X-Forwarded-For` 中的第一个地址来获取客户端 IP，因此代理必须设置这些请求头，并且应用只能通过代理访问。请让代理把 `X-Real-IP` 设置为它收到连接的来源地址（在 nginx 中为 `proxy_set_header X-Real-IP $remote_addr;`）。如果代理只是向 `X-Forwarded-For` 追加地址，客户端就可以把任意地址放在最前面。

HTTPS 设置完成后，请将 `NEXT_PUBLIC_APP_URL` 和 `BETTER_AUTH_URL` 改为 `https://` URL，更新 OAuth 回调 URL，然后重新构建。

### Content-Security-Policy [#content-security-policy]

生产构建会在 QRdx 自己的页面上发送 Content-Security-Policy：已登录页面的每个请求都会获得新的脚本 nonce，预渲染页面则使用脚本主机的允许列表。托管页面（`/p`）使用宽松的策略，因为它们会运行所有者的像素代码，并嵌入来自任意位置的媒体。如果你的反向代理也设置了 `Content-Security-Policy`，浏览器会同时执行两者，因此请不要在代理处设置。设置 `CSP_REPORT_ONLY=1`（构建时和运行时都要设置）可让策略以仅报告模式发送，便于你检查新的配置；违规情况会由 `/api/csp-report` 记录。如果你在 Vercel 之外通过 HTTPS 提供服务，请添加 `CSP_HTTPS=1`，这样浏览器会升级所有 `http://` 资源。

## 更新 [#updating]

请先备份数据库：

```bash
docker compose exec db pg_dump -U postgres qrdx > qrdx-backup.sql
```

然后拉取并重新构建。应用启动前，`migrate` 服务会再次同步数据库架构。

```bash
git pull
docker compose up -d --build
```

对于手动安装，请运行 `git pull`、`bun install` 和 `bun run db:push`，然后重新构建。

如果某次架构变更会丢弃数据，`drizzle-kit push` 会要求确认。这种情况下，请在终端中运行 `docker compose run --rm migrate`，以查看并确认这些变更。
## 故障排查 [#troubleshooting]

- **启动时提示 "Invalid environment variables"：** 日志会列出每个缺失或无效的变量。可选变量必须注释掉，不能设置为空值。
- **提示 "BETTER_AUTH_SECRET is missing" 或 "You are using the default secret"：** 设置 `BETTER_AUTH_SECRET`，然后重新创建容器。
- **OAuth `redirect_uri` 不匹配：** OAuth 应用中的回调 URL 必须严格为 `<NEXT_PUBLIC_APP_URL>/api/auth/callback/<github|google>`。将 `BETTER_AUTH_URL` 设置为相同的基础 URL。
- **应用无法连接数据库（`fetch failed`）：** 使用普通 Postgres 时，`DATABASE_HTTP_ENDPOINT` 必须指向正在运行的代理。请检查 `docker compose ps db-proxy`。
- **`migrate` 一直不结束：** `drizzle-kit push` 正在等待确认。参见[更新](#updating)。
- **修改 `NEXT_PUBLIC_*` 的值后没有生效：** 请重新构建镜像。
- **端口 4444 已被占用：** 修改 `docker-compose.yml` 中 `db-proxy` 的端口映射。只有在主机上进行本地开发时才会用到该端口。
- **提示 "the --mount option requires BuildKit"：** 你的 Docker 没有 BuildKit。请安装 `buildx` 插件，或更新 Docker。
- **构建中途停止，出现 `Killed` 或退出码 137：** Docker 内存不足。请至少分配 8 GB（Docker Desktop：Settings → Resources），然后再次运行 `docker compose up -d --build`。
- **提示 "sign-in code email is off for this deployment"：** 当 `NEXT_PUBLIC_APP_URL` 为 `localhost` 时，不会发送邮箱验证码。本地测试请使用 GitHub 或 Google 登录。
