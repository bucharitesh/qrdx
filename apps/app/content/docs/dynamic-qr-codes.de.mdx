Ein dynamischer QR-Code kodiert einen Kurzlink wie `https://qrdx.dev/q/aB3dE5f` statt deiner endgültigen URL. Beim Scan öffnet sich der Kurzlink, der zum von dir festgelegten Ziel weiterleitet. Du kannst das Ziel jederzeit ändern, gedruckte Codes veralten also nie, und jeder Scan wird gezählt.

Statische QR-Codes aus dem Playground und der `qrdx`-Bibliothek bleiben kostenlos und unbegrenzt. Dynamische Codes benötigen ein QRdx-Konto.

## Dynamischen Code erstellen [#create-a-dynamic-code]

- **Dashboard:** Öffne das [Dashboard](/dashboard), klicke auf **Neuer Code**, gib die Ziel-URL und optional einen Titel ein. Lade den Code als PNG, WebP oder SVG herunter.
- **Playground:** Wähle den Inhaltstyp **URL**, gib deinen Link ein und aktiviere **Dynamisch machen**. Der QR-Code wechselt zu einem Kurzlink und behält dein Design bei. Wenn du die URL später bearbeitest, klicke auf **Auf neue URL umleiten**, um das Ziel zu aktualisieren. **Design im Code speichern** speichert das aktuelle Design zusammen mit dem Code.

Ziele müssen `http://`- oder `https://`-Links sein. Links mit Benutzernamen oder Passwort sowie Links zu anderen QRdx-Kurzlinks werden abgelehnt.

## Eigene Kurz-Endungen [#custom-back-halves]

Jeder Code erhält eine zufällige 7-stellige Endung, also den Teil nach `/q/`. Mit Pro und Business kannst du stattdessen eine eigene wählen, etwa `https://qrdx.dev/q/spring-menu`: Fülle beim Erstellen oder Bearbeiten eines Codes das Feld **Eigene Kurz-Endung** aus. Der Dialog zeigt dir während der Eingabe an, ob sie frei ist.

- 3 bis 64 Zeichen: Buchstaben, Ziffern, `-` und `_`, nicht beginnend oder endend mit `-`.
- Kurz-Endungen unterscheiden Groß- und Kleinschreibung, wie generierte: `Spring-Menu` und `spring-menu` sind zwei verschiedene Links.
- Auf `qrdx.dev` ist eine Kurz-Endung über ganz QRdx hinweg eindeutig, und Wörter, die wie QRdx-Seiten aussehen (`admin`, `api`, `docs`, `login`, `pricing`, `settings`, ...), sind reserviert.
- Auf deiner eigenen [Custom Domain](/docs/custom-domains) muss sie nur auf dieser Domain eindeutig sein, und nur `api`, `p` und `q` sind reserviert. Daher funktioniert `go.yourbrand.com/pricing`. Eine solche Endung gehört zur Domain: Sie hat keinen `qrdx.dev/q/`-Link.
- Wenn du die Kurz-Endung eines Codes änderst, ändert sich sein Link: QR-Codes, die mit der alten gedruckt wurden, funktionieren nicht mehr, also lade den Code erneut herunter.

## Codes verwalten [#manage-codes]

Im Dashboard kannst du:

- **Link bearbeiten:** Ziel oder Titel ändern. Der gedruckte Code funktioniert weiter und öffnet beim nächsten Scan das neue Ziel.
- **Typ ändern:** einen Website-Link in eine [gehostete Seite](/docs/landing-pages) umwandeln, eine Seite wieder in einen Link oder eine Seite in einen anderen Seitentyp. Der Kurzlink und die Scans bleiben erhalten. Siehe [Ändern, was ein gedruckter Code öffnet](/docs/help/dynamic-codes/change-the-type).
- **Design im Playground bearbeiten:** öffnet den Code im Editor, weiterhin an seinen Kurzlink gebunden.
- **Archivieren:** Der Kurzlink zeigt eine Seite „Nicht mehr aktiv“, bis du den Code wiederherstellst. Archivierte Codes zählen nicht zu deinem Tarif-Limit.
- **In den Papierkorb verschieben:** Der Kurzlink zeigt eine Seite „Nicht mehr aktiv“ (HTTP 410), und der Code zählt nicht mehr zu deinem Tarif. Stelle ihn über **Papierkorb** wieder her oder lösche ihn dort endgültig, was auch seinen Scan-Verlauf entfernt; der Kurzlink zeigt danach die Seite „QR-Code nicht gefunden“. Löschen über die API (`DELETE /v1/codes/{id}`) ist sofort endgültig.
- **Duplizieren:** kopiert Ziel, Design, Ordner, Tags und Notizen in einen neuen Code mit neuem Kurzlink und ohne Scans.
- **Versionsverlauf:** Jede Änderung wird auf der Seite des Codes protokolliert. Beim Wiederherstellen einer Version werden zuerst die aktuellen Einstellungen gespeichert, sodass sich eine Wiederherstellung rückgängig machen lässt.

## Codes organisieren [#organize-codes]

- **Ordner:** Verschachtle bis zu 5 Ebenen tief. Ziehe Codes auf einen Ordner oder nutze **In Ordner verschieben**. Beim Löschen eines Ordners rücken seine Codes und Unterordner eine Ebene nach oben.
- **Tags:** Filtere nach mehreren Tags, um Codes zu finden, die alle davon haben.
- **Favoriten und Notizen:** Markiere Codes mit einem Stern und halte private Notizen fest; Notizen sind durchsuchbar.
- **Suche** umfasst Titel, Ziele, Notizen, Tags und Kurz-Endungen (füge einen Kurzlink ein, um seinen Code zu finden).
- **Massenaktionen:** Wähle Codes aus, um sie zu verschieben, zu taggen, pausieren, archivieren, favorisieren, in den Papierkorb zu legen oder als ZIP mit PNG-, WebP- oder SVG-Dateien herunterzuladen.
- **CSV-Import:** **Codes → Importieren** erstellt bis zu {facts.importRows} dynamische Codes aus einer CSV-Datei (Ziel, Titel, Ordner, Tags, optional eine eigene Kurz-Endung in der Spalte `slug`). Außerdem kann jeder Code in einen Ordner einsortiert und allen Codes Tags hinzugefügt werden. Ein langer Import lässt sich pausieren und setzt nach einem Neuladen oder einem Verbindungsabbruch fort, ohne doppelte Codes zu erzeugen. Am Ende stehen eine Ergebnis-CSV (mit dem Kurzlink jeder Zeile) und ein ZIP mit den Codes als PNG oder SVG. Der Import von mehr als einer Zeile und eigene Kurz-Endungen erfordern Pro.

Codes gehören zu dem Workspace, in dem sie erstellt werden. Jedes Mitglied des Workspaces kann sie erstellen und bearbeiten; Mitglieder können ihre eigenen Codes löschen, Inhaber und Admins dagegen jeden Code im Workspace.

<Callout type="info">
  Codes laufen nie ab: Ein Tarifwechsel nach unten schaltet bestehende Codes nie ab. Über dem Limit kannst du Codes weiterhin bearbeiten und archivieren, nur erstellen oder wiederherstellen kannst du keine weiteren, bis du wieder darunter liegst.
</Callout>

## Tarife [#plans]

| | Kostenlos | Pro | Business |
| --- | --- | --- | --- |
| Aktive dynamische Codes | 10 | Unbegrenzt | Unbegrenzt |
| Scans | Unbegrenzt | Unbegrenzt | Unbegrenzt |
| Scan-Verlauf | {facts.freeScanHistoryYears} Jahr | Unbegrenzt | Unbegrenzt |
| Massenerstellung über die API | Nein | Bis zu {facts.apiBatchCodes} pro Anfrage | Bis zu {facts.apiBatchCodes} pro Anfrage |

Die Codes eines Workspaces nutzen den besten Tarif unter seinen Inhabern. Siehe [Tarife und Limits](/docs/plans-and-limits) für alles Weitere, was jeder Tarif enthält.

## Scan-Analysen [#scan-analytics]

Jeder Code hat eine Analyseseite mit Scans im Zeitverlauf, eindeutigen Besuchern, Top-Ländern und -Städten, Geräten, Betriebssystemen, Browsern und Referrern für die letzten 7, 30 oder 90 Tage, 1 Jahr oder 3 Jahre oder für die gesamte Zeit seit dem ersten Scan des Codes (begrenzt durch den Verlauf deines Tarifs: Gesamtzeit gibt es bei Pro und Business). Du kannst die Scans im gewählten Zeitraum als CSV exportieren.

Das wird für jeden Scan erfasst:

- Zeit (UTC) sowie Land, Region und Stadt, sofern die Hosting-Plattform sie liefert (Vercel-Geo-Header auf qrdx.dev)
- Gerätetyp, Betriebssystem und Browser, erkannt anhand des User-Agents
- Nur der Hostname des Referrers, nie die vollständige URL. Die meisten QR-Scans haben keinen Referrer.
- Ein Besucher-Hash: ein gesalzener SHA-256 aus IP-Adresse, User-Agent und Tag. Er zählt eindeutige Besucher pro Tag; die IP-Adresse selbst wird nie gespeichert.
- Bei Pro und Business, wenn der Code [eine genaue Standortangabe anfragt](/docs/precise-location) und der Scanner dies erlaubt: sein Standort, auf 3 Dezimalstellen gerundet (etwa 100 m), und die Genauigkeit, die sein Browser gemeldet hat

Bekannte Bots, Link-Vorschauen und Browser-Prefetches werden nicht gezählt.

## REST API [#rest-api]

Verwalte Codes programmatisch unter `https://api.qrdx.dev/v1/codes`. Anfragen werden mit einem [API-Schlüssel](/docs/developers/api-keys) oder einem OAuth-Zugriffstoken authentifiziert (`Authorization: Bearer <key or token>`), das den Scope `codes:read` oder `codes:write` hat. Wie du einen davon bekommst, steht unter [REST API](/docs/developers/rest-api). Ein Schlüssel wirkt auf den Workspace, in dem er erstellt wurde. Token-Anfragen wirken auf deinen eigenen Workspace. Anfragen aus einer angemeldeten Browser-Sitzung funktionieren ebenfalls und wirken auf den Workspace, den du zuletzt im Dashboard geöffnet hast.

| Methode | Pfad | Beschreibung |
| --- | --- | --- |
| `GET` | `/v1/codes` | Codes auflisten. Abfrage: `status` (`active`, `archived`, `all`), `q`, `limit` (≤ 100), `offset` |
| `POST` | `/v1/codes` | Einen Code oder ein Array mit bis zu {facts.apiBatchCodes} Codes erstellen (Arrays erfordern Pro). Body: `destinationUrl`, optional `title`, `style`, `domainId` und `slug` |
| `GET` | `/v1/codes/{id}` | Einen Code abrufen |
| `PATCH` | `/v1/codes/{id}` | `destinationUrl`, `title`, `style`, `domainId` ([eigene Domains](/docs/custom-domains)), `slug` oder `archived` aktualisieren oder `kind` zwischen `redirect` und `page` wechseln |
| `DELETE` | `/v1/codes/{id}` | Einen Code und seine Scans löschen |
| `GET` | `/v1/codes/{id}/scans` | Analysen für `range` (`7d`, `30d`, `90d`, `365d`, `1095d` oder `all` bei Pro und Business; begrenzt durch den Verlauf deines Tarifs). Füge `limit` (≤ 500) für einzelne Scans hinzu und `before` (das letzte `scannedAt`) für die nächste Seite |

Einen Code erstellen:

```bash
curl https://api.qrdx.dev/v1/codes \
  -H "Authorization: Bearer $QRDX_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"destinationUrl": "https://example.com/menu", "title": "Spring menu"}'
```

```json
{
  "data": {
    "id": "cm3x...",
    "slug": "aB3dE5f",
    "shortLink": "https://qrdx.dev/q/aB3dE5f",
    "defaultShortLink": "https://qrdx.dev/q/aB3dE5f",
    "domain": null,
    "destinationUrl": "https://example.com/menu",
    "title": "Spring menu",
    "contentType": "url",
    "kind": "redirect",
    "pageId": null,
    "status": "active",
    "style": null,
    "scanCount": 0,
    "lastScannedAt": null,
    "archivedAt": null,
    "createdAt": "2026-10-31T12:00:00.000Z",
    "updatedAt": "2026-10-31T12:00:00.000Z",
    "organizationId": null
  }
}
```

Übergib `slug`, um den hinteren Teil der URL festzulegen (Pro und Business; die Regeln stehen unter [eigene hintere URL-Teile](#custom-back-halves)). Mit einer `domainId` wird er auf dieser Domain geprüft, sonst auf `qrdx.dev`:

```bash
curl https://api.qrdx.dev/v1/codes \
  -H "Authorization: Bearer $QRDX_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"destinationUrl": "https://example.com/menu", "slug": "spring-menu"}'
```

Die Antwort enthält dann `"slug": "spring-menu"` und `"shortLink": "https://qrdx.dev/q/spring-menu"`. Ein auf einer eigenen Domain gewählter hinterer Teil hat `"defaultShortLink": null`, weil er nur auf dieser Domain existiert. In einem Array muss jedes `slug` unterschiedlich sein.

### Viele Codes in einer Anfrage [#many-codes-in-one-request]

Bei Pro und Business kannst du ein Array mit bis zu {facts.apiBatchCodes} Codes senden. Generierte hintere URL-Teile wiederholen sich innerhalb des Batches nie und kollidieren nicht mit bestehenden Codes. Links, die Google Web Risk nicht rechtzeitig prüfen kann, werden kurz nach dem Erstellen des Batches erneut geprüft. Ein Code, dessen Link die Prüfung als unsicher meldet, wird deaktiviert ([Sicherheitsprüfungen](/docs/code-controls#safety-checks-on-links)). Ein Batch gilt als Ganzes oder gar nicht: Hat eine Zeile ein Problem (ein ungültiges Ziel, ein belegtes oder reserviertes `slug`, ein unsicherer Link), wird nichts erstellt. Der Fehler `data.details` listet jedes Problem nach `index` auf, also der Position der Zeile im Array (ab 0).

Sende einen `Idempotency-Key`-Header mit einem Wert, der für den Batch eindeutig ist, etwa eine UUID. Wenn die Anfrage in ein Timeout läuft oder die Verbindung abbricht, sende dieselbe Anfrage mit demselben Schlüssel erneut: Du bekommst die Codes zurück, die der erste Versuch erstellt hat, mit dem Header `Idempotent-Replayed: true`. Ein Versuch, der mittendrin abgebrochen wurde, wird abgeschlossen, ohne dass Codes doppelt entstehen.

```bash
curl https://api.qrdx.dev/v1/codes \
  -H "Authorization: Bearer $QRDX_TOKEN" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: 6f1c2a9e-spring-tables" \
  -H "Prefer: return=minimal" \
  -d '[{"destinationUrl": "https://example.com/table/1", "title": "Table 1"},
       {"destinationUrl": "https://example.com/table/2", "title": "Table 2"}]'
```

Jeder Code kommt mit seinem Design zurück. Wenn das Standard-Theme deines Workspaces ein Logo einbettet, summiert sich das bei einem großen Batch. Sende `Prefer: return=minimal`, um jeden Code ohne `style` zu erhalten (also ID, Slug, Links, Ziel, Titel, Status und Erstellungszeit). Ein Batch, dessen Antwort nicht in 4 MB passt, wird mit `PAYLOAD_TOO_LARGE` abgelehnt, bevor etwas erstellt wird.

Ziel ändern:

```bash
curl -X PATCH https://api.qrdx.dev/v1/codes/cm3x... \
  -H "Authorization: Bearer $QRDX_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"destinationUrl": "https://example.com/summer-menu"}'
```

`style` akzeptiert dieselben Designfelder wie der Playground (`fgColor`, `bgColor`, `bodyPattern`, `cornerEyePattern`, `level`, ...). Für ein Logo sende `logoIcon`<IfAvailable feature="fileStorage"> oder die `logoFileId` einer hochgeladenen Datei</IfAvailable> ([Logos im Style eines Codes](/docs/developers/rest-api#code-logos)). Kodiere `shortLink` in deinen QR-Code, zum Beispiel mit der [`qrdx`-Bibliothek](/docs/getting-started) oder der [Image API](/docs/developers/image-api).

Fehler verwenden ein einheitliches JSON-Format, `{ "code": "...", "message": "...", "status": 400 }`, zusätzlich einen `docs`-Link, wenn eine Seite die Lösung erklärt:

| Status | Code | Wann |
| --- | --- | --- |
| 400 | `VALIDATION_ERROR`, `INVALID_SLUG` | Ungültiger Body oder ungültige Abfrage (Details in `data`, bei einem Batch nach `index`) oder ein `slug`, das die Regeln verletzt oder reserviert ist |
| 401 | `UNAUTHORIZED`, `INVALID_TOKEN` | Kein `Authorization: Bearer`-Token oder ein ungültiges, abgelaufenes oder widerrufenes Token ([Token abrufen](/docs/developers/rest-api#get-an-access-token)) |
| 402 | `LIMIT_REACHED`, `PLAN_REQUIRED` | Über dem aktiven Code-Limit deines Tarifs oder Massenerstellung bzw. eigener `slug` ohne Pro |
| 403 | `INSUFFICIENT_SCOPE`, `FORBIDDEN` | Token ohne den nötigen Scope oder eine Workspace-Rolle, die das nicht darf |
| 404 | `NOT_FOUND` | Der Code existiert nicht oder gehört nicht dir, oder der Endpunkt existiert nicht |
| 409 | `SLUG_TAKEN` | Ein anderer Code verwendet dieses `slug` bereits (auf `qrdx.dev` oder auf der eigenen Domain) |
| 429 | `RATE_LIMITED` | Zu viele Anfragen; wiederhole sie nach dem `Retry-After`-Header |

## Self-Hosting [#self-hosting]

Dynamische Codes funktionieren auch auf selbst gehosteten Instanzen:

- `NEXT_PUBLIC_SHORT_LINK_BASE_URL` legt den Ursprung der Short-Links fest. Standardmäßig wird deine App-URL verwendet.
- `SCAN_HASH_SALT` legt den geheimen Salt für die Besucher-Hashes fest. Ohne ihn wird einer aus `BETTER_AUTH_SECRET` abgeleitet.
- Land, Region und Stadt kommen aus den Geo-Headern von Vercel. Hinter Cloudflare ist nur das Land verfügbar (`CF-IPCountry`); anderswo werden Standorte als unbekannt angezeigt.
- Gebietsregeln verwenden die IP-Koordinaten von Vercel (`x-vercel-ip-latitude`, `x-vercel-ip-longitude`), wenn ein Scanner keinen Standort geteilt hat. Anderswo treffen sie nur Scans mit einem geteilten Standort.
- Rate-Limits greifen, wenn Upstash Redis konfiguriert ist.
