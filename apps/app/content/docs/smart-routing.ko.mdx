[동적 QR 코드](/docs/dynamic-qr-codes)는 보통 모든 스캔을 하나의 목적지로 보냅니다. 스마트 라우팅을 사용하면 인쇄된 코드 하나로 iPhone에서는 App Store를, Android에서는 Google Play를 열 수 있습니다. 스페인어를 쓰는 방문자에게는 스페인어 페이지를, 영업시간 외에는 다른 혜택 페이지를 보여줄 수도 있습니다. [대시보드](/dashboard?to=codes)의 코드 페이지에 있는 **스마트 라우팅** 패널에서 설정합니다(코드를 열고 **설정** 탭을 여세요).

스마트 라우팅과 UTM 파라미터는 Pro와 Business에 포함됩니다. 웹사이트 링크를 여는 코드에 적용되며, [호스팅 페이지](/docs/landing-pages)는 리디렉션하지 않으므로 라우팅이 없습니다.

## 규칙 작동 방식 [#how-rules-work]

- 코드 하나에 최대 20개의 **규칙**을 만들 수 있습니다. 각 규칙에는 조건("언제")과 동작("그러면")이 있습니다.
- 스캔할 때마다 규칙을 **위에서 아래로** 확인합니다. **모든 조건이 일치하는 첫 번째 규칙**이 스캔의 이동 위치를 결정합니다. 화살표로 규칙 순서를 바꿀 수 있습니다.
- 일치하는 규칙이 없으면 스캔은 코드의 기본 목적지로 이동합니다.
- 조건이 없는 규칙은 모든 스캔과 일치하므로, 그 아래의 규칙은 실행되지 않습니다.
- 규칙을 삭제하지 않고 사용하지 않으려면 **끄세요**.
- 변경 사항은 다음 스캔부터 적용되며, 코드를 다시 인쇄할 필요가 없습니다.

어떤 이유로 규칙을 평가할 수 없어도 스캔은 기본 목적지로 이동합니다. 라우팅 때문에 코드가 작동하지 않는 일은 없습니다.

## 조건 [#conditions]

각 조건은 **아님**으로 반전할 수 있습니다(예: "국가가 US가 아님").

| 조건 | 일치하는 경우 | 참고 |
| --- | --- | --- |
| 기기 | 스캔하는 기기가 휴대폰, 태블릿, 데스크톱 또는 기타 기기일 때 | 브라우저의 user agent 기준 |
| 운영체제 | iOS, Android, Windows, macOS, Linux, ChromeOS, HarmonyOS 등 | iPhone과 iPad는 모두 iOS로 간주 |
| 국가 | 나열한 국가 중 한 곳에서 스캔했을 때 | `US, CA, GB`와 같은 2자리 코드 |
| 지역 | 나열한 지역 중 한 곳에서 스캔했을 때 | `US-CA, US-NY`와 같은 코드(국가 + 하위 구역) |
| 언어 | 방문자의 브라우저 선호 언어가 나열한 언어 중 하나일 때 | `es`는 모든 스페인어 변형(`es-MX`, `es-ES`)과 일치하고, `pt-BR`은 브라질 포르투갈어만 일치 |
| 시간대 | 선택한 요일에, 직접 고른 시간대 기준으로 두 시각 사이에 스캔했을 때 | 22:00–02:00 같은 구간은 자정을 넘어가며 시작하는 요일에 속함 |
| 날짜 범위 | 두 날짜 사이에 스캔했을 때 | 한쪽을 비워 두면 "까지" 또는 "부터"가 되며, 날짜는 브라우저의 시간대 기준 |
| 스캔 횟수 | 처음 N번의 스캔이거나 N번 이후의 스캔일 때 | 기록된 스캔을 셉니다(봇은 제외). 여러 사람이 동시에 스캔하면 근삿값이 됩니다 |
| 영역 | 스캔한 사람이 한 지점에서 반경(100 m~500 km) 안에 있을 때 | [정밀 위치](/docs/precise-location)가 켜져 있으면 스캔한 사람이 공유한 위치를, 아니면 IP 주소의 대략적인 위치를 사용 |

국가, 지역, 영역에 쓰이는 IP 기반 위치는 스캔한 사람의 IP 주소에서 얻으며, QRdx는 이 IP 주소를 저장하지 않습니다. 위치를 알 수 없으면 위치 조건은 일치하지 않습니다("아님" 조건은 일치합니다). 영역에 대한 설명과 코드를 특정 영역 안에서만 작동하게 하는 방법은 [정밀 위치와 지오펜싱](/docs/precise-location)에서 확인하세요.

## 스마트 앱 링크 [#smart-app-links]

**규칙 추가 → 스마트 앱 링크**를 선택하면 규칙 두 개가 한 번에 만들어집니다. iOS는 App Store 링크로, Android는 Google Play 링크로 이동합니다. 그 외(데스크톱, 다른 휴대폰)는 웹사이트 같은 기본 목적지로 이동합니다.

## A/B 테스트 [#ab-tests]

규칙의 동작을 **URL 간 분할(A/B)**로 설정하고 URL과 가중치가 있는 변형을 2개에서 5개까지 추가하세요. 70과 30으로 분할하면 방문자의 약 70%가 첫 번째 URL로 이동합니다.

- 배정은 **고정**됩니다. 같은 날 다시 스캔한 방문자는 같은 변형을 받습니다. 쿠키가 아니라 익명의 일일 방문자 해시를 기준으로 합니다.
- 코드의 분석에는 분할의 변형이나 가중치가 마지막으로 바뀐 이후의 **변형별 스캔**이 표시됩니다. 각 스캔에는 제공된 변형이 저장됩니다. QRdx가 변형을 저장하기 전에 기록된 스캔은 현재 규칙으로 다시 계산하며, 카드에 추정치로 표시됩니다.
- 분할에도 조건을 둘 수 있습니다. 예를 들어 "독일 방문자에게만 A/B 테스트"처럼 설정할 수 있습니다.

## 규칙 테스트 [#test-your-rules]

패널 하단의 **규칙 테스트**에서는 저장하지 않은 변경 사항을 사용해, 기기, 운영체제, 국가, 지역, 언어, 날짜와 시간, 스캔 번호, 방문자별로 스캔이 어디로 이동할지 보여줍니다. 어떤 규칙이 일치했는지와 다른 규칙이 일치하지 않은 이유를 나열하고, UTM 파라미터를 포함한 최종 URL도 보여줍니다.

## UTM 파라미터 [#utm-parameters]

**UTM 파라미터** 패널은 `utm_source`, `utm_medium`, `utm_campaign`, `utm_term`, `utm_content`와 직접 정한 파라미터(최대 10개)를 각 스캔이 여는 URL에 추가하여, 분석 도구가 QR 트래픽을 구분할 수 있게 합니다.

- 파라미터는 라우팅 이후에, 스캔이 이동하는 URL에 추가됩니다.
- URL에 이미 있는 파라미터는 절대 대체되지 않으며, URL의 나머지 부분은 입력한 그대로 유지됩니다.
- `qrdx_`로 시작하는 이름은 [전환 추적](/docs/tracking-and-conversions)용으로 예약되어 있습니다.

## 요금제와 다운그레이드 [#plans-and-downgrades]

Pro에서 저장한 규칙과 UTM 파라미터는 다운그레이드해도 계속 작동합니다. 한도는 새로 만드는 것만 막습니다. Pro가 없어도 규칙을 끄거나 삭제하고 UTM 파라미터를 제거할 수 있지만, 변경하려면 다시 Pro가 필요합니다.
