ホスト型ページでは、QRdxにアップロードしたファイルを表示できます。メニューやパンフレットのPDF、フォトギャラリー、音楽やポッドキャスト、動画などです。アップロードしたファイルは **ダッシュボード → ファイル** に保存され、アップロードしたワークスペースに属します。それぞれのファイルには固定のリンクがあり、ファイルを差し替えても引き続き使えます。

## アップロードできるファイル [#what-you-can-upload]

| 種類 | 形式 |
| --- | --- |
| PDF | PDF |
| 画像 | JPEG、PNG、WebP、GIF、AVIF |
| 音声 | MP3、M4A、AAC、Ogg、WAV |
| 動画 | MP4、WebM、MOV |

H.264動画のMP4は、すべてのブラウザで再生できます。スマートフォンで撮影したMOVファイルも多くの場合は再生できますが、ブラウザで再生できないときはMP4に変換してください。SVG、HTML、アーカイブ、Officeドキュメントはアップロードできません。これは、ストレージから配信されるものが訪問者のブラウザ上でコードを実行できないようにするためです。

アップロードされたファイルは、使用前にすべて検証されます。サイズが事前に通知された値と一致していること、先頭のバイト列が実際にその種類のファイルであることが条件です（`.pdf` に名前を変えたHTMLページは拒否されます）。拒否されたアップロードはストレージから削除され、**ブロック済み** として一覧に表示されます。

## プランごとの上限 [#limits-per-plan]

| プラン | ワークスペースあたりのストレージ | 最大ファイルサイズ |
| --- | --- | --- |
| フリー | 50 MB | 10 MB |
| Pro | 5 GB | 100 MB |
| Business | 50 GB | 250 MB |

ワークスペースには、オーナーが持つプランのうち最上位のものが適用されます。上限が制限するのは新規アップロードだけです。ダウングレード後や、ワークスペースがストレージ容量を超えている場合でも、すでにアップロードしたファイルは、それを使っているすべてのページで引き続き配信されます。新しくアップロードするには、不要なファイルを削除するか、プランをアップグレードしてください。

## ページでファイルを使う [#use-files-on-a-page]

ファイルを表示できるブロックは5種類あります。どのブロックも、アップロードしたファイルか、他の場所にあるファイルへのリンクを使えます。

- **PDF** は、タブレットとパソコンではドキュメントをページ内に表示し、**PDFを開く**（スマートフォンではフルスクリーンビューア）ボタンと **ダウンロード** ボタンを備えます。
- **ギャラリー** は、写真を1〜3列のグリッドで表示します。写真をタップするとフルスクリーンで開き、スワイプまたは矢印キーで切り替えられます。
- **音声** は、カバー画像とプレイリスト付きでトラックを再生し、1曲が終わると次のトラックが始まります。ダウンロードボタンは任意です。
- **動画ファイル** は、アップロードしたMP4またはWebMを再生します。GIFのようにミュートでループ再生することもできます。YouTube、Vimeo、Loomの動画には、代わりに **動画** ブロックを使ってください。再生をタップするまでYouTubeからは何も読み込まずに、動画を埋め込めます。
- **ダウンロード** は、保存できるファイルを一覧にし、それぞれに個別のラベルを付けられます。

**新規コード** の **PDF**、**画像**、**MP3 / 音声**、**動画** のページタイプでは、これらのブロックがあらかじめ配置された状態で始められます。

ブロックでは、**アップロード** で端末からファイルを追加するか、**マイファイルから選択** で以前アップロードしたファイルを再利用するか、リンクを貼り付けます。

## ファイルの差し替えと削除 [#replace-or-delete-a-file]

**ダッシュボード → ファイル** を開き、ファイルの横にあるメニューを使います。

- **リンクをコピー** は、ファイル自身のリンク（`https://qrdx.dev/api/files/<id>`）をコピーします。このリンクは動的QRコードの転送先としても使えます。
- **ファイルを差し替え** は、同じリンクのまま新しい内容をアップロードします。たとえば来シーズンのメニューに差し替えられます。そのファイルを使っているページやコードには、1分以内に新しいバージョンが表示されます。差し替えられるのは同じ種類のファイルだけです（PDFはPDFで差し替えます）。
- **削除** は、ファイルを完全に削除します。ページやコードがまだそのファイルを使っている場合は、先にQRdxがそれらを一覧表示します。削除後、それらのページではファイルがあった場所に「ファイルは利用できません」と表示されます。

メンバーは自分がアップロードしたファイルを差し替え・削除できます。オーナーと管理者は、ワークスペース内のすべてのファイルを管理できます。

## 報告されたファイル [#reported-files]

すべてのホスト型ページには **不正利用を報告** リンクがあります。ファイルがルールに違反している場合や、著作権者から削除を求められた場合、QRdxはそのファイルをブロックできます。ブロックされたファイルは、1分以内にすべてのページとQRdxのリンクでの配信が停止され（ページには「ファイルは利用できません」と表示されます）、同一のコピー（25 MBまで）は再度アップロードできなくなります。

## ストレージの設定（セルフホスト） [#set-up-storage-self-hosting]

ファイルのアップロードには [Cloudflare R2](https://developers.cloudflare.com/r2/) を使用します。設定しない場合、ファイルページには「このサーバーではストレージが設定されていません」と表示され、アップロードAPIは `503` を返します。ブロックでは、他の場所にあるファイルへのリンクは引き続き使えます。

1. Cloudflareのダッシュボードで **R2** を開き、バケットを作成します（例：`qrdx-files`）。
2. **R2 → Manage API tokens** で、そのバケットに対して **Object Read & Write** の権限を持つトークンを作成します。
3. 次の環境変数を設定して再起動します。

   ```bash
   R2_ACCOUNT_ID=your-cloudflare-account-id
   R2_ACCESS_KEY_ID=token-access-key-id
   R2_SECRET_ACCESS_KEY=token-secret-access-key
   R2_BUCKET=qrdx-files
   # Optional: serve files from a public bucket URL or custom domain
   R2_PUBLIC_BASE_URL=https://files.example.com
   ```

4. バケットにCORSポリシーを追加します（**Settings → CORS policy**）。ブラウザはR2へ直接アップロードするため、バケットはアプリのオリジンからの、`Content-Type` ヘッダー付きの `PUT` リクエストを受け付ける必要があります。

   ```json
   [
     {
       "AllowedOrigins": ["https://qrdx.example.com", "http://localhost:3000"],
       "AllowedMethods": ["PUT", "GET", "HEAD"],
       "AllowedHeaders": ["Content-Type"],
       "ExposeHeaders": ["ETag"],
       "MaxAgeSeconds": 3600
     }
   ]
   ```

   `https://qrdx.example.com` は、ダッシュボードを開くときに使うオリジン（スキームとホスト、末尾のスラッシュなし）に置き換えてください。`http://localhost:3000` は、ローカルの開発サーバーからアップロードする場合にのみ残してください。

### 公開ファイルか署名付きリンクか [#public-files-or-presigned-links]

訪問者は常に `/api/files/<id>` からファイルを開きます。このURLは保存されたオブジェクトへリダイレクトします。

- `R2_PUBLIC_BASE_URL` を設定した場合（バケットに接続したカスタムドメイン、またはその `r2.dev` URL。後者はCloudflareがレート制限をかけており、テスト用途のみ推奨されています）は、公開URLにリダイレクトします。オブジェクトキーにはランダムなIDが含まれるため、ファイルを一覧表示したり推測したりすることはできません。
- 設定しない場合、バケットは非公開のままで、リダイレクトは常に1時間で期限切れになる署名付きリンクになります。

どちらの場合も、差し替え、削除、ブロックされたファイルは、1分以内にQRdxのリンクでの配信が停止されます。ブロックされたファイルは、公開URLからも直ちに外れます。そのオブジェクトはランダムな部分を含む `quarantine/` キーに移動され（管理者が復元できるように保持されます）、QRdxのリンクは `410 Gone` を返します。

ブラウザは `staging/` キーにアップロードします。アップロードの検証が済むと、QRdxは検証したバージョンそのものをファイル自身のキーにコピーします。そのため、まだ有効なアップロードリンクがあっても、検証済みのファイルを置き換えることはできません。

<Callout type="info">
  完了しないアップロードは、2時間後にストレージ使用量に含まれなくなり、次にそのワークスペースへ誰かがアップロードするときにクリーンアップされます。バケットにオブジェクトのライフサイクルルール（**Settings → Object lifecycle rules**）を追加し、プレフィックスが `staging/` のオブジェクトを1日後に削除するようにしてください。中断されたアップロードの残りも削除されます。
</Callout>
